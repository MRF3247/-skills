# 周报分析：分层口径与北极星指标

适用于平台导出的阅读/互动明细（公众号、行为类后台）。一个月里往往只有几天有真实流量，**月度均值会被个别爆款污染**；先按自然周切，再谈结论。

## 从后台截图读周数据（人工截图 → 周汇总表）

流程：`+record-list` 找本期附件 `file_token` → `+record-download-attachment` 下载 image.png → `vision_analyze` 整图读全指标 → 用已填好的同表账号行反推映射 → 按 `record_id` 更新空行 → `+record-get` 读回。

小红书「笔记数据总览」（右上角切「近7日」/「近30日」）→ 周汇总表字段：

| 周汇总表字段 | 截图指标 |
|---|---|
| 阅读 | **观看数**（不是曝光数） |
| 点赞 | 点赞数 |
| 分享 | 分享数 |
| 留言 | 评论数 |
| 粉丝数 | **总粉丝数（存量）**，这一页没有，须另取 |
| 周 | 统计周期（如 `10-19 至 10-25` = w44） |

- **存量 vs 流量**：`粉丝数`/总粉丝/累计粉丝一律是存量；净涨粉、新增关注、取消关注是流量。截图上两类同时出现时，先认口径再填数。
- 「笔记数据总览」页只有涨粉三件套，**不显示总粉丝数**；总粉丝在「粉丝数据」页或账号主页。每周更新这一格需要单独来源，提前跟用户约定。
- 用已填行反推映射能验证「哪个数字填哪格」，但验证不了语义——净涨粉凑巧等于已填的粉丝数时尤其危险，存量字段对不上就问，别推断。

## 六层分析（每层都带真实数字）

| 层 | 算什么 | 典型结论形态 |
|---|---|---|
| 1 总量盘点 | 总阅读、日均、**中位数**、零读数天数、发文数 | 日均被单日拉高、中位数才反映常态；零读数天多说明没持续运营 |
| 2 渠道结构 | 私域（消息/会话/朋友圈/主页）vs 公域（推荐/搜一搜）绝对值与占比 | 推荐占九成以上 = 流量靠算法不靠订阅关系 |
| 3 搜索长尾 | 搜一搜占比、对应标题数 | 占比极低 = 标题没埋搜索词，没有持续流量 |
| 4 内容集中度 | top1 占全周/全月比例、**剔除爆款后的篇均与中位数** | 单篇占九成 = 成绩等于一篇爆款，日常水位才是真基线 |
| 5 互动质量 | 分享人数/阅读人数、收藏同口径、跳转原文人数 | 爆款周互动率反而下降 = 公域泛流量只读不转 |
| 6 节奏与归因 | 发布日对齐阅读、峰值滞后发布日几天、周内哪几天出峰 | 脉冲式（发一篇涨两天后归零）；推荐延迟常以多日滞后体现 |

## 三个北极星指标（长期只看这三个）

1. **剔除爆款后的篇均阅读** —— 内容基本盘，不看它就会被爆款骗。
2. **收藏率 + 分享率** —— 内容值不值得存/转；比阅读量真实。
3. **私域阅读绝对值** —— 订阅关系有没有长大；公域流量不沉淀就不算资产。

## 口径陷阱（先写清再给数）

- 首尾周常被导出窗口截断（如首周只有 2 天），对比只拿**完整周**；不完整周要标出天数。
- 「分享人数/阅读人数」是人数比，**不是转化率**（分子分母口径不同），只能看量级。
- 发布日 ≠ 流量日：推荐池延迟会让峰值出现在发布后数日，这类归因必须标「推断」而不是「实锤」。
- 「全部/合计」行已经包含各渠道，拆分表里要排除，否则重复计数。
- 篇数与有数据篇数对不上时（如发文 11 篇、来源表只 4 篇），先确认剩余篇目是真的 0 阅读还是漏导，不要直接当结论。

## 跨账号/跨平台对比：先看平台机制，再比数

- **服务号不参与推荐流**：导出里「推荐」列恒为 0，流量≈100% 私域（消息+会话+主页+搜一搜）；同名公众号同期推荐可占九成以上。两者总阅读差几十倍是机制决定的，**不能当成内容质量差距**。
- 对比不看总量，改比 **私域占比 / 分享率 / 篇均阅读**。服务号常见「阅读少但分享率高」——能点开的人更精准。
- 「发得少所以没流量」要先证伪：先算 阅读/发文（触达）。触达只有个位数时，加发只会稀释；问题在粉丝盘与推送入口，不在频率。
- 跨平台口径先标明再汇总：公众号=阅读/推荐，视频号=播放，小红书=曝光/观看/封面点击率。把「曝光」和「阅读」放同一轴对比会直接得出错结论。

## 同一指标在不同平台不是同一列（跨账号汇总前先对表）

| 大盘指标 | 公众号 / 服务号（`tendency.xls`） | 小红书（近30日导出） | 口径差异 |
|---|---|---|---|
| 阅读 | 渠道日趋势·渠道=全部·**阅读人数** | **观看** | 人数 vs 次数 |
| 分享 | 账号日指标·**分享人数** | **分享** | 人数 vs 次数 |
| 收藏 | 账号日指标·**微信收藏人数** | **收藏** | 人数 vs 次数 |
| 点赞 | **导出里没有**（后台单篇图文有「赞」「在看」两个数，需另采） | **点赞** | 公众号要 赞+在看 才等于一个「点赞」 |
| 涨粉 | **导出里没有**（用户分析模块才有新增/取消关注） | **净涨粉** / 新增关注 / 取消关注 | 公众号需另采 |
| 粉丝总数 | 用户分析模块（存量，不在导出里） | 粉丝数据页/账号主页（存量） | 存量口径，不能拿净涨粉顶替 |
| 发文 | 账号日指标·发表篇数 | 总发布（图文+视频） | 视频计入与否不同 |
| 额外可用 | 跳转阅读原文人数、渠道结构（搜一搜/推荐/朋友圈） | 曝光 / 评论 / 主页访客 / 完播率 / 封面点击率 | 小红书有曝光可算曝光→观看转化 |

跨账号汇总的落地方式：源表能取到的全进长格式 helper 表（含 评论/曝光/主页访客/新增关注/取消关注/跳转原文），取不到的留 null 并在组件名标注覆盖范围；「点赞」保持统一列（公众号一旦补采，取 赞+在看 并入）。

## 主动声明做不了的

缺粉丝数/送达数 → 算不出打开率；缺涨粉数 → 算不出转化；缺完读率 → 算不出内容留存；周数太少（<6 周）→ 不做显著性/回归，相关系数不可信。把这些列出来，比硬算一个假结论有价值。
