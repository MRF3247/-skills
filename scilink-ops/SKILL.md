# SciLink 运营综合（发布登记 + 周数据 + 看板核对）

创作完成后的全部运营动作都在这本 Base 里。下面三段就是完整循环，不要拆成多个 skill。

## When to Use

- 用户发来**已发布**稿件的飞书云文档链接 → 做「发布登记」。
- 用户（或每周提醒）把上周后台数据截图/Excel 放进多维表格 → 做「周数据填表」。
- 填完数据后 → 做「看板核对」（只看数字对不对，**不碰样式**）。
- 关键词：发布日历、发布记录、物料、周数据、每周数据、粉丝数、看板、仪表盘、运营提醒。

## 运营节奏（用户定下的固定流程）

1. **发布后**：用户发云文档链接 → 我登记选题/物料/发布日期/发布账号。
2. **每周**：我提醒用户把上周各平台后台数据截图放进多维表格 → 用户放好 → 我汇入「周数据汇总」。
3. **填完**：我核对仪表盘数字是否正确，**有异常只向用户汇报，不擅自改看板样式**。

# 一、发布登记（发布日历）

| 字段 | 类型 | 填法 |
|---|---|---|
| 选题 | text | 云文档标题（`<title>` 内容，原样）|
| 物料 | text(url 样式) | Markdown 链接 `[标题](云文档链接)` |
| 发布日期 | datetime | `YYYY-MM-DD`（存 `00:00:00+08:00`）|
| 发布账号 | select（多选）| 只能已有选项 |

发布账号选项：`刀客轻研🍠`、`刀客轻研服务号`、`刀客轻研公众号`、`刀客轻研SciLink🍠`、`梧柚官号`、`梧柚素人`。

默认组合（资讯/科研/文献解读类）：**`刀客轻研公众号` + `刀客轻研SciLink🍠`**（用户原话：跟已有记录里那两个账号一样）。方法/工具/科研干货类历史上用 `刀客轻研服务号` + `刀客轻研🍠`，不确定时问一句。梧柚系列不归本流程。

步骤：

1. 取标题：`lark-cli docs +fetch --doc '<URL或token>' --as user`，从 `data.document.content` 开头的 `<title>…</title>` 取（wiki/docx 都行）。备选（仅 wiki）：`wiki +node-get --node-token <tok>`。
2. **发布日期**用户没说就问，不臆测“今天”。
3. 查重：先 `+record-list` 看同链接/同选题是否已登记。
4. 写入：

```bash
lark-cli base +record-batch-create --base-token Ub3bbJcwsacKULs03Ysc3UmBnCe \
  --table-id tbltQrk5R0TtQmWi \
  --json '{"create_records":[{"选题":"<标题>","物料":"[<标题>](<url>)","发布日期":"2026-10-27","发布账号":["刀客轻研公众号","刀客轻研SciLink🍠"]}]}' --as user
```

5. 核验：`+record-get --record-id <新id>` 读回四字段再回话。

已登记示例：选题`ESMO新数据：小细胞肺癌维持治疗进展`；物料`[ESMO2026｜ESMO新数据：小细胞肺癌维持治疗进展](https://my.feishu.cn/wiki/FJmPwcPCuiMxXDkNH77c0cKAnIf)`；2026-10-27；公众号 + SciLink🍠（选题截掉了“ESMO2026｜”前缀；默认用全标题，遇前缀确认一句）。

## 指标映射（小红书）

| 表格字段 | 后台指标 |
|---|---|
| 阅读 | 观看数 |
| 曝光 | 曝光数（**只有小红书两号有**；公众号/服务号留空，不要填 0）|
| 点赞 | 点赞数 |
| 分享 | 分享数 |
| 留言 | 评论数 |
| 粉丝数 | **当周末总粉丝数** = 上周总粉丝数 + 本周净涨粉（净涨粉 = 新增关注 − 取消关注）|

⚠️ 粉丝数填**总粉丝数**，不是净涨粉。
- **小红书**：截图没有粉丝总数，只能累加：本周总粉丝 = 上周总粉丝 + 净涨粉（新增关注−取消关注）。
- **公众号/服务号**：用户会传两张图，「数据概况」给阅读/点赞/分享/在看/留言，「用户分析-用户增长」给**累计关注人数**（直接当粉丝数用，不需累加）；该页的「周↑x%」可用来自校上一周记录（例：43 对应 +10.26% → 上周 39，与表一致）。
⚠️ 周号 = **ISO 周号**（`date.isocalendar()[1]`，周一→周日）：`w43 = 2026-10-19→10-25`、`w42 = 10-12→10-18`、`w41 = 10-05→10-11`、`w40 = 09-28→10-04`。2026-10-26 全表校正过（原普遍写大 1）。

## 取数与写入

1. 读源：`+record-list --table-id tblrjNRl7QJFxDQV --format ndjson --output ./t1.ndjson --overwrite`，取目标周附件 file_token。
2. 下载：`+record-download-attachment --table-id tblrjNRl7QJFxDQV --record-id <rid> --file-token <tok> --output ./x.xlsx --overwrite`。路径只能相对 cwd；已存在必须 `--overwrite`。
3. 取数：Excel 用 `/Users/Jin/.hermes/cache/scratch/xlsvenv/bin/python`（本机无 pandas，该 venv 已装 openpyxl + xlrd），按 `isocalendar()[1]` 分箱；截图用 `vision_analyze` 读曝光/观看/点赞/评论/净涨粉/新增关注/取消关注并核对周期。
4. 粉丝基线：从最早一周前总粉丝数逐周累加净涨粉；无基线问用户。
5. 写入：`+record-batch-update --json '{"update_records":{"<rid>":{"阅读":285,"点赞":21,"分享":6,"留言":6,"粉丝数":104,"周":"w43"}}}'`。字段是 number，写数字；缺行用 `+record-batch-create`。
6. 核验：`+record-get` / `+record-list` 读回。

## 用导出 Excel 做历史周聚合

- 观看趋势→阅读；**曝光趋势→曝光**（仅小红书）；点赞趋势→点赞；评论趋势→留言；分享趋势→分享；净涨粉趋势→粉丝数累加。
- 公众号/服务号是 `tendency_*.xls`：sheet0，A 块(col1 日期/col2 渠道/col3 阅读人数)，B 块(col5 日期/col6 分享人数)。
- ⚠️ 公众号 xls **只取「渠道=全部」行**，全渠道相加会重复计数（实测 3113 会变 6233；分享 38 不受影响）。
- 公众号/服务号导出只有阅读人数和分享人数，**点赞/留言/粉丝数要向用户要**（用户会手填；公众号粉丝 39 确实是总数，阅读高来自「推荐」渠道）。
- 对拍习惯：先算最新一周与已填值比（285/21/6/6、3113/38、53/4），对不上就是映射或周界错了。

## 行顺序（用户指定）

- 表格无排序配置，行顺序 = 创建顺序。要求：**周升序（w40→w43）**，周内账号固定 **公众号 → 服务号 → 小红书：刀客轻研SciLink → 小红书：刀客轻研**。
- 新增一周按这个顺序追加，不要按账号批量插。
- 顺序错了只能重建：`+record-delete --json '{"record_id_list":[…]}` --yes` 再按目标顺序 `+record-batch-create`。Bitable 无移动单行 API。

## 字段与公式

- **曝光**（fld3O0QBcc，number）：仅小红书两号填值，源为截图「曝光数」或导出 xlsx 的「曝光趋势」；已回填 w40→w44。
- 自算「观看÷曝光」只能当内部转化参考，**不等于后台的「封面点击率」**（例：w44 刀客轻研 408/3366=12.1%，后台封面点击率写 6.8%），汇报时别混用。
- 阅读/点赞/分享/留言/粉丝数 已是 **number** 类型；新增数据写数字。
- **总互动**（fldIyp47bc）= `[点赞]+[留言]+[分享]`。互动类图表用它，不要 combo 拆 3 指标。
- **周涨粉**（fldZh3hYbr）= 本行粉丝数 − 同账号上一周粉丝数（无基线周返 0）：
  `IF(COUNTA([周数据汇总].FILTER(CurrentValue.[账号]=[账号]&&CurrentValue.[周]="w"&TEXT(VALUE(RIGHT([周],2))-1,"00")).[粉丝数])=0,0,[粉丝数]-SUM(…同上…LISTCOMBINE()))`

# 三、看板核对（只核对，不改样式）

看板：`blk0ftlLBLIVUk3H`，已接近定稿。布局：左上「日历」视图块(x0 y0 w9 h6，用户自己加的，不要动)，其下第一排 5 张指标卡(x0 y6 起)：累计阅读、上周总阅读、上周涨粉、总粉丝、**小红书上周总曝光**；再下：周阅读(line 全宽)、涨粉趋势(line)、互动趋势(line)、分享量构成(pie)。

- 小红书上周总曝光 = `series 曝光 SUM + filter 周 is 当周`（公众号/服务号曝光为空，SUM 自动忽略）。

**每周填完数据后的核对清单**（逐项用 `+dashboard-block-get-data` 取数，与手算比）：

1. 累计阅读 = 所有周所有账号阅读之和。
2. 上周总阅读 = 最新周阅读合计；总粉丝 = 最新周粉丝合计；上周涨粉 = 最新周周涨粉合计。
3. 三条折线的横轴应为 **周**（不是账号），每个账号一条线，条数 = 账号数。
4. 数值异常（如某周骤降/为 0、粉丝数倒退、互动大于阅读）先怀疑自己的取数或周号，再向用户汇报。

**纪律**：看板样式（组件增减、图表类型、布局坐标、名称、配色）一律不改；发现样式类问题只描述并等用户拍。只有用户明确要求时才连续做结构变更。

指标卡换周提醒：**每进新一周，四张卡的 filter 周号（上周总阅读/上周涨粉/总粉丝/小红书上周总曝光）要同步改成新周**——这属于数据口径维护，不算改样式，但改完要告诉用户。

布局调试技巧：多块同时改坐标容易与未移动的块瞬时重叠、被服务端自动重排；可靠做法是**先把要动的块全部搛到远处暂存区（如 y30+ 逐个堆叠），再依次放入最终坐标**。用户手动加过块（如「日历」view）时，先 `+dashboard-block-list` 读现状再动，别把它的位置覆盖了。

技术注意：X 轴 = 第一个 group_by；组件 `type` 不可改（需 delete `--yes` 后重建），删除会让服务端重排布局；`+dashboard-block-get-data` 首次常返 `null`，重试几次。
