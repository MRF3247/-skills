# 分层合成方案实测记录（2026-08，10 套风格）

## 结论：整块插画 + HTML 分层排版 + 视觉审核（8-9.2/10）

> **⚠️ 最终判定（2026-08-06 同日稍后）**：用户看过 v5 后仍说「用 html 让你排版果然还是不行，要么设计和排版都用 AI 生图引擎做吧」——**整个 HTML 分层渲染路线被最终否决**。v5 的设计语言（文字长在画面里/阶梯错落/徽章贴纸感/留白克制）是**正确的设计方向**，但要**翻译成生图提示词**（见 ai-fullposter-direct.md 的 DESIGN_LANG 与 gen_ai_fullposter.py），而不是继续走 HTML 渲染。本文件其余内容保留作「设计语言字典」与历史参考。

用户两轮否决后的收敛方案：引擎出「上图下文整块插画（自带下方留白区）」→ HTML 排文字层 → Chrome headless 导出 → MiniMax 视觉审核。完整流程见 SKILL.md「分层合成方案（最终收敛）」一节。

## v5 定稿方案（2026-08-06，用户强纠正后的正解）

### 核心发现
- 插画是 1776×2368 = **正好 3:4，与 1242×1656 同比例 → 整幅铺满 object-fit:cover 零裁切**。之前 v4 把它切成上方 1242px + 底下贴 414px 新背景 = 把插画自带的留白切掉又贴了块布，硬切根源在此。
- **10 套插画底部都自带干净留白区**（S1-S5/S7-S9 浅色、S6/S10 深色，用 PIL 采样底部 15% 平均亮度确认）。文字直接叠上去 = 「文字长在画面里」（春日海报/Let's Park 参考的核心手法），零接缝问题。

### 封面 v5 结构
```
整幅插画铺满（1242×1656，零裁切）
+ 文字区 absolute bottom（无背景块，只有 padding）
  kicker 小眉题（字距 12px）
  主标题：宋体衬线 96px，两行阶梯错落（row2 margin-left 92px），强调字换色
  「5步法」徽章：圆角+描边+rotate(-6deg) 贴纸感（涂鸦风）
  副标题：一句话 ≤30px（砍掉 hashtag 行——用户嫌字多）
+ 深色系底部两段渐变蒙版兜底（rgba(0,0,0,0.5)→0.15→0，高 460px）
  浅色系不需要蒙版（插画留白本身够干净），seam 高 60px 几乎透明
```

### 关键决策（每条对应排版参考笔记）
- **文字砍半**：只留 kicker + 两行标题 + 徽章 + 一句话副标。hashtag 行砍掉（「设计的质感」留白克制 + 用户嫌字多）。方法卡同理：标题去重、金句拆两行（金句 quote 单独一行衬线大字号 + 进度 progress 小字分开）。
- **标题阶梯错落**：两行不等长 + 第二行右缩进（活人感封面：不追求绝对对齐）。避免 v3/v4 的「两行换色双焦点」。
- **徽章贴纸感**：rotate(-6deg) + 圆角 + 3px 描边 + 阴影（涂鸦风：像随手贴的标签）。
- **字体**：标题 Songti SC（宋体，学术古典感，文艺封面参考）；正文 PingFang。深浅色系各自配色（浅底深字/深底浅字，PIL 采样亮度 >150 深字 <150 浅字）。
- **深色系兜底蒙版**：两段渐变（底部 0.5 → 45% 处 0.15 → 透明），保证辅助文字可读又不遮画面（3D 科技/复古印刷这类深色插画必须，浅色系不需要）。
- 配色严格取自插画主色（S6 青蓝紫、S10 金棕），文字与插画同一色谱（配色 6 法参考）。

### 布局 bug 教训（v4.4 修过）
- **tags 绝对定位（position:absolute; bottom:34px）会与副标题重叠**：内容短时 flex center 布局把 sub 下探压到 tags 上。修复：tags 改 flow 布局（margin-top），textzone 内全部用文档流，别混 absolute。
- 副标题与标签重叠的根因是「absolute 元素不占文档流」，文字区内容高度变化时必踩。规则：**文字区内所有层级一律 flow 布局**。

### 方法卡 v5
- 整幅插画铺满 + 顶部标题直接叠画面（不再贴实底 headband 色块——那也是一种「贴块」）：用同色系渐变遮罩（shade-top 520px）兜底标题可读性。
- STEP 徽章：实底胶囊（hl 色底 + 反白字），放标题行前（「数字+概念开场」参考）。
- 标题去重：kicker 写「文献检索 · 第一步」，title 只写「锁定领域」，副标题 subtitle 写方法——v3 曾把「锁定领域」写两遍。
- 信息卡：圆角 16px + 2px 描边 + 左侧 8px 色条 + 阴影（教学卡参考）；浅色系白卡深字、深色系深卡浅字（不透明度 0.92+，深色背景必须够实否则边界溶解）。
- 底部金句拆两行：quote（衬线 34px 加粗 + 左侧色条）与 progress（23px 小字）分开——「先找源头再看热点」曾被混进一行进度里。
- 文案去重：副标题/顶部引导卡/底部金句不要反复讲同一句（v4 曾三处重复「先找源头」），引导卡改讲「被引频次」，金句讲「慢就是快」。

## 引擎 prompt 模板（实测 8-9 分）

封面：
```
竖版海报主视觉插画（3:4），<风格提示词>。画面：<医学科研主体元素>。
画面下方留出约四分之一高度的干净空白区（无任何元素）供排版文字。高细节，无文字
```

方法卡背景：
```
竖版知识卡片背景插画（3:4），<风格提示词>。画面：<装饰元素>，
中间是干净的<底色>空白区域（约占画面六成，无任何元素）供排版文字。极简构图，大量留白，高细节，无文字
```

要点：必须写「无文字」；留白区要明说「干净空白区」；风格提示词直接抄视觉风格家谱各家族「风格提示词（中文）」。
⚠️ **留白必须与插画同色系渐变**（用户明确纠正，反例 S4 纯白留白被否）：prompt 里写「下方留白区与画面整体同色系渐变过渡、自然融合」，不能是突兀的白色/异色块。

## HTML 分层模板要点（compose_posters_v5.py）

- **插画整幅铺满**（.art 1242×1656 object-fit:cover），文字 absolute bottom 叠留白区，无独立文字背景块
- 深色系：`.seam` 两段渐变蒙版（bottom 0.5 → 45% 0.15 → 透明，高 460px）；浅色系 seam 高 60px 几乎透明
- 文字区层级全 flow（**禁止 absolute 混排**，见布局 bug 教训）
- 标题宋体 Songti SC；徽章 rotate(-6deg) 贴纸感；row2 阶梯缩进
- 模板用 `${key}` 占位 + str.replace 填充（CSS 花括号与 str.format 冲突）
- 深浅色判定：PIL 采样插画底部 15% 平均亮度，>150 浅底深字 / <150 深底浅字

## Chrome 导出要点

- `--force-device-scale-factor=2 --virtual-time-budget=8000`（10MB 大图必须等加载，否则 broken image）
- file:// URL 必须完整 quote：`"file://" + quote(os.path.abspath(path))`（中文路径）
- img src 用绝对 file:// URI，不用相对路径（HTML 在子目录时相对路径解析错）

## 视觉审核迭代顺序（每轮实测收敛）

1. v3 首轮必出问题（可读性：背景压字）→ 加实底背板（v4 做法）
2. v4 二轮（衔接：接缝生硬）→ 加渐变遮罩
3. v4 三轮（配色/风格微调）→ 收敛 8.5-9.2 —— **但用户仍否决：框架错了，精致化无用**
4. v5 换框架（整幅铺满 + 文字长画面）→ 用户认可，评分 7.5-8.5（分数比 v4 略低是因为 v5 不再用背板遮丑，但方向对了）
