## 2. 腰部选题库（waist_lib.py）

- 评论抓取：ThreadPoolExecutor(8)，复用 `.comments_cache/{bvid}.json`（fetch_comments 缓存），1,950 条约 15-25 分钟
- LLM 分析：**按主题分组、每批 40 条打包**（不逐条）→ 每主题输出：
  1) 共性选题模式（2-4 个，各带证据）
  2) 评论区用户诉求/痛点（**原话引用**，从评论样本挑）
  3) 最具冷启动价值的 3 个选题标题（可直接用）
  4) 高赞播代表样本表
- 11 主题 ≈ 45-50 批 ≈ 25-30 分钟；产出 `内容增长/腰部选题库.md`
- 同一主题大组（如其他/泛内容 1,601 条）分 41 批，每批 30-60s

## 4. 已踩的坑（复现路径）

1. **fans=0**：catalog `account.fans` 枚举时多为 0 → 从 accounts.yaml 读；accounts.yaml fans 是「46.49万」字符串 → `_parse_fans`（endswith 万 → float×10000）；账号名别名（医学SCI文献解读（医嘉研）vs 医学SCI文献解读）→ 双向 startswith 别名表。
2. **静默截断**：waist 存 `[:300]`、每主题 `min(len,120)` → 报告标题说全量实际抽样。修复：全量分批，无上限。教训：批量分析脚本的样本数必须打印出来供核验（`主题分布: {...}`）。
3. **% 格式化崩**：`"...赞播比≥4%..." % (...)` 中 % 后跟全角「」→ `unsupported format character`。LLM prompt 统一 f-string。
4. **ad-hoc 验证模式**：脚本改动后写临时验证（tempfile hermes-verify- 前缀）：单元断言（_parse_fans 边界）+ 集成断言（2-4 账号画像字段完整/数值合理），跑完清理。
5. **目录合并去重**：编号体系演进产生同账号多目录（不同批次内容互补），合并时同名文件按内容 md5 去重、不同加「（旧批次）」后缀，删空目录；用户可反悔排除类操作 → 保证可回滚。
