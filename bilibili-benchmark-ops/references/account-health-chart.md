## 为什么用月度中位数（核心设计决策）

B站稿件播放量是**累计值**：2021 年稿件播放 8 万可能是攒了 5 年，2026 年新稿 8 千可能才发几天。
直接按发布时间画原始播放折线 → 横轴越靠右天然越低，**误判"账号衰落"**（实际是积累时间短）。
解法：按月聚合取中位数——每月发稿的典型表现，消除积累效应。

## 图元素

- 折线（绿）：月度播放中位数，左轴
- 柱状（半透明蓝）：月发稿数，右轴（区分"衰退"（发了没人看）与"停更"（没发））
- 着色点：月度平均赞播比 ≥4% 绿 / 2-4% 黄 / <2% 红（质量维度，与流量维度解耦）
- 虚线参考线：全时段播放中位数（低于线=低于自身常态）
- 粉色星：爆款 TOP3（月内出现峰值的内容）

## 健康度评级算法（build() 内联）

- 趋势：近12月中位 ÷ 前12月中位 → >1 上升 / ≥0.5 平稳 / <0.5 衰退
- 质量：全部稿件平均赞播比 → ≥4% 优 / ≥2% 良 / <2% 差
- 活跃：近12月发稿数 → ≥12 活跃 / ≥6 低活跃 / <6 濒停
- 综合：上升+优良=健康上升；平稳+优良+活跃=健康平稳；衰退或濒停=衰退/停更；否则亚健康

注意：评级对"发得多但中位跌"（如顺利毕叶 156 篇但趋势衰退）会标衰退——合理（热度下降）。
对"更新少但中位高"（大师兄 7 篇/年中位 6.8 万）标衰退/停更——**需结合评级卡明细解读**（它只是更新少，内容仍强）。

## 踩过的坑

1. **fans 格式**：catalog `account.fans` 可能是 0 或 "29.2万" 字符串 → `_fans_num()` 解析（万×10000），模板显示时用 `x.xx万` 格式且模板里不要再加"万"字（会出"29.20万 万"）
2. **Python % 格式化 vs HTML/CSS %**：模板含 `width:100%`、JS `'%'` 等，用 `%` 占位会崩（unsupported format character）→ 模板用 `__KEY__` 占位 + `str.replace` 链式填充
3. **catalog glob 混入 _summary.json**：`.catalog/*.json` 会匹配 `_summary.json`（顶层是 list 不是 dict）→ `d["account"]` 报 `TypeError: list indices must be integers` → 必须跳过 `"_summary" in f`
4. **表格渲染前验证**：生成后用浏览器（本地 http.server + browser_navigate/vision）截图确认 Canvas 折线/柱状/参考线正常
