# 平铺表情包库合并（N 主题包 → 一个内容命名平铺库）

变体用途：把「按主题/来源分文件夹」的表情包库（如 30 个小红书主题包）并成一个与 GIF动图 同形态的
内容命名平铺库（`NNN-内容名.ext`）。2026-09-02 实测：315 文件（30 包）→ 静态表情包/ 308 件，用户 3 问确认后一次执行。

## 流程

1. **先问清 3 个决定**（用户确认过才动手）：① 平铺库放哪/叫什么（与既有库并列的子文件夹，如 `静态表情包/`）；② 原主题文件夹移空后删除 vs 保留双份（推荐删除 + 来源信息归档进新 README）；③ 跨包重复图 dHash≤8 留清晰版删重 vs 全保留（本用户素材库惯例=去重）。
2. **库存盘点**：文件数/扩展名/总像素（PIL）；排除 `.DS_Store`、README；混在里面的 **mp4 抽首帧**（`ffmpeg -y -i x.mp4 -frames:v 1 frame.jpg`）后按帧内容命名，视频本体同库保留原扩展名。
3. **MiniMax-M3 全量识图**（并发 5，断点续传 JSON，每 10-15 条落盘）：prompt 要一行 `内容：<8~25字可区分同系列的中文短名>`，不要序号引号。见 image-asset-curation 的 references/minimax-m3-batch.md。
4. **文件名清洗**：去全角/半角标点、空格、`/\\:*?"<>|`，保留 CJK/字母/数字/`-`；重名内容追加 `-2`；≤60 字符。
5. **dHash 判重（≤8 位海明距离）**：keeper = 分辨率最高（w*h，平局看文件大小）；重复图**移入 `_整理记录<日期>/去重图/` 暂存而非 rm**（可回滚、用户可复查后清空）。
6. **命名映射 + 产物**（放 `_整理记录<日期>/`）：`rename_map.csv`（原相对路径→新位置→原包）、`回滚.py`（读 csv 反向 move + 重建目录）、`去重明细.md`（keeper↔移出对照）。
7. **执行**：判重图先移出 → 保留图 `mv` 进平铺库（全局序号 001..N，按原包排序保持同包相邻）→ 删除空主题文件夹（跳过保留目录）→ 校验：平铺库数 = 保留数、无重名、原目录零残留。
8. **README 改归档风格**：顶部说明重组时间/结构/映射位置；原逐包来源帖链接+赞藏数据降级为「来源档案」附录保留（历史张数注明以 rename_map.csv 为准）。

## 坑（实测）

- **判重账本别算反**：`kept = 全部文件 − removed_set`（removed_set = 各判重簇的**被删方**并集），不是「不在 keeper_map 里的」——keeper_map 的 key 只有保底方，按 key 排除会把被删方全留在计划里导致执行时源文件已移走而崩溃。写完校验 `len(kept) + len(removed) == 总数`。
- 模型会幻觉人物身份/动作（如把吃冰棍说成啃肉）——抽查可疑命名，抽时间轴帧复核（细节见 gif-meme-collection 技能「抽查」节）。
- 别动 `GIF动图/` 等未要求整理的目录；`.DS_Store` 全程排除。
- 可复用脚本（本用户工作区）：`~/Documents/Hermes/表情包整理/` 下 recognize.py（识图）、merge_plan.py（判重+计划+样本预览）、execute.py（执行+映射+回滚生成）。
