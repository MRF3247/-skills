# 资料／教材宣传图文：PDF 截图配方 + 双版本成稿

场景：用户给一本 PDF（教材、手册、资料包），要「目录截图 + 图文并茂页截图放到云文档，再写小红书版和公众号图文版」。这类稿不是资讯解读稿：没有研究设计、没有 ⚠️ 口径段，主体是「痛点 → 资料能解决什么 → 里面有什么 → 怎么拿」的引流结构。

## 一、从 PDF 取截图

前提：本机 `python3` 有 `fitz`（PyMuPDF）。`execute_code` 的沙箱解释器没有它，直接用 `terminal` 调 `python3`。

### 1 · 先摸清每一页是什么

```python
import fitz
d = fitz.open(pdf)
for i, pg in enumerate(d):
    txt = pg.get_text()
    first = [l for l in txt.split("\n") if l.strip()][:1]
    print(i+1, len(pg.get_images(full=True)), len(pg.get_drawings()), len(txt), first)
```

判读：`drawings` 高（几百）＝ 表格／流程图／色块卡片；`get_images()` 非零的页往往只有一两张装饰图。**文字型 PDF 的「图文并茂」页多数是矢量绘制，`get_images()` 会是 0**，靠图片数挑页会全部选错。

目录直接用 `d.get_toc()`（章节层级）和 `d[1].get_text()`（目录页正文）读，后者同时拿到「全书 N 篇 N 章 N 节」这类可在文案里引用的硬信息。

### 2 · 按内容包围盒裁剪 + 3 倍渲染

```python
def crop(pdf, n, out):
    d = fitz.open(pdf); pg = d[n-1]
    r = fitz.Rect(0, 0, 0, 0)
    for b in pg.get_text("blocks"):
        r |= fitz.Rect(b[:4])
    for dr in pg.get_drawings():
        r |= dr["rect"]
    r = (fitz.Rect(r.x0-10, r.y0-10, r.x1+10, r.y1+10)) & pg.rect
    pg.get_pixmap(matrix=fitz.Matrix(3, 3), clip=r).save(out)
```

- 3 倍 ≈ 216 dpi，A4 出 1500×2100 左右，手机放大看文字仍清楚。
- 裁剪去掉页脚页码与上下大片留白，比整页截图好看得多，也让 grid 里每张图高度接近。
- 封面／封底通常没有 drawings，包围盒退化成文字块 → 直接用整页渲染。

### 3 · 不要用「缩略图拼版 + 视觉模型」来筛选页

把 12–18 页拼成一张 contact sheet 让视觉模型点评，它会串页、把「深色流程块」说成「二维码页」、报告里出现根本没拼进去的文件名。**用文本（每页前 700 字）判断内容价值，用 drawings 数判断视觉密度**，两个都高的页才进候选；最后只对人选页做 1–2 次单页细看。

### 4 · 选页清单（一本 5 篇 15 章的教材实测好用的一组）

| 用途 | 页型 | 为什么 |
|---|---|---|
| 小红书 P1 | 封面 | 证明「这是一本书」，带书名和页数 |
| 小红书 P2 / 公众号 P2-P3 | 目录（1–2 页） | 证明体量与覆盖面（几篇几章几节） |
| 主力钩子 | 错误对照表（如「十四类高频错误」左错右对） | 扫一眼就看出专业度，天然「收藏夹」属性 |
| 主力钩子 | 检验清单（N 条 + 不合格信号） | 观众会截图自查，转发率高 |
| 视觉页 | 三栏彩色卡片 / 带箭头的流程图 | 排版最像成品，适合公众号小节头图 |
| 收尾 | 封底 / 二维码页 | 引流落点，只放最后一张 |

## 二、成稿结构

### 小红书版（≤1000 字含 tag，图 5 张）

```
（声明：本文为科研方法资料整理，内容整理自《X》教材，不构成任何科研决策建议）

一句反常识判断（「被放养不是运气问题，是没人把流程告诉你」）

处境三连 +「这本书是什么」（页数／篇章节数／最贵的那几页）

▫️坑一 …（带页码）▫️坑二 … ▫️坑三 … ▫️坑四 … ▫️坑五 …

坑之外：书的骨架（几个阶段）+ 能直接抄的东西（清单、模板、自检表）

完整版 X 页，需要的话评论区留「关键词」

#tag ×6（末两位固定 #刀客轻研 #SciLink）
```

要点：**每条 ▫️ 后面挂页码或章节号**——引流贴的唯一硬证据就是「我手上真有这本东西，第 54 页长这样」；痛点从书里真实的坑反推，不要编。

### 公众号版（1000–1200 字，图 9 张左右）

开头处境段 →「这本书是什么」（一段，带篇章节数）→ 图 → 一个认知结构（时间线／框架）→ 图 → 四个小节（选题／开题／统计／写作或 AI 降痕），每节一段文字 + 一张对应截图 → 一句很现实的点 → 图 → 领取方式 + 二维码 → 声明。

公众号图多不是凑数：**每张图必须是正文那一段的页面**，图文对位。

## 三、写进飞书云文档

- 三节结构（用户定稿，别自作主张加节）：`一、封面及素材截图`（单行分栏，图注在栏内）／`二、小红书版本`／`三、公众号版本`／`四、待确认`。
- **素材节＝一个 grid、一行到底、N 张 N 栏**（`width-ratio = 1/N`，本类文档 7 张就用 0.142857），**封面固定第一栏**；**图注写在各栏内**：`<column …><img path="@./cover.png" width="150"/><p>封面图（四拼图＋文案）</p></column>`，栏外不再挂总图注 blockquote。多行多列 + 栏外总图注的老写法已被用户改回一行。
- **`<img>` 直接做 column 的子块，不要包 `<p>`**：包了会被当行内元素推到栏右侧（用户原话「为什么每张图都靠右了？左边是空的」）；且裸 img **必须带 `width`**，否则按列宽撑开约 7 倍。机制与回读断言见 `scilink-pic` 的「落飞书：图片块的硬属性」节。
- `<img path="@./x.png" width="380"/>` 用于宽一点的并排图，`width="620"` 用于公众号正文里的大图；XML 生成时 `os.chdir` 到图片目录，路径才解析得到。
- 正文段一律过 `body_xml.py`（每句一个 `<p>`、段间 `　` 空行段），图片作为独立块插在文本块之间；脚本按 `<<IMG1>>` 这类占位符切分文本块再逐段转换，不要手写 `<p>`。
- 回读断言：`<img>` 数＝素材图 + 正文图、`<grid>` 数＝图组数、`column>…<img` 直相连的数量＝图数（确认没被 `<p>` 包）、`　　`=0、`<br/>`=0、`<p></p>`=0，且公众号段里 `<img name=…>` 的出现顺序与稿子一致。

## 四、坑

- **`。）` 结尾的声明句会被拆成两段**（见 SKILL.md 文档排版 2c）：括号里不写结尾句号。
- **重建分栏时不要用 `src="<markdown file token>"` 复图**：会把整组图重建成 `name="test.jpg"`、`scale` 全变（0.0455 → 0.31），图就废了。复用同一批图一律 `path="@./本地文件" width="…"` 重新上传。
- **文件名用 ASCII**（`cover.png` / `stat14.png`），中文名留给 `caption` 和交付说明——XML 路径里有中文容易出转义问题。
- **不要用 `get_images()` 挑「图文并茂」页**：矢量表格页全是 0 张图。
- **别整页截图**：A4 整页放进 grid 后图小字更小，读者在手机上什么都看不清，裁剪包围盒才有效。
- 云文档建好先 `docs +fetch --doc-format xml` 回读一次再向用户报完成；wiki 页面在浏览器里是登录墙，打不开不代表文档没建好，以 API 回读为准。
