# 刀客轻研视觉物料（栏目版式规范）

> **对外名字：SciLink-pic，简称「pic skill」**（用户 2026-11 定）。目录/技能名必须是 ASCII 小写连字符，所以文件标识写 `scilink-pic`；跟用户对话时直接用「pic skill」。

**一句话目标**：把用户给的内容变成刀客轻研的图。**先判栏目、再排版——栏目不同，版式完全不同，不要拿一套样式套所有内容。**

## 栏目总览（先选栏目，再动手）

| 栏目 | 什么内容归它 | 输出 | 模板／脚本 |
|---|---|---|---|
| **插画封面**（默认） | 新闻、科普、评论、观点类稿子要一张引流封面 | 1080×1440，AI 插画 + logo + 上白下蓝渐变，大字标题后叠 | `assets/cover-template.psd` + `scripts/finalize_cover.py`／`add_cover_text.py` |
| **论文速读** | 一篇论文/临床研究（有摘要、有结果数字） | 1080×1440×2 页，徽标「论文速读」+ 作者主张/临床问题 + 中英摘要 + 局限 | `templates/paper_read_card.html`（HTML+Chrome，推荐）或 `scripts/compose_paper_card.py`（纯中英对照老卡） |
| **政策速读** | 指南、共识、政策/文件、医保目录这类“条文型”内容 | 1080×1440 封面 + 来源配图一套 | 「截图作封面」节 + `templates/policy_shot.html` |
| **品牌包装截图 P2/P3** | 资讯稿要交来源页截图、关键结果截图 | 1080×1440 截图 + 品牌包边 + 马克笔高亮 | `scripts/shot_p2p3.py`・`crop_highlight.py`・`compose_brand_shot.py` |
| **单图长海报** | 一段文案/话术要“一张图把内容展示完整”（可很长） | 宽 1080，高度不限 | `templates/poster_brand.html` + Chrome headless |
| **实拍压字** | 用户自己的照片/拍屏要先压一句文案 | 原尺寸 | `scripts/add_snap_text.py`（+ 提亮 `brighten_screen_photo.py`） |
| **引流封面** | 拉新/涨粉/加到客服：要人扫码领额度（不给具体内容，只要转化） | 1080×1440，右上品牌锁定 + 大标题 + 二维码区 + 四行长胶囊 + 卖点三卡 | `templates/lead_qr_card.html` + Chrome headless |

**推荐逻辑（不熟就先问一句，别自己猜）**
- 内容是一篇论文、给了 DOI/PMID/摘要 → **论文速读**（先核材料范围：全文／仅摘要／仅题录，拿不到就汇报阻断，不硬凑）。
- 内容是新闻报道/行业动态/科普话题 → **插画封面**（要发布就再配 P2/P3）。
- 内容是指南/政策/文件条款 → **截图作封面**（材料截图版式，已定稿）：官方文件整页首页当主体，中间不自写文案；拿不到清晰原件时才退回「单图长海报」。
- 用户明说“一张图展示完整”“别切图”“长图” → **单图长海报**，不要拿 1440 高的封面硬塞。
- 用户给的是照片/拍屏 → **实拍压字**，不要走生图管线。

> 用户口径：**「插画封面」= 以前那套 AI 插画 + PSD 模板的封面**；「论文速读」= 论文专用栏目版式。两个名字要在交付里说清楚，别混着叫“封面”。

**固定高度版面（1080×1440）统一按“撑满”验收**：内容最低行到页脚蓝条 **≤ 5%（尾页 ≤ 10%）**。空着就是**间距/元素尺寸没拉开，不是要加内容块**——用户会直接说「下半部分还有很多空白，段落间排版可以再松弛一点」。度量直接跑 `python3 scripts/check_bottom_gap.py <成品.png>`（自动识别底部深蓝页脚条，打印内容底、页脚上沿与剩余百分比），不要靠缩略图目测。**不要手加 `--footer-px 128`**：该参数是**逻辑 px**（页脚 64px 就传 64），传 128 会把页脚当成 128px 高、结论直接错成“只剩 1px”。

## When to Use

- 用户要给某篇稿子/新闻/文档配一张封面 → **插画封面**节（下文“画风/配色/流程”都属这个栏目）
- 用户描述一个画面（「画个造假者得意、编辑追着打电话」）要出封面 → 插画封面
- 已有的插画封面要按同一套规范重做/改构图 → 插画封面
- 用户要把论文做成卡（「论文速读」徽标 + 作者主张／临床问题 + 摘要 + 局限）→ **论文速读**节 + `templates/paper_read_card.html`
- 用户要把论文做成逐节中英对照卡（老版式，按章节出图）→ 「三线表版」节 + `references/paper-card-layout.md`
- 用户要 **P2／P3 来源页截图**（马克笔高亮/品牌包装）→ 「品牌包装截图」「P2／P3」节
- 用户要在**实拍照片**上压文案、或拍屏照片发暗要提亮 → 「实拍照片压字」节
- 用户要**政策/指南速读** → 「截图作封面」节（材料截图版式，封面 + 来源配图一套）
- 用户要**引流卡/扫码海报**（加客服、领额度、涨粉，没有具体内容要讲）→ 「栏目 · 引流封面」节

## 栏目 · 论文速读（定稿版式，2 页）

| 版式 | 用什么时候 | 输出 |
|---|---|---|
| **A · 摘要中英对照卡** | 发小红书/公众号，要好看、要双语 | `scripts/compose_paper_card.py`，通常 2 页 |
| **B · 速读卡（HTML，论文专用）** | 用户要「论文速读卡」这种专门针对论文的版式 | `templates/paper_read_card.html` + Chrome headless，2 页 |

两种都是 1080×1440、同一品牌语言（#006EBB、三线表、蓝条页脚、右上 logo+关键词），可以并存于同一篇文档（**新增，不替换已有图**）。

### B 版：速读卡（HTML，2 页，论文专用）

天头固定蓝底白字徽标 **「论文速读」**（只放 P1），右侧 logo + 关键词。**只保留三样提炼件：作者主张、临床问题（都放摘要之上）、局限（放最后）**——其余字段用户明确不要。

**页序（2 页就够，别铺成 4 页）**
- **P1**：徽标 + 中文标题（大字）+ 英文原标题（小字灰）／右上 logo + 关键词 → 粗黑线 → **两卡并排：作者主张 ｜ 临床问题**（浅蓝底、左侧 4px 蓝条）→ `Abstract 摘要` 标题 + 42% 短细线 → `Background · 背景`（英上中下，中文左侧 4px 蓝条）→ `Findings · 结果`（文字左、自绘图右，图宽 300px，图下脚注「数据取自本文摘要，图为刀客轻研绘制」）。
- **P2**：续页天头**只有右上 logo + 关键词**（右对齐一行，左侧不写标题）→ 细粗线 → `Methods · 方法` → `Interpretation · 解读` → **局限**（浅底圆角框）。
- 页脚始终品牌蓝条：出处白字 + `n/N`。

**局限的写法**：**作者承认就写「作者承认」，没承认就只写「读者观察」，不要两栏硬凑**。作者未在摘要承认时，框内用一行灰字写「摘要无局限讨论段」，下面只列读者观察条目（开放标签、随访过短、对照组非现行最优、无外部验证、不良事件更高、未报告 PRO／亚组）。

**间距必须松弛（这是验收项，不是审美）**：两段内容排完常空出半页，用户会直接说「段落间的排版你可以再松弛一点」。做法是拉间距，**不是把删掉的字段加回去**：
- 两卡 `margin-top:30px`，卡内 17px / `line-height:1.72`
- `Abstract` 标题 `margin-top:40px`；正文块 `margin-top:34px`
- 英文 `line-height:1.68`；中文 20.5px / `1.74`
- 续页三块之间 `margin-top:60px` / `64px`；局限框 `margin-top:58px`、条目间距 15px
- 验收：P1 底到蓝条 ≤ 约 5%，P2 约 10%；仍空一片就继续加间距。

**从 SciLink 完整规范里只吸收这三条**（其余字段用户否掉了：像台账、太密、不好看）：
- 结果数字只从 Findings／Results 与表格抄；效应量必带 95%CI 与 n，缺失写「原文未报告」；**不做换算**。
- 拿不到的写「未获取」，**不得留空、不得用「大概／约」补**。
- 观察性研究只写关联不写因果。

完整 10 字段（身份与已读范围／一句话主张／临床问题／数据与人群／方法主干／关键数字／对照与可比性／局限／可支撑的用途／待核清单）**默认不做**；只有客户或用户重新点名「按 SciLink 规范全量出」时才加，那时才配 `[Sx]` 定位与来源索引表。

**做法与坑**
- 每页 `.sheet` 固定 `width:1080px;height:1440px;overflow:hidden`，页面堆叠后 `--window-size=1080,1440*N` 一次截图，再按 `i*2880` 裁单页（2x）。别一页一个 HTML，也别靠自动分页。
- 分页**手排**（字段少、每页两块），写死 `margin-top` 比靠高度计算稳。
- 落文档：新增用两列 `<grid>` 追加，**不要替换已有图**；要替换旧版就把旧节的 `<h1>` 到文末整段切掉再拼（回写坑见 `references/paper-card-layout.md`），覆盖后回读 `imgs` 计数。

## 栏目 · 论文速读（老版：逐节中英对照三线表卡）

一个章节一张卡，中英对照，自动分页，可配原文/自绘小图。脚本：`scripts/compose_paper_card.py`；**天头几何、配图配方、验收清单见 `references/paper-card-layout.md`**。

**先核素材，再动手（用户明确要求）**：拿到文档／DOI 后先判断「这一篇能不能做卡」——摘要（Background／Methods／Findings／Interpretation）拿得到就做；拿不到就**先汇报阻断原因，不要硬凑、不要拿别处的数据补**。
- 摘要：`curl "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pubmed&id=<PMID>&retmode=text&rettype=abstract"`——PubMed 摘要不要求 OA，`isOpenAccess: N` 也拿得到。
- 原文配图：Europe PMC 查 `inPMC`／`isOpenAccess`，顶刊多为 N；期刊站 `curl` 常 403 ⇒ 改自绘数据图，交付里说明「图非原图」。
- **不要用 EuropePMC 的 `abstractText` 再 `re.sub(r'<[^>]+>',' ')` 清洗**：摘要里的 `p<0·0001` 会被当成标签开头，一路吞到下一个 `>`，把 Findings 整段数字吃掉（实测两次，看着像「摘要缺一半」）。要干净摘要就用上面的 efetch 原文。

**版式阶梯（1080×1440，纯白底，自上而下）**
1. **天头第一行：中文译名（左，`--fs-t-cn` 44px 粗体品牌蓝）+ logo（右，34px 高）**，logo 下一行关键词「医学前沿 · 科研动态 · 医务生活」（17px 灰，右对齐）——一左一右，中文标题是主角。
2. **天头第二行：英文原标题占满整行、小字**（`--fs-t-en` 21px 灰黑，宽 = 整版心）。用户定的层级就是**英文小、中文大**，别把英文标题也做成大字。
3. 天头下粗线 5px（深灰 `RULE`），**只用来分隔天头与正文，仅 P1 有**。
4. `Abstract` + 品牌蓝 `摘要` **同一行并排**（不要再写「摘要（中英对照）」——会与 Abstract 重叠）。
5. 栏目细线：**1px、长度 = 版心 42%、颜色更浅**，必须比第 3 步的粗线**更细更短**。
6. 正文：`--block "Methods · 方法|EN|中文"`，摘要的子部分（Background / Methods / Findings / Interpretation）当**子标题**排——蓝字加粗、字号小于章节标题，不加粗线、不独立成页。
7. **地脚只有蓝色粗条 66px**，出处白字在条内、页码 `n/m` 右端。**正文底部不再画粗黑线**（三线表只留顶线与栏目线）。

**续页（P2 起）只有三样东西**：右上角 **logo + 那行关键词**、正文、页脚蓝条。**没有中英标题、没有章节标题、不写「（续）」、没有任何粗线**——直接从 `Findings · 结果` 开始。这两点用户各纠正过一次：关键词不能丢（「右上角不止 logo 啊，三个关键词也得保留」）、续页粗线不要（「那条粗黑线是用来跟标题隔开的，没有标题就不要了」）。

**字号一组定死**：`--fs-t-cn 44 --fs-t-en 21 --fs-sec 36 --fs-en 19~20 --fs-cn 22~23`。中文标题必须 > 章节标题（44 > 36）；版面拥挤先降英文，中文保底。

**蓝值必须取 logo 像素**：`assets/logo.png` 里 B>R+30 的像素均值 = **(0,110,187) = #006EBB**。不要凭印象用 `#205CCC` 之类的“接近蓝”——用户一眼能看出「不是 logo 的蓝」。

**分页**：装不下就分页，**不要为了塞一页把字缩到读不动**；按“均分”而不是“填满再换页”（否则末页只剩一小段 + 大片空白）。

**默认页序＝结论先行（用户定稿，别再按摘要原顺序流式排）**
- **P1**：`Background · 背景`（中文段末尾补一行方法注脚，如「（3 期、开放标签、1:1 随机；主要终点为盲法独立评审的 PFS 与 OS）」）→ `Findings · 结果`（配图）
- **P2**：`Methods · 方法` → `Interpretation · 解读`
- 理由：首页直接给核心数字（刷到即拿到结论）＋有图更满；方法与解读合起来正好铺满第二页。
- **只放这四个块**：`--page-tags`（「① 结论先行｜② 方法与解读」）、`Bottom line · 一句话总结`、`Limitation · 局限`、`Keywords · 关键词` 都试过并被用户删掉（「这些还是都不要了，先这么跑着试试」）。默认一个都不加，用户重新点名才加。
- 要强制断页用 `--block "PAGEBREAK|||"`：自动分页只按高度算，会把结论页拆散。
- **剩余空白竖向居中，不要靠加块填**：脚本把 `leftover − 段距摊派` 的一半加到起始 y，两页都留白但上下对称。半页空白全压在底部是最难看的形态，用户会以为是没排完。

**配图：文字在左、图在右，图稍小**
- `--block` 第 4 段直接填图片路径，该块文字栏自动收窄、图右对齐并与文字顶部对齐，图宽默认 300px（≈1/3 版心）。用户口径：「图片可以稍微小一些，保持版面整洁」。
- 来源优先级：**原文图 > 自绘数据图 > 用户提供的 PDF/截图**。顶刊多非 OA（Europe PMC 查 `isOpenAccess`/`inPMC`，Lancet/Elsevier 站点 curl 直接 403），**取不到就明说取不到，不要拿别处的图冒充原文图**。
- 自绘图只能用**原文报告过的数字**，并在图上加脚注「数据取自本文摘要；图为刀客轻研绘制」。
- **图型跟着摘要给的数字走**：摘要给的是「里程碑时间的生存率」（6／12／36 个月 xx% vs xx%）就画分组柱状图；给的是「中位生存期」（7.2 vs 3.9 个月）就画中位生存期对比柱状图。**不要拿里程碑数据去伪造 KM 曲线**，也不要拿中位数去补里程碑率——数字对不上就是编。同一批卡片尽量固定一种图型，视觉才成系列。

**坑**
- 自动填料时**最后一段不要再加 gap**，否则会溢到地脚蓝条里（实测 y_end 超出 1440）。
- 英文按词换行、中文按字断行（脚本已内置）；不要把 `repair-deficient` 拆成 `re / pair-`，也不要把 `dMMR` 拆成 `dM / MR`。
- 拆页口径：论文类 `Abstract → Methods → Results(Findings) → Interpretation`；临床类 `Study design → Patient characteristics → Efficacy → Safety`。Methods/Findings 属于摘要内部，先当子标题排，独立成页只针对正文的真章节。
- **续页可用高度必须按本页实际表头重算**：P1 有中英标题＋粗线，续页只有 logo，若拿 P1 的 `avail` 去摊段距余量，续页空白会被算少、最后一页仍留 40% 空白。正确写法 `page_avail = (H - 脚注条 - 40) - 本页表头结束 y`，余量摊进段距的上限放宽到 150px 才铺得开。
- 用户明确否过：**微黄纸张底/渐变**（要纯白三线表）、**logo 居中当主角**、**每个小节都塞进第一页**、**摘要页不放论文标题**、**英文标题在上且比中文大**、**续页写「摘要（续）」**。

## 栏目 · 政策速读（已定稿：材料截图版式）

政策/文件/指南/医保目录类内容**不进生图、不自写文案**：把文件本身的截图当主体，版式见下文「截图作封面（官方文件 / 新闻页截图当主体）」。三句话记住：中间只放材料截图、底条纯蓝不留字、来源配图与封面共用同一套天头地脚。

骨架可直接复制 `templates/policy_shot.html`（改 tag 文案与图片路径即可出两页）。**不要**拿论文速读硬套——政策内容没有 Abstract、没有 HR，结构对不上。

## 栏目 · 单图长海报（HTML + Chrome headless，用户要「一张图把内容展示完整」时）

用户给一段文案（常是 RTF／md/产品话术），要「做成刀客轻研海报，一张图，没有尺寸要求，内容展示完整」时：**不要走生图模型**，用 HTML 排版 + Chrome headless 截图。文字要逐字准确、要长图，生图做不到。

**模板骨架**（实测一次通过）：
- `@font-face` 直接读 `/Users/Jin/Library/Fonts/MiSans-{Regular,Medium,Demibold,Bold,Heavy}.ttf`，`font-family:'MiSans'`；不写 font-face 会回落成苹方/思源，品牌感丢失。

## 截图作封面（官方文件 / 新闻页截图当主体）

用户丢来一张要引用的原始截图（政府红头文件、期刊页、新闻页），要求「按我们的风格重排成封面，右上角补 logo 和关键词」。这类封面**不走生图**，也不要拿 `compose_brand_shot.py` 自动填充——手写 HTML + Chrome headless，才控得住「首行是完整句子」和「底部不硬切」。

**版式（1080×1440，已定稿：封面与来源配图成对，天头地脚完全同构）**

- 天头 **90px**：左＝描边圆角胶囊（`#006EBB` 2px 描边、20px 600 字重）——封面写栏目名（如「政策速读」），来源配图写「原文截图」；右＝logo（**高 28px**）+ 下一行关键词「医学前沿 · 科研动态 · 医务生活」（15px 灰、右对齐）。「右上角 logo + 关键词」是硬要求。
- 天头下 1px `#E3E8EF` 细线（y=90）。
- 中间 stage：`top:100px; height:1240px`，只放材料截图，等比放到接近满宽。
- **中间不自写任何文案**：没有主标、没有副标、没有题录行。用户口径「中间部分不需要自己写文案了，直接贴这个文件的截图把空白部分填上即可」——想加回大字就是返工。
- 底部 **100px 品牌蓝纯色通栏，不写字**（政策速读的蓝框不放主题、不放发布信息）。来源信息（机关名／文号／日期／DOI）写进文档正文或 caption，不塞底条。
- 不给截图加边框、圆角、投影、衬板——材料是主体，装饰会被判「设计感太重」。

**两页一套的产法**：同一份 HTML 复制一份，只改 `<div class="tag">` 文案和 `<img src>` 路径，天地头自然对齐。**不要各写一套 CSS**——用户会直接点出「第二页完全放飞自我了，要跟前面统一天头地脚」。

**材料取哪一段（决定成品像不像官方件）**
- 官方文件：取**整页首页**——红头机关名 + 双红线 + 通知标题 + 文号 + 正文开头 + 落款公章 + 成文日期，一个都不能少。先裁掉上下空页边再等比缩到高 1240（实测 1654×2040 → 1005×1240，左右只剩 37px，视觉上就是铺满）。
- 新闻页：从**文章大标题**开始截（没有标题就不算「带标题的截图」），裁掉右侧栏、二维码广告、订阅框、社交按钮。

**裁截图与出图五个坑**
1. **要「带标题」的新闻页别用 `shot_offline.py`**：它 HIDE 掉了 header，标题永远不在图里。改用线上页直接截：
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
     --hide-scrollbars --force-device-scale-factor=2 --window-size=1280,2200 \
     --virtual-time-budget=12000 --screenshot=/tmp/page.png "<URL>"
   ```
   再按主栏裁（先量 `p` 的 left/right，别整宽裁）。
2. **裁左边界必须到 `x=0`**：留 80~300px 的“安全边距”会把标题首字切掉，表现是整行少 1–2 个字母（`Chinese` 显示成 `se`），要连试几轮才看出来。
3. **`compose_brand_shot.py` 会自动放大居中裁切**（`--max-upscale`），你在 PIL 里裁的「顶部」不一定是成品顶部；要求整页／首行精确时改手写 HTML。
4. **Chrome 缓存 `file://` 图片**：同名文件重裁后再截图仍是旧内容（表现「怎么改都不对」）。每轮换**新文件名**并在 HTML 里同步改路径。
5. **定位「首行」靠拼条试读，不要靠像素阈值**：按暗像素行切块找段落起点不准（图注、版权行、下划线链接都干扰）。一次裁 3–4 个候选横条拼成一张竖图，问一次 vision「每条第一行分别是什么」，挑对的那条再裁。
6. **Chrome 直截 URL 会整图发灰**：Nature 页面 body 背景是 `#B2B2B2`（RGB 178,178,178），不是白。修法（先量背景像素，别默认 178）：
   ```python
   a = np.array(img).astype(np.float32) * (255.0/178.0)   # 178→255，黑字仍是 0
   img = Image.fromarray(np.clip(a,0,255).astype(np.uint8))
   ```
   输出后抽角像素复验应为 `(255,255,255)`。`shot_offline.py` 走的本地渲染是白底，不受此影响。
7. **P2 去配图时要把整个图区的伴生物一起去掉**：新闻页正文里的大图（如毕业照）不是单独存在的——它上面的**分享图标排**（mail／Bluesky／X／Facebook）、下面的**图注行**（`Credit: xx/VCG via Getty`）、图区的 `Credit` 都要一起切掉，否则成品会出现「图标悬浮」「图注指向一片空白」。做法：裁段一（标题 → 副标题 → 作者，止于作者行末、**不再往下带一行**），裁段二（**正文首段第一行** → 段末），中间夹 8–10px 白底拼接。拼接后必须问一次 vision：「正文第一行是否完整句子开头、有无图标残影」。

**分两段拼的时候，接点必须在句子边界**：先裁窄条问 vision 找到正文第一行（本案例 `Master's and doctoral candidates…`）的 y，再从那里起裁；从段中间切会得到 `graduate with…` 这种半句，一眼看出是硬拼。

**标题逐字从图上取，不要凭记忆复述**：同一篇的英文标题常被记错关键词（把 `Chinese doctoral students` 写成 `PhD students`），而图里是真实标题——正文/文档一旦照记忆写就跟图打架。

### 政策文件的实质在附件

政策/通知类内容，**正文页往往只有「现发布 + 请各单位加快推进实施」**，实质全在附件。用户会直接问「这个通知其实没什么信息，好像都在附件里」。

处理：读附件 → 选 6 张带标题的关键页 → **标红色下划线**（有批注就按批注逐句划）→ **一行分栏按文件顺序装完**，每栏一张图 + 一行「页码 + 这页说什么」；不要一张张散插在正文段落之间（用户口径：「这些截图要用分栏装起来，按照顺序放进分栏，而不是插入文中」）。

**定稿形态是「一个 grid、一行到底」，不是多行分栏**——用户会强调「是一行分栏里把所有图片按顺序排进去，只有一行分栏」。封面也排在这一行里（第一栏），N 张就 N 个 column，`width-ratio` 取 `1/N`：

```xml
<grid><column width-ratio="0.1429"><img src="tok_封面"/><p>封面</p></column>
      <column width-ratio="0.1429"><img src="tok1"/><p>① 第3页　一句话结论</p></column>
      ... 共 N 栏 ...</grid>
```

换装优先用 `block_replace` 把已有的单个 `<img>` 块整块换成这个 grid（比删旧 grid 再 append 稳）。**`block_delete` 跨 grid 的范围会 FAIL**（中间夹 `<grid>` 就不行），要拆成多次：h2+p 删一次、每个 grid 各删一次。插完回读 `grid` / `column` / `img` 三个计数，并确认全文 `img` 数等于应有张数。

一行 7 栏时附件页正文小字必须点开才能读，这是用户接受的取舍——**交付里点一句就行，不要因为「字小」擅自改回两栏**。

完整做法（先读批注、逐页取首行选页、180dpi 渲染、续页切残表、按起止句逐行画 3.2pt 纯红下划线、表格「整块框起来」用 `find_tables` 同行并集画矩形、命中 0 就缩短关键词）见 `references/pdf-page-annotation.md`。

附带核一件事：**附件之间的口径差异本身就是可写的点**（同一份文件里博士版只给两种实践成果形式、硕士版给三种；硕士允许「个案报道」，博士要「一组病例 + 较强临床分析能力」）。

**自检（每次出图都过）**：中间有无自写文案、底条是否空白、两页天头高度与关键词是否一致、材料截图是否含红头/标题/公章（或新闻标题）、左右白边是否只剩窄边。截图若必须在中途截断长正文，底部压 190px 白色渐变（`rgba(255,255,255,0)`→`#fff`）让字淡出；整页文件或截到标题为止的取景不需要 fade。

## 栏目 · 引流封面（二维码拉新卡）

**版式（自上而下，定稿；顺序不要动）**
1. **右上角品牌锁定**：蓝底白字标签（栏目名 ≤8 字，如「科研 AI 工作台」）＋ logo 相邻，`gap:16px`、`order` 让**标签在左、logo 在右**，整组右对齐。**左上角留白**：不要 kicker 小字、不要那行「医学前沿 · 科研动态 · 医务生活」（用户明确删过）。

7. 深蓝页脚（`#004E86`）收口。

**否决清单（都试过，别再现提案）**
- ❌ **12 个独立小胶囊**（3 列×4 行）：像标签墙、单调。
- ❌ **四阶段分组 ＋ 同色四阶蓝**（左侧 `01 选题…04 发表` 色块 ＋ 胶囊由深到浅）：用户当场评价「我觉得很丑」。**定稿就是朴素整齐的四行长胶囊**，不要用色彩/编号去“设计感”。

## 生图引擎（先定引擎，再写提示词）

**默认引擎＝豆包 Seedream（通过 libtv CLI 调）**。用户 2026-10 明确：「你就用豆包那个引擎就行了，这个是默认的模型」。

| 优先级 | 引擎 | 怎么调 | 用途 |
|---|---|---|---|
| **1（默认）** | 豆包 **Seedream 5.0 Pro** | `libtv`，`-s "model=Seedream 5.0 Pro"` | 中文海报／中文文案内嵌／新版封面首选 |
| 2 | **Lib Image 2.5 Pro**（`lib-image-2.5-s`） | `libtv`，编辑指令模式 | 必须「保持 ref-set 画风不变、只改内容」时用它 |
| 3（降级） | Hermes `image_generate`（MiniMax image-01） | 工具直调，纯文生图 | libtv 不可用/未登录时才用，**交付时必须说明「本次用 MiniMax，非豆包」** |

**libtv 的坑（每条都踩过）**：

- 二进制**不在 PATH 上**，在 `/Users/Jin/.libtv/libtv`（`which libtv` 会回 not found，别据此断定「引擎不可用」）。
- `-s model=` **只认 modelName 且要带空格**：`Seedream 5.0 Pro`。传 modelKey（`doubao-seedream-5-0-pro`）或去掉空格（`Seedream5.0 Pro`）都报「未找到模型名字」。不确定先 `libtv model search seedream -t image`。
- `quality` 取值因模型而异：`Seedream 5.0 Pro` 只收 `1K/2K`（不是 4K）；`ratio` 支持 `3:4`。
- 三连准备：`libtv workspace use <folderId>` → `libtv project create "<名字>"` → `libtv project use <uuid>`，再 `libtv node create ... --run`。
- 取图**用 `data.url[]` 里的 CDN 原图 curl 下来**，不要用 `libtv download`（会叠水印）。
- 登录态检查：`libtv status`（看 `auth.loggedIn`）；掉了走 `libtv login`，不要在 skill 里存 token。

**交付时必须报引擎**：哪张是豆包出的、哪张是降级引擎出的，写在同一句交付说明里（用户会追问「这是用 MiniMax 做的吗」）。

## 文案是后处理叠的：改文案不重生图

封面大字由 `add_cover_text.py` 叠上去，**不是模型生成的**。所以分两笔账：

| 改什么 | 重跑什么 | 成本 |
|---|---|---|
| 只改封面文案 | `add_cover_text.py 无文案成品.png 输出.png "新文案"` | 秒级、零算力 |
| 改构图/人物/元素 | 重跑豆包 Seedream | 一张一次算力 |
| 色板 Δ 超标 | `hue_align.py` / `warm_grain.py` | 秒级、零算力 |

流程所以固定为「先出无文案成品（art → 色板 → finalize）→ 文案最后叠」：文案往往要改 2–3 轮，先有无文案版就能反复叠字，不用重跑模型。

**汇报用词**：只换文案时说「重压文案」或「重做带文案版」，不要说「封面图重出」——会被追问「文案变了为什么还要重生图？」（实测被问过）。

**正文做合规改写时，封面文案必须同步降级**：点点提「标题像广告」「高频敏感词」时，只会改正文不算改完——封面主标/副标（如「总生存显著 但需留意…」）同样在被扫范围。做法：① 正文改完先回看「封面建议文案」与图上文字，按同一口径换成中性说法（`总生存显著` → `总生存数据公布`）；② 图上文字是位图，**不会跟着正文变**——重跟 `add_cover_text.py 无文案成品.png 输出.png "新主标" --subtitle "新副标"` 重压一版（零算力），不要重跑生图模型；③ 交付时主动点明「图上的字是位图，需重压文案，已给出新版/要不要重压」，把选择权交回给用户。

## 人物规则（遇到具体人物名字时）

用户给出一个具体人名（如「主角是李子祺」）时，**先问一句**：

> 这个名字是网上能搜到的公众人物，还是你原创/内部的人物？

| 图分类 | 做法 |
|---|---|
| **网上能搜到**（公众人物、综艺嘉宾、名人） | 自己去找 1–2 张参考图（百度图片搜「名字 + 节目名」、百度百科图册、新闻图），下载后作为第二张参考图入边；从图里读出 2–3 个高辨识特征（发型分缝 / 眼镜 / 胡须 / 脸型）写进提示词 |
| **原创/内部人物** | 请用户描述 3 个识别特征，或直接要一张参考图 |
| 用户没给名字、只说职业 | 自己按主题设计一个不指向真人的形象 |

**面部画法（强制，照 ref-set）**：**不画具体五官**——没有鼻子、没有嘴；眼睛仅靠眼镜框暗示或两点极简形状；皮肤用**极浅的灰蓝／乳白色**，不用肉色；靠头部轮廓、发型、眼镜、下颌线区分人物。头身比 1:4——1:5，头略大。提示词里必须显式写「面部不画五官：无鼻子无嘴巴，眼睛仅用眼镜暗示，皮肤用极浅蓝白，不要肉色」，否则模型会画成写实或半写实脸，跟画风打架。

**肖像提醒**：把真人画进对外发布的封面时，交付时提一句「这是基于公开图片的漫画化呈现，用之前确认一下场景」。

> **写规则前先分类**：画风 / 配色 / 比例 / 封面模板 / 文字门槛 / 安全区 = 固定项，可写死；**人物身份、职业、服装、画面内容、出现哪些字 = 内容项，永远跟主题走**，不能固化。把个案要求写成通用规则会被用户当场纠正。

## 固定规则（每次生成都必须满足）

1. **人物身份由主题决定**：画谁、什么职业、什么衣着、什么神态，全部跟着主题走（可以是医生、学生、审稿人、教授、编辑、商人……）。**不要预设身份**；用户没指定时按主题最合理的身份画，并在交付说明里写清用了什么身份。参考图里是医生不代表新图也是医生——身份变了就必须在提示词里点名写出来。
2. **配色不得偏离 ref-set 的单色蓝系统**：米白／乳白 #FDFBF1 打底，中蓝 #246DB4、亮蓝 #3A88C7、天蓝 #90BDDC、浅中蓝 #6C9DCA、浅灰蓝 #BFD4E2 层层递进，深蓝 #1250A1 只做暗部与强调；整体是**同一色相的明度梯度**，几乎不用第二个色相（红色最多做小面积印章）。明度高、干净通透、有玻璃感和颗粒。
3. **文字只渲染被要求的内容**：用户或画面脚本里明确要求的文字才出现（印章、标签、标题等），逐字照写；**没要求的一律不生成**——纸张/屏幕/胸牌上的「文字」用横线或色块占位，避免乱码和编造。
3b. **必须是「扁平矢量编辑插画」，不是 3D 渲染**（用户 2026-10 退回的最严重一次）。判据：色块平涂＋硬边阴影块＋低对比渐变，**全图覆盖细密颗粒噪点（磨砂印刷肌理）**；人物是几何块面拼接、无真实材质反射、无光滑塑料高光、无景深虚化。看到圆柱光泽、皮肤反光、柔和体积光 = 跑偏，重生。提示词里必须显式写否：「二维扁平矢量插画，绝对不是 3D 渲染：不要 Blender/C4D 建模感、不要立体圆柱感、不要真实材质反射、不要光滑塑料高光、不要景深虚化、不要照片级光影」。
3c. **亮部要有淡暖黄光**：纯冷蓝会显得单调，也是用户反复提的点。提示词写「亮部带一点点暖黄／米白光（很淡的暖色反光）」；模型不出时用 `scripts/warm_grain.py` 后处理加（只叠亮部，暗部不动，避免发脏），跑完色板通常反而更近参考图（实测最差 Δ 30.3 → 19.0）。
4. **安全区**：顶部 0–250px 会被白渐变淡化、800–1440px 会被蓝渐变盖住。主角的脸和核心道具必须落在 **y≈300–800** 区间。

### 3. 色板验收（必跑）

```bash
python <skill>/scripts/palette_check.py <skill>/assets/ref-set/palette-sheet.png 生成的图.png
```

主色（占比前 4）**ΔRGB ≤ 25** 算对上；`25–30` 可交付，但要在交付说明里把偏差写出来（用户接受过一次 26.3）；`> 40` 必须重生或跑 `scripts/hue_align.py` 只调蓝色域。

**验收对象优先是 finalize 之后的成品，不是原始出图**：PSD 的顶部白渐变＋底部蓝渐变会改掉主色占比，实测同一张图原始出图 Δ 26.0、套完模板后降到 18.0（本来一张要「修」的图直接合格）。顺序固定为 `art → finalize → palette_check(成品) → 不过才调色`，反了会白调一次色。

**`hue_align.py` 也会把本来合格的图拉差**（实测 26.0 → 38.0，因为整张图的蓝色域被一起平移）。所以：跑完必须复测，**Δ 变大立刻丢弃校正版、回退未校正图**，不要把「跑过校正脚本」当成交付条件。同理 `warm_grain.py` 跑完也要复测。

## 机制/结构要准确的图：先双参考图生图，PIL 只是兜底

用户会拿一张真实机制示意图来对账（例：Tarlatamab 双特异性抗体桥接 T 细胞与肿瘤细胞）。这类图的评判标准是**形态正确**（两个结合臂不同、分别直接贴住两个细胞的表面受体）。

**顺序不能反**：① 先按下一节「双参考图生图」把用户的参考图 + 上一版成品一起喂给 Lib Image 2.5 Pro，做定点修改；② 只有模型连续两轮仍画不对结构、或用户对画面不满意时，才上 PIL 手画。

> 纯 PIL 硬画容易被判「丑」——实测两笔都踩过：三个元素占太大地方、为了准把肺器官与气泡装饰全删了。真要上 PIL，**背景/装饰照旧保留，只把主体换掉并缩小到约 40% 宽**。

PIL 兜底路线的要点：

1. `S=3` 超采样＋`LANCZOS` 缩回（否则圆形边缘锯齿）；最后叠极轻高斯噪点（σ≈3）做出磨砂印刷感。
2. **“咬住”关系用叠层次序画**：先画抗体色块 → 在接触位置画米白色凹槽圆 → **再把细胞突起/球头重画到凹槽上**（不重画会被凹槽盖掉，视觉上就变成一根空管，看图的人只能判“没接触”）。
3. 两个结合臂必须**颜色和宽度都不同**（亮蓝窄上臂、深蓝宽下臂），否则无法表达「双特异性」。
4. 验收不能只靠 vision 模型的一句话判定：它会对着小图说「没接触」。用像素断言——沿中轴取一条竖列，看到突起色（如 #6C9DCA）与抗体色（#3A88C7）**相邻**、且凹槽里有球头色像素，才算接上。
5. `finalize_cover` 后再跑 `palette_check`：程序化平涂图常常 Δ 落在 25–27（因为色块占比集中），略超 25 可交付，在汇报里写明数值。

## 用户给了参考图时：双参考图生图，不要纯文生图

用户发一张机制/实物示意图并说「按这个重画」时，**默认应当是图生图，把参考图真的喂给模型**。纯文生图（text2image）出来的东西看似对、形态错，会被追问「你是不是没把我的图给模型读」。

正确姿势（Lib Image 2.5 Pro）：

```bash
$LIBTV upload "肺底图" -t image --resource <上一版成品.png>
$LIBTV upload "机制参考" -t image --resource <用户给的参考图.png>
$LIBTV node create "封面" -t image -s "model=Lib Image 2.5 Pro" -s modeType=image2image \
  -s ratio=3:4 -s quality=max --left-add 肺底图 --left-add 机制参考 --prompt "<保留 A + 替换 B>" --run
```

- **两张参考各司其职**：参考 1 = 构图与画风底子（肺轮廓、气泡、颗粒、底部留白），参考 2 = 要准确重画的结构（细胞形态、连接关系）。提示词写成「保留第一张的 X/Y/Z，只把内部内容换成第二张的 A/B/C」。
- **不要删环境元素**：用户否过一次「把肺和装饰全删了只剩三个大色块」——**只换主体、不拆背景**；主体还要**缩小**（占画面宽度 ~40%），别铺满。
- **结构不够准就做第二轮定点编辑**，不要重抽整图：把上一轮成品再当参考 1，指令写成「其余全部不变，只改中间这个连接结构为…」。实测一轮就修好（扁平淡蓝、肺与气泡保留、抗体两臂不同且两端贴住）。
- 多张参考时只能用 `--left-add` 重复传，**`--left` 与 `--left-add` 不能同时用**（会报错）。

## 专业医学元素：先找学术级参考图，再生图

画细胞、受体、分子、信号通路这类**有客观形态**的东西时，**禁止凭空画**。用户 2026-10 明确要求：先生网上找到学术级（期刊图 / PMC / 教科书）参考图，再图生图。Tarlatamab 那次就是反面教材——按文字描述硬生，抗体两臂形状和连接关系全错。

流程：

1. **搜图**：`web_search "<分子名> structure schematic figure review PMC"`，优先 PMC / Frontiers / Nature Reviews / 学会官方图，避开科普公众号和商业试剂公司插图（常画错）。
2. **拿图**：PMC 页的图可直接 curl `https://cdn.ncbi.nlm.nih.gov/pmc/blobs/...`；Frontiers 去 `/articles/<doi>/full` 页找 figure 原图。下完 `vision_analyze` 看一眼确认“画的就是这个分子/通路”。
3. **双参考图生图**：参考 1 = 品牌底图，用**未叠模板的原始出图（raw art）**而非已叠 PSD 的成品（成品会带底部蓝渐变，模型学进去叠两次）；参考 2 = 学术参考图（保证形态）。提示词写「保留第一张的画风与构图，把主体换成第二张里的 <元素>，结构、连接关系按第二张来」。
4. 交付时在文档里写明参考图出处（期刊 + DOI），**并按用户 2026-10 要求做两件事**：
   - 把参考图以**引用块 + 小图**的形式贴进文档（用户 2026-10 口径：「应该作为引用块放进去，小一点，不要喧宾夺主」）——不要独占一张大图。写法：
     ```xml
     <blockquote>
       <p>参考图（生图依据）：MET 受体结构域示意，Front. Cell Dev. Biol. 2020;8:490 图1，DOI 10.3389/fcell.2020.00490</p>
       <img path="@./met_ref.png" width="420" height="168"/>
     </blockquote>
     ```
     插入位置：四图 grid 之后；`width/height` 按原图长宽比缩到 ~420px 宽。
   - 在「封面（带文案）」那张图块上加一条评论，写清参考了什么、怎么用的、DOI：
     ```bash
     lark-cli drive +add-comment --doc <docx token> --type docx \
       --block-id <img 块ID> --content @comment.json --as user
     ```
     `comment.json` 的 elements **只接受 `text` / `mention_user` / `link` 三种 type**（不是 `text_run`），例：`[{"type":"text","text":"…"},{"type":"link","link":"https://doi.org/…"}]`。图片块 ID 从 `docs +fetch --detail with-ids` 的 `<img id="doxcn…">` 里取。

## 五、P2／P3 来源页截图（物料库标准）

每条资讯稿要四张图：`封面（无文案）`＋`封面（带文案）`＋`P2`＋`P3`。封面走上文流程，P2／P3 走这一节。

| 图 | 内容 | 口径 |
|---|---|---|
| **P2** | 来源页顶部：栏目＋标题＋日期＋作者＋导语开头；该页命门数据段若已在屏内，就把那一段**整段刷黄** | 1080×1440（3:4），无 cookie 横幅、无 Sponsor Message／广告位、无大片空白 |
| **P3** | 同一页的**关键结果段**（样本量／终点／效应量／CI／发生率／死亡数） | 同上，高亮**整句或整段** |

> **高亮口径（用户 2026-10 定，别改回只标数字）**：用户原话「怎么只有几个单词被标注了重点？要整句或者整段」。`--mark-mode sentence`＝含关键数字的整句刷黄，`--mark-mode para`＝整段刷黄（默认 P3 用 para）。
>
> **去重（同一条硬规则）**：P3 要截的段落如果已经出现在 P2 的取景内，**只保留 P2，不出 P3**（用户原话：「p2 和 p3 的内容重复时，只需要保留 p2」）。脚本会自动算 `p3_dup_of_p2`，命中就不生成 P3；这时文档分栏改 3 栏 `width-ratio="0.333333"`，多维表格的 P3 列留空并在文档里注明原因。

一条命令出两张：

```bash
python3 <skill>/scripts/shot_p2p3.py \
  --url "<文章URL>" --slug measles-us --anchor "1,338 cases" \
  [--mark-mode para|sentence|none] [--only p2|p3|both] [--mark-in p2|p3|both] \
  [--masthead "PubMed · British Journal of Anaesthesia · 2026-10-24 · PMID 42926172 · DOI 10.xxxx/xxxxx"]
# 输出 /tmp/shots/<slug>-p2.png（1080×1440）、-p3.png（1080×1440）
# stdout JSON: http / mark / y_para / p3_dup_of_p2 / crop_x
# 要带黄条的 P2：--only both --mark-mode para  ← P3 重复会被自动跳过，stdout 里 p3_dup_of_p2=true
# 要「干净无黄条」的 P2：--only p2 --mark-mode none   ← 实测 --only p2 分支不打点，出来就是干净图
# P3 关键结果段很长（PubMed Findings / Results）时，固定 3:4 窗口会切头切尾：
#   先 --only p3 --mark-in p3 --mark-mode para --zoom 1.15 出整页（-full.png），
#   再 python3 <skill>/scripts/crop_highlight.py <slug>-full.png <slug>-p3.png --masthead "⋯"
#   —— 包围盒只用来定位，**不是把周围内容全裁掉**：默认 --mode context 以高亮段为锚、
#   保留上下上下文（Methods 尾/Interpretation/版权行）填满 3:4，看起来仍是真实文献页截图；
#   高亮段超过窗口 72% 高时自动缩小，保证首尾完整。--mode tight 只在确实只要一段时用。
# 站点带退订弹窗（Retraction Watch / Substack 类）：脚本已内置两次清理，不用手工干预
# 三段修复（2026-10 实测）：① 截图前 OVERLAY_JS 删 fixed/sticky 大遮罩（弹窗多在第一轮 hide 之后才注入）；
# ② masthead 改成 PIL 在顶部画 52px 灰字带（页内插入会被站点布局挤成窄栏、只剩尾部两字）；
# ③ 裁切用「可见段落 10/90 分位 + 最小宽度 900px」（隐藏元素 rect=0 会把左边界拉到 0；窄栏会把 3:4 窗口压矮到切掉高亮段）
```

- **P3 必须保留页面上下文，不是只把高亮段裁下来**（用户原话：「我要的确实是关键段落，但我也没说要把别的都删掉，为什么你 p3 现在只有关键段落了呢」）。P3 的定位是「一张真实的文献页截图，重点段刷黄」：用 `crop_highlight.py` 的默认 `--mode context`（高亮框只当锚点，上下保留 Methods 尾 / Interpretation / 版权行填满 3:4），`--mode tight` 只在用户明确说「只要这一段」时用。
- **固定 3:4 窗口直接从页面裁会切头切尾**：长段落（PubMed Findings / Results）先 `--only p3 --mark-in p3 --mark-mode para --zoom 1.15` 出整页，再 `crop_highlight.py <slug>-full.png <slug>-p3.png --masthead "…"`；高亮段超过窗口 72% 高时脚本会自动缩小页面，保证首尾完整。单独要 P3 时不会触发 `p3_dup_of_p2`（去重只在 `--only both` 生效）。

- **`--masthead` 是给「页面自己不显示题录」的站准备的**（PubMed 文献页实测：只渲染 Abstract，标题/期刊/日期全在不同区块且常不渲染）。它会在截图顶部插一条灰字题录行，把站点·期刊·日期·PMID·DOI 补齐，并在文档里注明「该页未渲染标题，题录见顶部行」。
- 不要把页面自己的栏目标题（`Skip to content`、搜索框、PubMed 顶栏）留在图里：HIDE 里已按 `[class*=usa-banner] / [class*=rss] / [class*=error] / [class*=search-form] / [class*=top-bar]` 屏蔽，但**别加 `[class*=in-page]`**——它会把文章正文一起删掉。

- **NEJM 官网打不开就换 PubMed 文献页**：nejm.org 与 doi.org 跳转在 camofox 里常直接 500，重启浏览器也未必救得回来。做法：① 用 `https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=DOI:%22<DOI>%22&format=json&resultType=core` 把 DOI 换成 PMID；② 截 `https://pubmed.ncbi.nlm.nih.gov/<PMID>/`，配 `--masthead "PubMed · N Engl J Med · <日期> online · PMID … · DOI …"` 补题录（PubMed 页只有 Abstract，不渲染期刊/日期）；③ 想要「P2 干净 + P3 带黄条」时：先跑一次 `--mark-mode para`（两张都带条），拿它的 `-p3.png`；再单独跑 `--mark-mode none --only p2` 拿干净 P2。因为 `--mark-in p3` 常会判成 `p3_dup_of_p2` 直接不出 P3。
- **PubMed 的标题/作者/PMID 在 `<header>` 里，而 HIDE 默认把 `header` 删掉**（2026-10 实测：截出来的 P2 只剩 Abstract，没有标题）。拍 PubMed 页必须加新参数 **`--keep-header`**（已加到脚本），HIDE 会保留 header/nav/footer。
- `--anchor` 要拿正文里**唯一**的短串（例：`0.55` 比 `7.6` 稳，后者常被截断成日期或页码）；找不到 anchor 会回 `mark: no-anchor`，此时不会出 P3。
- **P3 与 P2 重复时（`p3_dup_of_p2: true`）**：交付三图（两封面 + P2）三栏，或者从脚本额外保存的全页图 `<slug>-full.png` 里自己裁一张以黄条为中心的 3:4 特写当 P3（1200→1080 缩放，字不糊）。
- **副标题过长**：`add_cover_text.py` 的副标题会自动缩字号直到整行 ≤990px（用户给的长副标如「中国牵头，29国230家医院参与，PFS 7.6 vs 5.4个月」也能一行放下）。
- **`--anchor` 千万别拿「行首那半句」**（会被前一段抢到）；`--mark-in p3` 只给 P3 打黄条，P2 保持干净。
- 要先有 camofox：`curl -s http://127.0.0.1:9377/health`（不在就跑 `~/.local/bin/camofox-browser`）。443/Cloudflare 站的备选路线见 `references/publish-and-archive.md` 第二节。
- **出版社/学会站经常 403 或 camofox navigate 500**（gastrojournal、gastro.org 实测都有）：先 `curl -sL -o /dev/null -w '%{http_code}'` 看能不能直接拿到 200；能拿到就走离线渲染——
  ```bash
  python3 <skill>/scripts/shot_offline.py --url "<页面>" --slug pbc \
    --anchor "linerixibat" --mark-mode para \
    --masthead "gastro.org · American Gastroenterological Association · October 22, 2026"
  # 出 /tmp/shots/<slug>-offline-p2.png；若黄条不在 P2 窗口内会再出 -p3.png
  ```
  它做四件事：curl 取 HTML → 删外链 CSS/JS/图片（否则 headless 等网络会挂）→ Python 侧打点（整段给 `<ul>` 刷黄底、整句给含数字的句子包 `mark`）→ 本地 Chrome headless 全页截图再按正文栏宽裁 3:4。页码兵器的三个坑都在里面了：脚本必须放 `</body>` 前（放 head 里执行时 body 还没解析）、打点要在“删外链”之后（反了会把注入的脚本一起删）、同一个 anchor 取“正文最长的那块”（否则会命中被隐藏的导航条目，等于白打）。
- **camofox 跑一次成功、紧接着第二次 navigate 就 500**（实测常态）：每轮重跑前 `pkill -f camofox-browser` 再启，不要在一个进程里连着跑多条。
- 出完图必须 `vision_analyze` 自检三件事：**标题日期可读／无 cookie 与 Sponsor 残留／黄条落在数字上**。任何一条不达标就重跑，不要手工糊图。
- 上传到多维表格走 `+record-upload-attachment`，文件名带选题关键词：`{内容标题}-p2.png` / `-p3.png`；封面对应 `-封面.png` / `-封面带文案.png`（不要留 `cover_plain.png` 这种英文临时名，用户会看到）。

### P2／P3 三个必踩的坑（都是实测）

1. **黄条不能直接改 `innerHTML`**：正则会把 `href="…"`、`data-*` 里的数字一起 replace，页面被撕出 `12" target="_blank">` 这种裸代码。正确做法是 `TreeWalker` 遍历文本节点，逐个文本节点包 `<mark>`（整句模式）。
1b. **整段高亮不能用 `<mark>` 包 `<p>`**：mark 是行内元素，包块级段落会渲染成段左两条黄竖线（像标签不像高亮）。整段模式改成包一层 `span` 刷 `background` 再塞回 `p`。
2. **Sponsor Message／空广告位要按文本特征删**：它们常在高 300px+ 的空容器里，按 class 名（`[class*=sponsor]`）抓不全；扫 `div,section,aside,figure` 的 textContent 里含 `sponsor message|advertisement` 的块，删掉最近容器。
3. **懒加载大图常常加载不出来**：`img.complete && naturalWidth===0` 的图别留着——它的位置会变成一大块白，连图注一起隐藏（`i.closest('figure,div')`）。
4. **3:4 别整宽裁**：新闻站正文栏只占视口一半，整宽裁会留 1/3 白边并让字变小。先量所有 `p` 的 `left/right` 得到正文栏宽度，按这个宽度裁 3:4，再放大到 1080×1440。

## 实拍照片压字（用户自己拍的屏幕照 + 文案）

用户会丢一个飞书文档，里面是**实拍照片**（手机/相机拍屏幕，带摩尔纹、屏幕边框、键盘、Dock），要求“在每张上面加一句文案”。这不是封面，**不要走生图管线**，用 `scripts/add_snap_text.py` 直接把字压在原图上。

**先把原图拉下来**：`docs +fetch --doc-format xml` 里取 `<img … src="<token>">`，再 `lark-cli drive +preview --file-token <TOKEN> --type source_file --output /tmp/pics/x.bin`（`drive +download` 对内嵌图回 403，+preview 能拿到原文件；后缀用 PIL 判）。

**样式口径（用户逐轮调出来的，默认就用这套）**：淡黄色字 `FFE066` ＋超粗中文（`/Users/Jin/Library/Fonts/MiSans-Heavy.ttf`）＋**黑色 2px 描边**＋**白色硬阴影**（位移约字高 9%，**不模糊**）＋斜体 ~16°＋**位置居中**（`--pos center`）。字号起始给克制的（画宽 3.3%–3.8%），用户说“再大”就 +30% 递进；**3072 宽的照片实测最后定在 5.5%–6.5%（约 168–199px）**，再大就会压过页面主体。

| 项 | 取值 | 备注 |
|---|---|---|
| 填充 | `FFE066` | 不要用 `FFF3B0` 这类更浅的淡黄：粗体小面积填充会被看成白字（实测被说成“白字黄边”） |
| 描边 | `--stroke-color 000000 --stroke-px 2` | px 按 **1080 宽参考**换算（3072 宽的图上会按比例放大），不要当画布绝对像素用 |
| 阴影 | `--shadow-color FFFFFF --shadow-ratio 0.09` | 硬边、右下方偏移；白背景上靠黑描边分界 |
| 斜体 | `--skew 16` | transform 会让字块整体偏移，脚本已按**墨迹包围盒**重新居中，不要自己手调偏移 |

**文案按用户口述逐字调**：去加号、去逗号这类要求很常见。没有标点时用 `$'第一句\n第二句'` 手动换行（脚本支持 `\n` 强制断行），**不要指望 `--wrap` 自动断对**——无标点长句会被硬切，容易把词拆开。

```bash
python3 <skill>/scripts/add_snap_text.py 原图.jpg 成品.jpg "文案" \
  --pos center --size-ratio 0.035 --wrap 14 --stroke-color 000000 --stroke-px 2 \
  --shadow-color FFFFFF --shadow-ratio 0.09 --skew 16
# 字号不够大就改 --size-ratio（用户常说“整体再大 30%”，就 ×1.3），其他项不动
# --wrap 按字数装箱，脚本内置“按标点断句不拆词、标点不落行首”；无标点的长句才硬切
# 没有标点却要指定断点：文案里直接写 \n（bash 用 $'…\n…'）
```

**落位要先看图再定**：照片里的“空白”往往是无效区——默认优先压在**输入框/任务栏/Dock/键盘**这一带，**不压**表格数据、DOI/标题/作者、核心功能列表。一张一条命令，`--pos` 可用 bottom/top/center/left/right，`--margin` 微调到不压正文。

**用户说“放正中间”就按正中间放**：即使字放大后会压到论文标题/表格中段，也不要自作主张挪去空白处——定位是用户定的，我们只负责把字做清楚；交付时用一句话说明“居中+大字号会压住 XX”，把选择权交回去。

**写回文档的固定做法（用户明确要求）**：**原始三张照片原样保留不动**，在其下另起一组“加文案版”三列 grid 放成品（`<grid>` 三个 `<column width-ratio="0.333333">`，每图带 caption 写清是哪句文案）。不要把原图换成成品，也不要只交成品。

**自检**：放大看四件事——填充色是淡黄不是白、斜体看得出来、阴影是硬边不发虚、字号没有压过页面主体。粗体小字容易把“淡黄+白描边”看成反的，别只信缩略图。

### 提亮拍屏照片（用户说「照片有点暗」时）

拍屏照片偏暗要提亮，但**不能把屏幕上的字洗白**——用户会补一句「同时不能让屏幕上的内容看不清」。做法固定为「抬中间调 + 重新压黑场」，不要用纯 gamma 或直方图均衡：

```bash
python3 <skill>/scripts/brighten_screen_photo.py 原图.jpg 提亮.jpg \
  --mode lift --lift 1.25 --black-point 0.08 --exposure 1.0 --sat 1.04
# lift: x' = 1-(1-x)^k（黑仍是黑、白仍是白，只抬暗部与中灰）
# black-point: 提亮后字会发灰，再用 (x-bp)/(1-bp) 把暗字拉回深色
```

- **顺序是「先提亮原图，再压文案」**：对已压字的成品提亮会把字一起拉亮、边缘发浅。提亮 → `add_snap_text.py` → 上传文档。
- **`--mode gamma` 会整体发白、`--mode clahe` 实测反而把画面压暗**（局部均衡重分配亮度），两者都不适合拍屏素材；只用 `lift`。
- **验收用数字，不用“看着还行”**：提亮前后各算一遍 —— 平均亮度 +15~22、**对比度（灰度 std）回到原图水平（差异 <2）**、暗字占比（<60 灰阶）不塌超过三分之一、过曝（≥250）涨幅 <3 个百分点。只提亮不压黑时暗字占比会掉近一半（实测 6.9%→3.6%），那就是“字被洗白”的量化信号。
- 调色只能解决“暗”：摩尔纹、屏幕反光、拍屏发虚是拍出来的，交付时说明清楚，别承诺靠调色消掉。

## 截图/拼图型封面：别加设计层，也别用实色 fade 层过渡

当封面主体是「N 份文档/模板的真实截图」而不是 AI 插画时：

1. **用户要的是整齐拼图，不是设计**。衬板、投影、旋转、编号标签、kicker 都会被一句「设计感太重了，就整整齐齐拼图给我」打回。先按纯拼图交付，需要装饰时再问。拼图的画数与尺寸算术见 `html-to-image` 的「多份文档/截图整齐拼图」节。
2. **不要在 HTML art 层里放实色 fade 层去接 PSD 的底部蓝渐变**。PSD 的蓝渐变从 y≈850 就开始叠色，fade 层在自己的高度末端以纯米白 #FDFBF1 实色结束时，下一个像素露出已经被 psd 染蓝的底 → **一条横跨全宽的硬边**（用户会说「右侧出现实线、很割裂」）。
3. **矩形衬板（`.plate`）同样是硬边源**：圆角矩形的左右边和底边在图区里是可见直线，叠上 fade 后右下角会形成一个直角硬边。换成椭圆柔光：
   ```css
   .halo{position:absolute; left:-20px; top:110px; width:1120px; height:960px;
     background:radial-gradient(closest-side ellipse at 50% 46%,
       rgba(198,224,244,.95) 0%, rgba(212,232,246,.80) 34%,
       rgba(228,241,250,.52) 58%, rgba(243,249,253,.20) 78%, rgba(253,251,241,0) 94%);}
   /* 点阵同样用 mask-image 径向遮罩淡出，否则点阵矩形的四边也会显形 */
   ```
   最后一段 stop 必须是**完全透明**（不是米白实色），否则椭圆边缘又是一道边。
4. **验收靠程序不定目测**：把成品按行取均值求导，看 y 700–1050 有无单行跳变；`y ±1 行均值差 > 25` 就是可见的横线（卡片自身的边缘正常，会集中在卡片所在行）。再裁该区域单独问一次 vision。

## 引擎无关的硬事实（踩过）

- `psd-tools` 的 `layer.topil()` **不含图层蒙版**。模板的渐变写在 `layer.mask` 里，必须读 mask 自己合成。
- 图层顺序：白层在蓝层之上、logo 最上；隐藏的旧底图（`ChatGPT Image ...`）直接跳过。
- **脸太具体**：默认模型会把眼睛鼻子嘴巴全画出来。提示词写死「不画鼻子、不画嘴，眼睛只用眼镜暗示」，皮肤指定极浅蓝白而非肉色；细节见「人物规则」。
- **元素数量不可控**：要求「正好 N 个」时模型不会数（实测：要 10 张纸→出 8 张；下指令补足→变 12 张；再下指令减两张→才到 10）。做法：按实测差值下「加/减 M 个」的具体指令，连做 1–2 轮；**每轮编辑后都重新数、重跑色板验收**，因为每次编辑会让色值再漂一档。
- 配色漂成「亮蓝一片」：只对蓝色域跑 `hue_align.py`（色相 175–255）拉回来，不要动全局。
- **MiniMax image-01（Hermes 默认 image_gen，降级引擎）是纯文生图，不能图生图**：`assets/ref-set/` 的参考图进不了它的输入，风格只能纯靠提示词锁。它默认偏 3D 光泽渲染，**必须写一长串否词**（见固定规则 3b）并把「扁平矢量＋细密颗粒噪点＋亮部淡暖黄光」写成正面要求；出图后先用 `vision_analyze` 问一句「这是 3D 渲染还是扁平矢量插画、有没有颗粒噪点」，答 3D 就重跑，别靠调色救。
- **别把「which libtv 找不到」当成引擎不可用**：它在 `/Users/Jin/.libtv/libtv`，不在 PATH 上。2026-10 就因为漏了这点直接用降级引擎（MiniMax）出了整批封面，被用户追问「我没说要用 MiniMax」。
- **camofox 连续 500 / `page.goto Timeout 30000ms`**：不是网址问题，是浏览器会话残留（navigate 失败 3 次会销毁 session）。`pkill -f camofox-browser` → 重新 `~/.local/bin/camofox-browser`（background=true）→ 等 `curl :9377/health` 回 `browserConnected:true` 再重试，一次就通。
- 英文印章/标签（REJECTED、RETRACTED 等）现代模型基本拼对；中文方块字作印章易乱码，中文需求优先做成“无字图案”或大字标题单独排版。
- 用户没点名的文字：模型会自己编小字（论文标题、胸牌、招牌）。提示词必须写「纸张内容用横线占位，不要自行编造文字」。

## P3 裁剪的坑（retina / 长页面）

`shot_p2p3.py` 存的 `<slug>-full.png` 在 retina 下宽度可能是 1942、9502 等奇怪值。裁 P3：
