# 子代理分章契约模板（照抄进每个 task 的 context）

> 用法：把 `<>` 里的内容换成当前素材的实际内容。子代理看不到主对话，**四块必须齐全**，缺一块就会收到对应类型的脏输出。

```
【背景，务必读完再动手】<这是什么素材：作者/标题/载体/长度；素材形态：逐字稿？扫描稿？自动字幕（无标点）？>。

【产出用途】<最终交付物给谁用：面向什么受众的什么内容账号/什么报告；主推产品或结论是什么；写作风格要求（术语要配一句大白话？语气？字数？）>。

【写作要求】全部简体中文。原文若为外文：术语首次出现给「原文全称（中文译名）：一句大白话/生活化比喻」。摘要 <250–450> 字：先一句话结论，再讲这节到底讲了什么，必须含具体信息（步骤/数字/职责/术语定义/真实例子），禁止「本节介绍了……」式空话。知识点拆解 <3–8> 条/节，每条必须能独立成篇：标题≤<20> 字、有钩子（疑问句/反差/数字/身份代入），不要「关于 X 的介绍」。每条给：知识点（一句话）、原文依据（可引原文片段）、目标读者（<受众枚举>）、切入角度（怎么讲、为什么有人看）。不许编造原文没有的内容，原文没讲清的写「原文未展开」。

【输出格式】严格照抄以下结构，便于机器合并；不要加任何额外前后缀、不要加代码块围栏：

## <节编号>. <节标题>（<起>–<止>）

**中文摘要**

<摘要正文>

**知识点拆解 → <产物名>**

1. **<标题>**
   - 知识点：...
   - 原文依据：...
   - 目标读者：...
   - 切入角度：...

（条目之间空一行；节编号/标题/起止取自该文件第一行）

【本节文件（绝对路径，逐个处理，顺序即输出顺序）】
<绝对路径 1>
<绝对路径 2>

【最后】用 write_file 写到 <输出绝对路径>，然后只回一句话：文件路径 + 覆盖哪几节 + 节数。不要把正文回给我。
```

## 配套的反向约束（易被忽略，务必带上）

- 「不要把正文回给我」——不写这句，子代理会把整篇产物塞回 summary，父上下文的节省全部作废。
- 「不许编造 / 原文未展开」——不写这句，摘要会自行补常识，交付物就不能回原文核对了。
- 「不要代码围栏、不要前后缀」——不写这句，合并脚本要额外剥离 ```` ``` ````。
- 「独立成篇的标题」——不写这句，会收到「关于 XX 的介绍」这类无法直接使用的条目。
