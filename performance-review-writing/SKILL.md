# 绩效考核表写作

## When to Use

- 用户要写或重写绩效考核表、试用期目标设定、中期/终期评估、转正述职。
- 用户岗位职责变更，原绩效指标不适用，需要重定口径。
- 用户让「梳理最近干了什么」以支撑考核、汇报或述职。
- 不适用：写周报/日报（用 weekly-review-planning），写业务方案（用 content-strategy-plan）。

## 0. 铁律
- 不改用户手里的原表，只在副本里填（用户一般会自己复制一份）。
- 不编任何数据。HR/老板能查后台，编一个数字毁掉整张表。缺的数一律列成缺口清单，写明去哪个后台取，让用户补。
- 分数自己算，不口算估。加权总分算到小数点后一位再判档位。

## 1. 先读表，算清评级死线
打开表格先抓三件事：
1. **档位区间**（如 A[95-100) / B[90-95) / C[70-90) / D[60-70) / E[0,60)）
2. **合格线在哪** —— 通常 D 及以下＝不符合录用条件/终止试用期。自评分绝不能落进不合格区间，尤其是「据实填写」的部分最容易把总分拖穿。
3. **加权公式**，并检查表里有没有写中期/终期如何折算。没写就让用户去问 HR —— 若中期和终期各占一半，中期分数就锁死了终期上限。

然后做「分数预算」：先定总分目标（合格线上留 3-5 分余量），反推每项该给几分，最后写文字。顺序反了会写出与分数打架的达成情况。

## 2. 从本地产物反推工作事实，不靠回忆
用户说「帮我梳理最近干了啥」时，翻产物目录，不靠对话记忆。
1. 找产物根目录（内容/运营类一般在 `~/Documents/<业务线>/`，含 产品资料/增长策略/会议纪要/成稿/物料 等子目录）
2. 列交付物：`find . -maxdepth 2 -type f`，重点抓方案、报告、稿件、物料、会议纪要
3. **mtime 不可信** —— 目录整体迁移会一次性刷平所有时间戳。要时间线就读文件内 frontmatter 的 `date:` 或文件名里的日期
4. 按板块归类：策略体系 / 对标研究 / 内容生产 / 品宣物料 / 跨部门协同。每块列「产出物 + 数量 + 留痕路径」
5. 单列一张「数据缺口表」：只有后台能取的数字（发布量、播放、涨粉、私域进线、官网注册），逐条标清取数后台

## 3. 定指标前先分清岗责口径
- **执行岗**：发了多少条、有没有按时交。
- **管理岗**：团队产能、矩阵覆盖、流程 SOP、线索归因、品宣项目零差错。
- 试用期内职责变更时，不要硬套原指标，也不要简单换一套：**基线锚在「接管日」而不是入职日**，按「执行期 / 管理期」分段考核。
- 分段考核必须配一句职责变更说明（时间范围 + 前后岗位 + 指标为何重构），让数据落差有制度解释，而不是能力问题。

## 4. 目标值一律写「基线＋环比」
- 不写绝对值（「粉丝到 1 万」），写「较基线 +X%」。绝对值受平台流量和投放预算影响，不归个人控；相对值才可辩护。
- 基线低反而是优势：基数小，同样的绝对增量能做出好看的百分比。
- 每项指标挂一行「数据来源」，具体到后台名或记录表。这是事后对账的唯一凭据。

## 5. 未达标项：承认 + 归因 + 改进，三件套缺一不可
- 承认用中性事实句（「与基线持平」「样本不足 N 条，环比目标本期无法验证」），不用自我否定的措辞。样本不足导致目标不成立，是专业说法，比编百分比安全。
- 归因指向不受个人控制的变量（赛道流量窄、无投放预算、产能优先顺序），且必须能被外部事实支持（同类对标号更新量、公司未开投放）。
- 改进措施具体到动作和占比（「选题结构从资讯速递转向痛点实操，占比提至 50%」），不写「加强学习」。

## 6. 交付形态
- 交一份可直接粘贴的 markdown：按「指标定义/公式 → 100% 目标值 → 权重 → 数据来源 → 达成情况」逐栏给文本，用户在 Excel 里复制。
- 清单逐条列全，不省略、不用「等」收尾。
- 结尾列出还需用户确认的事项（团队人数、考核截止日、HR 折算规则、某项工作到底做没做），不替用户假设；若某处事实不明，给「做了 / 没做」两版文案让用户选，别写含糊的中间态。

## 7. 坑
- 追溯修改已签字的中期指标会惹麻烦。中期沿用原指标据实评、再加一句职责变更说明承接终期，比改表安全。
- 过程指标（完成 N 篇）在考核里最吃亏：做到是本分，做不到算失职。业绩主项用结果或管理产能指标，过程指标只作支撑。
- 「产出 N 条」写成「带 N 人团队产出 N 条」是同一件事实，管理岗口径的分量完全不同。
- 自评分数必须和文字对得上：写「超额完成」给 75 分会被质疑不认真，写「未达成」给 90 分会被质疑不诚实。
- 别把用户的低估当客观事实（「涨粉 10 个，哈哈」不代表这项没价值）。管理岗的产能、体系、流程本身就是成果，要主动替用户认领。
