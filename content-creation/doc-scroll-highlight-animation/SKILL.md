# 原文滚动高亮动画 · 设计规格

把一份权威原文（官方新闻稿 PDF、官网页面、论文）做成一镜到底、与旁白台词逐句对位的滚动/高亮动画。
本技能负责**设计侧**：选哪几段、精确坐标、笔迹节奏、浮出方案、节拍表、施工标注图。
HTML 动画实现与视频导出归**视频设计师（video-designer）bot**；串行协作，交付物是「坐标 JSON + 节拍表 + 标注图」三件套。

## 铁律（用户明确纠正过的，逐条照做）

1. **只标核心信息，默认 2 处，最多 3 处。** 满页多色标记会被判「很难看」——观众记不住 5 个重点。先让用户/编辑确认「哪两句必须被记住」，其余段落只作为镜头经过的背景。
2. **一个自然语言结构最稳**：一处说明「这是什么/给谁」（适应症、人群），一处说明「结果如何」（终止、达到终点、失败）。这就是 2 处的默认切法。
3. **笔迹节奏按片长决定**：短片（≲15s）一律**从头到尾顺序单笔**，同一时间只跑一处标记；只有长片（≳40s）才考虑多处并发。顺序 ≠ 一段一笔：同一段里两个短语可以先后扫（先 A 再 B），但不要跨段同时亮。
4. **素材用用户给的那份原文本身**，不要重排/重绘版面。原版式（页头、字体、排版）就是可信度来源；重绘页面等于把「原文」变成「二次加工」。
5. **关键句必须浮出（float-out），但放大有物理上限，先算再承诺**：官方稿正文常只有 8–9pt，整页铺满 1920 时正文才 ~25px，手机端读不动——这是浮出的理由。但浮出块**不可能整行不折行地放到 40px 以上**：上限 `px/pt = 画幅宽 ÷ 栏宽pt`（1920 ÷ 532pt = 3.61 px/pt → 8pt 正文最多 28.9px）。所以正确做法是「贴天花板」而不是「放大 1.75×」：按栏宽裁切、正文 ~25–27px，可读性由中文对照行（比英文大一档）+ 投影/压暗的对比承担。要 40px 以上只能把被扫中的短语单独二级放大，代价是多一次视觉跳动，非必要不做（编辑与用户都判它和「一镜到底」冲突）。
6. **一镜到底、无硬切**：所有转场用连续性动作——补片+抬起+回落、缓下移、全程缓推近。
7. **浮出块左右必须离开画幅边缘 ≥ 100–120px**（约画幅 6%），投影才看得见、才读成「一张浮起的纸」；零留白会被看成「贴了一条白带」。**留白按末帧镜头缩放折算**：全程缓推 1.000→1.035 会把画面再放大 3.5%，名义 120px 实测只剩 ~92px——排版面时把末帧缩放因子放进分母，别按舞台坐标算。

## 工作流

### 1. 定核心信息
跟编辑/用户敲定 1–2 处（见铁律 1–2），拿到**逐字原文**。台词是中文、原文是英文时，浮出块右下角是否加一行小灰字中文对照，问一句即可（默认不加，保持原文纯净）。

### 2. 抽取精确坐标（禁止目测）
用 PyMuPDF 读文字的**行级 bbox**，把目标句所在的行并成一个裁切框。直接跑：

```bash
~/Documents/Hermes/venvs/huashu/bin/python \
  <skill_dir>/scripts/pdf_highlight_boxes.py 原文.pdf --page 1 \
  --phrase "surgically resected Stage II (high risk) or" \
  --phrase "terminating the clinical trial" \
  --out _pdf_浮出块_boxes.json --preview _pdf_浮出块_示意预览.png
```

（任何能 `import fitz` 的 python 都行；本机已知可用的是 `~/Documents/Hermes/venvs/huashu/bin/python`。用前先 `import fitz` 确认，别猜路径。）
脚本一次给出：pt 坐标、指定 dpi 的像素坐标、**每个框内到底有哪些行**、以及带描边框的标注示意图。

### 3. 复核裁切框（必须做）
看脚本的 containment 报告：框内**只能**是目标行。跨行短语会出现「框内还夹着上半行无关文字」的情况，这很正常（一个矩形盖两行），确认夹带的是同段上下文、不是别的段落即可；夹进无关段落就改短语或手工给 y 范围。

### 4. 施工标注图
预览 PNG 就是给实现方的施工图（脚本已直接产出）。两条硬要求（都是返工过的点）：
- **标签一律放在正文之外的留白**（页面边距外），绝不压在原文上。
- **右栏留足宽度**，否则右侧说明被画布裁掉半句。
出图后用视觉工具自查一次：框是否切字/错行、标签是否遮字、说明是否完整。

### 5. 节拍表 → JSON + README
秒级列出「画面 / 笔迹 / 印章」，标明每拍对应的台词半句，落到素材目录的 JSON 与 README，实现方按表渲。模板见 `references/float-out-recipe.md`。

### 6. 渲染后做帧级视觉审（自己抽帧量，别采信实现方的审片 PNG）
实现方渲完要它给关键帧（起始、每处浮出中点、印章落定、尾声），但**验收必须从交付的 MP4 里自己抽帧**：审片 PNG 是二手件，同名覆盖的版本、导出中途态都可能跟成片不一致。两步：

```bash
shasum -a 256 成片.mp4 | cut -c1-16   # 与素材台账钉的哈希对一下，确认磁盘上就是被验的那一版
python3 <skill_dir>/scripts/frame_qa_metrics.py 成片.mp4 --at 0.5 3.2 5.6 8.5 10.6
```

脚本给出每帧：卡片 bbox 与左右留白、卡片内文本行高（估正文/中文对照实高）、投影带宽亮度差、马克笔黄/红像素量。判读规则：
- **留白**：目标 ≥100px；实测量出来是 0–11px 就是「贴白带」，退回重排版面。
- **投影**：贴卡 2–30px 带应比卡外 40–70px 带**暗一档**（实测 ~101 vs ~121）；两带等亮说明投影被画幅裁掉或没渲染。
- **笔迹顺序**：同一颜色的像素量应逐帧递增（如红 2,067 → 21,689）；某帧一次性到位、后面不变 = 并发，短片不合规。
- **印章**：完整在画幅内（右/下留白 >50px）、不压浮出块正文、章内只有主词。

内容口径与医学红线由编辑帧级复核，设计侧只判上面四项 + 构图/可读性。

## 浮出块（float-out）机制

完整配方与数值见 `references/float-out-recipe.md`。核心三层结构：
1. **原位盖白纸补片**——不盖就会出现「背景原文 + 浮出副本」重影，这是最容易犯的错。
2. **同一块原文复制一份放大抬起**（~1.75×）+ 投影，锚点用自身中心（FLIP 式），读起来才像「这行从文档里浮出来」。
3. **背景整体压暗**（约 45% 亮度 + 0.8px 轻微模糊），浮出块独占视觉重心。

## 网页滚动动画用户固定规格（2026-09-18 定稿，每次必查、用户不再重复提醒）

做**网页**（SingleFile 存档 HTML / 网页另存页）滚动动画时，以下要求是默认配置，不用问：

1. **画布 1920×1080 带透明通道**：空白处必须 alpha=0。三格式交付：MP4（yuv420p，无透明，普通用）+ ProRes4444（yuva444p10le，**唯一可靠的透明通道交付物**）+ VP9.webm（本机 ffmpeg 残缺版编不出 alpha，只是预览件，别向用户承诺它透明）。
2. **网页要带阴影、居中成卡片**：白底圆角卡片（~1720×960）+ box-shadow 双层投影，四周透空。参考实现：`剪辑项目/2.癌症疫苗的真相/素材/_ctgov_anim/` 与 `_imcode001_anim/`（anim.html + render_web.mjs，CDP 常驻无头 Chrome 管线，可直接复制改目标句）。
3. **高亮停在目标句**：滚到目标句→轻推近聚焦→荧光绿马克笔（rgba(57,255,20,.96)）逐词扫过→定格收尾。用户指定的句子用「段落空白规范化后按 token 序列匹配起止」来定位 span 范围——SingleFile 存档正文带换行/多空格，直接 split 会错位（踩过：768 词整段被误高亮）。**马克笔样式（2026-09-18 纠正）：一笔画完效果=①词与词无缝：空格也包 span（mk-space，padding:0 .06em; margin:0 -.06em 盖住词间缝），词 span 本身不加 padding/border-radius；②行与行留缝：绝对不加纵向 padding，行距即缝隙（实测 3–4px）；③索引映射：词/空格交替排列后，词 k 在 span 数组的 2k，目标区间 highlight 范围要 ×2。**
4. **网页保留原貌、从页顶滚起（2026-09-18 用户要求）**：不隐藏原站导航/Logo/页头——用户要「网页原来的模样，从最上面开始往下滚」，滚动动画从 scrollStart=0 开始。仍须隐藏的只有：沉浸翻译插件残留（#mount、.imt-fb-container、.immersive-translate-popup-overlay 等）、滚动条。滚动距离变长时把滚动段时间拉长（如 4.2s）保持节奏平滑。
5. **聚焦放大倍数要保守**（≤1.10–1.2）：目标是段落完整落位不切半行字；终帧验收标准=高亮段上下各能看到一行未高亮上下文、四边无切字。
6. **验收流程**：探针帧（0.2/4.5/8.4s 等）→像素程序检查（透明四角 alpha=0、绿色像素量逐帧递增且只覆盖目标行高）→Kimi 看图审帧（kimi_ask.py，现用 KIMI_MODEL=kimi-k3；审片问题→修 anim.html→重渲探针→再审）→全量渲 255 帧→三格式导出→**从 ProRes4444 成片解帧终验 alpha+哈希**（不信源 PNG）。

## 坑（都会导致整轮返工）

- **单页文档别硬凑长滚动**：官方稿正文常集中在上半页，页尾全是免责声明——滚到页尾很难看。「行进感」靠缓下移 + 推近 + 浮出三件事构成，不靠滚动距离。开渲前先算一遍：正文可读尺度下，两处目标的纵向间距够不够产生可见位移。
- **不要把整页当主画面读**：整页铺满时的字号是给「版面感」用的，可读性由浮出块承担。
- **背景暗化 + 模糊是成对的**：只压暗显得脏，只模糊显得花。
- **印章别压正文**：收尾印章落在浮出块外侧或下方空白（右下角为宜），压在引语文字上等于把刚做好的一句话又涂掉。
- **合规相关但非核心的句子保持原样、不上色**（如 safety 相关表述）——删了失真，标了会把画面叙事带偏。
- **台词时间轴优先于画面美观**：浮出停留秒数必须覆盖对应台词句时长；对不上就调停留、不调台词。
- **印章里别再抄一遍卡片上的信息**：登记号/日期已在浮出块角标出现过，章内重复 = 同一信息出现两次，还把小字压到 <25px（手机端等于噪点）。章内只留 `TERMINATED` 这类一个词，落点在画幅层固定定位（别放进会缩放位移的卡片里，否则会被画幅切边）。
- **中文对照的强调只用加粗，不要底色块**：底色块会被读成一次标记，跟马克笔高亮抢语义（一笔下去两个「重点」）。
- **中文对照措辞由医学编辑逐字定稿**，翻译口径（如「数值不平衡」不得写成归因表述）照抄，设计侧不润色。
