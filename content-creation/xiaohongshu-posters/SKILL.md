# 小红书海报制作（HTML → PNG 渲染管线）

> **⚠️ 路线分界（动手前先判断属于哪条线）**：
> - **纯文字排版**——把一篇成稿排成多张 3:4 文字卡（指定字体/字重、马克笔强调、小字引用、正文成段）→ **必须走本 skill 的 HTML 渲染路线**。生图引擎写不对成段中文，字准是这类任务唯一的验收标准。
> - **视觉海报/封面**——要插画、要画面、要氛围 → 走 AI 生图引擎（libtv doubao-seedream-5-0-pro 直接生成带文案整图，见 **ai-poster-generation** 技能的铁律 1c 与该技能目录下的 `references/ai-fullposter-direct.md`（不在本技能内））。用户说过「设计和排版都用 AI 生图引擎直接做」，指的是**这条**线，不是文字卡。
>
> - **已有成品图压字** —— 手里已经是一张排好的图（教材截图拼图、课程资料页、实拍照片），只需在上面压封面文案 → 走本 skill 的 `scripts/cover_caption.py`（PIL 叠字）。不要重走 HTML（排版收益为零），也不要丢给生图引擎（它会把已经排好的图重画掉）。
> - **多页文档的密集拼图** —— 把一套 PDF 的目录页/页面缩略图铺成“一格不漏”的 3:4 收集感图，或一条横向长图 → 走 **html-to-image** 的 `references/dense-page-grid.md`（PIL 拼版 + 数据块填空格 + 像素级对称验收）。这类图不重排任何文字，别在本 skill 的 HTML 管线里做。
>
> 两条线可以混用（AI 生成主视觉封面 + HTML 渲染的文字内页），但风格会不统一，要提前把这个取舍交给用户定。

场景：用户要「把 X 内容排版成小红书风格海报/封面/方法卡」，或「按视觉风格家谱里的风格改造图片」。风格来源：`/Users/Jin/Documents/医时知识库/视觉风格参考/视觉风格家谱.md`（视觉素材流水线见 skill: visual-reference-pipeline）。

## 流程

1. **挑风格**：从家谱文档选 2-3 个契合赛道的家族，做成系列（医学科研实测好用的组合：矢量扁平现代插画/深青绿底+暖黄强调、现代极简包豪斯/黑白+红点缀+网格线、点彩半色调/米白纸底+朱红+圆点纹理）。文档里的中英风格提示词可直接抄给即梦/MJ 做配图。
2. **写 HTML 模板**：3:4 竖版，`@page size: 1242px 1656px`，页面 padding 92-96px，字体 PingFang SC。起点：`templates/poster-template.html`（三套风格完整 CSS + 医学装饰 SVG）。多页用 `<!-- ==== N 标题 ==== -->` 注释分页。
3. **渲染**：`scripts/render_posters.sh <输入.html> [输出目录]`——先把多页 HTML 拆成单页，再逐页 Chrome headless 截图。可选 `<输入>.页名.txt`（每行一个页名）控制输出名，缺省自动 01、02…
4. **QA 循环（必做）**：每轮渲染后检查 → 修 CSS → 重渲染，直到无问题。实测 2 轮可收敛（首轮必出问题，别跳过）。
   - **几何问题（溢出/压线/出界/密度/留白）用像素测量，不要交给视觉模型**：拼版缩略图分辨率不足，实测它会把**最空**的一张报成「最挤」，据此改版会越改越错。跑 `scripts/verify_cards.py` 出数值结论。
   - 视觉模型只用来评审**观感与层级**（字重区分是否明显、马克笔是否糊字、配色是否克制、版式节奏）。

## 关键参数

- 画布：1242×1656（3:4）。Chrome `--force-device-scale-factor=2` 保证清晰度（输出 2484×3312 等效）
- 字号（实测安全档）：主标题 ≤76px（88px 会溢出）、正文 42px、卡片文字 36-38px
- Chrome 路径：`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`
- 输出命名规范：`01_封面_风格名.png`、`02_第一步_风格名.png`（系列感）

## 坑（全部实测踩过）

- **Chrome --screenshot 只截当前视口**：长页面多页 HTML 无法滚动定位截取，必须先把每页拆成独立 HTML 再逐页渲染（render 脚本已内置拆分）
- **绝对定位横线会压标题**：曾用 `position:absolute; top:250px` 的 divider 横穿标题区造成「线压字」——改成文档流元素 + `margin-top` 拉开间距
- **中文标题易溢出**：14 个全角字 × 88px ≈ 1232px，已超过 1242 宽画布 → 字号保守 + 手动 `<br>` 断行，别依赖自动换行
- **卡片阴影/边框出界**：box-shadow 偏移 ≤8px，页面 padding ≥92px，否则阴影贴边甚至裁切
- **右半留白失衡**：纯左对齐长文本会「左重右空」——右侧加半透明 SVG 装饰（DNA 螺旋/细胞圆点），但 `opacity ≤0.15` 且避开卡片区域，否则压文字
- **风格落地别贪多**：每张卡的红色/黄色强调色只用于关键词加粗（`<b>`），正文保持中性色，才像「科研干货」而不是花哨营销图
- 文字对比度：深色底上的浅色卡片内文字要用更亮的颜色，否则小屏阅读吃力（QA 时重点看）
- **渲染工程别只留在 scratch**：`~/.hermes/cache/scratch/` 闲置 24h 会被清理。交付时把 `build.py`、**本轮采用的正文稿**（如 `正文_最新版.txt`）、成品一起拷进目标目录——下一轮用户只会再贴一次正文，没有工程文件和上一版源文件就得重搭套版，也失去了「机械推导 + 逐字 diff」的基准。
- **解析器要能吃「没有标题也没有引言」的稿**：用户删掉封面与序之后，正文会以「一、…」直接开头。别写死 `lines[0]=标题 / lines[1]=引言 / lines[2:]=章节`——先用章节标题正则找第一处匹配位，把之前的部分当**可以为空**的头，否则 `cur` 为 `None` 直接崩。

## 长文分段文字卡（把一篇成稿排成 N 张 3:4 图）

适用：用户给一篇成稿（公众号长文/科普稿/视频脚本），要求「分段排版成多张小红书图片」，并指定字体、字重、强调方式。

### 铁律：用户已定稿的文字，排版时一个字都不许改

- 只允许**插入标记**（`<mark>` 等），不改字、不改标点、不重排段落、不合并分章。稿子定稿后你的角色是排版师不是编辑——**已否决过的内容意见不要再提第二次**。
- 版式需要的新增文案（封面副标题、目录、时间轴、页码、「（续）」）必须**单独列表**告诉用户「这些是我加的，要删要换说一声」。
- 版式层面的标点改动（如章节号「一、」在版面上渲染成「一 ── 」）也算改动，一并说明并给出恢复办法。
- 交付前跑 `scripts/verify_cards.py --text <原稿> <pages目录>` 的**双向文字核对**：①每段原文逐字出现在渲染结果里；②剥离「原文 + 已报备的版式文字」后残差为空——**残差就是你没报备的私加内容**。
- **比对前必须先把段末的括号引用剥掉**：引用已按用户要求摘成独立小字块、且去掉了外层全角括号，拿整行原文去 `in` 全文会必然失败——实测它会把一半以上段落误报成「丢字」，白查一轮。切法：`re.compile(r'（(?=[^（）]*DOI:)[^（）]*）\s*$')`，剥掉后正文与引用分别核。
- **用户是一轮轮重发改稿的**（常见增量：删几处高亮、换页码起算点、去掉某页标题、引用格式微调）。每轮只应用本轮增量、重新出全套图，回复按「要求 → 结果」逐条列表，每条都给回退办法；被否决过的意见不要在同一轮或下一轮再问一次。
- **他在对话里贴回新版全文时，别凭手感重打**：从上一版源文件**机械推导**一份「按他列的增删改应该长什么样」，再同自己的转写逐字 diff。实测这步能一次抓全所有改动、并证明未改段落零字符漂移；直接手抄会在引号（`"…"` vs `“…”`）、空格这类肉眼看不见的地方造出假改动，而这一切的红线正是「一字不改」。
- **结构性改版前先存副本**：品牌名、页序、字号体系、卡数这类大改，先把当前成品整体移进目标目录下的 `历史版本/N_改了什么_张数/` 再动手（用户明确要求过「复制一个副本再修改」）。目标目录顶层只留最新一套 + 一个 `历史版本/`。

### 流程

1. **解析原稿**：按空行/小标题切分，把段末带 DOI 的括号引用**单独摘出来**做小字块，不要混在正文段里。
2. **分卡**：正文约 300-420 字/卡；**段落不跨卡拆断**；章节头优先做视觉锚点。先算字数再定卡数——单卡字数不足会留下大片空白，这是后面调字号也救不回来的。
3. **写单页 HTML 生成器**（Python）：每卡一个独立 HTML（`--screenshot` 只截视口，不能滚动多页）。用 `${key}` 占位 + `str.replace()`，**不要用 `str.format()`**——CSS 和 JS 的花括号会直接抛 `ValueError: expected ':' after conversion specifier`。
4. **注入适配/测量脚本**：`templates/autofit-cards.js`。注意**本用户的定案是全篇统一字号**，所以脚本在这里只做测量（把 `used/avail/fill%` 写进 `document.title`），不再逐卡改字号——见下文「字号：全篇统一是定案」。
5. **渲染 + 验证**：`scripts/render_cards.sh` 渲染并回读适配结果；`scripts/verify_cards.py` 三项分跑——`--png` 像素级几何校验、`--text` 双向文字核对、`--marks` 高亮清单核对。
6. **交付**：文件名 `NN_<页名>.png` 跟随**最终页码**（页码起算点会因增删卡而变）。重出前先把上一版输出从目标目录清掉——页码重编后新旧混排会让用户拿到错序的图；但**用户自己已有的文件（他先前做的封面等）绝不覆盖**。

### 字号：全篇统一是定案，自动适配降级为「测量」

- **标题与正文字号全篇统一**，取最满那张卡放得下的值（实测正文 40px）。用户口径是「以『一 发现现象』这一页的字号为准」——逐卡适配出的 40↔58 跳变他读到的不是「有节奏」而是「不统一」，这条优先于「每张恰好填满」。
- 于是适配脚本只剩**测量**职能：在 `document.title` 写 `used / avail / fill%`（超限加 `OVERFLOW`），**不改字号**。渲染后逐页回读即可同时拿到「哪张溢出」「哪张太空」。片段见 `references/text-carousel-layout.md` §9③。
- **下限 40px 仍是分卡报警线**：需要低于 40 才放得下的卡，多分一张，不要继续缩字。
- **可用高度 = 容器高 − `body` 之上【所有】兄弟节点的外高（含 margin）− 安全余量（120px）**。只减紧邻的章节头会漏掉复合头部块（日期/标签），DOM 判定放得下、实际却溢出到页脚。

### 顶端对齐，不要居中

- `.stack{justify-content:flex-start}`。用户把居中判为「莫名其妙」，明确要求每页文字顶端对齐。
- 理由不止观感：字号统一后各页行数不同，居中会让**每页正文起始高度都不一样**，翻页时视线上下跳。顶端对齐后起始高度一致；无标题的续页正文自然上移，正好接住上一页。

### 下部留白与空页合并

统一字号后必然有页填不满，按这个顺序处理，**不要靠缩字去填**：
1. 先重新分卡（正文 300-420 字/卡，段落不跨卡拆断）。
2. 剩下的空页，用户接受「空着」；**只有明显太空**时才把下一页内容提前并入。
3. **并入前先实测**再决定：把并入后的 `used` 与 `avail` 比。放不下就**不要硬塞**——如实报出「压行高/缩引用字号能省约 N px、还差约 M px」的算术，把「保持两页」与「舍弃最后一段」两个选项交给他拍板，他会自己决定删段。

### 标记与引用

- **每段最多 3 处马克笔**。一段里挂 5 个高亮会变成一块蓝色色块，重点全部失效。规则：按优先级排序候选术语，超限即停。
- **长句高亮要换淡笔触**：用户点名「这句话高亮」时照做，但跨度超过约 14 字的高亮必须降到更淡的一档（alpha .26 → .14）。35 字的长句在 40px+ 字号下会跨 3 行，原浓度会连成一块实心蓝带，比不标还糟。
- 引用小字**跟随正文缩放**（`0.55 × 正文字号`，不低于 19px）+ 灰色 + 左侧蓝竖线缩进。用户要「很小的字」时也不要缩到读不出——小是层级，不是不可读。
- **用户定过的引用格式**：摘成小字块时**去掉最外层全角括号**（以作者名开头）；颜色比正文浅一档（正文 `#0E2A49` → 引用 `#7B8595`，DOI 加粗后 `#5B6473`）；**DOI 部分加粗**。他说「稍微深一点点，不要比正文深」——「深」是相对上一版，任何时候都不能深过正文。
- **高亮清单从 HTML 源码统计，不看拼版缩略图**：`<mark>` 是字符串事实，`verify_cards.py --marks` 逐页列出实际标记的术语与条数。缩略图分辨率不足，实测视觉模型会凭空报出没标记的词、又漏掉真标记的词——据此「修」高亮只会越修越错。

### 卡面固定元素（本用户已定过，不要每轮重新问）

- **左上角品牌**：`刀客轻研 SciLink`——中文在前、`SciLink` 大小写照写（写成 `sciink 刀客轻研` 会被判错）。
- **右上角一律留空**：不许出现「话题 · N 篇论文」这类副标签。
- **页脚只留右下角页码**（`NN / NN`）；奖项名、栏目名之类的小字一并去掉。页码从第一张正文卡起算。
- **封面与序卡可以被要求整块删掉**（「第一页直接从正文章节开始」）。这时整套卡不再出现标题与引言——**必须在回复里提醒他把背景补进帖子正文**，否则刷到的人不知道这是什么奖。这是内容后果不是版式问题，但只有你会先发现。

字号以外的排版常量（纸底配色、马克笔 CSS、章节头、封面光束/时间轴、思源宋体字族与字重映射）见 `references/text-carousel-layout.md`。

## v4 排版重做方法论（2026-08-06，评分 4.5→9.0）

首版 HTML 排版被用户诊断为「很丑」（4.5/10），按 19 份排版学习笔记重做后 8-9 分。**系列通病清单**（先诊断再动手）：插画-文字硬切、标题两行换色双焦点、卖点被埋副标题、卡片无阴影无描边、标签层级不分、底部小字看不见。

v4 解决手段（每条对应参考笔记，直接复用）：

1. **插画→文字接缝**：`.seam` 同色系渐变（`top:1120px; height:180px; linear-gradient(to bottom, 透明→同色系50%→文字区底色)`），文字区底色与插画底部同色系 → 消除硬切。浅色套系渐变到浅底、深色套系渐变到深底，渐变参数按主题配（`seam` 字段）。
2. **标题层级重构**：`kicker(28px) → 单行主标题(94px 宋体) → 卖点徽章 → 副标题(32px) → 标签(24px 降级)`。主标题不换色成双焦点；强调短语用 `.row2` 换色即可。
3. **卖点徽章**：核心方法论（如「5步法」）做成 `inline-block` 圆角胶囊贴在标题后，`font-size:42px; border:3px solid; box-shadow`——结果话术前置。
4. **字体**：标题用 `font-family:"Songti SC","STSong","SimSun",serif`（学术感），正文 PingFang SC——衬线×无衬线对比。
5. **方法卡卡片系统**：`border-radius:16px + border:2px solid 主题色低透明度 + box-shadow + border-left:8px 强调色`；标签「操作方法/为什么/重点看」用 `■` 前缀 + 小色块，卡片内短句化。
6. **STEP 徽章化**：`STEP 01` 做胶囊放左上（`color:文字区底色; background:强调色`），kicker 改「文献检索 · 第一步」——**标题去重**（原版「锁定领域」在 kicker 和 title 重复出现）。
7. **底部金句 + 进度拆两行**：金句用衬线大字号（`36px`）+ 左侧强调色条，进度小字独立一行——结论金句收尾。
8. **标签改 flow 布局**：`position:absolute; bottom:34px` 的 tags 会与副标题重叠（flex 居中时 sub 下探压住 absolute 标签）——**tags 用文档流 `margin-top`，不要 absolute**。这是实测渲染故障，不是视觉误判。

## v4 深色套系专项（S6 3D/S10 复古深棕 等）

- **卡片边界溶解**：深色插画背景上卡片透明度过高会「溶进背景」→ `card_txt_bg` 不透明度提到 0.93-0.94 + 统一主题色描边。
- **徽章与强调字撞色**：深色套系里「不用瞎翻」和「5步法」徽章同色会视觉打架 → 深色系 `.row2` 用浅色（亮青/米金），徽章保持强调色反白——徽章成为唯一色彩焦点。
- **深色接缝**：深色插画底部粒子硬切 → seam 渐变加深（`透明 0% → 35% 40% → 85% 75% → 底色 100%`），让光点"熄灭"在暗处。

## 批量合成脚本模式（10 套风格一次出图）

多套风格共用一套模板时用 Python 脚本 + `${key}` 占位填充（不是 `format()`——CSS 花括号会冲突）：`THEMES` dict 每套存全部配色字段（cover_bg/text/hl/kicker/sub/tags + card_* + seam/shadow/border），`fill()` 用 `str.replace("${key}", v)`，Chrome headless `--screenshot` 每套单独渲染。改动配色只动 THEMES，不动模板。参考：`libtv生成/compose_posters_v4.py`（v3 有备份，成品在 `成品_v4/`）。

## 已有成品图 + 压字封面（PIL）

### 封面文案：先定目的，再分三层写

压字之前先把文案定下来。用户会先给一句话目的（例如「重点是要告诉大家我这个帖子是分享资料的」）——**这句话是文案的靶心，不是可以直接当文案用**。

但**不要每条文案都喊「来领 / 无偿分享」**。用户纠正原话：「不要每句文案都是告诉大家来领资料……有些文案能引发他们想要资料的冲动也可以」。九句全直白像广告，全含蓄又没人知道点进来有东西。一律分三层混着给：

| 类型 | 长什么样 | 用在哪 |
|---|---|---|
| **结果型** | 从搜不到到一搜就准 / 全套流程整理好了 | 主图——前半句给结果，后半句暗示有现成东西，不喊领 |
| **痛点型** | 文献不会搜，论文写不动 / 该补的我都整理在这 | 引流图——先戳痛，再给归属 |
| **直白型** | 医学文献检索+阅读 / 全套资料无偿分享 | 兜底——信息最明确，不绕弯 |

**九句里留 2–3 句直白型就够**，其余走勾需求。交付时每条标类型 + 指出哪 2–3 句最推荐，并说明推荐理由（哪句是真人在说话、哪句容易被当成标题党）。

两条附带规则：
- **不编数字、不夸大**。「90% 的人第一步就错了」这类除非正文真能立刻给出「第一步错在哪」，否则会被当标题党。
- **和封底/正文不撞词**。已经在封底用过的口号（如「压到十分钟」）不要在封面重复。

### 压字参数

手里已经是一张排好的图（教材截图拼图、资料页、实拍），用户说「把它做成封面，正中写上文案」：PIL 在原图上直接压字，30 秒出图、参数可反复调，还能一次出多版给用户挑。

```bash
python3 scripts/cover_caption.py 底图.png 封面.png "文献检索+文献阅读技巧" "全套教程"
```

缺省即「亮黄字 + 黑描边 + 白硬阴影 + 伪斜体」。用户定过的规格（实测通过）：亮黄 `#FFD600`、黑描边 10px、**白影为不透明硬阴影（不模糊）**、倾斜 ≈11°（shear 0.20）、阿里巴巴普惠体 115-Black（本机 `~/Library/Fonts/`，比 STHeiti Medium 粗一档，做标题首选）。

**阴影只要硬的。** 用户两次纠正过：先要白色，再明确「不透明的硬阴影，不要过渡」。柔化模糊的白影会被判成脏边，别自己加 `GaussianBlur`。做法是拿主体图层（已含黑边）当蒙版填纯白，整块平移，不做任何羽化：

```python
white = Image.new("RGBA", lay.size, (255, 255, 255, 255))
white.putalpha(lay.getchannel("A"))      # 形状 = 黄字 + 黑边，颜色纯白且全不透明
shadow.alpha_composite(white, (sx + 10, sy + 13))
```

硬的代价要提前告诉用户：**白色硬阴影压在浅色/白纸底上对比很弱**——密排小字处能看见它遮掉底纹，纯白留白处几乎融进去。要它更明显只有三条路（加大偏移 / 白影满包围四周外扩 / 压暗底图 20-25%），先问再动，不要自作主张加深。

**改文案就要重算字号。** 每轮改字都会推翻上一轮的字号：同一句 1080 画布、4 字用 168px、7 字只剩 106px、13 字只剩 63px。改完必须报出实际像素宽（目标 ≤ 画布 85%，两侧各留 ≥100px），别沿用上一版字号直接出图。

四条技术点，换任何图都成立：

1. **中文字体没有真斜体，用剪切变换造**：`layer.transform((w,h), Image.AFFINE, (1, k, 0, 0, 1, 0))`。不用再翻 italic 字体文件，找不到的。变换必须在**足够大的透明画布**上做（宽 = 字宽 + 字高×k），做完 `crop(getbbox())` 自动裁边，否则倾斜部分被裁掉。
2. **左右补偿按行宽，不按字号**：倾斜后墨迹重心偏右，几何居中看起来偏左。**近满宽的行（>70% 画布宽）补 +10px，短行只补 +2px**——两行用同一个补偿值，短的那行一定显偏（实测第一版就是被指“整体偏左、第二行又偏右”）。
3. **白阴影单独一层**：白色字层整块平移，先合成阴影再叠主体，否则阴影会盖住自己的黑边。硬影不做模糊（原因见上），先叠阴影后叠主体这一步不变。
4. **底图压一层 10% 白蒙版**（`Image.blend(img, white, 0.10)`）：密排小字的截图背景会与标题抢注意力，蒙版把背景推后一档，字立刻跳出来，比加粗描边有效。

字号反算：中文字宽 ≈ 字号，半角（`+`、数字、空格）≈ 0.5 字号。要一行占满 85% 画布就用 `0.85*W/字数单位` 起算——拍脑袋填 100px 会顶出画布，填小了又没有“大字报”的冲击力。两行常见结构是上长下短，第二行放大到 2 倍左右形成压场。

交付前用 vision 复核三点：两行是否视觉居中（不是几何居中）、左右留白是否够、字有没有压住底图的关键内容。用户对封面会反复问“字够不够大”——字号是唯一不能靠视觉模型判断而要靠数字定的项，把实际像素宽报给他。

## HTML 交付物验证模式（2026-08-07 新增）

纯静态 HTML 交付物（指示图/模板页等）的正确验证链：
1. **结构自检**：`python3 -m py_compile` 不适用 HTML；用 `html.parser` 严格解析——标签配对闭合、无嵌套错误、无未闭合标签（`<meta>/<img>` 等 void 标签排除）
2. **渲染截图**：Chrome headless `--screenshot=/tmp/x.png --window-size=1280,2000 file:///...`（file:// 直接可截，无需起服务器）
3. **视觉审核**：截图后用 vision 模型审核布局（卡片完整/色块不重叠/无乱码），kimi-k2.5 thinking disabled 秒回可复用（脚本见 visual-reference-pipeline 的 kimi 调用模式）
4. 交付物是 HTML 时无 package.json/npm test 可跑——验证 = 结构解析 + 实际渲染，两者都过才算完成

**vision_analyze 401 的 fallback（2026-08-07 实测）**：hermes 会话在 .env 加新 key 后未重启时，vision_analyze 会 401（见 **ai-poster-generation** 技能目录下的 `references/vision-review-models.md` 的 key 生效坑，不在本技能内）。此时**不需要重启也能验证**——写个小 Python 脚本直调 kimi（`urllib.request` → `api.kimi.com/coding/v1/chat/completions`，model=`kimi-k2.5`，`thinking:{"type":"disabled"}`，图片 PIL thumbnail≤1400px → JPEG base64，key 从 `Hermes/APIs/kimicode API.rtf` textutil 读取）即可审核截图。注意 kimicode key 走 `api.kimi.com/coding/v1`，不是 moonshot.cn（否则 401）。脚本模板：临时 /tmp/kimi_audit_img.py 模式，用后删除。
