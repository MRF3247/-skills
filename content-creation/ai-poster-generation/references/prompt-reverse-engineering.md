# k3 批量深度分析：参考图 → 提示词倒推管线（2026-08-06 实测）

用途：用 kimi-k3 批量对「排版参考样张 / 视觉风格家谱样张」做深度分析并倒推可执行提示词，结果回写 Obsidian 库。k3 单张 200-300s（thinking 全开、6000-8000 token 输出），批量必须断点续传 + 串行限流。

## 脚本（都在 libtv生成/ 工作目录，2026-08-06 实测）

| 脚本 | 作用 |
|---|---|
| `k3_deep_analyze.py <layout\|style> <图> [输出] [模型]` | 单张分析。layout=排版提示词任务，style=风格提示词任务。输出写 `_k3_分析缓存/<type>_<图名>.md`（断点续传依据）。**默认模型 k3 走 kimicode 端点**（resolve_endpoint 统一返回 api.kimi.com/coding/v1 + kimicode key）；第 4 参可传 `kimi-for-coding` / `k3-256k` |
| `k3_build_list.py` | 扫描 Obsidian 库生成任务清单 `_k3_清单.json`：排版参考 19 份笔记各取样张区第 1 张（layout）+ 视觉风格家谱 11 家族各取前 2 张样张（style） |
| `k3_batch.py <start> <end>` | 串行跑清单区间，缓存命中跳过，失败不中断（可能限流，间隔 2s），进度写 `_k3_进度.log`，结果落 `_k3_全量结果/` |
| `k3_merge_back.py` | 把结果回写：排版笔记追加「k3 深度优化版」章节，家谱文档追加「k3 深度风格提示词」章节（去重防重复合并）——**旧格式，用户已否定，见下方「回写格式」** |
| `k3_embed_table.py` | **回写正解（2026-08-06 用户拍板）**：把 k3 分析内嵌进家谱 HTML 表格的对应样张行——表头加「k3 深度分析」列，有分析的样张行末追加 `<td style="font-size:12px">溯源一句 + 可复用提示词（压缩单行）</td>`，无分析的样张行不加（留空）。同时删除表格后追加的长文章节。**注意：表格正文用 `<br>` 连接溯源+提示词，不能有换行/列表（会撑爆单行 td）** |
| `k3_cleanup_dup.py` | 清理重复章节：删无「· 样张名」后缀的旧版章节，只留新版（合并事故后修复用） |
| `k3_dedup_cells.py` | 清理表格行内重复的 k3 单元格（每行只保留第一个，修复 k3_embed_table 重跑导致的重复内嵌） |
| `merge_family_doc.py`（Hermes 目录） | **误删恢复关键**：家谱文档可从 `Hermes/浏览器采集_识别结果.json`（340 条记录，含建议命名/元素/中英提示词）+ 样张图全量重建——JSON 是唯一真源，`rm` 家谱目录后可整库恢复 |

## 回写格式：表格内嵌，不是追加长文（用户 2026-08-06 强纠正）

**用户原话**：「为什么我看不懂你用kimicode更新过后的视觉风格家谱文档了，表格下面的那一大堆的文字是说的哪张图也没讲啊。我要的只是你在表格里针对每张图进行分析」。

即：**分析必须内嵌进表格里对应的样张行**（每行新增「k3 深度分析」列），**绝不能**在表格后面堆一篇长文——长文不指明对应哪张图，用户读不懂。排版参考笔记同理（追加章节式回写也被否定）。

用户最终要求：**每个家族文档只保留一个表格，4 列：样张｜名称｜元素｜风格提示词（中文）**。之前的「5 列+英文提示词」和「6 列+k3 深度分析列」全部被否：

- **不要英文提示词列**（用户：「不要英文提示词」）

| 脚本 | 作用 |

| `kimi_style_prompts_retry.py` | 补跑缺失的：只处理 `风格提示词_kimi.json` 里没有/为空的条目，每张重试 3 次（间隔 5s） |
| `rebuild_family_tables.py` | 重建 11 家族文档为 4 列表格（样张\|名称\|元素\|风格提示词中文），风格提示词取 kimi 新版，缺的用 MiniMax 旧值兜底并**在末尾警告列出**（missing_kimi 清单）；同时重建 00_索引.md |

**全量实测（340 张）**：预热后 ~10-15s/张（token 缓存命中），全程 ~2h 分两批。**约 1/3 偶发空返回**（content 为空、非报错），重试后绝大多数成功（解剖/敏感图也过，证明是瞬时错误而非内容拦截）——**空返回必须重试，不要当作拦截放弃**。

**两类失败要区分处理**：
1. **空返回（content 为空）** = 瞬时错误 → 重试（kimi_style_prompts_retry.py，3 次间隔 5s；仍失败用 kimi_style_final9.py，5 次间隔 15s 逐个单跑）。**诊断技巧：批量连续失败时，用独立脚本单张 curl 调用一次——若单张成功，证明是批量限流/瞬时错误而非内容拦截，放心继续重试**（实测「人物雕像_节点网络插画.gif」批量重试 5 次全空、单独调用一次成功）。
2. **短输出（content 非空但 <10 字，如「复古未来主义」「超现实拼」）** = 输出被 max_tokens 截断 → **加大 max_tokens（300→500）重生成**，实测 7 条全部恢复正常长度。批量脚本落盘后要检查 `len(v) < 10` 的条目清单，别只看「非空」就当成功。

内嵌格式规范（k3_embed_table.py 实现，2026-08-06 定稿，**仅供旧 6 列格式参考，4 列新格式已不适用**）：
- 表头加一列 `<th>k3 深度分析</th>`（注意闭合：`</th></tr>` 替换为 `</th><th>k3 深度分析</th></tr>`）
- 有 k3 分析的样张行末尾加 `<td style="font-size:12px">**溯源**<核心流派主句，截断到第一个换行前，≤150字> + <br> + **提示词**<中文可复用提示词压缩单行，≤350字> </td>`
- 未分析的样张行不加单元格（其余行保持 5 列，只有分析行 6 列——HTML 表格允许行间列数不一致）
- 同时删除表格后所有追加长文章节（`</table>` 之后只留换行）
- 溯源只取「核心流派：」到第一个换行的主句（k3 原文常带列表项，正则要 `核心流派[：:]\s*(.+?)(?:\n|$)`，否则列表被吞进 td 撑爆单行）

## 回写脚本的幂等与恢复（2026-08-06 事故教训，都是血泪）

1. **幂等保护的 `continue` 是灾难**：`k3_embed_table.py` 第一版在「行已有 k3 单元格」时 `continue`——它跳过了 `new_lines.append(line)`，**把整行数据行删掉了**（Genes 行直接消失）。正确写法是 `if not in line:` 包住插入逻辑，绝不能用 `continue` 跳过 append。
2. **行级幂等缺失 → 重复内嵌**：重跑脚本时已内嵌的行又追加一个 k3 单元格。修复：插入前检查 `'<td style="font-size:12px">' not in line`；已产生的重复用 k3_dedup_cells.py 清理。
3. **误删家谱目录的恢复路径**：`rm -rf` + `mv` 备份失败导致整个家谱目录被删。恢复：`cd Hermes && python3 merge_family_doc.py`——从 `浏览器采集_识别结果.json`（340 条）全量重建 11 家族文档 + 00_索引 + 样张引用，然后重跑 `k3_embed_table.py` 重新内嵌（k3 结果文件在 `_k3_全量结果/` 不受影响）。**JSON 是唯一真源，识别结果 JSON 只增不删的铁律再次被验证**。
4. **改动前先备份、验证用 hash 而非目测**：批量改 Obsidian 文档前 `cp -r` 备份到独立目录；改完用 `md5 -q` 记录全库 hash，重跑脚本后 diff 确认零变更（幂等）或精确变更。验证脚本排除 00_索引（glob `[0-9]*.md` 会误含它，它本无表格）。
5. **不要 import 生成脚本复用函数——`spec.loader.exec_module` 会执行整个模块的 main**（2026-08-07 事故）：为复用 `merge_family_doc.py` 的 classify() 做视觉样图家族分类，import 时整个脚本重跑，家谱文档被从「4 列 kimi 版」覆盖回「5 列 MiniMax 旧版」（340 张全退回，k3 内嵌丢失）。恢复：重跑 `rebuild_family_tables.py`（kimi 提示词 JSON 是独立真源不受影响）。教训：① 复用前确认脚本有 `if __name__ == "__main__"` 保护，没有就**复制函数体**而非 import；② 跑完任何「分类/重建」类脚本必须抽查目标文档（行数/列数/提示词内容特征）确认没被意外改写。另：从家谱文档 alt 提取文件名分类时，alt 无扩展名，要做扩展名探测循环（`.jpg/.png/.webp/.jpeg/.gif`，gif 易漏）。

## 回写防重复的两个坑（2026-08-06 实测踩过，别再踩）

1. **防重复判断必须用「章节标题 marker」而非「样张名 in 全文」**：第一版用 `sample_name in txt` 判断，但家族第 2 张样张（如「期刊封面_富士山浮世绘」）的样张名若在正文里被引用（第 1 张分析里提到"富士山造型"），会被**误判为已合并而跳过**——11 家族全丢了第 2 张。修正：判断 `f"k3 深度优化版（{DATE}）· {sample_name}" in txt`（章节标题带样张名后缀）。
2. **新旧章节标题格式不一致会造成重复合并**：旧版章节标题是 `## k3 深度优化版（2026-08-06）`（无后缀），新版带 `· 样张名`。若先按旧格式合过一轮、再改判断逻辑重跑，防重复检查找不到带后缀的新标题 → **全部重复合并一遍**（家族出现 3 个章节）。修复：`k3_cleanup_dup.py` 删无后缀旧章节。教训：**改判断逻辑前先确认已写入文件的章节标题格式，或一次性用带后缀格式从头跑**。

## 调用（关键参数）

- **推荐端点：kimicode 专用端点 `https://api.kimi.com/coding/v1`**（2026-08-06 用户指定消耗 kimicode 的 token，key 在 `/Users/Jin/Documents/Hermes/APIs/kimicode API.rtf`，72 字符 sk-kimi 开头，用 textutil -convert txt 读取；**不是** `~/.hermes/.env` 的 KIMI_API_KEY）
- kimicode 端点上可用的模型（实测 `/v1/models` 列表）：`k3`（1M ctx）、**`k3-256k`（首选，见下）**、`kimi-for-coding`（K2.7 Coding，262k）、`kimi-for-coding-highspeed`。**kimi-for-coding 做参考分析质量接近 k3**（风格溯源稍浅，但提示词直接可用），也接受图片输入
- **模型首选 `k3-256k`，不是 `k3`**（用户 2026-08-06 拍板：官方文档确认「256k 上下文内效果与 k3 相同，k3(1M) 消耗约为 k3-256k 两倍」，单张参考分析用不到 1M 上下文）。实测 k3-256k：70-110s/张、~5000 tokens/张，质量与 k3 一致。脚本默认模型已改为 `k3-256k`
- **kimicode 端点比 moonshot 端点快且省**（实测同图）：~99s/张、~5000 tokens vs moonshot 180-240s/张、~8200 tokens——批量优先 kimicode 端点
- 旧端点（备选）：`https://api.moonshot.cn/v1/chat/completions`，model=`kimi-k3`，**不要**传 `thinking.disabled`（k3 就是要深度思考），max_tokens=6000
- 图片：PIL thumbnail 到 1400px 内 → JPEG base64（超过 shell 参数上限会 `Argument list too long`，必须走 Python urllib 而非 curl -d 内联）
- 分批复跑：41 任务 ≈ 2.3 小时串行（moonshot k3）或 ~70 分钟（kimicode k3/k3-256k）。跑完一批 `k3_batch.py 21 41` 续下一批；中断重跑同区间即可（缓存跳过已完成）
- **全量实测（2026-08-06 完成）**：41/41 零失败，总 207,727 tokens（平均 5,066/张），总耗时 72 分钟；结果落 `_k3_全量结果/`（layout 19 份 + style 22 份）。按用户指示跑完**不自动回写** Obsidian——回写需用户点头后跑 `k3_merge_back.py`

## 任务提示词要点（让 k3 输出可直接用的东西）

layout 任务要求五段：排版结构解构（版式/信息层级含字号关系/网格对齐/间距节奏）→ 字体系统（标题/正文/强调方式，含可商用字体替代）→ 配色系统（自然语言色系+逻辑+对比策略）→ 视觉手法（图文关系/装饰/特殊技巧）→ **可复用排版提示词**（中英双语，新手照做也能出效果）。

style 任务要求六段：风格溯源（流派+代表画家/作品）→ 画面内容（元素/构图/层次）→ 技法质感（笔触/纹理/光影）→ 配色 → 文字排版 → **可复用风格提示词**（中英双语，风格名+元素+构图+技法+配色+氛围，目标 85%+ 还原度）。
