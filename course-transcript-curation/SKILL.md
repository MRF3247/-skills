# 课程逐字稿 → 知识库三层结构（并同步得到大脑）

用户手上有多门付费课（谢无敌·小红书、戴小胖·小红书电商、安先生·个人IP、dbsilent·AI自媒体…），每门课都要求同一套产物。本技能是已验证配方。

## 一、目录与三层结构（不可自创别的结构）

```
<课程名>/
├── 00-导航/          00-索引-<课程>导航.md + 总纲-知识地图.md
├── 01-精华读本/      00_前言与导读.md + 技N章（跨节去重合并，成品主体）
├── 02-每节整理/      NN_节名（整理版）.md（一节一篇，保留原貌 + source 回链）
└── 03-逐字稿原文/    完整逐字稿 + 每节/ 分片（机器转写，原料层）
```

- 用户说“整理完”= 两个目录都要齐：`01-精华读本` 与 `02-每节整理`。开工前先用 find 盘点哪个目录空着。
- **编号偏移是常态**：逐字稿分片文件名带 02..16 这类编号（第一个分片是 02），整理版与节序对齐（01..15）。逐字稿分片号 = 节序 + 1，别把两套编号搞混。
- 新目录默认是空的（00-导航/01-精华读本），不是“丢了”。

## 二、逐节整理模板（子代理必须照抄范本，不要另创格式）

```markdown
---
title: NN_节名
source: "[[<逐字稿文件名，不含扩展名>]]"
tags:
  - <课名标签>
  - 每节整理
---

# NN 节名

> [!abstract]
> 3-6 句摘要（本节讲什么 + 关键结论）

## 一、…（小标题按内容实拟；加粗关键词；适合处用表格）
## 案例与数据
## 金句

> [!quote]
> - "逐字稿原话"

## 整理说明
- 转写纠错对照表（逐字稿写法 → 正确写法）
- 专有名词正确写法、存疑处、录制时间点

---
🧭 [[00-索引-<课程>导航]]
```

**硬规则（写进每个子代理的 context）**：
1. 只依据逐字稿，**绝不许补充原稿没有的信息/案例/数据/产品名/结论**；看不清处按上下文还原并在「整理说明」标存疑。
2. 专有名词必须写对形（Claude / Gemini / DeepSeek / Perplexity / Monica / OpenRouter / n8n…），以逐字稿实际提及为准，不自作主张硬塞。
3. 术语首次出现给全称 + 一句大白话（生活化比喻）——用户对此是硬要求，如“ASR＝把录音自动变成文字的机器听写员”。
4. 宁全勿简：子话题、演示步骤、提示词原文、界面操作路径均保留（长约 1 万字符量级，长节更长）。
5. 先读**已存在的那一篇**（如 01_…（整理版）.md）作范本，风格靠它对齐；第一篇不存在时先手动写一篇再开工。

## 三、并行子代理配方（实测：99 节以下很快）

- 一个子代理包 **2 节**（按逐字稿字节数大小搭配均衡，最长的节配最短的），7-8 个并行；超过 10 节就搭两批。
- 每个任务的 context 必须自带：绝对路径、编号映射（逐字稿号→整理号）、完整模板、硬规则、纠正对照表要求。子代理不知道前后对话。
- **子代理自报不可信**：全部回来后自己跑一轮核对：文件存在与字符数、`source` 是否指向真实存在的逐字稿、frontmatter/abstract/导航尾齐否、编号有无重号，再抽读 1-2 篇查幻觉。
- 并行产出风格会轻微漂移（分节数量、表格密度不一）——接受；不一致的是**编号与结构**，那由范本锁定。

## 四、精髓读本（用户要“一本书”）

- 先问用户：分几篇/怎么分模块（用户常选“按 N 大模块分 N 篇”）、是否同步得到大脑。别自己拍。
- 每篇 = 一个模块，跨节去重合并；硬规则照第二节（尤其“不重复展开其他章内容，用 [[章名]] 互引”）。
- 每章固定尾节：`## 案例与数据` / `## 金句` / `## 📌 跨模块补充与延伸` / `## 本章来源`（列 [[整理版]] 链接 + 节序）。
- `00_前言与导读.md` 自己做（不要派给子代理）：手册定位、两条主线、目录、阅读路径、三层结构说明、课程时效与切片溢出提醒。
- 同一知识点会同时出现在两章（如“模型对比”在“提示词基础章”与“工具选型章”）：这是有意的分工，在索引与两章正文互相指路，**不要强行删除以凑去重**。

## 五、导航层（自己写）

- `00-索引-<课程>导航.md`：库怎么用（目录树 + 三层关系）、推荐阅读路径、精华读本清单（每条一句话）、每节整理表（节 | 整理版 | 来源逐字稿）、模块→来源节对照、整理规则与注意事项。
- `总纲-知识地图.md`：mermaid 流程图 + “每章解决什么问题/前置依赖”表 + 跨章主线 + 常见认知坑。
- 在两个文件里点名**逐字稿切片溢出**的节（机器分片常把下一节内容混在尾部），说明已在整理说明里标注归属，避免用户以后认为是整理错了。

## 六、同步得到大脑（见 skill: getnote-cli）

1. 先在用户已有的库（如「内容运营」EJXeaLon）建/找文件夹：`getnote kb directories <topic_id> -o json`；不存在才 `kb directory-create <topic_id> "<课程名>"`。**不要自建平行知识库**（无删除接口，建错只能用户手删）。
2. 上传前清洗：去 frontmatter、Obsidian 双链 `[[X|Y]]`→Y、`[[X]]`→X（得到大脑不认双链）。只动临时副本，**不改 Obsidian 原文件**。
3. `getnote save --content-file <f> --title "<标题>" --tag "<课程名>" -o json`，每条 sleep ≥1.2s，note_id 记 state.json 幂等续跑。
4. `getnote kb add <topic_id> <id...> --directory-id <dir_id>`（每批 ≤20）→ 核对 `success_count` / `failed_note_ids: []`。
5. 核对：`kb directories <topic_id> --directory-id <dir_id> -o json` 看 total/条目；抽 3-4 篇 `getnote note <id>` 比 content 字符数是否与本地逐字符相等。

### 命名（用户已两次纠正，务必注意）

- 标题 = **编号 + 名称**，**绝不加来源/系列前缀**（“谢无敌小红书手册 03 …”被要求改回）。
- 单纯编号：`00 前言与导读`、`03 选品体系`。
- **同一课程里两套编号共存**（精髓读本按章、每节整理按节）时，用 **`第N章 X` / `第N节 X`** 区分，否则 App 里两个“01”会混。
- 事后改名：`getnote note update <id> --title "新标题"`（只传 --title 不动正文）。

## 七、坑与检查清单

- [ ] 开工前 find 盘点源目录，搞清“哪部分没整理完”
- [ ] 大工作量（>10 节）先跟用户对齐：交付范围 / 分几篇 / 不否同步得到大脑；否则白干
- [ ] 子代理每个包 2 节、给范本、给编号映射、禁编造
- [ ] 回收后必自校（文件/字符/source/结构/抽读）
- [ ] 逐字稿切片溢出、机器转写错字、模型版本时效、“存疑”标注 = 必须在文末呈现
- [ ] 得到大脑：库内文件夹用 --directory-id 一步到位（不带 --topic-id 的 save + 带 --directory-id 的 kb add）
- [ ] 汇报时给：篇数、命名规则、逐字符核对结果、已知存疑项
