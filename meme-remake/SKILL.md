# 梗图 / 对比图模板复刻

## When to Use

- 用户发来一张梗图/对比图截图，要求「参考这张图出一个我们 XX 的版本」。
- 用户要一张上格 before / 下格 after 的对比图，图上有环绕重复文字的内心戏。
- 不适用：从零创作海报（走 `xiaohongshu-posters` / `ai-poster-generation`）；只要截图不要重排（走 `html-to-image` 形态 3）。

用户丢一张英文梗图截图说「参考这张图给我出一个我们 XX 的版本」时走这条。**不用 AI 生图**——梗图靠结构不靠画功，SVG 线条 + JS 生成文字能在 3 轮内做到结构逐项对应，而且文案随时可改。**拉锯战几乎全部发生在右侧品牌位，不在梗图本体**（原因见「品牌位」一节）。

## 先定文案锚点，不要先画

梗图的信息 100% 在文案里，画只是载体。开工前把四个空填死：

| 位 | 原梗 | 自己的版本 |
|---|---|---|
| 上格标题 | 刚学 X 的你： | 保留句式 |
| 下格标题 | 看完这 N 页的你： | N 换实数 |
| 环绕重复词 | I'm BROKEN / I'm OK | 中文情绪词，见下 |
| 右侧品牌位 | 原产品 logo | 自家产品/封面组 |

- **数字必须实数核对**：原梗的 26 页不能沿用，自己数（多本书页数相加要真的相加一次）。
- **环绕词不要直译**：译成「我崩溃了」是死梗。用受众自己的内心话，上下两格形成对立（我搞不懂 → 我有谱了 / 我抓瞎了 → 按流程走）。
- **指代有歧义先问一句**：用户说「我们的 SOP 教材」而库里有多本时，一次问清（哪本 / 全部），别猜完整套做完返工。
- **品牌位形态开工前先三选一定死**（这条能省掉整场返工）：① 小 logo（原梗的对称结构，两格都放）② 书封卡片 ③ 四行文字书单（书名 + 各自页数）。用户只说「放我们的书」时**先问这一句再动手**，别默认做书封——书封字号被画布宽度物理卡死，他一旦嫌小，书封→2×2→缩人→竖排→书单会连烧四五轮。**文字书单是默认最优解**：字号能到 31px、不压左侧画面、还自带「这套有几本、各多厚」的信息。

## 拆原图参数（vision_analyze，一次问全）

对原梗截图问：画布比例、上下格高度、分割线颜色粗细、小人画法（有没有五官、只画上半身还是全身、手的姿态）、环绕文字的排布规律（螺旋混乱 vs 同心圆整齐）、中文标题字号与位置、logo 位置尺寸。

可复刻点通常只有 5 个：**画布比例、分割线、小人姿态差异、环绕文字的乱/整对比、右侧品牌位**。其余细节不用抠。

## 四个核心技法

### 1. 手绘抖动 = SVG filter，不要手画贝塞尔

```html
<filter id="hand"><feTurbulence type="fractalNoise" baseFrequency="0.028" numOctaves="3" seed="7" result="n"/>
  <feDisplacementMap in="SourceGraphic" in2="n" scale="3.6" xChannelSelector="R" yChannelSelector="G"/></filter>
```

整个小人 group 套一个 `filter="url(#hand)"`，`stroke-width:7` `stroke-linecap:round`，线条自动变手绘波浪。省掉逐条手调贝塞尔。

### 2. 环绕文字用 JS 生成，不手摆

混乱格 = 3 条螺旋臂，逐字步进时半径和角速度都加正弦扰动：

```js
th += (step / Math.max(r,26)) * (1 + 0.75*Math.sin(i*0.7 + a0));
r  += dr * (1 + 0.55*Math.sin(i*1.31 + a0));
// 字旋转角 = 切线角 + 抖动
deg = th*180/Math.PI + 90 + Math.sin(i*0.9)*26;
```

整齐格 = 同心圆数组 `{r, size, n, op}`，每圈 `th = i/n*2π`，零扰动。

中文一个字一个 `<text>`：`text-anchor:middle` + `dominant-baseline:middle` + `transform=rotate(deg x y)`。

### 3. 白色 halo 层（缺了必被退回）

在小人黑线之前，把**同一组路径**再画一遍 `stroke="#fff" stroke-width="26"`。文字被推离线条，手部形状才看得清。没这层，密集文字会和同色线条糊成一团，vision 复查一定判「手势看不清」。

### 4. 半径硬限幅，防文字被 viewBox 裁掉

螺旋的 r 会越绕越大冲出画布（cx=250、宽 520 时 r 上限 ≈240）。用 `rr = Math.min(r, 240)` 限幅，y 方向再乘 `squash≈0.74` 压成椭圆——原梗的文字团本来就是扁的，顺带更像。

文字透明度随圈数递减（内圈 ~0.88 → 外圈 ~0.6），全同透明度会糊成一整块黑板。

## 品牌位：书封要用原书的设计语言重画

要放自家教材且用户说「只放书名」时，别直接铺原封面拼图（缩到 100px 后小字全糊），也别用黑框白卡（会被判丑）。先渲出原书 PDF 第 1 页（`fitz` dpi=150）用 `vision_analyze` 拆出四件事：底色、主标题字体（衬线还是黑体）、点缀色、版式轴线。再按这套语言做 3:4 小书封：

- 底色 `#F7F8F6` 或纯白 + 1px `#E1E6EA` 细边 + 软阴影 `0 2px 9px rgba(16,42,67,.07)`；书名色 `#0E2437`。粗黑边框＝「卡片」感，用户会直接说丑。
- 书名用**思源宋体 Heavy**（`~/Library/Fonts/SourceHanSerifSC-Heavy.otf`，拷进工作目录用 `@font-face` 引相对路径）。Heavy 比 Bold 明显更醒目，是这个尺寸下最省力的放大手段；宋体是学术感的来源，黑体书名会被读成「卡片」而不是「书」。
- **只放书名 + 书名号，不加任何装饰线**。顶部短粗线、底部蓝细线这类点缀做完就会被要求删掉，别浪费一轮。书名号《》各占 1 个全角位，必须算进最长行字数。
- 行用语义 `<br>` 手写（「医学文献/检索与阅读」），不能让 `word-break` 自己断（「医学文献检/索与阅读」会被退回）；`white-space:nowrap` 锁住。

### 书名字号的物理上限：先算再画

字号 ≈ 卡片内宽 ÷ 最长行字数（含书名号）。`white-space:nowrap` 下超了不会换行，会**直接溢出卡片**，所以每次改字号都要先算一遍内宽，别靠试。

并排/网格放在 960×1280 两格梗图右侧（约 550px 可用）时：

| 排法 | 单本尺寸 | 书名字号上限 |
|---|---|---|
| 并排 4 本 3:4 | 134×178 | **19–20px** |
| 2×2 3:4 | 196×261 | 21–22px |

用户说「字太小」时不要只是把字号一点点往上顶——顶两轮就到墙了。直接报账并给三个选项让他选：

1. **缩小人给书封让宽度**：把 `.figure` 的 px 宽度改小，`viewBox` 等比缩放不会裁切；低于画稿 75% 梗图主体就没了。
2. **改 2×2**：字大 10%，但浅灰色块变重、压过左侧小人。
3. **缩标题**：46 → 38，两者比例拉近，代价是标题丢气势。

**已知走不通**：小书封别用 `writing-mode:vertical-rl` 竖排——多列宽度不可控，实测直接溢出被裁、四边自检报 FAIL，书名号还会旋转变形。

### 书封走到墙时，直接换成文字书单（用户体验最优解）

用户在书封字号上打两轮还嫌小时，不要继续调卡片——**拆掉书封、改成四行文字书单**，字号立刻从 19px 跳到 31px（比标题 46px 只低一阶），视觉层次反而更对，也不占左侧小人的宽度（小人能回到 520 原尺寸）：

```html
<div class="booklist">
  <div><span class="bn">《医学文献检索与阅读》</span><span class="bp">71 页</span></div>
  ...
</div>
```

```css
.booklist { margin-top:30px; display:flex; flex-direction:column; gap:3px; }
.booklist div { display:flex; align-items:baseline; justify-content:space-between;
                width:524px; margin-left:-8px; white-space:nowrap; }
.bn { font-family:'SHSong',serif; font-weight:900; font-size:31px; line-height:1.4; color:#16324F; }
.bp { font-size:18px; font-weight:600; color:#7A8794; margin-left:14px; width:64px; text-align:right; }
```

三条硬规则：

1. **容器宽度必须按最长书名实算**（含书名号，1 个书名号 = 1 个全角位）。宽度给小了，`space-between` 会把页数推出容器，四行右边缘就不齐了。实测 31px 字号、12 字书名时容器需要 524px。
2. **页数必须给 `width:NNpx; text-align:right`**，只靠 `space-between` 对不齐。验收：取图右侧像素区按行分组算每行最大 x，四行必须是同一个值（实测四行均为 1828px @2x）。
3. 书名号字形左旁白会把整块书单视觉右移，容器加 `margin-left:-8px` 才能和标题左边缘对齐。

层次分工：标题黑体黑、书名**宋体 Heavy + 深藏青 #16324F**（字体和颜色双区分）、页数苹方灰。页数用「71 页」带空格，和标题里的总页数必须加得上。

## 渲染与验收

```bash
python3 scripts/render_meme.py meme.html out.png --w 960 --h 1280 --scale 2 --ratio 0.75
```

脚本用系统 Chrome headless 出 2x（960×1280 → 1920×2560），并做两道自检：尺寸必须等于 `w*scale × h*scale`、四边各 3px 的墨点像素必须为 0。

- **`--virtual-time-budget=6000` 不能省**：文字是 JS 生成的，不等渲染完会截到只有小人的半张图。
- **四边墨点检查是防贴边/裁切**：文字环贴边在整图上几乎看不出，程序一查一个准。
- **vision 要分区放大复查**：整图缩放看不出手指，用 `region` 分别裁上格/下格的小人，问「头部双臂线条是否连贯、手势能否一眼认出」。

## 交付口径

- 2K 3:4 PNG 落到 `~/Downloads/`，文件名 `<主题>_中文_3x4_2K.png`。
- 回复里给一张**「对照原梗的替换逻辑」表**（原梗元素 ↔ 这版元素），用户靠它一眼验收是否逐项对上。
- 附「能改的地方」清单（环绕词 / 卖点句 / 加 slogan 或二维码 / 出 1:1、16:9），并报出工程 HTML 路径——改字就是改那个文件再重渲。
- 涉及数字的（页数、条数）在回复里写清怎么算出来的。
- 交付时若某处受物理限制（书名字号、书封数量和排法），**把算式和取舍一次摊开**（内宽 ÷ 字数 = 上限；三条破法各牺牲什么），让用户一次性选定，不要挤牙膏式连改四五轮。

## 坑

- **证据型拼图不要自造装饰块撑场面**：把目录页/正文页铺成九宫格时，空出来的格子别自己画「248 页」数据块或封面合图——用户会直接说「第 8 格莫名来个 248 页很奇怪」。填不满就从 PDF 正文里挑表格密集的页补位：`len(page.get_drawings())` 最高的那几页就是表格页（实测对照表页 500+，普通正文页 <60）。真实页面和目录页同质，也更可信。

- 品牌素材按体量分开处理：**小 logo 可以两格都放**（原梗的对称结构）；**成组的书封只放下格**——上格是「还没有这本书」的状态，两格都摆书封会被要求删掉上格那组。
- 删掉右侧卖点句（用户常要求「这句删掉」）后必须重算 `.side` 的 `padding-top`：内容高 = 标题行高 + gap + 封面组高，居中值 ≈ (640 − 内容高)/2，实测 960×1280 两格结构下从 112 调到 214。不调就整组浮在上半格、下方空一大块。
- 品牌位别直接铺原封面拼图：多本封面缩到 100px 宽后内部小字全糊，vision 复查必判「看不清」。改用 CSS 画小书封，规格与字号算法见上面「品牌位」一节。
- 姿态差异要一眼可辨：上格双手抓头 / 下格比耶这类，手指画成 3 条 20–30px 短线够用，画得太小会被文字吃掉。
- 环境里已有相关技能：渲染细节与长图/裁切口径见 `html-to-image`，此处只记梗图特有部分。
