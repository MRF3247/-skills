# 中文自媒体文案：写法与去 AI 味

## When to Use

- 用户要写或改一条中文自媒体稿：小红书笔记正文、视频号口播稿、B 站简介、公众号短文
- 用户发来一段旧稿说"AI 味有点大"、"润色一下"、"改得像人写的"
- 用户拿一篇英文/外部报道要你写成中文科普帖（事实边界与 AI 味双重风险）

不适用：纯技术文档、学术论文、会议纪要（各自有专门技能）。

用户要写或改一条中文自媒体稿（小红书笔记正文、视频号口播稿、B 站简介、公众号短文）时用本技能。

**核心：AI 味要在写的时候避，不是写完再洗。** 用户对 AI 味很敏感（会直接说"这篇 AI 味有点大"），润色返工比一次写对贵得多。深度特征库可加载 bundled 的 `humanizer` 技能（34 条，英文起源）；本技能补**中文自媒体特有**的部分和医学口径。

## 流程

1. **定三件事**：话题、平台（决定长度与语气）、受众。话题长但用户没说平台 → 按小红书图文写（他主阵地），并说明可改口播版。
2. **先列事实骨架，再写句子**：数字、人名、机构名、来源先摆好，句子里只做连接。医学稿尤其如此（错了要返工）。
3. **写完自己扫一遍下面"中文 AI 指纹"清单**，命中的当场改掉。
4. **交付格式**：正文 → 附命中过的指纹诊断（如果他要求诊断）→ 自审残留 1–2 条。不要只丢一段稿子说"看看"。

## 中文 AI 指纹（写完必扫）

- **加粗小标题分节**（"**先看数据**"、"**它为什么没被重视**"、"**一句我记住了的话**"）—— 最重的一条。真人写小红书不用这种结构，删掉小标题，让段落自然流下去。
- **段段收金句**：每段最后都收一句漂亮话 = 广告腔。全篇只在 1–2 处用力。
- **emoji 装饰**（⚠️、✨、🔥 放在句首/小标题前）—— 正文里直接删；小红书的表情用在段末或话里，不用于标记分类。
- **"不只是 X，它是 Y" / "不是 X，而是 Y" 高密度**：一篇最多一处，多了像在教训人。
- **三项排比凑节奇**：列举客观事实（胸腔打开、摄氧量上去、循环加快）可留；为制造节奏凑的三项要拆。
- **句长均匀**：全篇句子差不多长 = 最容易被识别。长短交错，插一句五六个字的短句。
- **零犹豫**：通篇确定、无一处不确定，反而不像人。允许一处真实犹豫（"我一开始不太信"），但**全篇只用一次**。
- **过场句（给下一段抬轿子的铺垫/总结句）**：「第一例已经跑通，人有名有姓。」「两位参与其事的专家都没把话说满。」「X 讲得更直接」——这类句子不带任何新信息，只负责捧一下上文、引出下文。用户对它的判词是「这个措辞很 AI」「这句也很 AI」「AI 味叙述，修改一下」。处理：**整句删掉**，让事实直接接事实（上一段说完制度，下一段就从「今年 6 月，某某……」开场），不要换成另一个过渡句。
- **句首套话**（「先看数据」「值得注意的是」「本质上是」）与结尾祝福体（「你值得」「愿你」）—— 删。结尾用事实或别人的原话收。

## 句式黑名单（AI 味的骨架，用户会当场点出来）

这三类同一个病根：**拿结构换分量，信息没增加**。用户对它们的反应是「AI 味太冲，删掉」「典型 AI 句式，滚远点」——不是嫌词差，是嫌句子在演。

| 句式 | 例 | 为什么假 |
|---|---|---|
| 「不是 X，而是 Y」「不只是 X，而是 Y」 | 不是运气差，而是系统漏 | 先立稻草人再推翻，节奏是模板给的 |
| 「真正 X 的是 Y」 | 真正难收的是下游 | 空壳主句给下句抬轿子，删掉不损失信息 |
| 「比 X 多一道 Y」 | 比只看期刊名多一道核对 | 对比结构代替信息，听着有分量其实没内容 |
| 「A 靠 B，也靠 C」开场 | 败露靠一通电话，也靠 PubPeer | 对仗开场，正文本事在后面 |
| 硬造动词 | 撑起 7 篇论文／撬开／炸出／换来／翻车／追着跑 | 中性事实被改成有情绪的比喻，一眼看出在凑画面 |

替代做法：动词只用事件本身带的（认定、审查、建议撤稿、发表、通报、回应）；段落之间靠时间与主体推进，不靠过渡金句。

**不许给读者派活。**「别把发表当成免检」「记住」「自查一下」「你需要」是自媒体劝导腔。内容号结尾**不做强引流、不塞产品名**（用户明确要求过），收在事实上就停。

## 事件类选题：新闻口吻，不是点评口吻

用户说「用新闻报道的口吻写」时，改的是句子结构，不是把语气调冷：

- **首句给主体＋时间＋机构＋认定了什么**，数字紧跟；不用「近日」「据悉」。
- **判断句必须有宾语**：「NIMS 认定 Xavier 两种都做了」，不能写「判定两种都干了」——无主语的判断句是 AI 最典型的省略。
- **段末只许是事实、数字或机构原话**，任何一段都不许用漂亮话收尾（连「真正难收的是下游」这种也不许）。
- **机构名／数据库名／榜单名先中文官方名再标英文缩写**：萨维塔医学和技术科学研究所（SIMATS）、撤稿观察（Retraction Watch）。
- **删解释性同位语**：「约三分之一是自引」后面不要再加「也就是自己引自己」——受众是圈内人时这是废话。只给真外行看不懂的术语留半句白话。
- **标题必须贴主题**：事件型标题写清「谁＋出了什么事」（印度学者造假被查，41 篇论文撤稿）。只堆数字或只留悬念会被判「不贴主题，重写」。dbs 公式库里 #1／#7 那类悬念公式适合观点稿，事件稿套 #26 数字锚 + #24 人群限定。

## 交付前程序化自检

禁用清单靠眼睛扫必漏，跑一遍代码再交：

```python
banned = ["不只是","而是","真正","多一道","其实","反而","值得注意的是","本质上是",
          "说白了","撑起","撬开","翻车","这意味着","换句话说","你","记住","别把"]
[print("HIT", b, body[max(0, body.find(b)-15):body.find(b)+15]) for b in banned if b in body]
print(len(body.replace("\n","")), len((body + tags).replace("\n","")))
```

命中要逐个看上下文：「比」在专有名词里（比厄尔名单）不算违规，其余照改。字数两项都要报（正文 / 含 tag 合计）。

## 成稿落位：SciLink 选题库子文档 + 回填字段

用户说「写成稿」时要的是三步，缺一步会被打回重做——**先读写作 DNA → 按 DNA 写 → 落到选题库子文档并回填字段**。

1. **先读已蒸馏的 DNA，不要重蒸馏**：SciLink 账号的写作 DNA 已在 `~/Documents/Hermes/写作DNA/SciLink/`（`Writing-DNA.md`、`语言DNA.md`、`文章结构模板.md`、`写作视角与认知框架.md`、`视觉风格指南.md`，`raw/` 里是成稿语料）。每次写稿先读整合文档，再按本次体裁回看 2-3 篇同类 raw 校准句感。这个账号是**长句式**账号，与通用小红书「一句一段、短句」相反。
   DNA 的量化目标：平均句长 ≥40 字、长句（≥50 字）约三成、短句（≤15 字）≤15%；并列信息用 `▫️` 列 3-5 条；`⚠️` 边界段 + 免责句 + 固定 6 个 tag；全篇不加小标题、不加粗。语料不足 20 篇时才按 `writing-dna-skill` 重新蒸馏，别凭印象写。
2. **子文档六段式**（每篇成稿一个 wiki 子节点，与其余选题子文档同构）：标题＝选题标题 → 元信息（日期/系列/内容分类/DOI/来源链接/封面文案/生图引擎/P2 说明）→ 图文标题 → 润色正文（小标题行标注「正文 X 字／含 tag Y 字，N 个 tag」）→ 出处（原题/来源或期刊/作者/链接）→ **事实核对表 + 发布边界**（逐条「稿中说法｜原文依据｜状态」，边界写成「只能写 X，不得写 Y」）。
   一条命令建好：`lark-cli docs +create --parent-token <选题库 wiki node> --title "<选题标题>" --doc-format markdown --content @/tmp/doc.md --as user`——`--parent-token` 直接吃 wiki node token，不用先 `wiki +node-create`；markdown 表格会转成真表格。
3. **回填选题库记录三字段**（子文档 ≠ 记录，两边都要有）：`图文建议标题 fld6INSLTV`｜`封面建议文案 fldXY4cwQ2`｜`润色正文 fldHZF29L7`，用 `+record-batch-update --json '{"update_records":{"<recX>":{...}}}'`；写完用 `+record-list` 读回核验（`+record-get` 读回可能显示 EMPTY，别据此判定失败）。

⚠️ **用户发来的多维表格链接里 `?table=ldx…` 不是数据表**。选题库里另挂着 `产品内容选题库`、`常用信源（用于人工筛选）` 这类 **docx Block**，两者共用一个 wiki 节点；把 `ldx…` 当 `--table-id` 传会回 `800010116 … resolves to a docx block, not a table`，而 `+table-list` 只列出 table Block，容易误判“这个 Base 只有一张表”。要往这种块里写稿：`lark-cli base +base-block-list --base-token <token> --as user` 列出全部 Block，从 `type=docx` 那条拿 `docx_token`，再用 `docs +update --doc <docx_token> --command overwrite --doc-format markdown` 写入（空文档可直接 overwrite，不丢东西）。用户说“放到这个文档/这个表里”时，**先判断他要的是数据表记录、还是 Base 里的 docx Block**，两者别混。

## 收批注再返工

用户会让你把标题与正文直接写进飞书长文里空着的「标题：」「正文：」，然后他在文档里逐句批注。写入命令、批注读取方式与替换流程见 `references/feishu-review-loop.md`——**先把批注逐条列成对照表再动笔**，他的批注经常是「整句删掉」「这词不用」，不是改措辞。

## 医学内容的写法（用户的核心场景）

- **相关 ≠ 因果**：写"研究提示、跟……有关"，并主动交代样本不大/时间短；不写"能治""能防"。
- **个案 ≠ 疗效**：病例只当故事写，并明写"这是一个人的故事，不能当疗效看"——这句话看着像免责，实际上是防评论区抬杠。
- **术语首个出现给一句白话**，优先用生活化比喻（医生的受众也吃这一套，但他们更在意准不准）。
- **边界话要变成人话**：合规提醒不要写成"⚠️ 注意：本内容不构成医疗建议"，而是折进句子里（"说'相关'比说'因果'稳"）。
- 单独一句的金句引语只引真人的原话，不要自己造标语（造出来的最像 AI）。
- **要引文献，不要写新闻播报**：用户会明确要求「不能写成新闻或科普建议，要引用具体论文」——此时交付形态是**论点 × 文献对照骨架**（每条结论挂一篇同行评议文献，标期刊 / IF 档 / 能否免费下载 / 直链），媒体转述只能当线索、不能当信源。选题切入点按「计数层 < 机制层 < 新情报」排序：只复述病例数等于已被做烂的新闻稿；机制（如疫苗的免疫学代价）、政策成因、前瞻裁决点才立得住。
- **新闻稿的信源必须是原论文，不是媒体条目**：拿 Medscape 一类报道写稿时先回溯原研究论文（层级：原论文/会议摘要 > 监管批准通知与说明书 > 媒体转述；媒体只能当线索）——题录核验、免费全文与官方图的拿法见 `medical-evidence-sourcing`「从一条新闻回溯到原论文」。
  两处最容易写错：① **署名以论文为准**，媒体按大会报告人写，很容易把报告人当成第一作者；② 国内状态查不到官方来源就不写。
  **例外：政策/教育/行业类新闻本来就没有原论文**（报道一份征求意见稿、一次学位改革、一项监管决定），权威媒体的新闻特写本身就是一手源，照写，但必须核三件事：**文件状态**（征求意见稿 ≠ 已实施 ≠ 已取消）、人名、机关全称。不能因为「找不到论文」就不写，也不能把报道的措辞升一级写成结论。
  **「文件状态」要往两个方向核，不只防“抬高”**：外媒写的 `draft` /「草案」不等于中方的「征求意见稿」——原件可能已经是**已发布试行**版（有红头、发文字号、「现发布…请…实施」字样）；反过来，报道说「已实施」而原件仍是征求意见稿的也有。所以状态只认官方原件首页的**红头+发文字号+发布字头**（部委官网 → 业务指导委员会 → 高校/机构转载的 PDF），不认媒体的形容词；核不到原件就写「据报道」，不给文件定性。定性写错会一路传进标题、封面和子文档，比数字错更难被发现。
- **英文报道里的人名是拼音，中文化必须核到汉字；核不到就不点名。** 英文媒体给的是 `Zhou Feifei` / `Liping Duan` 这种拼音，直接音译成汉字等于猜名。做法：`web_search "<机构> <推测中文名> <科室/职务>"` 反查（如「北京大学第三医院 脊柱外科 周非非」），核到的写汉字，**并把核实出的真实职务写进去**——往往比英文报道的描述更具体（英文写 a member of a national advisory committee，实名身份是「全国医学专业学位研究生教育指导委员会秘书长」），可信度直接抬上去；英文里的角色也别照抄（spinal surgeon 在中文机构里可能是「骨科副主任」）。核不到真实姓名的（学生、患者）一律改写成「他带的一名学生」「一位参与者」，**绝不按拼音猜字**：名字写错比不写更糟。
- **外文标题、栏目名、文件文号一律逐字照抄页面原件，不要凭记忆复述。** 同一篇稿件的英文标题换个词很常见（`Chinese doctoral students` 被记成 `PhD students`），凭印象写会跟图里的真实标题、跟子文档前后打架。标题要进正文／封面／图注时，从页面上复制粘贴，不从脑子里取。
- **媒体标题普遍比论文乐观一档，先看原论文标题是陈述句还是问句。** 媒体把观点／综述文（perspective、review、Trends 系那种「are we there yet?」）写成「AI 或能／首次／突破」是常态；写稿时封面与标题只能落在论文自己的限定上（未验证、不能进常规临床），不得复述媒体标题当自家结论。顺手把落差做成开头引子（「看到标题说 X，点进原文结论正相反」）——既是认知冲突型选题的天然钩子，也自动守住了事实边界。
- **指南／共识更新类稿件：写「新增了什么」之前必须拉开放全文核，不能从媒体稿倒推。** 媒体稿会同时犯两类错——**漏项**（建议清单里写了「A 或 B 也可用」，媒体只报 A，整类选项消失）和**框架误记**（把上一版就有的框架写成本次更新）。核实动作：全文里按病名／药物关键词定位小节 → 读该节的 `### Consensus recommendations` 清单（规范措辞在清单里，正文段落只是解释与证据）→ 看这段引的参考文献是不是上一版共识，是就别写「新增」。**要写进稿子的数字逐个回原文搜**：建议清单里没有的数字（步数区间、睡眠小时数）往往来自图表或媒体转述，写进去要降级措辞或标明口径。完整清单与核对表见 `references/guideline-update-coverage.md`。
- **用户自拟的句子要逐项回原文核，别只评措辞。** 他会拿一句自己写的稿子问「就这么写行不行」——先核事实再谈表达。典型错误是**把两种药并列成「同一类」**：同一份共识／指南常给两药相反的定位（A「仍有价值」、B「应停用」），并列即事实错误；差异通常有药理根源（是否引起低血糖），写错会被懂行的人一眼挑出。回答形态：**直接判语（能用／不能用 + 哪几个字必须删）→ 逐条毛病 → 改好的版本（给一句版和两句版让他选）→ 字数账 → 原文依据**。不要只说「基本可以」。
- **同一试验在不同报告时点的数字会变，跨期或跨试验比较前先对齐随访时长。** 媒体引的"II 期 44%"是最初一次中期分析，5 年随访时同一终点变成 49%（HR 0.51）——拿新结果直接对旧数字说"缩水"是没对齐随访；正确写法是各自标出中位随访（60.3 个月 vs 24.6 个月），并把旧试验拉到与新的相同时间节点再比。绝对率只在同一时点可比（4 年 72.4% vs 49.1% 不能与 5 年 68.8% 混用）。
- **交稿前做一次「核心情报覆盖自查」**：主终点数字 + 风险比（换成人话「风险降 X%」）、独立评审（BICR）复核、预设亚组、安全性里**可管理**的那一半（起病时间/可逆/靠减量处理）、探索性总生存（事件数、是否到最终分析节点）、同期对照试验。
  媒体稿普遍只传第一条；用户会直接问「这版有没有传达出原论文的核心情报」，先自查再交比被追问划算。

## 封面字/标题的中文化（用户硬要求）

用户原话是「尽量用中文，英文的话担心有的人看不懂」。所以医学内容的**封面主字与标题一律中文**：

- **主字不出现英文缩写**。细分病名太长时向上收一层：DLBCL → 封面写「淋巴瘤」（「弥漫大B细胞淋巴瘤」放不进封面大字）；**没有通用中文名的**（如 R-CHOP 这种五药联合缩写、MMR）保留英文，但只能放**小字角标**。缩写在小字里当「可信度锚」给懂行的人看，例：大字「一线淋巴瘤，该换方案了吗？」＋小字「R-CHOP＋双抗｜复发风险↓51%｜尚未获批」。
- **能换中文白话的指标全换**：HR 0.49 →「复发风险降 51%」（写明是**相对**降低）；PFS →「稳住不复发的时间」；R0 →「传染数（一个病人能传染几个）」。
- **未获批 + 只有顶线数据**时，封面/标题禁用「新标准已确立」「生存期翻倍」「一线治愈」；只写「或迎新标准」「可能改变格局」。**总生存无差异时不得只讲无进展生存的获益**——这是最容易骗到自己人的一处。
- **「境外已批、国内未批」是另一条独立边界**：标题禁写「国内已能用 / 已进医保」，正文只在末尾一句交代国内状态，且**查不到官方来源就不写**（自媒体「已申报上市」不算来源；官方依据看国家卫健委《新型抗肿瘤药物临床应用指导原则》最新版的药物清单里有没有它）。
- **总生存（OS）未成熟 ≠ 阴性，也 ≠ 能写「活得更久」**：这时只能讲「推迟进展」，并带上「中位」「研究者评估」两个限定词——中位 PFS 的绝对差（如 24.9 vs 16.3 个月）是在描述总体，不是个体预测。
- **大会报告的数字与审评机构口径可能不一致**（同一试验，会议上报的中位 PFS 与监管页写的「因删失无法充分描述」可以并存）：以官方页面为准，冲突时在稿里标出口径，**不要挑好看的那个写**。
- 每个选题/成稿交付都附一张**禁用词清单 + 必须标注的边界**，团队会拿它核稿。
- 交标题/封面字时**附禁用词清单**，用户会拿它核团队稿件。
- 用户说「调用 dbs 的 skill」时：先跑 `dbs` 主入口要求的版本检查脚本（`scripts/check-update.sh`，无输出则不加提醒），再用 `dbs-xhs-title` 的公式库执行，**每条文案注明公式编号 + 原始爆款 + 为什么选**（可溯源的公式匹配是它的核心价值，自由发挥会被视为没在用工具）。dbs 主入口默认只编排不执行，但用户说「帮我创作」时期望**本轮直接交成品**，不要再让他把提示词发一遍。
  **`dbs-content` 不是笔，是结构工具**——它自述定位是「你不帮人写内容，你帮人诊断内容该怎么做」，只出五维诊断报告。所以分工是：用户说「用 dbs 做内容结构规划」时，用它的**形式匹配 + 五维（文字洁癖／表达效率／认知落差）**产出**分段大纲**（每段一句话写清作用），再把大纲 + 事实骨架交给写手（本技能或 Kimi）落句；标题走 `dbs-xhs-title`。三段各管一件事，别让 dbs-content 碰句子。

## 用 Kimi 代笔：调用方式与改稿循环

用户明确要求「用 kimi 的文字写作能力」时按这条走。**接口在 `~/.hermes/.env` 的 `KIMI_API_KEY`，走 Moonshot 直连，别绕 CLI**（CLI 的登录态与模型配置各机不同，直连最快也最稳）。现成脚本：`scripts/kimi_text.py`（读 prompt 文件 → 出正文 → 打印实测字数）。

- **先写 prompt 文件，不要一句话丢过去。** 稿子质量取决于 prompt 里给了什么。固定五块：① 可用事实清单（编号，并写明「只准用这些，不许加数字、不许编引语」）② 分段大纲（每段一句作用，写明「不要加小标题，让段落自然流下去」）③ 写作禁令（无小标题／无加粗／无 emoji 分类／句长交错／套话黑名单／术语首现给半句白话）④ **正文字数预算** ⑤ 输出格式（只输出正文 + 最后一行固定 tag，不要说明）。
- **thinking 模型的坑**：`kimi-k3` / `kimi-k3.1-pro` 默认思考，`reasoning_content` 会把 `max_tokens` 吃光、`content` 返回空串（`finish_reason: length`）。两个修法，优先第一个：请求里加 `"thinking": {"type": "disabled"}`；或把 `max_tokens` 抬到 8000+ 再取 `content`。另：这两个模型**不接受自定义 `temperature`**（只允许 1，传 0.85 直接 400）。
- **字数预算按总数算，不按正文算**：正文预算 = 1000 − tag 字数（5 个 tag≈27 字）− 余量，即正文压到 **≈880–900 字**。给写手的指令里写正文额度，交付前实测 `len(全稿.replace("\n",""))`；只给「不超过 1000 字」的软约束，写手会写满 990 + tag 后超限。
- **超限／结构塌了不要自己动笔改，发第二轮**：把上一版原样回贴，列**编号问题清单**（超了多少字、哪一段结构塌了要拆、哪一段信息量最低要整段删、哪几个词重复了几次），要求只输出改好的稿。两轮内一般收敛，而且保留了「Kimi 写」这个前提。
- **成稿后逐条回原文核事实**（见下节），并交一张「事实核对表」。
- **用户给了原句就照抄，不要再让模型改写。** 他在批注里写「改为：<句子>」时，直接把这句放进正文；再让写手「润色」一遍会把他刚洗掉的味道装回去。模型只负责它自己那几段。
- **接口报 `engine_overloaded_error` 是秒级限流，不是配置错**：睡 5–10 秒重试，两三轮内就通；重试后先检查返回里有没有 `choices`，拿到 `err` 就继续等，别把错误 dict 当正文读。

## 用户偏好（硬要求）

- 先给结论再讲原因，不要铺陈。
- 外部数字/报道附出处，链接必须真含对应段落（他会点开核）。
- **外链能不能打开用浏览器验一次，别用 `curl` 的状态码判定**：政府站（fda.gov）对 curl 回 404、药企站与 Medscape 回 403，浏览器打开全部正常。批量粗筛可以用 curl，最终发给他的每条链接以浏览器打开确认为准；本机 TUN 代理下 `web_extract` 还可能回 `Blocked: URL targets a private or internal network address`（DNS 假 IP），同样改用浏览器。
- **链接回 404 先按标题关键词搜一次再下结论**：新闻站（Medscape 等）改标题会同时换 URL slug，旧链 404 **不等于**稿件被撤——搜回新地址给用户，别只说「没了」。
- 引外部内容时给播放量/日期快照。
- 不要为"显得专业"堆术语；术语必配大白话。

## 小红书投流素材（付费投放）

用户会按平台要求产出**投流笔记素材**：选题 → 标题 → 内容框架 → CTA。付费投放比自然流多两层约束（平台导流规则、学习与医疗类目准入），写错是直接烧钱。约束清单、CTA 分档表与协作约定见 `references/xhs-paid-traffic-constraints.md`，动笔前先读。

必守三条：
- **CTA 只能收口到站内动作**（评论报数据 / 主页群聊 / 私信 / 关注）。正文、图片、封面、评论区出现网址、微信、二维码、公众号名或谐音变体，投流直接拒审。
- **效果承诺与绝对化是红线**：包发表、保过、录用率、代写、最 / 第一 / 唯一 / 100% 全部不用。
- **交付必须带内容框架，不能只交标题**。用户会直接说"只列标题我不知道怎么写"。每条给：封面大字（≤12 字）/ 首句 / 正文分块要点 / CTA。

## 正文长度与引用落位（发布前必核）

平台硬数字，写完先拿工具数一遍再交——改稿比被打回便宜。

- **小红书正文上限 1000 字（含标点）**。交付前核实（`len(body.replace("\n",""))`），**写进交付说明的字数必须是这个实测值**——凭感觉估出来的数字会在用户核稿时被对出来，还得回头改交付稿。
  **用户说「正文不超过 N 字，包括 tag」时，把 tag 先扣掉**：正文额度 = N − tag 字数 − 20 字余量（5 个 tag 约 27 字）。指令里只给总上限、不给正文额度，写手会写满再超；交稿时三笔都报（正文 / tag / 合计）。
  **超限就当场给两版**，别等用户发现：① 完整版（内嵌全部引用，给公众号/知乎/长图/自家底稿）；
  ② 平台可发版（删引用行，正文只留「X 年那篇」这类指代，完整清单放评论区置顶）。
- **小红书正文里的网址不可点，且带链接易判导流限流**。论文与来源链接不塞正文，落位顺序：
  **评论区第一条 + 自己置顶 > 印在图上 > 正文只写编号或年份**。交付时把「评论区置顶」的现成文本一并给，
  并提醒发完立刻置顶。
- 图卡首行带出处（`作者. 期刊 年;卷:页 ｜ DOI`）——科研人截图保存时图里自带引用。

### 引用格式（用户硬要求）

- **不要「文中编号 + 文末参考文献表」**。改在**每个编号出现的位置就地写全**：
  `（编号 作者. *标题*. 期刊, 年, 卷: 页. DOI: 10.xxxx/xxxx）`，文末参考文献表整节删掉。
- **标题要保留**：就地引用时读者不点链接也该知道这篇讲什么。用户若要严格沿用无标题格式，他会自己说。
- 编号按**文中出现顺序**重排，不留跳号；正文外另提的同期工作单独标「同期独立工作」并注明不计入篇数。
- 卷/期/页以 CrossRef 为准：**自己早前给过的缩略页码可能反而不如用户原稿准**（实测 S143 的完整值就是 S143-S156），别默认自己是对的。

### 外部 AI（Kimi 等）写的稿：不直接采用，逐句回原文核

用户会拿一份外部 AI 稿让你「改格式」。**改格式的同时必须顺手核事实**，最容易错的三类：

| 类型 | 典型 | 核查手段 |
|---|---|---|
| 数量级 | 「约半毫秒」实为「微秒级延迟」 | 回原文 grep 时间量词（latency / ms / µs） |
| 严重程度 | 「全盲」实为 `visual acuity limited to light perception`（仅存光感） | grep 描述患者基线状态的词 |
| 首例/唯一口径 | 「全球首例人体治疗」实为 `the first reported case of partial functional recovery…` | grep `first`，看限定词限定在哪个词上 |

本地有 PDF 就 grep 关键词，没有就读全文/摘要原句。交稿时**附一张「改动 + 依据」表**，用户会拿它核团队稿件。

**跨受众的「论文串讲」类稿件（诺奖/重大突破）**：叙事骨架、双受众分层、官方关键文献从哪来、引用数与配图版权口径，
见 `references/science-progress-paper-chain.md`。

## 小红书话题标签（tag）怎么打

用户会直接问「这篇要打什么 tag」。平台上限 **10 个/篇**（超了不显示），**前 3 个权重最高**，按五档配比，每档至少留一个：

| 档 | 作用 | 例（科研号选题） |
|---|---|---|
| 热点大词 | 吃事件流量，时效期最肥 | #诺贝尔奖 |
| 精准核心词 | 搜它的人就是目标受众 | #光遗传学 |
| 受众词 | 圈定人群 | #医学生 #SCI论文 #读研 |
| 垂类常规词 | 稳定类目归属 | #科研 #科研日常 #文献阅读 |
| 品牌词条 | 攒自家入口，必打 | #刀客轻研SciLink |

交付形态：一张「标签／档位／为什么」表（用户要看出你懂他受众）＋ 一版「只打 5 个」的精简组合（热点＋核心＋受众＋精准场景）＋ 备选池单列。**同义大词别同时打**（#诺贝尔奖 与 #诺奖 二选一），会被当堆砌。

**红线：非认证账号不得发医疗科普。** 平台只对公立三甲医生或公立医院主治医师及以上开放医生认证；非认证账号发医疗科普会被判违规下架/限流。所以**医学类选题打「科研/学习/阅读」类目词**，避开 `#医学科普` `#健康科普` `#医疗科普` `#疾病科普` 及具体病名/科室词。同时提醒：正文与图里也不要出现「能治 / 复明 / 疗效」话术——这类词既踩类目又踩事实边界。

时效提示：热点流量高峰在事件公布后 3–7 天。回答前先用 `date` 实测「距今几天」（别凭印象），再决定还值不值得抢这个词。

## 「给我一套选题」的交付形态

用户说「整理出一套适合给医生/科研人/医学生看的小红书选题」时，交的不是标题清单，而是：

1. **开头一句结论**：这批新闻在库里实际聚成几个事件、几篇有效稿（他会以此判断你有没有真查）。
2. **事实骨架表**：每条硬事实一个编号 + 一句出处（官方页 / 论文 / 会议摘要），后面的选题用编号引用（「依据：事实 3/4」）——文案只准用这张表里的数字。
3. **选题按受众分组**（医生 / 科研人 / 医学生 / 患者），每条给：封面大字（≤12 字）→ 3 个标题备选 → 正文骨架 3–5 点 → 依据（事实编号）→ **风险边界**（这条哪些话不能说）。
4. **收尾三张表**：禁用词与必标边界、术语白话对照、**建议发布顺序**（先发知识卡与临床可操作，安全性与科研深度放后面，受众最广且最不容易被挑错）。
5. **落一份 md 文件**给团队用（选题 + 出处链接明细 + 三张表），聊天里给同一份内容。落盘目录 `~/Documents/Hermes/小红书成稿/`，文件名 `YYYY-MM-DD_选题.md`；聊天里用 `MEDIA:/绝对路径` 附上，正文照旧完整贴出（不要只给路径）。

## 段落级行文（用户会逐句抠；说「狗屁不通」通常指顺序而非用词）

- **解释性前提放在结论前面。** 先交代口径／证据窗口／来源，再给结果。倒过来写（先抛「共识主张 X」→ 再抛「某试验显示反例」→ 最后才解释两者为何不矛盾）读者会在撞上矛盾处卡住，卡顿感就是这么来的。
- **跨段指代一律写实。** 正文分段后「这两类药」「这个方案」「上面那条」会断链——读者的手指在滑，不会往回翻。改写成药名或类别名。
- **引外部观点不许删说话人。** 把「评论者某某指出……」的人名删掉，句子就变成无主句，读者会当成本文、甚至本文所引那份文件的判断——这是把外部评论冒充成文件结论。
- **一段一件事。** 两个不相干的话题（如试验结果／费用可及性）钉在同一段，中间必须有过渡；没过渡就拆段。
- **正文改动要连表一起改。** 事实骨架表、禁用词表、术语对照表与正文是同一份交付物；只改正文不改表，用户会拿表核出不一致。

## 常见返工点

- 给了小标题结构 → 被打回。
- 全篇句子一样长、每段都收尾 → 被打回。
- 医学断言写满（"大笑能降皮质醇 30%"不交代研究质量）→ 必须补边界句。
- 标题只有数字和悬念、不说清「谁出了什么事」→ 被打回重写。
- 用了「不是 X 而是 Y」「真正 X 的是 Y」「比 X 多一道 Y」→ 被打回，这三句一律不许。
- 结尾给读者派活或带产品名 → 被打回（内容号不强引流）。
- 判断句省略宾语（「判定两种都干了」）→ 补主语与宾语。
- 机构名/数据库名先英文后中文 → 反了，中文官方名在前，英文缩写放括号。
