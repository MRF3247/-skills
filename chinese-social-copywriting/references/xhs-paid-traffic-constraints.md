# 小红书投流素材：约束、交付格式与分档

适用于为品牌号产出**付费投放**的笔记素材（选题 → 标题 → 内容框架 → CTA）。自然流可以宽容的地方，投流不行——每条素材都要过审、要花钱。

---

## 一、CTA 三层漏斗（导流唯一合法路径）

平台禁止笔记站外导流，所以「引导用户去用我们的产品」只能拆成三层，层与层之间不能越界：

| 层 | 位置 | 允许写什么 |
|---|---|---|
| **L1 笔记内** | 正文末、评论区 | 只能写**站内动作**：评论报数据、主页群聊、私信关键词、关注、收藏 |
| **L2 承接** | 专业号私信自动回复 / 粉丝群公告 / 官方留资组件 | 学习与医疗类目走平台官方留资（客资收集）通道，这是官方给投流获客的口子 |
| **L3 产品** | 群内或官方组件里给 | 引导**在平台内搜品牌词**，不给外链 |

投流前必须先把 L2 搭好（私信自动回复 + 粉丝群 + 官方组件）。承接层没搭就投，最贵的那段流量全浪费。

**一条都不能破**：L1 写「加微信领资料」＝整条笔记白投。

---

## 二、红线清单（逐条过）

1. 正文 / 图片 / 封面 / **评论区** 都不出现：网址、短链、微信号、谐音变体、公众号名、二维码、手机号
2. 不写「免费领取」诱导站外；改站内群聊或官方组件
3. 「体验名额」必须真实、有期限，走官方组件报备
4. 评论区别用统一话术批量回复（判协同营销）；真实回复
5. 效果承诺一律不用：包发表 / 保过 / 录用率 / 一定能中 / 统计一定显著
6. 绝对化一律不用：最 / 第一 / 唯一 / 100% / 全网最低
7. 学术代写叙事不进素材：可以说全流程，落点放在**数据分析、统计、图表**
8. 不贬低同行与既有工具；做对比时两边都说，否则判引战
9. 案例必须真实且脱敏，需授权；不编使用经历
10. 医学数据类内容提示「上传前做脱敏」——既是合规也是信任加分
11. 学习 / 医疗属受限类目：投流需主体资质 + 行业资质，品牌号需专业号认证
12. AI 生成图片 / 配音的素材按平台要求打 AI 标识

---

## 三、交付格式（用户硬要求）

**只给标题会被打回**（用户原话即「你标题列出来了我都不知道怎么写」）。每条素材必须成套：

- **封面大字** ≤ 12 字（决定点击率）
- **首句**（决定停留）
- **正文分块要点**（按屏 / 按图分块，不是一段散文）
- **CTA**（站内动作，见上）
- 标题 ≤ 20 字（含标点），勾选标题公式时标公式编号，便于回溯

分批交付时附：合规红线清单 + 投放优先级建议（哪几条先投、哪几条只做自然流）。

---

## 四、动笔前先建「弹药库」

顺序不能反：**先分清哪些能说、哪些要改口径，再动笔**。投流素材一旦用了内部宣传口径，既违平台规则又给自己挖坑。

流程：读产品资料 → 列「能说的实锤口径」→ 列「要改写的宣传口径」→ 才开始写。

改口径的通用模式（SciLink／刀客轻研 实测）：

| 内部 / 宣传口径 | 对外改成 | 原因 |
|---|---|---|
| 业界独家 / 唯一 | 目前同类产品少见支持 | 绝对化，且无法举证 |
| 「N 种算法」（跨套餐） | 主流算法（按套餐口径，低档 6 类起） | 笼统说＝虚假宣传 |
| 创新度 5 星、数据匹配度 5 星 | 平台的创新度 / 匹配度评分 | 平台自评不等于期刊评价 |
| 匹配 IF 9.3 期刊 | 可参考的期刊匹配方向 | 暗示能发 |
| 幻觉率低于 2% | 参考文献可溯源 | 宣传数据，投流别写 |
| 和统计老师结果 100% 一致 | 结果可提交统计老师复核 | 不能承诺一致 |
| 数据不存储 / 五重加密 | 按已核实口径写；两份资料口径不一致时取最保守的那个 | 口径冲突不写入素材 |
| 内测用户的医院 + 职称 + 科室 | 脱敏为「某三甲医院」 | 隐私，且需授权 |
| 个人发表量 / 团队成员资质 | 未经授权不写 | 背书不可自证 |

## 五、内容框架：五段式

```
① 处境钩子 ── 封面大字 + 首句，写具体场景，不写抽象标签
② 归因 ────── 给一条可验证的因果，不贴「焦虑 / 内卷」这类情绪标签
③ 评价转向 ── 说出同行没讲清的那一层（认知落差）
④ 让用户先做一个低门槛动作 ── 判断自己属于哪类起点（转化关键步）
⑤ CTA ────── 按起点分档收口，只走站内
```

**两条铁律**：
- 产品**只在 ④⑤ 段出现**。①②③ 段插产品＝判广告，且共鸣崩掉。
- CTA 必须让用户做**一个具体的、低门槛的站内动作**，不能是「了解更多」。

---

## 六、CTA 必须按用户所处阶段分档

不要让所有笔记都指向同一个产品入口。用户的起点不同，硬推同一个入口，转化率会明显掉——**话术可以统一成「帮你把 XX 这一步走完」，入口按起点分**。

### 选题类素材

| 起点 | 用户状态 | 产品入口 | 笔记内 CTA 话术 |
|---|---|---|---|
| A 假说驱动 | 有想法，没方案 | 选题助手 | 「评论区说你的方向，我帮你看看有没有空白」 |
| B 数据驱动 | 有数据，没方向 | 数据反向选题 | 「你手里多少例、多少变量？评论区报一下，我告诉你这数据能撑起什么题」 |
| C 文献驱动 | 没数据，没方向 | 选题 + 文献 | 「主页群聊有一份选题自查表，先照着填一遍」 |
| D 方法驱动 | 有方法，缺工具 | 自定义科研 / 建模 | 「收藏这张顺序图，对着自己的数据走一遍」 |

### 数据分析类素材

| 起点 | 用户状态 | 产品入口 | 笔记内 CTA 话术 |
|---|---|---|---|
| Ⅰ 数据没动过 | 不知道该跑什么 | 一键预分析 | 「评论区报几个数：多少例、多少变量、有没有时间变量」 |
| Ⅱ 跑过基础统计 | 要进阶建模 | 智能模型训练 | 「评论区说你的研究类型和结局指标」 |
| Ⅲ 结果有了 | 图表不达规范 | 出图能力 | 「主页群聊，说你的目标期刊类型」 |
| Ⅳ 怕不专业 | 不敢信结果 | 过程透明 + 可复核 | 「评论区说你想复核哪一步」 |
| Ⅴ 卡在软件 | 学不会 R / SPSS | 零代码路径 | 「收藏这张流程，对着自己数据走一遍」 |

**让用户报数据本身就是留资动作**——报例数、变量数的评论既是互动也是线索，转化链路最短，这类素材优先投。

## 七、好用的白话锚点（医学科研题材）

术语配一句外行能懂的话，投流素材里比专业表述更能停住人：

- **去混杂因素** = 称体重前先脱掉衣服鞋子，不然你称的不是你自己
- **基线特征表** = 分组之前先证明两组人「本来就可比」
- **校准曲线 / 决策曲线** = 模型说不准不准（校准）、说临床实不实用（决策）
- **过拟合** = 训练集上漂亮，换一批患者就崩

## 八、协作约定

- 用户会点名 skill（如 dbs）。**开工前先确认那个 skill 是否真覆盖该任务**；不覆盖就直说，不要顶着 skill 的名义自己产出——用户会验证并当场问「这是 XX 做的吗」。已知 dbs 没有「生成选题」的 skill：`dbs-content` / `dbs-resonate` / `dbs-hook` 都是诊断器（处理已有选题、已有文稿），`dbs-xhs-title` 只出标题，`dbs` 本身是编排器且其规则禁止在编排轮直接产出交付物。
- 内部定调要遵守：**核心竞争力和收费点落在「选题之后的数据分析」**，参考文献真实性不作为最亮卖点；效果上只讲「可发表性预判」「规避方法学硬伤」，不讲录用。
- 投流素材与自然流素材**混投**（如选题拉新 + 数据分析承接付费），不要把所有预算压在同一个能力上。

## 九、交付落地：飞书《社媒选题库》表

选题库沉淀在飞书知识库《社媒选题库》文档的一张表里，列固定为 **痛点 ｜ 标题 ｜ 封面文案 ｜ 首句 ｜ 要点**（痛点＝粗分类，如 论文选题／数据分析／图表与投稿，只在每组首行填）。用户会自己粘一部分进去，再让你「按表格格式填进去」。

- **继续出新批次时默认追加到这张表**，不要另起文档——这是长期资产，用户偏好一份资产一张表。
- 表里**没有 CTA 列**。当用户既要求「CTA 必须落到产品」又要求「按我的格式填」时：严格按现有 5 列填，然后在回复里**提议加第 6 列 CTA（站内）**，不擅自改结构。
- 回填/补全这张表的命令链路（fetch with-ids → 重建整表 → block_replace → 空单元格计数验证）见 `feishu-cli-workflows` 的「回填/补全用户手填一半的表格」一节。
