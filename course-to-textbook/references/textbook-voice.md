# 教材体例：去来源指向、去作者自述

## 为什么要做

教材一旦出现「课程讲师说」「原课程没有」，读者立刻判定这是二手转述，权威性归零，而且能顺着找到原课。教材自己必须站成信源：所有内容以教材口吻直接给结论。

同理，作者自述（「我核实过」「我的译文」）会暴露编写过程，让读者注意到“有人在替我筛过”，反而削弱可信度。正确做法是把可验证性直接交给读者：给 PMID、给官方链接。

## 一、来源指向 → 教材陈述

| 改前 | 改后 |
|---|---|
| 课程讲师用了一个很朴素的比喻：构建检索式就像做加减法 | 构建检索式很像做加减法 |
| 课程讲师的原话是，高级检索是最需要掌握并熟练的检索方式 | 高级检索是最需要掌握并熟练的检索方式 |
| 课程举的例子是冠心病 | 以冠心病为例 |
| 课程推荐的 / 课程给的实用建议是 | 常用的选择 / 一个实用的建议是 |
| 课程讲师试过一次性构建完整检索式 | 很多人试过一次性构建完整检索式 |
| 课程讲师明确反对这个判断顺序 | 这个判断顺序是反的（直接说结论） |
| 课程讲师说这个方法「十天左右」见效 | 这个方法十天左右就能见效 |
| 这一章课程里没有，是我补的 | **为什么要有这一章**：前面教你搜，但没教你怎么判断「这次搜完了没有」 |
| 这一篇课程里没有 | （整句删掉，直接进正文） |

改写要点：去掉主语后的句子必须自己站得住。只删「课程讲师说」会得到「给了一个判断：……」这种残缺句，要顺一遍。

## 二、作者自述 → 客观陈述

| 改前 | 改后 |
|---|---|
| 我核实过真实存在 | （PMID 9742977，可在 PubMed 核对） |
| 下面是我的译文 / （我的译文） | 以下为译文 / （译文） |
| 我实际在 PubMed 上跑过 | 在 PubMed 上实跑过 |
| 我觉得应该贴在每个新手电脑上 | （整句删掉，直接给那句话本身） |
| 我不建议使用 | 本书不推荐使用（并给实在理由，不给道德说教） |
| 所有工具我会给官方链接 | 书中给出官方链接 |
| 我把它整理成一张表 | 整理成一张表 |
| 我按实用性排序 | 下面按实用性排序 |

## 三、保留：读者视角的「我」

这些删掉反而生硬，全部保留：

- 举例与比喻：「我想找临床医生科研成长平台」「我想要一碗不太辣的面」
- 自问：「我现在是想让结果变少还是变多」「我读这篇是为了什么」
- 自查清单：「我的检索词覆盖了吗」「我的结果量匹配吗」
- 工具评估：「它替我省下的是重复劳动还是判断工作」「我一周用几次」

判据：**这个「我」是不是读者自己在说话**。是 → 留；是作者在报告自己做了什么 → 改。

## 四、第二层 AI 味：来源和自述清干净之后还剩这些

来源指向和作者自述都清零了，稿子仍然能被认出来。剩下的是**语气层**的痕迹，比前两类更难自查，因为每一句单看都“没错”。

### 4.1 评价性形容词引导语（最典型）

作者在给读者端东西之前先夸一句，这是 AI 最稳定的写作习性：

| 改前 | 改后 |
|---|---|
| 有一个观察值得放在这里： | 一个观察： |
| 有一句话值得贴在每个新手的电脑上： | （删引导，直接给那句话） |
| 一个比教科书更好懂的定义是： | 定义可以这样说： |
| 有一个很实用的判断： | 一个判断： |
| 这是本章最值得记住的一句： | （删引导，直接给那句话） |
| 这是最实用的一张表，建议存下来： | 工具对照表： |
| 有一个比例，是对 AI 最清醒的定位： | 一个比例： |
| 最实用的路。具体做法有四步： | 这条路最省力： |
| 这一节是本章最重要的部分。 | （整句删掉） |

判据：**这句话去掉之后，内容有损失吗**。没有就是夸，删。「值得」「最实用」「最好懂」「最清醒」「最值得记住」五个词是重灾区，成批出现即为未定稿。

### 4.2 命令式「记住」

教材不是教练。「记住」「请记死」「必须记住」满篇都是，读起来像训话。改成陈述句，结论本身已经说清了：

| 改前 | 改后 |
|---|---|
| 一个必须记住的限制 | 一个限制要留意 |
| 记住这个手感 | 这个手感要练出来 |
| 一条铁律，请记死 | 一条铁律 |
| 记住这些名字 | 知道这些名字 |
| 记住这个一一对应关系 | 理清这个一一对应关系 |

例外：指向专家本人记忆的（「他记住的案例是印象深的」）是正常语义，不是命令式，别误改。

### 4.3 段落节奏：先看下游块，别看段落长度

短段落先别急着判死。**判据是引导句后面跟的是什么块**：

- 短句 + **列表 / 表格 / 代码块 / 引用块** → 结构正常。这些块本来就需要引导语，硬合并会毁掉版式。
- 短句 + **普通段落** → 这才是 AI 节奏（一句引出、换行、再说内容），可以合并成一段。

本次全书 588 段里有 78 段不足 15 字，看数字像大问题；逐条看过，**只有 10 处是真问题，其余 68 处全是列表项、代码块输出行、图片说明**（「命中 38,424 条。」「1. 读摘要」）。按长度批量合并会把正常排版改烂。

写自动合并脚本时，跳过列表/表格/代码/引用的块——**脚本合并 0 处不是脚本坏了，是本篇结构本来就没问题**。先读懂这个信号再决定要不要“修”，别因为工具没产出就改判据。

### 4.4 批量改写脚本的引号陷阱

多篇合起来几十处替换，`old_string` 里的标点必须和原文**逐字一致**。原文段落用过中文引号 `“”` 之后，替换对里写英文 `"` 会整条未命中——本次第一批 10 处只命中 6 处，全是因为这个。

批量前先 `grep` 或读原文确认引号与标点形态；脚本要打印每条的命中/未命中，未命中的补第二遍，不要相信第一次跑完的“改 X/N”总数就收工。

## 五、交付前痕迹全查：文本层 + 文件层

### 5.1 词表必须含原课的品牌名与机构名

只查「课程 / 讲师 / 本课 / 原课」清的是元叙述，**查不出讲师随口举的品牌名**。讲「什么是检索」时顺手拿自家或同行产品举例（「在百度输入这句话，结果里出现了解螺旋」），这类专名散在正文里，句子本身毫无破绽，读者一搜就到原课。

词表三类都要有：**来源类**（课程/讲师/授课/课堂/录屏/课件/本课/原课）、**机构与品牌**（原课平台名、公司名、其产品名、站名）、**人名**（讲师名）。第三类最容易漏——讲师常自称，名字会出现在例句和注释里。

`PPT` 这种缩写会误伤（产品能力关键词里就有「汇报PPT」），命中后逐条看语境，别直接替换。

### 5.2 讲师当成方法论教的专有缩写（最隐蔽的一类）

5.1 查的是「顺口举例提到的品牌」。更难发现的是**讲师把自家框架名当方法论教给你**：它伪装成通用术语，内容往往也对，只有名字是品牌资产。

典型形态：某生信课把「找差异分子 → 功能富集 → 看互作网络 → 贴近临床意义」压成一个四字缩写，并配一个同名公众号。这四步是通用流程，那个缩写却是课程品牌。教材原样保留，等于把品牌词当学术术语传给读者，读者一搜就落到原课。

**判定信号**（在源里 grep 该词，看上下文）：

- 伴随「咱们 / 我们 / ××大大的课 / 听过××的课」出现 —— 基本可判为平台自有
- 该缩写能展开成若干步骤，但搜索引擎里只指向同一家机构
- 与具体产品 / 公众号 / 连载专栏同名

**清除方式是展开，不是删除。** 直接删掉内容会断，读者不知道这几步在干什么。把「（四字缩写）」改成「（差异分析 → 功能富集 → 互作网络 → 临床关联）」，信息量不降反升，还去掉了品牌。

同一批要顺带核的还有：讲师自称（××大大）、课程连载专栏名、无代码分析平台名。这几个在演示节里出现频率很高，因为它们常被当成「推荐工具」讲。

### 5.2b 扫描词表必须含 ASR 变体

品牌名在转写稿里经常是错字，两个后果：①你可能把变体抄进了书；②你用正名 grep 会搜不到源里的证据。

实测变体：`解螺旋 → 解解蟔旋 / 解罗旋`、`仙桃学术 → 监讨学术 / 线套学术`、`生信研究 → 深性研究`。

做法：BRAND 列表里正名和变体一起放，再用模糊式兜一遍（`解.螺.旋`、`[监线]讨?学术`）。OCR 文本里的错字形态和 ASR 不一定一样，两侧各扫一次。

### 5.2c md / PDF / 交付包三处都要扫

工作目录的章节 md、合并后的 PDF 全文、以及**打包 zip 里的 md** 各扫一遍。zip 里是另一份拷贝，改完 md 忘了重打就是旧版发出去——三处都 0 才算清。

### 5.3 文本层：md 与 PDF 各扫一遍

```python
import re, glob
SRC  = r"课程|讲师|本课|这门课|原课|课上|课里|授课|课堂|录屏|课件"
AUTHOR = r"我核实|我查过|我实际|我的译文|我把它|我觉得|我认为|我建议|我补|我加|我删|我写|我引用|我选|我按|我照|我会给|我不建议|值得抄"
EVAL = r"值得放在|值得贴在|很实用的|更好懂|最清醒|最值得记住|最实用的一张表|最重要的部分"
CMD  = r"记住|牢记|记死"          # 会误伤“他记住的案例”，命中后逐条看语境
BRAND = ["<原课平台名>", "<公司名>", "<其产品名>", "<讲师名>"]   # 每次按课程清单填
for f in sorted(glob.glob("第*.md")):
    t = open(f, encoding="utf-8").read()
    print(f, "来源", len(re.findall(SRC, t)), "自述", len(re.findall(AUTHOR, t)),
          "评价引导", len(re.findall(EVAL, t)), "命令记住", len(re.findall(CMD, t)),
          "品牌", [k for k in BRAND if k in t])
```

md 干净后，对合并好的 PDF 再扫一遍——md 干净但 PDF 有，多半是某篇漏改，或卡片/图注这类没被正文替换覆盖的地方。

**PDF 全文检索前先去掉换行符**（`t = "".join(p.get_text() for p in d).replace("\n", "")`）。排版会把长词切到两行，`北京大` / `学医学部` 分开存，直接搜「北京大学医学部」得到 0 命中——这个假阴性会让你把「还在书里」误判成「已经清掉」，反过来也可能把「写对了」误报成「漏了」。跨行的长词、机构名、带空格的英文术语全部中招。

```python
import pymupdf
d = pymupdf.open(pdf_path)
pages = {i+1: d[i].get_text() for i in range(d.page_count)}
for k in [*BRAND, "课程", "讲师"]:
    hit = [n for n, t in pages.items() if k in t]
    if hit: print(k, hit)
```

### 5.4 文件层：读者翻不到但会被扒出来

正文清零之后还有四处会泄底，位置都很隐蔽：

```python
import pymupdf
raw = open(pdf_path, "rb").read()
d = pymupdf.open(pdf_path)
print(d.metadata)                                   # title/author/creator/producer 应全空
for kw in [b"helix", b"jlx", b"slide", b"pptx", b"convert"]:
    if raw.count(kw): print("二进制命中", kw, raw.count(kw))
for i in range(d.page_count):                       # 嵌入图片的原始文件名
    for img in d[i].get_images(full=True):
        print(img[7] if len(img) > 7 else img[0])
print({f[3] for i in range(d.page_count) for f in d[i].get_fonts()})
```

| 位置 | 会泄什么 | 判据 |
|---|---|---|
| `metadata` | 制作工具写进的 title/author/producer | 全部为空或中性；有工具名或原课名就清 |
| 二进制字符串 | PPT 转出的图带 `slide`、原课域名 | 直接 `open(...,'rb').read().count(b'...')` 查 |
| 嵌入图片名 | PPT 截图的原始文件名（`slide_012.png`） | 只应出现 `X4`/`X133` 这类对象编号；有语义文件名就说明图是直接拷来的 |
| 字体 | 课件模板字体 | 只应有正文用到的宋体/黑体/等宽字体子集 |

**插图源 HTML 也要 grep**：图是重画的，但图里可能照抄了原文措辞（`grep -l "解螺旋\|讲师\|课程" figs/*.html`）。图内的字 vision 复查看不出“这是哪来的”，只有源文件能查。

### 5.5 报告口径

查完先报**命中数与页码**，再报“其余全清”的具体项（元数据、二进制、图片名、字体、插图源各一行）。用户问“还有没有痕迹”时要的是可抽查的结论，不是一句“干净了”。

### 5.6 清过的稿子会重新长回痕迹：每次重出都要重扫

第一轮清干净的稿子在后续补章、补图、补段落之后会重新长出语气层痕迹——实测一本已宣布「清零」的书，隔几轮扩写再扫，仍有破折号 2 处、「不是…而是」1 处、评价性引导语若干（「第三问最关键」「全书最重要的一条」）。**「上次清过了」不是免检理由**：AI 味扫描要挂在 build 脚本里，每次重出全本都跑，而不是只在首次定稿时跑一次。

**扫描要连标题层一起扫。** 提示性冒号最容易藏在 `###` 小标题里（「### 12.5 一句话总结这个判断流程」），正文字句里反而没有。正则跑整篇文本、不跑单段；命中后按行号定位，标题层的改法是换个中性名词（「判断流程回顾」），不是删掉标题。

判干净的三个数：破折号 0、`不是…而是` 0、提示性冒号（含「一句话总结 / 关键点：/ 关键是：」）0。命令式「记住」的命中逐条看语境（指向专家本人记忆的不算），评价性「最关键 / 全书最重要」也要归零。

## 六、报告怎么给

**用户说“找出以 AI 口吻说我做了什么的地方，我看看哪些要改”时，先分类再动手，不要一口气全改。** 按严重程度分三档，每处给行号 + 原文 + 一句话问题，让用户挑范围：

- **A 必须改**：作者自述与作者评价（「我觉得」「我核实过」「我把它整理成表」）
- **B 建议改**：元叙述（「这一章课程里没有，是我补的」）——这条信息有来源交代价值，问题只在主语，教材体例里要么改编者口吻、要么直接不点明来源
- **C 不用改**：读者视角的「我」（见第三节），并明说删了会生硬

三档一次列完，用户直接回「A+B」就行；分几轮问会拖成三四轮。

改完按类报数 + 给改前改后对照，不要只说「都改好了」。用户要的是能抽查的清单：来源指向 N 处、作者自述 M 处、引号 K 处、破折号 J 处，每类举 3–5 条对照。
