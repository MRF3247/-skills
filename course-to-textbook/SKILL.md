# 课程 → 教材重构

## When to use

用户手里有**已落盘的课程**（视频 / 逐字稿 / PPT 页），要求“重构成一本教材 / 写成讲义 / 系统化整理”，而不是照搬课程章节。

关键区别：课程是按**讲课进度**组织的（讲到哪录到哪，同一个知识点被演示三次），教材要按**学习路径**组织（概念→方法→判断→实战）。照搬章节得到的是带时间戳的课堂记录，不是教材。

## 开工前必问三个参数

不问就写必返工：

1. **读者定位**（零基础学生 / 有课题的研究者 / 两者分层）—— 决定概念要铺多深
2. **篇幅**（精读版 3–5 万字 / 浓缩手册 1.5–2 万字 / 先出浓缩再扩）—— 决定每章颗粒度。实测参考点：15 章 / 3.4 万字 / 114 节 / 82 页正文 / 5 张图，每章 2000–3000 字。换成 5 篇 15 章这种体量，从下载到成书是一条完整流水线，不要按“篇”分批交付后又拼一次。
3. **操作演示怎么处理**（保留可复现步骤 / 只讲方法 / 关键步骤留图）

## 用户的硬要求（每一条都曾导致返工）

1. **不贴原始截图**。界面类图用 HTML/CSS 画线框（只保留讲解必需的元素 + 编号标注），流程/结构图用 SVG。理由：真实界面两三年就过时（书上写“点左上角”就是在制造错误），且截图版权归属不明。原始截图只当绘制参考。
2. **案例必须换掉原课的**。原课举的病例/文献要避开，避免和原课或自家产品演示撞车；每个引用逐条核验（PubMed 检得到、PMID/DOI/期刊/年份对得上），定稿前再用 DOI 反查标题作者年份。**宁可少引，不可编引。**

   **写“检索过程”类章节时，把案例的每一步命中数用 E-utilities 真跑一遍**，不要编“几万条”“几十条”这类模糊数量级。`eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi?db=pubmed&term=<式>&retmode=json` 拿 `count`，`esummary.fcgi` 拿标题/期刊/年份/DOI。现成脚本见 `scripts/case_ladder.py`。

   教材里每个命中数后面**标检索日期**（数据库每天在变，读者复跑数字必然不同），并在图注或脚注里写一句“数字会变，趋势不变”。

   阶梯要设计成能演出“加法变少、减法变多”的节奏：单词 → 主题词 → 加疾病概念 → **补自由词（OR，数字会反弹）** → 限研究类型 → 限时间。第 4 步的反弹是 OR 在起作用，不是写错，这是全章最好的教学点。

   同时要提醒一个真实陷阱：**最后一步的时间限定会把奠基性文献一起切掉**（实跑中“近五年”筛掉了 1998 年的 UKPDS 34，PMID 9742977）。教材里点名这篇被切掉的经典，比空讲“时间限定要谨慎”有用得多。
3. **剔除与业务无关的模块**。先问用户这块业务做不做（生信、湿实验、Meta 等最容易误入），不要因为课程里有就全保留。
4. **自有产品植入写“输入→输出”，不绑按钮位置与界面版本**——版本升级后不用回头改书。写之前先核能力边界（见下）。
5. **知识点清单先给人审**，方向确认后再写正文。直接上万字正文等着被全盘推翻。
6. **正文不指向来源，教材自己就是信源**。成稿里不许出现「课程讲师说」「课上讲」「原课程没有」「这一节是我补的」。读者买的是一本教材，不是课堂记录；留下来源指向，它永远像二手转述，还会被人顺着找到原课。要补的缺口直接当正常章节写（「**为什么要有这一章**：……」），不解释“这段是补的”。
7. **正文不出现作者自述**。「我觉得」「我核实过」「我的译文」「我把它整理成表」「我会给链接」全部改写：判断直接给，核验改成可查标识（「（PMID 9742977，可在 PubMed 核对）」）——既不说自己做了什么，又把核验能力交给读者。**读者视角的「我」要保留**（「我想找…」「我的检索词覆盖了吗」「我一周用几次」），那是代入感，不是自述。
8. **来源和自述清零后，还要过一遍语气层**。读者说“再看看还有没有 AI 味道”时，指的通常是这一层：评价性引导语（「值得放在这里」「很实用」「最好懂」「最清醒的定位」）、命令式「记住 / 请记死」、「最重要」滥用。三类都要砍。

   **别按段落长度判 AI 节奏。** 短引导句后面跟的是列表 / 表格 / 代码块就属正常版式，跟普通段落才是痕迹。曾按长度批量合并，脚本跑出 0 处命中——那不是脚本坏了，是结构本来就没问题；先读懂信号再决定改不改。

   对照表、自检脚本、引号陷阱，以及**交付前痕迹全查（品牌名 + PDF 元数据/二进制/嵌入图片名/插图源 HTML）**见 `references/textbook-voice.md`。几个词表查不到讲师随口举的自家产品名（「在百度输入…结果里出现了解螺旋」）——正文读着毫无破绽，一搜就到原课，所以要按原课列一份品牌/机构/人名清单单独查，PDF 的 metadata、二进制字符串、PPT 转图带的 `slide` 文件名也要一并过。

   交付前必须跑，五篇里来源/自述类命中超过 10 处就是没写完。

9. **品牌清除要连「方法论缩写」一起清**。词表扫平台名 / 讲师名 / 机构名只盖得住显式痕迹。最隐蔽的一类是**讲师把自家框架名当方法论教**：一个四字缩写展开成四个分析步骤，还配一个同名公众号。它在书里长得像通用术语、内容也对，只有名字是品牌资产。判定：在源里 grep 该词，看是否伴随「咱们 / 我们 / ××大大的课」。清除方式是**展开成它所指的通用流程**（「（四字缩写）」→「（差异分析 → 功能富集 → 互作网络 → 临床关联）」），不是删掉——删了内容断，读者不知道这几步在干什么。

   扫描词表必须含 ASR 错字变体（品牌名在转写里常被识别成同音怪字，用正名 grep 连源里的证据都搜不到），且**工作目录 md / 成品 PDF / 交付 zip 三处都扫**——zip 里是另一份拷贝，改完忘重打就是旧版发出。用户会主动要求「保证 XX 元素被去除掉了」，要自己先跑一遍并给可抽查的结论（三处各 0 命中 + 扫了哪些词），而不是回一句「干净了」。判定信号、变体清单与展开写法见 `references/textbook-voice.md` 5.1–5.2c。

   **词面 0 命中不等于干净，必须加一道结构级检查。** 品牌缩写最容易被**拆开写**：四字缩写成表格四行（`| **挑** | 找差异分子 |`、`| **圈** | 功能富集 |`…）或拆成列表项，grep 四字连写返回 0，内容却一个字没改——实测第一轮把两处连写改成通用流程后仍漏了这张表，是用户追问「保证被去除了哦」时才发现。结构级检查三件：①正则 `挑[、，]?圈[、，]?连[、，]?靠` 应为 0；②表格单元格 `\|挑\|`、`\|圈\|`、`\|连\|`、`\|靠\|` 均应为 0；③通读该章涉及这个框架的**标题 + 表格表头**，看是不是把缩写换了个说法还在。改完重跑构建，三层（词面 / 结构 / zip 内拷贝）同时归零才算交付。

## 流程

### 1. 拿官方结构，别自己猜

课程详情页通常带 `chapters/parts`，每节 `lesson.content` 里内嵌 `h2/h3` 大纲。**讲师的官方大纲比自己从逐字稿归纳的准**，也直接回答了“他为什么这么排”。顺带能拿到每节的课程简介（summary），可直接用于序章定位。

### 2. 知识解构（并行）

逐节抽原子知识点，字段：`id / lesson / page / time / type(概念|方法|步骤|判断|经验|案例) / title / point(一句话结论) / detail / quote(讲师原话)`。

丢给 `long-input-parallel-fanout` 跑：拆节 → 装箱 → 并行子代理 → 机械组装。两条硬约束写进每个子任务的 context：**不许编造原文没有的内容**、**原文没讲清写「原文未展开」**。

### 3. 语义归并（必做，不能跳）

字符串去重只能清掉字面重复（本例 349→340，只清掉 3%）。同一知识点被两个组分别描述时措辞不同，difflib 相似度只有 0.6 上下。**必须再按节喂 LLM 做语义归并**（340→278），prompt 写死「只合并讲同一件事的、独有信息一条不许丢、合并≠删除、事实数字专名不动」。

### 4. 重搭骨架

重排的三个信号：

- **演示录像占比高的节** → 压缩成“脱离视频也能复现的操作要点”，不是记录鼠标位置
- **同一主题散在多章** → 合并（本例“检索”被切到 5 个地方：概念/工具/方法/中文库/示例，必须合成一篇）
- **时代性内容** → 重新评估权重（过时工具删掉，AI 从“彩蛋节”提到独立篇）

骨架要给用户看，不是自己定。

### 5. 标缺口

先摸清课程自己的痛点定位，缺口就在它没打算解决的那一侧。扫三处：逐字稿关键词（不会 / 搜不到 / 耗时 / 看不懂 / 卡在）、每节开场的第一段（讲师在那里立靶子）、讲师明说「大家普遍遇到两个痛点」的位置。

定位会告诉你它的取舍：赌「懂了不会用」的课会大量铺实操演示、刻意浅化理论，但不会教「搜到的东西靠不靠得住」——那正是教材必须补的一篇（证据等级与偏倚风险）。反过来，偏理论的课缺的就是可执行动作。用户问「这门课针对什么痛点」时，按「课前 / 课中 / 课后 / 阅读 / 效率」分段列清单，每条给课程对应解法，最后点出设计取向和它没覆盖的那块。

课程没有、但读者必须有的部分单独列清单，每项写“为什么必须有 + 补法”：

| 典型缺口 | 补法 |
|---|---|
| 质量评价与证据等级 | 权威框架（证据金字塔 / RoB 2 / NOS / AMSTAR 2 / CASP / GRADE）—— 选型表、五个偏倚域、报告规范与评价工具的区别、掠夺性期刊识别信号，见 `references/evidence-appraisal.md` |
| 检索质量自查 | PRISMA 2020 的检索报告要求 |
| 零基础概念铺垫 | 自补（课程默认读者已懂） |
| 自有产品攻略 | 按产品能力清单写 |

### 6. 逐章写作 → 配图重绘 → 合并

每章统一结构：**学习目标 → 概念（定义 + 大白话 + 比喻）→ 怎么做 → 坑 → 练习**。

**篇幅超过 1.5 万字时拆成「上/下」两个文件写，最后拼**（`上.rstrip() + "\n\n---\n\n" + 下.lstrip()`）。一次写那么长，后半段质量会明显下滑，而且中途被打断就得从头来。写完立刻统计汉字数与 AI 味触发标记（破折号、「不是…而是」、提示性冒号），不合格的先修再交。

删：脱离视频无法复现的“点这里”、同一例子的重复演示、寒暄。  
留：**讲师的经验判断和坑**——这是课程相对教科书唯一的增量，最值钱。

写完一章先跑一遍 `lieflat-less-ai-tone` 的自查项再交：翻案腔（「不是 A 而是 B」「不在于 A 而在于 B」）、提示性冒号（「一句话总结：」「关键是：」）、揭晓式破折号、序数词小标题。术语卡里的 `**大白话**：` / `**比喻**：` 属结构化排版，不算提示性冒号，保留。

破折号按位置分三类处理：正文里的揭晓式停顿改冒号或句号；**列表项的「术语——解释」（`- 队列研究——跟一群人很多年`）改「术语：解释」**（这是全篇出现最多的一类，动辄十几处，漏掉就前功尽弃）；代码块与结构示意里的保留。

引号统一要在**全部篇目一次处理**，别等出 PDF 时逐篇顺手改。两类都要查：英文直引号 `"` → 中文弯引号；中文直角引号 `「」` 与弯引号 `“”` 的混用（同一本书两种都出现，多半是分章写作时风格漂移）。一行扫完：`t.count("「") + t.count('"')` 都应为 0。

## 判断标准的来源分三层（别拿记忆写）

- **稳定层**（教科书级方法学）：证据金字塔、研究类型与证据强度的对应关系 —— 可直接写，注明依据哪套框架
- **工具层**（评价清单）：RoB 2 / NOS / AMSTAR 2 / CASP / GRADE —— 联网核当前版本 + 附官方链接
- **易变层**（期刊分区、影响因子、掠夺性期刊名单）：**必须实时检索并标日期**，绝不凭记忆写数值

原则：有权威出处就给，查不到就明说“业界尚无统一标准”，不编规则。

## 自有产品植入：先核能力边界

写产品攻略前先查产品情报：`skill_view(name='scilink-product-intel')`，并读**那个技能自带的**能力边界清单（在它目录下的 `references/scilink-capability-boundary.md`）：

- **帮助文档实锤** → 可写
- **只出现在业务对接点/口头承诺里** → 标“待确认”，不能当已有能力写成卖点——读者会当场验证失败
- 用户说“我们有这个功能”不等于文档有；按待确认处理，并回头要文档

另外要问两个决定写法的问题：数据源覆盖哪些库（决定攻略放在哪一章、要不要提示读者另查）、检索可否导出复现（决定能不能作为论文里的正式检索策略推荐）。后者是硬伤：黑箱检索不能写进方法学。

### 教材里的产品攻略怎么写才不翻车

按四段写，缺一段就会写成广告或写成坑：

1. **输入什么 / 输出什么**：只写接口层面，不写点哪个按钮。
2. **它省掉了什么**：“省掉从几万条里翻的时间”这类可验证的收益。
3. **它做不了什么**：这一条最值钱。写明“不给你检索式、不告诉你命中数，所以做不了论文方法学里要求的可复现检索”。
4. **正确用法 + 不要做的事**：正确用法是“用它建词汇表 → 回 PubMed/知网做正式检索，流程一步不少”；不要做的事是“直接把它的文献列表写进论文，评审会问检索式和命中数”。

写到这个程度，读者照做不会失败，产品也不会被当“可代替正式检索”承诺出去。反向的写法（只慎不写边界、或把不可验证的能力当卖点）配一个「以产品当前版本为准」也救不回来。

## 配图方案

- **界面示意**：HTML/CSS 线框，只留检索框、字段下拉、逻辑行等讲解必需元素，编号标注对应步骤
- **流程/结构图**：SVG（检索式构建流程、布尔逻辑关系、精读流程、证据金字塔）
- 统一导出 2 倍图；图内文字用中文，术语首次出现给全称

**渲染优先用 Chrome headless 直接截图，不要先起 http server**——一条命令搞定，还能顺手 2 倍图：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --hide-scrollbars \
  --force-device-scale-factor=2 --window-size=960,2400 \
  --screenshot=out.png "file://<figs 绝对路径>/fig_1-1.html"
```

窗口高度给足（2400 够大多数图），再用 PIL 比对右下角像素、`ImageChops.difference().getbbox()` 裁掉底部空白。`--force-device-scale-factor=2` 直接输出 1920 宽，比渲染后放大清楚。

**camofox 只在需要操作 DOM 时才用**（点开折叠、等 JS 渲染完、滚动到某位置）：`python3 -m http.server 8877` 起在 figs 目录 → navigate `http://localhost:8877/fig.html` → evaluate `document.body.style.zoom='2'` + viewport 宽高翻倍 → GET screenshot。它拒 `file://`，命令与坑见 `camofox-browser-api` 的「把本地 HTML 渲成 2 倍图」。纯静态图不值得为它起浏览器。

**渲完必须用 vision 逐张复核**，不要信“代码写对了”：实测常出现树状图缺横向连接线（`::before` 只画了竖线，子节点悬空）、卡片底边不齐（内容行数不同，需 `flex-direction:column` + `margin-top:auto`）、多卡里只有一张被高亮导致视觉重心跑偏。逐条修完再嵌进正文。

插图位置跟着知识走，不跟课程顺序：属于「概念对比」的放小节开头，「结构分解」的放定义之后，图注写清“箭头方向是加工顺序，不是重要性”。

**图片文件名按图号命名，不按创建顺序。** 按 `fig4_boolean.png` 这种顺序号建文件，两篇一插、章节一重排，文件名就和正文里的「图 3-1」对不上了，回车查哪张图属于哪节时得反复翻 md。直接叫 `fig_3-1_boolean.png`，文件名自带定位，合并全书、调整章节顺序都不会错位。

**图内字号必须按最终印刷宽度反算。** 图在 md 里是 100% 版心宽，A4 版心约 174mm（≈493pt），所以 CSS 宽 980px 的图会被缩放约 0.5 倍——图内 12px 的字印出来只剩 6pt，看不清。定稿标准：**要印刷可读（≥8pt），图宽 980px 时图内最小字号要 ≥16px**。四栏以上横向图在 A4 纵向里缩得最狠，**改成 2×2 网格**字号能大一倍。渲染完先在 PDF 里看一页，别等交付后才发现图内小字废掉。

**`word-break: keep-all` 拦不住中文词内断行**（「二甲双胍」照断成「二甲双/胍」，「横断面研究」断成「横断面/研究」）。要点名保护术语：`<span class="nw">二甲双胍</span>` + `.nw{white-space:nowrap}`，或直接精简文案让整行放得下。图里已经写过的结语（如「这两类不是二选一……」）正文里不要再写一遍，读者会连着看到两段几乎一样的话。

## 交付：中文 Markdown → A4 PDF

用户要「给个 PDF 放桌面」时，别走 pandoc/LaTeX 链（中文字体、图片相对路径两处都容易崩）。走「Markdown → 教材版式 HTML → Chrome headless 打印」，样式完全可控。

```bash
python scripts/md2pdf.py 第一篇_认知.md ./_tmp.html     # 生成带教材版式的 HTML
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
  --no-pdf-header-footer --print-to-pdf="/Users/Jin/Desktop/书名_第X篇.pdf" \
  "file://<md 所在目录绝对路径>/_tmp.html"
```

四条硬要求：

1. **HTML 必须写在 md 所在目录**（图片是 `figs/xxx.png` 相对路径）。写到 `/tmp` 再打印，图全丢，症状是体积从 1.5MB 掉到 0.9MB、页数对但含图页空白——**看产物体积就能发现**，比翻页快。
2. **排版**：正文 `"Songti SC","STSong",serif` + `line-height:1.95`（长文用衬线耐久读），标题 `"PingFang SC"`，`@page{size:A4;margin:20mm 18mm}`，`table` 加 `break-inside:avoid` 防跨页劈开。
3. **打印前把英文直引号换成中文引号**：`re.sub(r'"([^"\n]{1,80})"', r'“\1”', md)`。中文里混直角引号在 PDF 上极扎眼，用户一眼就会指出。
4. **Chrome headless 会刷 `ERROR:task_policy_set` / `CVDisplayLinkCreateWithCGDisplay failed`**，这是 macOS 噪声不是失败；判成功只看 `N bytes written to file` 与产物大小。

**逐页核验，不能只看「生成成功」**：

```python
import pymupdf
d = pymupdf.open(pdf); print(d.page_count)
for i in range(d.page_count):
    if d[i].get_images(): d[i].get_pixmap(dpi=100).save(f"/tmp/p{i+1}.png")
```

把含图页 PNG 交给 vision 逐张看：中文字体是否正常（不是方块）、图有没有被裁、图注是否紧贴图下方、有没有词内断行。这一步实测能抓出「图注被图内结语挤到说明段之后」「图里写过的话正文又写一遍」这类肉眼翻 PDF 容易漏的问题。

**全书合订本**（分篇交完后用户常会想要一本完整的）：用 pymupdf 拼，顺手加书签和目录页。

```python
import pymupdf
out = pymupdf.open()
toc = []
for p, title in [(toc_pdf, "目录"), (part1, "第一篇 认知"), ...]:
    start = out.page_count + 1
    out.insert_pdf(pymupdf.open(p))
    toc.append([1, title, start])          # 层级 1 = 一级书签
out.set_toc(toc)                            # 没这句，70 页的书只能靠翻
out.save(dest, garbage=4, deflate=True)
```

目录页单独做成一个 HTML 打印成 PDF 再插到最前，别指望 markdown 里的标题自动出目录。

**目录必须能点，书签要到节。** 用户会明确要求「点击标题跳转到对应页」，而且会到手去点。两件事一起做：

1. **书签三级**（篇 L1 / 章 L2 / 节 L3）：定位每个标题在正文里的页码后 `doc.set_toc()`。
2. **目录条目加内部链接**：在目录页 `search_for(条目前 12 字)` 拿矩形，`page.insert_link({"kind": pymupdf.LINK_GOTO, "from": rect, "page": target, "to": pymupdf.Point(0,0)})`。

**加完必须逐条核对，不能只看数量对**：读每个 link 的 `from` 矩形 → `get_textbox(rect)` 取该处文字 → 检查目标页文本是否包含它。走一遍 135 个链接全中，才算交付。步骤与脚本见 `references/toc-and-pdf-nav.md`。

**这一步不幂等：跑两遍就翻倍。** `insert_link` 是追加，105 个条目会在同一位置叠成 210 条注解，功能上看不出来、页数也对，但成品已经脏了，而且不重建就清不掉。所以链接步骤**只能有一个入口**——写进 `build.sh` 就别再手动补跑（实测「build 里一次 + 手敲一次」直接翻倍），验证判据是**条数等于标题数**而不是「大于 0」。封面那种 `<a href>` 链接 Chrome 打印时已自动生成，先查 `LINK_URI` 是否存在再决定要不要补，否则同样叠两条。

**合并多文件时按章号排序，不要按文件名。** 章文件常写成 `第一篇_起步.md`、`第二章_选题.md`、`第十一章_硕士学位论文.md`，文件名排序会把「第十一章」排到「第二章」前面。正确做法是读每个文件前几百字、正则抓 `^## 第([一二三四五六七八九十]+)章`，按中文数字映射成整数再排。篇标题（`# 第一篇`）散落在各篇首章的 md 文件里，合并时跟着章走，不要单独抽出来。

### 目录：先定形态，别默认堆知识点

「目录要详细、显得知识点多」有两种解法，选错了整套返工：

| 形态 | 结构 | 体量 | 适用 |
|---|---|---|---|
| **只到节**（不确定时从这个开始） | 篇 → 章 → 节 | 1–2 页 A4 双栏 | 默认选择；用户说「直接到小节就行，不要继续往下展开」 |
| **层级细分** | 篇 → 章 → 节 → **子标题** | 2 页 A4 双栏 | 读者要看清结构，且正文里有现成的「第一步 / 第一层」编号 |
| **知识点密排** | 篇 → 章 → 节 → 提炼的知识点 | 5–6 页 390 条 | 只用于确实要「显得知识点多」的宣传场景 |

**用户的偏好方向是「越来越少」，不是「越来越多」——所以从最简形态起草。** 同一个用户先要「非常详细、显得知识点多」（于是铺了 390 条），拿到后说「太繁琐了，本章知识点没必要都罗列」；再给带子标题的两页版，下一本书直接说「知识点有点太细密了，直接到小节就可以了，比方说到 12.1 xxxxx 就行，不要继续往下展开」。**「详细」在他那里始终等于「层级清楚」，不等于「条目多」**；想加层级之前先问一句，不要默认往上加。

层级细分的子标题**从正文里天然的编号结构提取**（`**第一步：…**`、`**第一层：…**`、`**第一段：…**`），不硬造、不用 LLM 编。114 节里只有约 30 节能提出 2–5 条，其余只留标题——细而不碎正是要点。抽不到就让它空着，别为了填满去凑。

样板（2 页装完 5 篇 / 15 章 / 114 节 / 30 子标题，两页都填到 85%，左右栏差 <1%）：装箱算法、页高校验、字号参数见 `references/toc-and-pdf-nav.md`。

**知识点必须从正文逐节提炼，不能用正则抓正文里的加粗词**：教材里的 `**大白话**`、`**比喻**`、`**同时**` 会被抓进来，全是废条目（实测首个版本 6 个条目里 4 个是废的）。走 LLM：每节喂标题 + 正文前 1500 字，要求输出 3–5 个「6–14 字、能独立看懂、按正文顺序、不带编号和标点」的短语，产 `{篇|章|节: [知识点…]}` 的 JSON 落盘（86 节约 390 条，DeepSeek 几分钟、成本可忽略）。

子标题形态则相反，**只认正则、不用 LLM**：`\*\*(第[一二三四五六七八九十]+[步层条类阶段维度][^*\n]{0,28})\*\*`，另加「短标题：」式加粗短语兜底（6–20 字，剔除「泛读 / 精读 / 关键词 / 注意 / 结论」这类正文强调词）。

排版要点：
- **写作时就把节编号写进 `###` 标题**（`### 1.1 为什么不能等到时候再说`），不要只写「为什么不能等到时候再说」。目录是按 `###` 抽节的，标题里没有编号，生成出来就是一串没有序号的短语，四级结构直接不成立，回头补编号等于把 15 章标题重写一遍。
- **别用 `column-count` 排多页目录**。CSS 多栏的分页断点由浏览器决定，篇标题一落到栏底就把整段推到下一页，前一页下半留半页空白，末页只剩二十来行。可靠做法是**先算后写**：按条目类型赋权（篇 2.0 / 章 1.7 / 节 1.0 / 子标题 0.92），把权重总量均分到 N 栏，贪心装箱后输出静态 HTML，不经浏览器排版决策。细节见 `references/toc-and-pdf-nav.md`。
- `font-size` 节 8.9pt / 子标题 8.1pt / 篇 11pt、`line-height:1.32`、页边距 `@page{margin:13mm 12mm}`——这组实测两页填满 85%，再小就压不住留白、再大就溢页
- 四级视觉：篇＝黑底白字横条（`break-after:avoid`）、章＝左竖线粗体、节＝编号粗体、知识点＝`font-size:8pt` 灰字 + `::before{content:"· "}`
- **知识点挂在章末尾时要加归属标记**。直接把知识点行接在最后一节（往往叫「本章结论」）后面，读者会以为这些条目属于那一节。在知识点列表前插一行 7.4pt 灰字「本章知识点」，归属立刻清楚——但这正是用户嫌「繁琐」的来源，他不要这个形态时整块删掉，别只改标题。
- **篇/章标题不许落在栏末**：装箱时若某栏最后一条是篇或章，把它挪到下一栏开头（末栏除外，否则死循环）
- 页头写「全书 N 篇 · N 章 · N 节 · N 个知识点」，这行本身就是宣传点
- **统计篇/章/节数时排除非章级 H2**。「全书结语」「本篇小结」「前言」「附录」「后记」也是 `##`，按 `##` 计数会多算一章（实测两本书都中过：页头写 16 章实际 15 章、写 19 章实际 15 章，用户对着目录一点就发现）。判据：H2 标题含「结语 / 小结 / 附录 / 前言 / 后记」的只进目录、不进计数。
- **篇标题本身就是「第一篇 xxx」时，别再套一层编号标签**。模板若写成 `<span class="tag">{part}</span>{title}`，而 title 已经含「第一篇」，目录上就是「第一篇 第一篇 起步」。用 `PART 1` 这类序号，或先 `re.sub(r"^第[一二三四五六七八九十]+篇\s*", "", title)` 去掉前缀。这类重复 vision 一眼能看出来，但纯文本检查看不出来。
- **末页只剩一两条时，装箱后把轻栏并进前一栏**：`while len(cols) >= 2 and sum(w of last col) < 6: cols[-2].extend(cols.pop())`。用户会明确抱怨「最后一部分直接新开了一页，然后只在开头有一点，这样不好」。合并前先确认前一栏还有余量，否则会溢页。
- **目录只占 70% 页高说明字号偏小，不是该留白**。内容量固定时把篇/章/节字号整体 ×1.15–1.2 能填到 85% 且仍在一页内；一旦溢页就往回微调 0.05 以内。判据用 `max(block[3]) / page.height` 逐页量左右栏，两页都在 80–90%、左右差 <5% 即达标。
- **不要编页码**：87 节跨 60 余页，手动对页码必然错，错一个用户就当场发现。宁可不给页码。
- 过滤掉「本章小结 / 本节练习 / 自检」这几类节（它们没有知识点条目，混在编号节里层级打架），判断条件是「标题含关键词 且 无知识点」，别一刀切删标题含「小结」的正文节。
- 双栏会把同一组知识点从中间剖开，右栏顶部直接接着左栏底部的条目，没有「（续）」提示。可读性差但可接受；想更严谨就调 `break-inside` 或微调条目顺序让断点落在章标题处。

### 封面页与封底页（A4）

合订本要有封面和封底，和正文一样走 HTML → Chrome 打印，不要拿 PIL 拼——A4 版式（页边距、字号层级、深底配色）用 CSS 一行就能对，PIL 得自己算坐标。两份做成**同一个 HTML 的两页**，`@page{size:A4;margin:0}` + `.page{width:210mm;height:297mm}`，一次打印得两页，再按顺序插进合订本首尾。

- **logo 和二维码用 base64 data URI 内嵌**，不要写 `file://` 或相对路径。封面封底的 HTML 常被放到 md 目录之外，相对路径一换位置 logo 就丢；base64 后单文件自包含，换机器也不坏（体积几十 KB 量级，可接受）。
- **素材位置**（本机固定）：品牌文字 logo `~/Documents/素材/logo@3x.*.png`（`SciLink 刀客轻研` 蓝色字标），引流二维码 `~/Documents/素材/刀客轻研小助手二维码.jpg`。二维码带中心 icon，压白底方块再上深色封底才扫得出来。
- **封面排版骨架**：右上角 logo → 左上系列名 → 主标题（宋体 900、46pt，分两行）→ 英文副标题（字重拉大、颜色冷灰）→ 细短横线 → 目标读者一行 → 左侧竖线的三行简介 → 最底转化区（左二维码 + 右主标两行 + 能力关键词两行 + 官网链接）。**留白是优点不是缺陷**：中部空得慌就补一段简介，不要靠拉大行距去填。
- **不要放「篇/章/节/图」数据条**。那一块是转化位，不是数据位——二维码、一句行动号召、能力关键词（`·` 隔开、分两行排）、可点击的官网链接，比数据条有用得多。
- **封底反色**（深墨蓝 `#12202e` + 白字）：白底二维码居中 → 与封面**同一句**行动号召（大字）→ 能力关键词 → 官网链接 → 底部 logo、品类定位、免责声明。封面封底用同一套转化文案，别一边喊口号一边喊扫码。深底上二维码必须垫白底并留内边距。
- **官网链接做成可点击的 PDF 注释**：HTML 里用 `<a href>`，Chrome 打印会自动生成 link annotation；交付前用 `[l.get('uri') for l in d[i].get_links()]` 验证，能打出 uri 才算成。
- **口号和二维码两个要素必须跟用户确认一遍**，不要自己定稿：用哪张码（公众号 / 小红书 / 客服）、口号有没有标准版。这两样是品牌资产，改一次要重出全套图。
- **封面文案要改时改生成器，不要拿 PDF 去改。** 文案在 `make_cover_pages.py` 里，改完重跑 build 全链（合并 → 书签 → 链接）；直接在 PDF 上盖字会丢链接与字体，而且下次重建又回去了。用户改一句话就往回一次全链，不要试着局部补。
- **用户改书名后，封面有四处要一起改**：主标题、英文副标、中文副标、简介里的环节计数。只换主标题会自相矛盾（主标题「放养硕博自救指南」配英文「FROM TOPIC SELECTION TO GRADUATION」）。英文副标按新书名重译（起→发 = `FROM START TO PUBLICATION`），计数要跟实际章数对（原书写「十一个环节」而书是 15 章，就得改成「十五个环节」）。改完扫一遍全书旧书名残留，再判断哪些该留：章节名里含旧词属描述性标题（「第一章 硕博课题全景」），可以保留，交付时主动说明这一处。
- **同一句转化文案在封面和封底各有一份**，改错字或改措辞必须两处一起改。用户说「是我打错了」时，别只改他指的那一处——`flat.count("新文案")` 应等于 2、`flat.count("旧文案")` 应为 0，两个都查过再交。
- **删掉一段文案后版面会塔。** 封底删掉中间那段描述后，slogan 与品牌区之间會留出一大块真空。别靠加 padding 猜，把 slogan 包一层 `flex:1; display:flex; align-items:center; justify-content:center`，让它自动在剩余空间里垂直居中，删增文案都不用重新调。
- **二维码旁的品牌字标可以换成官网网址**，用户更愿意引导到自己的落地页。用 `<a href>` 包住显式域名（`ag.scilink.link`，不写 `https://` 前缀更干净），Chrome 打印自带链接注解，见下方验证方法。
- 插回合订本时书签一并加上（`[1,"封面",1]`、`[1,"封底",N]`），否则 70 页的书从封面翻起全靠拖。

### 交付形态：3:4 小红书截图

用户要把教材当资料展示（小红书 / 朋友圈）时，做 1080×1440、每张 4 页 2×2 拼图。直接跑 `python scripts/textbook_screens.py 全书.pdf 3,5,9,13 16,17,28,31`。

**「拼成一张图」= 3:4 的 1080×1440，不是竖排长图。** 不要因为「四页内容连贯」就自作主张改成竖排长图——小红书图片比例上限约 1:3，1:5.7 的长图直接传会被裁，且在文档里预览只有缩略图大小、根本读不了。用户说「拼成一张」只有一个意思：二乘二铺满一屏。真要连长图一起给，先问，不要替用户决定。

四条要点：

1. **选页只挑有章节大标题或插图的**，宁可跳章节也不要连续四页纯文字——每页都得有看点。四页不连续是特性，不是失误。**目录截图不足 4 页时用封面或含插图的正文页补位**（目录压成两页后，拼图脚本不能还按四页写，否则最后一格空白）；也不要为了凑满四页把目录硬拆成三页。
2. 每页 481×680（A4 比例），间距 16、外边距 51/32，正好铺满：`PW=(1080-2*51-16)//2`，`PH=int(PW*1.4142)`。尺寸改了要重算，别硬填。
3. `pymupdf` 200dpi 渲染再 `LANCZOS` 缩到目标尺寸，比直接低 dpi 渲染清楚；白底 + 淡阴影（`GaussianBlur(5)` 灰矩形垫底）+ 1px 边框，四页视觉统一，**不要加标题条之类的装饰文字**。
4. 出图后 vision 复核：四页完整无裁切、间距与阴影一致、没有一页空白过多。

5. **要加封面文案就用现成脚本**，不要自己现写 PIL：`xiaohongshu-posters` 的 `scripts/cover_caption.py`（黄字/黑描边/白阴影/伪斜体，参数化）。那边记了中文字体没有真斜体要 shear 造、以及按行宽做左右补偿的坑——本次重写了三轮才对。

6. **贴进飞书文档做分栏**时用 `docs +update --command block_insert_after` 写 `<grid><column width-ratio="0.333333"><img path="@/绝对路径.png"/></column>…</grid>`。三个坑：`path` **必须以 `@` 开头**（裸路径报 `path must start with @`）；锚点 block id 要连标题文字一起核（`图片素材：` 和 `标题：` 两个 `<h2>` 挨着，取错照样返回 success，图就进了别的章节）；**重传图用 `path`，别用 `src=token` 省上传**——拿错 token 会静默得到另一张图，返回的 block_token 正常，只有 fetch 回读 `<img name=…>` 逐个比对文件名才能发现。换顺序/换图就删整个 grid 重插，别逐列调。传文末的 `+media-insert` 做不到指定位置，不能用。

**但「删整个 grid 重插」只适用于你自己刚建的、内容可弃的 grid。** 用户已有素材的文档（他自己搭了结构、放了自己挑的图），任务永远是**补充**，不是替换：锚点取在目标区块**最后一个已有 block** 上 `block_insert_after`，新内容追加在后面，绝不删除或重排已有 block。删旧 grid 重插时如果锚点取错、或那条 grid 里本来就有用户自己放的三张图，会一次性冲掉他的东西，返回仍然是 `success`——只有 fetch 回读 `<img name=…>` 列表数一遍才知道少了什么。插入后必读一遍全量图片名，和插入前对比，只许多不许少。

## 交给外部模型审校时怎么处理反馈

把成书 + 源素材打包给另一个模型（Kimi / GPT 等）判质量，是有效的第二双眼睛——它能翻到你自己没回查的 PPT 页。但反馈**不能照单全收**，必须逐条回源验证：

1. **每条先在源素材里 grep 一遍**，用转写稿和 PPT OCR 双查。转写是 ASR 文本，同音错字多，关键词要试中文数字（「百分之二十」而不是「20%」）。
2. **分三档回话**：它判对了（认并改）、它判偏了（给出源里的原话反驳）、它有部分道理（指出哪半对哪半错）。一起打包说清楚，不要笼统「都改了」。
3. **改完必须整链重跑并重新打包**，否则对方验的还是旧版。
4. **整改要产出独立的复核文档**（`整改说明.md` 之类），不是聊天里报一遍就算。五节：改了哪几个文件（含未改清单）、逐条清单（文件:行 + 原文 + 改后 + 依据在哪份源素材）、对反馈的异议（附源里原话）、复核方法表（查什么 / 怎么查 / 期望值）、成品与素材路径。把这份文档打进交付包——只给结论不给方法，对方复核时会退回来问「怎么验」。

实测的判偏形态：审校说「你把学位论文的 10% 标准用到期刊投稿上，混淆了场景」，而源视频同一段里两句话都说过（「20% 以下甚至 15% 都可以」＋「整体要小于 10%」）——**不是混淆，是只取了严口径、没交代宽口径**。这类「结论错但观察到的问题真实」占反馈的相当比例，改法是把两个口径都写出来，不是推翻重写。

## 改动后的整链重跑

改了一处正文，要连锁重出六样：合并 md → 正文 PDF → 目录 PDF → 合订本 → 书签与跳转 → 截图与打包。手动敲一遍必漏一两步（最常见是忘了重跑 `add_toc_links`，书还是旧的链接）。**写成 `build.sh` 一条命令跑完**，每步 echo 序号，最后统一核对页数 / 书签数 / 链接数三个数。

**用户会改交付文件名，构建脚本的输路径不能写死。** 常见情形：上一版发出后用户把 `书名_全书.pdf` 改名成 `《书名》1105改.pdf` 并要求在原文件上改。此时脚本还往旧名写，结果是桌面上两份并存，用户看的仍是旧的。改稿前先看一眼桌面当前在用的文件名（`search_files(target='files', path='~/Desktop', pattern='*书名*')`），把它同步进 `merge` 脚本的 `dest` 与加链接脚本的 `PDF` 常量；两处都要改，只改一处会让书签加到一个不存在的新文件上报错。

```bash
set -e
PY="/Users/Jin/Documents/Open Programs/funasr/.venv/bin/python"
"$PY" combine_sskt.py                # 变量引用一律加引号：路径含空格（Open Programs），裸 $PY 会在空格处断词
```

## 坑

- **多本书共用一套生成脚本时，输出路径别写死到某一本的目录。** 复制封面/目录脚本给第二本书时最容易漏改 `out = Path(".../jlx_book/book/_cover.html")`——它会把第一本的封面 HTML 覆盖掉，而重建第一本时才发现封面变成了第二本。新增一本书就逐个检查脚本里的 `Path(...)` 常量归属哪本，构建脚本里的 PY/路径变量一律加引号（`"$PY"`，目录名 `Open Programs` 含空格，裸 `$PY` 会在空格处断词）。
- **合并脚本别把输出文件当输入**。合并产物 `全书.md` 若写在章节 md 同目录，下一轮 `glob("*.md")` 又把它读进去，字数直接翻倍（3.4 万→6.9 万，章数 15→16）。症状是合并完统计数字异常漂亮，PDF 页数也对不上。排除名单里必须同时有 `_` 前缀文件和合并产物本身。
- **别把课程章节当教材目录**。用户明确说“不要按现在的章节结构”时，照搬就是零分。
- **工具篇最容易失控**：按钮级操作（“某软件有四个区域”“用 > 写引用”）写进书就是过时的操作说明书。每个工具压到 1–2 条（解决什么问题、什么时候用它），腾出篇幅给核心篇。
- **工具章必须补上文献管理器**。原课几乎从不讲 Zotero 这类工具（讲师自己的习惯用 OneNote/Typora 记笔记），但读者一写论文就要插几十条引用、排参考文献格式，这一环缺了整章就散架。按“查、管、读、写”四个环节归位，每环节只留一个主力工具。
- **教材里不写第三方盗版全文渠道**。原课提到 Scihub 这类站点照实转述会误导读者：站点版权状态不稳、随时关停、下载文件被篡改的风险是真实的。改成正序五步：机构权限 → 馆际互借 → 开放获取（PMC/期刊 OA）→ 直接问通讯作者 → ResearchGate。
- **业务无关模块要主动删**，但删之前先列出来问一句——直接删可能删掉用户想要的基础铺垫。
- **PPT 页与口述的对应关系是重构的地基**：同页 OCR 文字比 ASR 准一个档，可用于反校逐字稿（见 `video-transcript-pipeline`）。没做这层对齐就写教材，概念定义会跟着听错。
- **自己在正文里写的每个数字都得有出处**。数字只能来自三类：课程原文、引用的文献、你自己跑出来的实测值；三类都不是就删掉。写成定性表述（“覆盖绝大多数需求”）也比编一个数安全。

  **最常犯的破口是「为了让内容具体，顺手补一个数」**。四种形态，每次收稿前按这几个模式逐条扫一遍：

  | 形态 | 长什么样 | 改法 |
  |---|---|---|
  | **区间化降精度** | 源里是 98.2%，正文写「超过 95%」 | 照抄精确值 + 带出处（作者 / 年份 / 期刊）。改了精度就算失真：读者拿 95% 去查，查不到任何文献支撑 |
  | **自己补比例** | 「数据库 60%、顶刊会议 30%、其他 10%」 | 改成无比例的顺序描述（「数据库打底，顶刊补关键节点，推送只当线索」） |
  | **自己补数量换算** | 「读 100 篇摘要，精读 10 篇，3 篇复述方法学」 | 改成判断标准而非配额（「读完能挑出几篇值得拆开」） |
  | **抹掉机构出处** | 源 PPT 写「北京大学医学部要求：直博 32 个月…」，正文写成「各校普遍要求」 | 具体规定的数字必须保留机构名（「以 ×× 的规定为例，各校不同」）。抹掉出处会让读者把它当国标用 |

  这四类的共同成因是「转述」：讲师说得笼统（「比例很高」「读很多」），写的时候为了可读性填了具体值。源里没给数就别给数，给判断标准。

  **有出处的数字也要当场验，不能只验「能查到」。** 拿文献当贯穿案例（一篇摘要演示四问、一组 RCT 数据讲效应量）时，逐个字段核对发表摘要：样本量、亚组人数、各终点效应值、95% CI、p 值。只看 PMID 打得开是不够的——数字错一位，读者第一次翻书就会发现。核对完把 PMID 与期刊年份一起写进正文，让读者能自己查。

  **复验时间敏感数字时允许自然增量。** 检索命中数每天都在变，写书日期与复验日期差几天、数字差 0.1% 以内（几十条）属正常，不是造假信号；判据是量级和趋势，不是逐位相等。反过来，**只验到一部分步骤就明说验到第几步**：接口跑不动时照实报「第 N 步复验通过，其余未验」，比笼统「全部核对无误」可信得多。

  **修辞性举例数字与统计断言分开报。** 「硬盘里存了 800 篇 PDF」「30 篇核心文献≈30–60 个工作日」这类是修辞与经验估算，不属于编造，但交付时要单独列出来让用户决定要不要模糊化。混在有出处的数据里一并说「都核过了」，等于把两种性质不同的数字糊成一种。

- **跨章一致性要机器查，不靠通读**。同一件事在两章用不同数字/维度表述，读的时候不觉得，读者一对就露。至少查三类：①**计数类**（正文说「十二个字段」、表格实际 14 行、章末结论写「十四字段」）②**维度数**（第 7 章「创新三维」、第 12 章「创新四维」——若是有意的递进，必须写一句「硕士三维，博士多一个范式维度」，否则读成矛盾）③**同义术语**（「本章小结」vs「本章结论」）。计数类直接用正则抓「[一二三四五六七八九十]+个/条/项/维/类」全列表，和表格实际行数对一遍。
- **自己补的基础定义先搜一遍再定稿**。“一次/二次/三次文献”这类看似常识的分类，不同教材分法并不一致（有的把综述归二次文献）。用主流分法写，并在交稿时告诉用户“我参照的是哪套，你如果有指定教材我按它调”——比默默选一种然后被推翻便宜。
