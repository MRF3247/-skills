# SciLink 医学选题侦察（多源直抓 → 选题 → 核验 → 入库）

## When to Use

- 给 SciLink 官号 / 个人号矩阵找医学资讯选题，受众＝**医生 / 医学生 / 临床科研者**
- 需要**不依赖 MedHOT、每日医讯**这类中间层，自己把当天/近一周的医学新消息抓全
- 批量补飞书「内容物料库」的 6 个基础字段（标题/话题度/分类/日期/链接/DOI）
- 需要按科室（心内/呼吸/重症/麻醉/影像/肿瘤…）定向找料
- **用户给一个主题（「抗炎的真相」这类），不要求最新、只要证据链全** → 走 §一·C 主题调研型，不是日期抓取

不适用：患者科普、纯美国医保/诉讼/人事、无数据转述。

## 一、抓：四条路，优先级从高到低

| 路径 | 用什么 | 适用 |
|---|---|---|
| **A 期刊直抓（主力）** | `scripts/fetch_all_sources.py`（EuropePMC 按 ISSN，54 本刊） | 论文、指南、RCT、队列——质量最高、DOI 天然可核 |
| **B RSS 直抓** | 同脚本（22 个源：Nature/NEJM/Lancet/JAMA/Cell/Science/WHO/CDC/行业媒体） | 新闻、快报、机构公告 |
| **C 中文官方源（国内线，必跑）** | 同脚本 `--only cn`（6 个源：NMPA 药品公告/药品动态、卫健委政策法规/工作通知/征求意见、国自然通知公告） | 国内新药获批、说明书修订、医保与职称口径、基金指南——英文源一条都覆盖不到 |
| **D 浏览器兜底** | camofox（`POST /tabs` → `/navigate` → `/evaluate`） | Medscape（403）、FDA 新闻稿（RSS 404）、中文政府站 412、文章页取页面日期 |

> 中文线是 2026-10 补的：此前 192 条选题库里有 10 条（药监局 AI 监管、职称评审新政、国自然指南、中华医学会征文）全部来自外部中间层，脚本一条抓不到。补源后实测当天就能拿到「国家药监局批准阿舒克森片上市」（10-26 当日）。

```bash
# 日常全量（近 3 天，含中文源）
python3 scripts/fetch_all_sources.py --days 3 --out /tmp/cand.json

# 只跑中文官方源（政府站节奏慢，建议 --days 14~30）
python3 scripts/fetch_all_sources.py --days 30 --only cn --out /tmp/cn.json

# 按科室定向（cardio/resp/icu/anes/radio/onc）
python3 scripts/fetch_all_sources.py --days 10 --dept icu --out /tmp/icu.json

# 只走期刊，最快
python3 scripts/fetch_all_sources.py --days 7 --only jr

# 有源超时/漏抓：只补缺的刊，不重跑整批
python3 scripts/retry_missing_journals.py --input /tmp/cand.json --days 3 --out /tmp/retry.json
```

- **补更前先定窗口，不要默认 `--days 3` 跑一遍再重跑**：先 `record-list` 统计表内「按原文日期的条数分布」，找出空的日期；窗口 = 从最后一个有记录的日期到今天（空 3 天就用 `--days 8`）。默认 3 天盖不住空档，第一遍白跑。
- **「今天」必须以 `date` 的输出为准，不能用会话上下文里的起始日期**：长会话会跨天（上下文写着某个日期，真实已经过了好几天），拿上下文日期算窗口会把空档算错、连跑两遍。顺序固定为 `date` → `record-list` 看日期分布 → 定 `--days`。
- **同一天补跑要按「上一轮跑的时刻」回补后半天的稿**：期刊在一天内陆续上线，上午跑过的窗口只覆盖到当时；当日再跑一次用 `--days 2` 即可把前一天／当天新增的条目收进来，不必从头重跑大窗口。

输出统一 JSON：`{source, kind, title, doi, url, published, pub_basis, issue_date, abstract}`。
源清单、可达性三档、覆盖验证见 `references/medical-news-source-map.md`。
**加刊只需在脚本 `JOURNALS` 字典加一行 `显示名: ISSN`。**

## 一·B、会议季专线（ESMO / ASCO / ASN / ECTRIMS 等）

大会期间和大会刚结束是选题最密集的窗口，但不是普通的「按日期抓」。四条硬规则（完整配方见 `references/conference-week-medical-topics.md`）：

1. **先判收官时刻，再判日期**：官网只给起止日期，最后一天常只半天。**注册台开放时间的末位 + 最后一场 session** 才是真收盘；重磅 LBA 多在倒数第二天/第三天的主席研讨会（Presidential Symposium）就放完了，最后半天多为官方 Highlights 复述。**收官前不定稿汇总**——Highlights 会给出「本周哪些数据最重要」的官方排序，是选题优先级的免费依据。
2. **换算前先确认时区制度**：欧洲大会会跨夏令时切换（10 月最后一个周日 CEST→CET），同一条日程前后差 1 小时；北京 = CET+7 / CEST+6。`TZ=Europe/Madrid date` 与 `TZ=Asia/Shanghai date` 对一次再回答。
3. **必须做「同步发表」核查**：大会议的重磅 LBA 多数同期上 NEJM / Lancet / Lancet Oncology / Annals of Oncology，会议摘要本身也常进 Annals of Oncology 补编带 DOI。只写试验名查 Crossref 会返回一堆无关论文，要加 `query.container-title=<刊名>` 逐刊查（见 reference）。**「会议报告一律无 DOI」是错的**，先查再写「无」。
4. **一条记录一条链接**：一篇 recap 覆盖 4 个 LBA 时，不要给多条记录共用同一链接（去重自检里链接不得相等）。给每个试验找独立稿（OncLive / ecancer / Targeted Oncology 单试验文章），**并核该页 `datePublished` 是否落在本次会期**——同一试验几个月前的 topline 公告稿标题很像，日期和数据都对不上本次会议。

5. **同批 LBA 同步发表时，先按试验名扫库、命中就更新旧记录**：一次大会常让同一批试验在几分钟内全上 NEJM（实测一轮 7 篇 LBA），其中有些试验**几个月前已有 topline 记录**（公司顶线公告、早期报道先入过库）。直接新建会让库里同一试验并存两条，用户按话题度排序时看到两条几乎一样的题。做法：入选前拿试验名（`Lp(a)`、`ZEUS`、`STREAM`…）扫一遍 `record-list` 的「内容标题」，命中就把那条改掉——`原文发布日期` 换成正式发表日、`DOI链接` 补论文 DOI、`来源链接` 换成本次报道页、标题加「正式结果／正式发表」；**话题度要按正式数据重打，通常是上调**（顶线只给方向，正式论文才有效应量、CI 与亚组，可讨论度更高）。汇报里写明「这条是更新不是新建」，并同时给出旧的 record_id。

会议季的均衡与选材：肿瘤会天然全是肿瘤，会后主动问要不要给非肿瘤科室配额度；**AHA／ESC／ADA 这类心血管-代谢大会反过来会清一色心血管**——抓完先数科室分布，单一科室占比 >70% 时主动配 1–2 条别的科室（麻醉、影像、精神、妇产），并在汇报里点明「这是会期主导、不是选题偏好」，不要等用户质疑「怎么全是心血管」；最高互动的往往不是最大阳性结果，而是**阴性/提前终止（非劣效失败）、双终点不一致（OS 阳 PFS 阴）、曲线交叉或 OS 未达显著、头对头试验**。

## 一·C、主题调研型（给定主题，不追新，追证据链）

用户直接给一个主题、说「未必要最新但证据链要全」时，**不要跑 `fetch_all_sources.py`**（那是按日期抓 RSS 的，与主题不匹配），改走这条：完整配方见 `references/topic-research-evidence-chain.md`。

1. **先把主题压成一句可证伪的论点**（「抗炎的真相」是标题不是论点；论点才是「药理抑制炎症并不改善结局」）。论点定了才知道要找什么、要反驳什么。
2. **找干预试验，不找综述**。Crossref `query.bibliographic` 检索，**不要用 web_search 搜试验名**——`CANTOS` 会返回庞德诗集和同名公司，`PREDIMED` 会返回房产中介，全是噪声。
3. **效应量逐字核**：要写进正文的每个 HR/CI/样本量，都从 EuropePMC 摘要 grep 出来，不凭记忆。记忆里的 0.85 和 0.87、CI 端点最容易错，而用户会逐条点开核。
4. **判证据等级并写进稿子**：正式论文 / 顶线公告（只有公司稿 + ClinicalTrials.gov，Crossref 查不到结果论文 → 只写公告公布的数字，标「全文尚未发表」）/ 会议报告 / `NEJMc…` 类 Letter。四种成色写法完全不同。
5. **结构＝现象 → 医学定义 → 干预尝试（失败也要写）→ 例外 → 什么真的有用 → 两条边界 → 收口**。阴性/失败证据放前面：堆阳性结果的稿子是宣传，「三个几十亿美元的试验都失败了」才是让人停下来的东西。
6. **参考稿只借现象，不借内容**：段落顺序、句子、案例、数据一律不能对得上；交付时主动说明「借了什么、没借什么」。
7. **字数上限用程序数，不靠目测**。用户给「不超过 1000 字」时要的是**去空白字符数**，用 `len(re.sub(r'\s','',body))` 数；先按目标的 90% 写（约 900 字），不要写完 1200 再删——实测从 1200 压到 999 要来回五轮、每轮重改三四处，白花力气。

### 一·C-2、考证 / 辟谣型（民间说法值不值得查）

用户拿来一个流行说法（「哈佛蔬菜汤能抗炎」「某食物抗癌」）问「值不值得研究一下」时，不要按新闻选题跑抓取，也不要把「查不到」当成失败：

1. **先查这个话题被官方辟过没有**：科学辟谣（中国科协）、央视新闻、省市市场监管辟谣号。已经辟过若干轮 → **不要再做「打假稿」**，重复已饱和，用户会直接说没信息增量。改走第 4 条。
2. **计数检索判证据厚度——这类选题最硬的产出**：`TITLE:"<说法关键词>"` 看命中数与主题分布（EuropePMC / Crossref 都行）。实测：`TITLE:"vegetable soup"` 命中 61 篇，全是食品工艺（减盐、提鲜、抗氧化测定），**一篇研究抗炎都没有**；`TITLE:"cruciferous" AND TITLE:"inflammation"` 全库 **1 篇**且结论是效应不一致。**「0 篇」本身就是结论**，比任何二手辟谣硬。
3. **溯源要落到人名和书名**：这类说法的「权威背书」几乎都能追到一个人（某博士在名校工作过 → 出书 → 商家贴名校标签）。核官方是否认证过（大学/学会官网从未发布），再查原始名称（很多是改名后的营销，原名往往很朴素）。这一段比「没有证据」有信息量得多。
4. **角度从「打假」换成「证据怎么被偷换」**：写四个跳跃——细胞实验的单一成分 → 说成该食物 → 再说成某道菜 → 作者履历说成名校研究证实。每一跳单看不撒谎、合起来就变味。这是科研方法论选题，正好打中账号核心受众，也避开与官方辟谣稿同质。
5. **顺手找那个「工序层面的折扣」**：流行说法常忽略做法本身（久煮破坏酶、高温损失水溶性维生素、只喝汤不吃渣）。找一个有文献支撑的机制点（如十字花科需黑芥子酶水解才生成活性成分、该酶怕热），稿子立刻有医学味，也不再是空对空。
6. **结论分两层写**：东西本身无害/有营养（别写成“这汤不能喝”）+ 被夸大的是头顶的功效。只否定功效、不否定食物，读者才听得进去。

### 一·D、企业新闻稿 / 临床前数据（药企 PR、管线进展、会议摘要）

用户丢一条公司新闻稿（「某药四靶点临床前结果公布」）当选题时，四个字段的写法跟论文类不同，别套错：

1. **证据等级先写在汇报第一行**：`临床前（动物模型）、企业自行公布、未经同行评议、未在期刊发表`。四件缺一件都会让稿子读起来像已上市。用户会直接要求标这条，不用问。
2. **内容分类不进「临床试验数据（高风险）」**（没有人体数据就不算临床）；临床前 / 管线进展 / 机制演进归 `["科研方法与行业分析（低风险）"]`。
3. **`DOI链接` 留空、`获取方式` 不标**（无 DOI → 按 §三·6 “无 DOI 不标”）；`来源链接` 写企业新闻稿 URL（官网 press-release 页，不是转载），`原文发布日期` 用新闻稿自己的日期。
4. **「世界首例」「first-in-class」必须连限定条件一起引**：企业 PR 里常写 “based on publicly disclosed development status”；把前提删掉只留“首个”就是绝对化，只放汇报/出处节，不进标题。
5. **话题度里的时效给高、痛点看受众**：企业管线新闻时效强（说给 28–30）但痛点不如指南/获批（20–30），不要因为“四靶点”听着新鲜就抬到 90+。

如果用户当天又改主意、要求“把原来那篇抹掉换成这篇”，旧记录**复用同一条**（改标题/分类/日期/来源/DOI 清空），不要新建第二条——两条并存就是重复选题。

## 二、筛：什么值得做

受众三条线，一条只挂一个主视角：
① 要发论文的医学生/规培生　② 靠论文评职称、不太懂统计的临床医生　③ 懂科研的临床科研工作者

优先级：
1. **传播向选题（2026-10 用户实测：流量最好）**——四类，与科研价值同等甚至优先：
   - **情绪向**：医生倦怠/抑郁、职称焦虑、规培困境、收入与职业尊严、医患冲突、中年医生转行（例：《医务工作者正在变得更抑郁》——Medscape 职业倦怠报告解读）
     - ⚠️ **情绪向信源只用权威低频源**（2026-10-28 用户定）：Medscape 年度职业报告、NEJM/JAMA「A Piece of My Mind」、机构年度调查、卫健委通报。**不抓丁香园/医脉通/医学界**——它们是竞品，人家先手发了再转载/洗稿不妥。
   - **共识更新向（数据好，2026-10-28 用户点名强化）**：新指南/共识发布、旧版被推翻、用药前移/阈值调整/新增章节
     - 信源：各学会官网公告（ADA/EASD、ESC、AHA/ACC、IDSA、AGA、KDIGO、ERS/ATS、中华医学会各分会）+ 同步发表的期刊（Diabetes Care、Diabetologia、Circulation、Eur Heart J、Gut、Chest 等）
     - 选题角度：**「和上一版比改了什么」才是卖点**——用药时机前移、新增章节（如 MASLD/MASH 首次单独成章）、阈值/分级调整、推荐级别升降；必须落到「临床上具体怎么变」
     - **标题公式**（学用户爆款《二甲双胍，过时了吗？》ADA/EASD 2026 T2D 共识）：**「<经典老做法>，过时了吗？」** ／ **「<颠覆点>：<新推荐>」**——用问句挑战固有认知造悬念；不要写「XX指南更新解读」这种中性题
   - **吃瓜向**：撤稿、图像/数据造假调查、大牛翻车、学术丑闻、期刊互相撕、药企丑闻（例：《离谱造假15篇SCI：一张图拉伸旋转反复用7次》——Retraction Watch / PubPeer / 高校通报）
   - **故事向**：患者故事、罕见病例、医生亲身经历（NEJM/JAMA「A Piece of My Mind」、Lancet Perspectives、MedPage patient stories）
   - **大事件**：诺奖、医保/职称重大政策、疫情暴发、FDA/NMPA 里程碑获批、顶级期刊里程碑论文
2. **能改变临床决策**的（新药获批、指南更新、诊断阈值被挑战）
3. **有硬数据的**队列/RCT（样本量＋HR/OR/AUC/灵敏度）
4. **科研方法与工具**（真实世界数据、生信、AI 辅助科研）→ ①②最爱
5. **反常识/阴性结果**（试验未达终点、机制意外）→ 互动最高，**别只收阳性**
6. **科室分布要均衡**：肿瘤类天然过剩（期刊与会议都偏肿瘤），必须主动给心血管/呼吸/急诊重症/麻醉/影像/肾/妇产配额度

**成果量级判定（用户问「最近有什么重大成果／专业人士一看就知道大的」时必用）**：先过这套尺子，再决定话题度和标题措辞。把顶刊机理论文当突破卖，评论区会被专业医生当场打脸。
- **A 级＝专业人士一眼认**：III 期随机对照达到主要终点；或共识/指南把「不可治愈」改写成「可治愈」；或首次在原本没有随机证据的人群做出随机对照。
- **B 级＝实质进展但不改实践**：随机 II 期、新靶点首个人体数据、样本极小的早期探索（3 例这类 `NEJMc` Letter 属此级，标题必须把「N 例／无对照」放在最前）。
- **C 级＝顶刊但不是临床成果**：Nature/Science 主刊的图谱、工具、机制、筛靶点方法。价值真实，标题写「重大突破」就是造假。
- 一句话判据：**有没有「主要终点 + 对照组 + 样本量」三件套**。缺任何一件就降到 B/C 级并改措辞。汇报时按 A/B/C 分级列出，并说明 C 级为何不收（用户会问「顶刊为什么不算」）。

⚠️ **传播向与科室均衡的张力**：传播向（尤其情绪/吃瓜）天然不分科室，不要为了“科室均衡”而砍掉高情绪选题——情绪选题以「医生职业」为科室（不属于任何专病），单独计入配额。

**传播向专用信源**（普通学术源抓不到）：**Retraction Watch（retractionwatch.com/feed/，已接入脚本 FEEDS，实测 14 天 ~10 条）**、Medscape 年度职业报告、NEJM/JAMA「A Piece of My Mind」、MedPage physician burnout 栏目。**不抓丁香园/医脉通/医学界（竞品，不做洗稿）**。**PubPeer 官方无 RSS（/rss /feed 全 404，2026-10-28 实测），要抓得走 camofox 网页**。找不到 RSS 时用 web_search 直搜关键词（「医生 倦怠 2026 报告」「撤稿 造假 论文 2026」「<学会> guideline 2026」）。

排除：**预印本（bioRxiv/medRxiv）一律不收**——没同行评议、结论常反转、太前沿，不适合医生向的公开内容（2026-10-26 用户决定；脚本已默认不抓，只需临时看前沿时加 `--with-preprint`）；另排除地方性政策（市/县级申报通知）、代写代投广告、只讲 AI 多强不讲边界的软文、**药企出资的期刊专刊**。

**地域代入感是硬筛选条件**：受众在中国，**单一欧洲国家（法国、德国、北欧尤甚）的区域性观察性研究、可行性研究、卫生服务研究默认不先推**——用户否掉「法国 11 家医院儿科麻醉远程会诊」的原话是「法国的估计大家不太乐意看」。优先级：中国研究者/中国人群 > 多国参与的国际多中心 > 美国 > 其他国家。欧洲研究要收，得是多国参与、或结论直接冲击现有实践（ESC/ESMO/EASD 大会 LBA、学会共识）。同质选题里同时有中国研究和欧洲研究时，先给中国那条。

**赞助专刊要剔除**：Nature 的 `Outlook`／`Focus`、JAMA 的 `Insights`、部分刊的 supplement 是药企出钱组织的专题，文末必有一行 `produced with financial support from <公司>` 或 `This article is part of ... a supplement produced with financial support from ...`。这类内容选题看着极好（一整套前沿综述），实际是广告位，原研数据和对照组都没有，照它写稿等于转述药企口径。判据不是栏目名，是**页面底部那行 funding 声明**——抓到一整套同主题稿时先抽一篇看文末。

**话题度**＝目标受众痛点相关度(0-40) + 时效性(0-30) + 可讨论度(0-30)，整数。**传播向选题（情绪/吃瓜/故事/大事件）的可讨论度按情绪共鸣强度或吃瓜爽感打分（0-30 打满）**，三分项理由只写汇报，不进表。

**内容分类**只能用固定选项，**且选项名带风险后缀、写入时必须是数组**（写裸名会失败）：
`["临床试验数据（高风险）"]` / `["新药获批（高风险）"]` / `["指南共识更新（高风险）"]` / `["观察性/真实世界研究（中风险）"]` / `["AI与数字医疗（中风险）"]` / `["公共卫生与疫情（中风险）"]` / `["科研方法与行业分析（低风险）"]` / `["科学奖项与基础研究（低风险）"]` / `["观点与评论（低风险）"]` / `["预印本/早期研究（中风险）"]`（已停用）。拿不准时先从现有记录统计实际出现过的分类值（见第四节），不要凭字段定义猜名字。

> ⚠️ 其中「预印本/早期研究」选项**停用**：预印本不再入选题库。只是字段选项还在（存量的历史数据不删），新条目一律不选它。

## 三、核：三件事，一件都不能猜

### 1. 链接要对得上标题
每条都打开比对**标题**，不能只看域名。聚合站/数据库里的 url 有相当比例 404 或指向别的文章。404 就换能打开的二手报道并写明。

**交付任何带链接的清单（选题清单、参考网站表、工具列表）前先批量探活**（并发 10 路，单条 20s 超时）：
```bash
curl -sSL -o /dev/null -A "<浏览器 UA>" --max-time 20 -w '%{http_code}' <url>
```
状态码判读：`200` 可用；`401/403` = WAF 拦脚本、浏览器正常，照发并注明；`404` = 路径失效；`000` = DNS/TLS 已死（站点迁移或下线），**必须换新域名或换替代站**，不要照抄旧链接——实测 Calgary Guide 已迁到 `calgaryguide.ca`、ECG Wave-Maven 域名彻底无响应要换 ECGpedia。用户会逐条点开核，死链一条就算错。

### 2. 日期只能取页面自带的
写入格式 `YYYY-MM-DD HH:MM`（Asia/Shanghai），**用页面印刷的日历日 + 09:00**，不要拿美东时间换算（上午的稿会跳日）。
取不到就留空，**禁止**用抓取日/建议日/推断值补。

⚠️ **三个已踩的坑**：
- **EuropePMC 的日期可能是未来期次**：Lancet 系、部分 Elsevier 刊会把"期次日期"当发布日期返回（实测出现过 2027-09）。脚本已把超今天的值清空并落到 `issue_date`。
- **web_extract 摘要行里的 `Published:` 不可信**：它会把期次月份当日期（实测 Lancet Resp Med 给 2026-10-01，真实 2026-10-21）。
- **出版社页面只认 meta，但字段名各家不同**：Wiley/OUP 常给 `citation_online_date`；**Lancet/Elsevier 没有这个字段，要读 `citation_date`（格式 `2026/10/31`）**，再拿正文的 `Published October 31, 2026` 交叉确认。只搜 `citation_online_date` 会一个都搜不到、误判「页面没日期」而回去用 RSS 日期。被 Cloudflare 挡时用 camofox 读。

### 3. 先判稿件类型，再判是不是新稿
RSS 标题看不出稿子类型，入表前必查 EuropePMC 的 `pubTypeList.pubType`：
```bash
curl -s "https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=DOI:%22<doi>%22&resultType=core&format=json&pageSize=1" \
  | jq -r '.resultList.result[0].pubTypeList.pubType|join(",")'
```
- `Letter` / `Comment` → 读者来信、编辑评论、作者回复，**不是原始研究**，当试验收就是假选题。判据：NEJM 的 `10.1056/NEJMc…` 全是通信（原始论文才是 `NEJMoa…`），JAMA 的述评也常与原文同批进 RSS。NEJM `currentIssue` 一轮 11 条里可能一半是通信/Image/Case，这也是「某天候选上百、入库 0」的常见原因，汇报里要按类型点明。
- **通信的标题会长得和原始研究一模一样**：一条 `PARP and Androgen-Signaling Inhibition in Metastatic Prostate Cancer` 读起来就是 III 期，DOI 却是 `10.1056/NEJMc2611171`——它是针对该试验的评论，不是试验本身。所以**打分、入库前先看 DOI 前缀（`NEJMoa` 原始 / `NEJMc` 通信），别拿标题判类型**；一字之差，错了就是把评论当重大成果卖。
- 只有 `Journal Article` 才可能是原研；`pubType` 为空或只有 `Preprint` 的一律不收（预印本已排除）。
- **反向也要查**：「是不是新稿」看 Crossref `published-online`，**远早于本次抓取日就是旧文重排**（期次上线、专栏合集把老文重新排进 feed，RSS 日期是重新推送日），直接剔除；比今天晚的日期按第五节处理。

### 4. 政策 / 指南文件类选题：先核「文件性质」，别信外媒的 draft

外媒写中国政策时习惯用 `draft` / `proposed`（草案、拟），但中方原件常常**已经正式发布**（试行版）——照搬英文措辞会把「已发布」写成「征求意见」，性质写反，而且这个错会一路传进正文、封面文案和标题。

- **先找官方原件**：部委官网（如 `moe.gov.cn`）→ 业务指导委员会（如全国医学专业学位研究生教育指导委员会）→ 高校/研究机构转载的 PDF。原件首页有**红头机关名 + 发文字号 + 落款日期**，这三样决定了它是什么级别的文件。
- **性质只认文件自己的字**：标题带「（试行）」＋正文写「现发布…请各培养单位…加快推进实施」= **已发布试行**；只有出现「征求意见稿」「公开征求意见」才是草案。有文号（`学位办〔2026〕26号`、`医专业学位委〔2026〕14号`）本身就说明是正式发文，不是讨论稿。
- **分层写上位依据与本文**：政策背后常有一份上位文件（部委《意见》→ 教指委《基本要求》），报道日期属于下层文件；把两者混成一个日期或一个文号，稿子里就会出现两个来源打架。
- 核不到原件时，正文只写「据报道」，**不写「已发布」也不写「征求意见」**；性质拿不准宁可推迟入库，也别先把错的定性写进选题表。

### 5. DOI 必须 Crossref 验
```
https://api.crossref.org/works/<DOI>   # 返回 title 与新闻主题对得上才算过；串行、间隔 ≥1.2s（会 429）
```
- **从 URL 推导优于从正文抓**：`nature.com/articles/<code>` → `10.1038/<code>`；NEJM/doi.org 的 URL 直接含 DOI；medRxiv/bioRxiv 去尾部 `v1`。正文里常引一堆历史文献，抓第一个 DOI 一定抓错。
- **新闻稿（`d41586-…`）的推导 DOI 常 Crossref 404**：新闻页本身可能没注册、或注册滞后。这时**别把新闻稿当文献收**，改去查它报道的原研论文：`api.crossref.org/works?query.bibliographic=<关键试验词>` 或 `query.container-title=<NEJM/Lancet>`，命中后**必查 EuropePMC `pubType` 再定证据等级**——同一篇报道可能是完整 RCT，也可能只是 `Letter`（例：一篇「3 例患者」的早期探索，NEJM 侧就是 `10.1056/NEJMc…` 的 Letter）。`Letter` 不是不能收（有真实数据、有新闻价值），但分类、话题度理由和汇报里的「DOI 验证结果」都要写明它是 Letter 和样本量，不能当大规模试验卖。
- 填表格式＝**纯链接，只有一个 URL**：`https://doi.org/<10.xxxx/xxxxx>`。**不加英文原题、不加「DOI:」前缀、不加任何说明文字**——这一列的名字就叫「DOI链接」，用户要的是能直接点开的东西，掺字进去等于没填。
- 确实没有论文的（会议摘要、监管文件、政策、教程、吐槽）→ **「DOI链接」列留空，一个字都不写**。也不拿新闻报道自身的 DOI 充数。**为什么**：这一列是给人点开看原文的，写说明既点不开、又把列弄脏；用户 2026-11-05 的要求原话是「只给我放 DOI 链接，除了链接不要写任何多余的屁话」。缺 DOI 的原因只写进汇报。
- 给历史脏数据补链接：从旧值里正则提 `10\.\d{4,9}/\S+` → 重新拼成 `https://doi.org/<doi>` → 批量 update 覆盖。**只做这一步，不要顺手把英文原题加回去。**
- 确实查不到论文的，留空即可——不要为了填满这列去猜 DOI，也不要写「推测 DOI」。

### 6. 取用门槛要标（获取方式标签）

选题入库时读者能不能直接打开全文，是选题可用性的一半——付费墙的稿子用户点开看到订阅页，等于白找。所以每条**有 DOI 的记录**都要打一个「获取方式」标签。

- 字段：`获取方式` `fldITOayUU`，单选 select，五个值：**开放获取**（绿）/ **有免费预印本**（浅蓝）/ **付费墙**（红）/ **注册墙**（橙）/ **待查**（灰）。
- **无 DOI 的条目不标**（本来就没有论文可点，标了反而误导）。
- 判定用 **OpenAlex**（免 key，比 Unpaywall 宽、对太新的 DOI 也有记录）：
  ```bash
  curl -s "https://api.openalex.org/works/doi:<DOI>?select=open_access,primary_location" -H "User-Agent: Hermes/1.0 (mailto:jin@example.com)"
  ```
  **判的是「出版社那个链接点开能不能白读」，不是「世上存不存在免费版」**——这两件事经常不一致，混为一谈就会把订阅制的论文标成免费：
  - `gold / hybrid / bronze / diamond` → **开放获取**（出版社页直接免费）
  - **`green` → 有免费预印本**（**不是开放获取**）。green 的含义是「出版社页仍要订阅，免费的只是 arXiv／PMC／机构库里的那份稿」，而且常常是 `submittedVersion` 投稿版，数据可能与见刊版不一致，写稿引用前要说明用的是哪一版
  - `closed` → 按 DOI 前缀细分：`10.1016/S0140-6736`、`10.1016/S2213-*`、`10.1016/j.lan*`（Lancet 系）+ `10.1161`（AHA/Circulation）→ **注册墙**（免费注册即可读全文，不是真付费）；其余（`10.1038` Nature、`10.1056` NEJM、`10.1001` JAMA、`10.7326` Annals、`10.1093` OUP、`10.1016` 非 Lancet 系…）→ **付费墙**
  - 预印本前缀 `10.64898`（medRxiv）/ `10.1101`（bioRxiv）→ 一律**开放获取**
  - 双保险：同一次请求里取 `primary_location.is_oa`，为 `false` 时即使 `oa_status` 是 gold/hybrid 也判 **付费墙**
- 查不到（404/超时）按 **付费墙** 处理，宁可标严；确实摸不清才用「待查」。
- **标完必须拿「来源链接」实测复核一次，不能只信 API**：`curl -sL -A "<浏览器UA>" <来源链接> | grep -c "Access through your institution\|Subscribe\|Log in"`，命中 >0 就是付费墙。API 说 open、页面说要订阅时**以页面为准**——用户会逐条点开核，标错一次整表返工，而且是当场被问「我点进去说要订阅啊」。
- **被问「你是不是跨过去抓到全文了」就直接说没有**：本流程只拿得到元数据 + 摘要（EuropePMC/Crossref/OpenAlex），不绕付费墙、不代下载。用户看到订阅页时先承认标签标错、再查 API 字段为什么误判，不要用「我抓到了」圆场。
- **一键跑**：`python3 scripts/tag_access.py --base-token <t> --table-id <t> --as user`（只处理有 DOI 且未打标签的记录，幂等，可重复跑）；判定逻辑改了要重标历史数据就加 `--force`。
- 脚本里 `lark()` 调 `record-list --output` 时 **stdout 不是 JSON**（只回 manifest 提示），直接 `json.loads` 会 `JSONDecodeError`——包一层 try，失败按 `returncode` 判成功。
- 时机：**每批选题写完立刻跑**，别攒着——攒到最后一次跑几百条 OpenAlex，中途挂了还得从头对。
- 字段顺序：飞书 API 不支持把字段插到指定位置，`+field-create` 只能加到末尾；要放在「DOI链接」旁边得让用户在表格里手动拖。汇报时说明，不要假装已经排好。
- **加选项 / 改选项颜色**：`+field-update` 是**整体覆盖**（PUT 语义），要连同 `name`、`type`、`multiple` 和**全部** options 一起发，只传被改的那个选项会把其余删掉；先 `+field-get` 拿当前定义再改。颜色枚举是 **`Gray`**（不是 `Grey`），其余：`Red / Orange / Yellow / Lime / Green / Turquoise / Wathet / Blue / Carmine / Purple`。

### 7. 钱与规模：公司不披露就不报点值

用户问「这个试验花了多少钱」、或自己想给标题挂金额时，按这条走——**试验花费药企几乎从不披露**，随口给一个数（「十几亿美元」）既不进汇报也进不了标题，用户一追问就露底。

1. **先查有没有官方披露**：公司 PR、SEC/交易所公告、年报。绝大多数只写「pioneering」「global」，没有预算数字。查不到就明说「未披露」。
2. **改算，别猜**：用公开的行业成本基准 × 本试验规模给出区间，并**把算法写出来**。可用基准：关键试验平均每例约 **4.14 万美元**（Moore TJ et al., *JAMA Intern Med* 2018，59 个 FDA 新药 pivotal trials）；同研究按领域拆分，**心血管领域中位约 1.57 亿美元**（最贵的一类）。
3. **给区间词，不给点值**：8323 人 × 4.14 万美元 ≈ 3.4 亿美元；再考虑中心数、国家数、随访年数上浮，交付口径写「几十亿元人民币量级（估算，公司未披露）」。**「几十亿」覆盖整个区间，比「二十多亿」安全**——后者是点值，一旦被质疑就得重新算。
4. **标题可以用，但正文明不写明「估算」由用户定，以标题党优先**：默认写法是标题挂「耗资几十亿」、正文跟一句「花费公司未披露，按行业每例成本基准估算，量级在几十亿元」。但用户实际口径是**标题党优先**（原话：「这种时候我要标题党，没有的事就不要声明」）——他会把这句扛自我台的话**整句删掉**。所以：他删就删，不要反复劝；把风险提示和补丁（⚠️ 段加半句的写法）放到交付消息里，而不是塞进他的文章。写稿时的完整处理见 `scilink-writing` Step 0「标题党优先」那条。
5. **别把收购价当试验成本**：药企早年收购整个公司的金额（含多个管线）不能算作单场试验的花费；写成「为这个试验花了 N 亿」是硬错。

### 8. 内容形式：六类，决定用哪种图文版式

用户 2026-11-10 定：**论文和新闻资讯要做成两种不同图文**，所以选题入库时必须打「内容形式」标签。字段 `fldms7NLUi`，单选，六个值（顺序固定）：

| 值 | 首轮回填条数 | 判定规则 |
|---|---|---|
| 原始论文 | 208 | 有 DOI 的期刊发表物（RCT／队列／基础研究／Meta 都算） |
| 新闻资讯 | 62 | 无 DOI + 媒体来源 + 讲一件事（含获批报道、大会报道、行业新闻） |
| 政策/监管 | 20 | 来源是 gov.cn／fda.gov／who.int 等官方站，或标题以 FDA/NMPA/卫健委开头且含监管动词 |
| 行业生态 | 19 | 撤稿·造假·论文工厂·学术不端·职称·规培·倦怠·跑路·中年危机·工会·招生就业类 |
| 综述/观点 | 10 | 现有分类＝观点与评论，或标题含 综述／观点：／社论／述评 |
| 企业管线 | 1 | 药企官网 PR、临床前数据、管线进展（无 DOI） |

**判定顺序（命中即止）**：① gov 域名 → 政策/监管；② 标题以 FDA/NMPA/国家药监局/卫健委/国家自然科学基金 开头 **且** 含 批准·获批·要求·警告·扩大·指导原则·办法·通知·目录 之一 **且** 无 DOI → 政策/监管；③ retractionwatch.com／pubpeer → 行业生态；④ 药企官网域名（celltrion/bayer/novartis/pfizer/lilly/astrazeneca/merck/roche/moderna/ionis/biogen/amgen）→ 企业管线；⑤ 标题含强生态词 → 行业生态；⑥ 分类＝观点与评论 → 综述/观点；⑦ 标题含 综述／观点：／社论／述评 → 综述/观点；⑧ 有 DOI → 原始论文；⑨ 其余 → 新闻资讯。

**首轮回填踩过的误判（下次照这个避）**：
- **不要用泛词当生态关键词**：「收入」「医学生」「焦虑」「职业」「绩效」「流失」会把「PURE 研究 COPD 负担」「面向医学生的实用指南」误判成行业生态。只能用强词（跑路、倦怠、职称、撤稿）。
- **标题以 `FDA` 开头 ≠ 监管文件**：「FDA 专家组不买账：某药三期数据被质疑」是新闻，必须同时含监管动词才判政策/监管。
- **有 DOI 的撤稿论文仍归行业生态**：撤稿/造假的判定要排在「有 DOI → 原始论文」之前。
- **自动跑完必须抽检每类 5 条**，少量例外手工改（首轮改了 3 条）；回填用 100 条一批的 batch-update，跑完读回确认空值＝0。

## 四、写：6 列 + 分批 + 读回

> **容器先认清**：选题库 base（`PCm9b6saQaJ8gmsqAxTcqWHtnVj`）下不只有数据表，还挂着 docx 块（「产品内容选题库」「常用信源（用于人工筛选）」）。`base +table-list` 只列表、看不到它们；枚举全部块用 `base +base-block-list`，返回的 `docx_token` 才是 `docs +fetch/+update` 能吃的参数（拿 `table=ldx...` 这种 id 直接去 `+record-list` 会报 *resolves to a docx block, not a table*）。往这类文档写入用 `docs +update --command overwrite --doc-format markdown --content @file`，原标题保留。**不要走 `base +app-get` / `+app-page-list` 这条路**（它们要 BaseApp token，拿 bitable token 一律报 `code 1`，白花两轮）。**用户说“放到这个多维表格里”时，先用 `+base-block-list` 找到目标块，不要自己新建子文档、也不要把信源类内容塞进选题表——弄错位置会被打回重做**；真建错了清理用 `wiki +node-delete --node-token <node> --obj-type wiki --yes`（漏 `--obj-type` 直接 validation 报错）。

飞书「内容物料库」只写 6 列（`内容标题/话题度/内容分类/原文发布日期/来源链接/DOI`），其余列留给后续步骤。**实测库与字段 id（2026-10-28，免再查）**：base `PCm9b6saQaJ8gmsqAxTcqWHtnVj` / 表 `tblfAf9h81t9oVq9`「资讯内容选题库」；内容标题 `fldhbzJpN2`｜话题度 `fldA6S6euY`(number)｜内容分类 `fldMEfxgp5`(select，值为数组)｜原文发布日期 `fldxUgwRLN`(epoch 毫秒)｜来源链接 `fldPmLFm7v`｜**DOI链接** `fldU3IEPbd`（纯 URL）｜**获取方式** `fldITOayUU`（select：开放获取/有免费预印本/付费墙/注册墙/待查，见 §三·6）｜**内容形式** `fldms7NLUi`（select，单选：原始论文/新闻资讯/政策监管/综述观点/企业管线/行业生态，见 §四·7）。字段清单在 `+field-list` 的 **`data.fields`**（不是 `data.items`，拿错会得到 0 字段而误判“表里没字段”）。

```bash
# 差集（幂等优先，已入库绝不重复录）
lark-cli base +record-list --base-token <t> --table-id <t> --limit 500 --format ndjson --output /tmp/existing.ndjson --overwrite --as user
# 分批创建（create 是数组）
lark-cli base +record-batch-create --base-token <t> --table-id <t> --json @/tmp/payload.json --as user
# 读回验收（别用 head 截断）
lark-cli base +record-list --base-token <t> --table-id <t> --limit 500 --format ndjson --output /tmp/check.ndjson --overwrite --as user
```

- **差集只能按 DOI 比，不能按标题比**：库里标题是中文改写版、抓取结果是英文原题，标题比对会把 100% 候选判成新的。DOI 用 `10\.\d{4,9}/\S+` 提取后比对；Elsevier 的 DOI 带括号（`10.1016/S0140-6736(26)02058-1`），正则在 `)` 处截断会漏判重复。
- **`--format ndjson` 的每行是扁平对象**（字段名直接是顶层键，不是 `fields`/`record.fields` 包裹）——先 `json.loads(line)` 再取值。**键名就是列名，列改名后键名跟着变**：这一列现在叫「DOI链接」，用 `r.get('DOI')` 读会全部拿到 `None`，把整表误判成「292 条全是空」。凡是脚本里硬编码过列名，列一改名就得同步改；不确定时先 `head -c 600` 看一行真实结构，或 `field-list` 对一遍列名再写逻辑。
- **差集比对**：从「DOI链接」的纯 URL 里正则提 DOI（`10\.\d{4,9}/\S+`）再比，不要拿整列字符串比。
- **无 DOI 的条目要二次去重（主题词 + 日期）**：NMPA 公告、MedPage 会议报道没有 DOI，DOI 差集天然抓不到重复；同一公告库里可能已有更详细的历史记录（标题不同）。写入前对这类条目按「核心名词匹配现有标题 + 日期相同」再扫一遍，命中就不写；发现已重复的用 `base +record-delete --record-id <recX> --yes` 删掉自己那条较窄的（`--yes` 必需，否则返回 confirmation_required）。
- **同一事件的第二个节点是「更新」不是「新建」**：一个药／一项试验常有多个上线节点——顶线公告 → 大会报告 → 正式论文 → 第二个国家批准。前一个节点已在库里、后一个节点带着新 DOI 进来时，**DOI 差集一定判它为「新」**（旧记录没 DOI、新记录有 DOI），直接建就是同一件事两条并存。所以建记录前先拿**药名／试验名**扫一遍「内容标题」，命中就更新那条：标题补上新节点、`原文发布日期` 换新日期、`DOI链接` 补论文 DOI、`来源链接` 换新报道页、话题度按新数据重打（通常上调）。汇报里写明「这条是更新不是新建」并给出旧 record_id。判据是「同一药、同一适应症」而不是「同一篇论文」——中外两个监管机构先后批准同一种药，是同一选题的进展，不是两条选题（会议季 LBA 的同类处理见 §一·B 第 5 条）。
- **创建成功与否以「表内总条数变化 + 读回命中」为准，不看 batch-create 的返回体**（它常回 `ok:true` 但解析不到 records）；读回时同时打印总数与抽查命中数，差额即漏写。
- **每 5-6 条一组走完全流程并立即写表**，不要攒到最后——会话有迭代上限，已入库的才算交付。
- **文字先全部写完再出图**（用户 2026-10 定）：一批选题进来，先把标题/封面文案/正文/润色稿四列填完、读回验收，**停下来等用户点名哪几条要出片**；不许边写边生图，也不许先出一张“看看效果”（生图一次一张算力，文字零成本）。会议／事件整批选题另建 `专题` 字段打同专题名，封面用 `add_cover_text.py --badge` 出顶部胶囊标签。
- **写完顺手查视图排序**：`base +view-list` 看 `_meta.sort` / `_meta.group`。默认按「话题度 desc + 分类分组」时，新选题会被历史高分老稿压在下面，用户会误以为「最近几天一条都没有」。改 `+view-set-sort '{"sort_config":[{"field":"原文发布日期","desc":true}]}'` + `+view-set-group '{"group_config":[]}'`，最新在顶。
- **来源链接列是纯字符串，不是对象**：写 `{"link":url,"text":url}` 会整批 `800010701 invalid_request: Request validation failed with N issues`（N＝记录条数，看着像每条都错）。正确值是 markdown 链接字符串 `[url](url)`——先 `record-list` 拉一条现有记录看该列长什么样再写，别按字段类型猜。
- payload 形状：create 是 `{"create_records":[{fldId:value}]}`（数组），update 是 `{"update_records":{"recX":{fldId:value}}}`（map），两者不通用。
- `--json @file` 只允许当前目录、`/tmp`、`~/files`。
- **datetime 列写 epoch 毫秒，不要写字符串**：`int(datetime(2026,10,26,9,0,tzinfo=timezone(timedelta(hours=8))).timestamp()*1000)`，读回自动显示成 `2026-10-26T09:00:00.000+08:00`。塞"原文未标注日期"这类文字会整批 `800010403`，日期原因只能写汇报。
- **「DOI链接」列只放两种值**：`https://doi.org/10.xxxx/xxxxx`（纯链接），或者**空**。不许出现英文原题、`DOI:` 前缀、「无（原因）」「未取得（待补）」等任何文字——用户 2026-11-05 明确纠正过两次（先清掉 100 条说明文字，再把 192 条改成纯链接）。写入前先 `record-list` 拉一条看该列现存格式，照抄。
- 写完立刻读回，逐条核 6 列是否落位、分类是否在合法选项内。
- **成稿不在本技能**：选题入库后用户说「把这条写成稿」时，走 `scilink-writing` 的流程（DS 初稿 + Kimi 润色 + 机检）→ 建「资讯内容选题库」子文档 → 回填 `物料文档` 纯 URL。只写记录不建子文档、或只建子文档不回填记录，都会被要求补做（用户已强调过三次）。
- **回填前先 `+field-list` 现查列名**：这张表的列被用户增删过（实测已精简到只剩 9 列：内容标题/话题度/内容分类/原文发布日期/来源链接/DOI链接/获取方式/是否采用/物料文档——原先的「图文建议标题 / 封面建议文案 / DS建议正文 / 润色正文 / 系列」已不存在）。照旧列名硬写会写错列或整批失败。
- **两个后置字段的 id 与用法**：`是否采用` `fldYEgVImP`（select，选项 `采用` / `不用`，写入是数组 `["不用"]`）、`物料文档` `fldy8z10Xu`（纯 URL）。用户口头说某条「不采用／这条不要了」时，**当场把 `是否采用` 写成 `["不用"]` 并读回确认**，别只回一句「好的」；也**别删记录**——删了话题度和当初入选的理由一起没了，用户回查时看不到它为什么被否。

## 五、判空与降级规则

- **抓 0 条 ≠ 空源**：先查该刊最新一篇日期（不限窗口），远早于窗口才换刊，只是刚落到窗口外就放大 `--days`。急诊/麻醉/肾脏类期刊发文慢，建议 10-14 天。
- **中文官方源节奏比期刊还慢**：NMPA 药品动态 1-3 天一条，卫健委政策法规 / 工作通知 / 国自然通知按周甚至按季度。用 `--days 4` 跑中文源基本只有 NMPA 有货（其余会打 `[CN EMPTY]`），**这是正常现象，不是坏了**；补中文选题请把窗口放到 14-30 天。
- **头部期刊发布有小时级延迟，早刷会以为「今天没稿」**：实测 2026-10-26 同一天两次跑，第一轮（14:30）NEJM 最新只到 10-24、Circulation 只到 10-22；约 1.5 小时后第二轮才抓到 NEJM 10-25 的 3 篇与 Circulation 10-26 的女性心血管共识 3 篇。**跑完后必须查「各头部刊最新日期」**：若 NEJM / Lancet / Nature Medicine / Circulation 最新条目 < 今天，在汇报里明写「今日期刊尚未上线，建议 2-4 小时后补刷」，不要默默当成“今天没新稿”。
- **筛选清空某一天时必须自证**：入库后统计「按日期：候选数 / 入库数」。若某天候选 ≥5 而入库 ≤1，汇报里要逐条说明砍掉的理由（重复 / 科室配额 / 无数据）。否则用户看到“那天一条都没有”会认为漏抓。
- 代表链接 404 且各媒体数字互相矛盾的选题：**直接剔除**，不要硬凑。
- **付费墙只读到首段就剔除**：Endpoints 等订阅制行业媒体只露导语，研究设计、样本量、终点一概核不了 —— 凭导语写选题等于编，换能打开的源或放弃此条。
- **论文官方 online 日可能比媒体报道晚一天**（期刊按美东发布、媒体按当天报道，时区一差就跨日）：两者都能核实时，**链接用能打开的报道页、日期用报道页日期**，「DOI链接」列照样填论文的 `https://doi.org/…`。绝不让表里出现晚于今天的日期。
- 作者/会议摘要/监管文件确实没有 DOI 的，**「DOI链接」列留空**（不写任何文字）；**但会议季先跑一遍同步发表核查再下结论**（`query.container-title` 查 NEJM/Lancet/Ann Oncol，见 §一·B）。会议季（ESMO / ASN Kidney Week / ECTRIMS 等）MedPage 的 `/meetingcoverage/` 是当天主力来源，很多条目确实只有会议报告，别因为没 DOI 就不收。

## 六、交付汇报（用户要求逐条列全）

每条给：`内容标题 | 原文日期 | 分类 | 话题度（含三分项理由）| 主视角 | DOI 验证结果 | 链接是否对得上 | 留空项及原因`。
另附：本轮新增条数、表内总条数、科室分布变化、剔除项与理由。

- **用户说「看看话题度高的，帮我挑一个」时，交付的是一个推荐，不是一张表**：先报近两周分档（≥95 / ≥90 各几条），再给**一个**主推荐 + 四条理由（数据干净度、平台合规风险、受众对口度、能否接成系列）+ 一句标题建议 + 一个备选（标明它的短板，如样本小、偏某科室），完整榜单放最后。一次给五个选项让他挑，等于没挑。
- **挑之前先跑 `scripts/check_dupes.py --in <ndjson>` 清重复**：用户翻高分榜时看到同一试验两条，会先怀疑整表质量。判据是同 DOI 或标题 bigram 相似度 ≥0.42，保留高分那条、`base +record-delete --record-id <recX> --yes` 删另一条，并在汇报里报「删了哪两条、保留哪条、删后总条数」。

- **用户回查「这几次的都更新到这个表里了吗」时，不要回一句「都在」**：重新 `record-list` 拉全表，把这几轮的每条按标题关键词逐条匹配，输出一张含 `record_id | 话题度 | 原文日期 | 标题` 的核对表，并明确报「读回 N/N、缺失 0、重复 0」。多轮入库后最容易出的是**同一选题重复录入**（无 DOI 的会议/政策类尤甚），命中多条要在表里标出「重复 N 条」并给出清理建议。

## 七、常见坑（都实际踩过）

1. Nature/Lancet 用 curl 直接用浏览器 UA 可过；NEJM / JAMA(jamanetwork) / MedPage / OUP(academic.oup.com) 一律 403（Cloudflare，camofox 也被挡）→ 日期改取 Crossref `published-online` 或 EuropePMC `firstPublicationDate`，链接照样发 doi.org 或期刊页，汇报里注明「curl 被墙、浏览器可正常打开」。
1b. NEJM 刚上线的论文（页面写 `Ahead of Print`）EuropePMC 常无摘要，`abstract` 字段是空的 → 关键数字按这个顺序补，别编：**① 学会官方新闻稿**（AHA `newsroom.heart.org`、ACC 会议报道页、ESC press office）——大会同步发表的稿子，学会稿里直接给完整 HR/CI/事件率、样本量和随访时长，是机构口径而非记者转述，最可靠；**② NEJM 官方 X/Threads 帖**；**③ 2 Minute Medicine / MedPage 转述**。三层都拿不到就只写试验名与结论方向（阳性/阴性），不填数字，汇报里注明「摘要未上线」。
1c. **EuropePMC 的 `abstractText` 会在 Results 中途被截断**（实测停在某个 P 值后面，安全性与局限整段丢失）：`curl -sL -A "<浏览器UA>" https://doi.org/<DOI>` 抓出版社页面，`re.sub(r'<[^>]+>', ' ', html)` 纯文本化后按关键数字（`2.44`、`satisfaction`）定位并打印上下文，通常能把 Results/安全性/局限补全并拿到研究者原话——LWW（Anesthesiology）这类页面 curl 直接 200，摘要全文就在 HTML 里，不需要登录。
2. camofox 复用同一 tab 连续 navigate 会突然 400/500——每条 URL 新建 tab；Lancet 首次 nav 常 500，重试一次即成功。
2b. **中文政府站（NMPA 全站、卫健委列表页）curl 一律 412**（WAF 要 cookie/JS），脚本已做成 curl 先试、失败自动落 camofox；直接把目标 URL 喂给 `POST /tabs` 会 500——必须先拿一个能过的 warm 页（如 `https://www.nmpa.gov.cn/`）建 tab，再 navigate 到目标。camofox 的 `activeTabs` 堆到两位数后全部 400/500，先 `pkill -f camofox-browser` + `pkill -f Camoufox.app` 再 `launchctl kickstart -k gui/$(id -u)/com.mednews.camofox`。偶发 `410 Gone`（建 tab 竞争）重跑一次即恢复，先别改代码。
2b-1. **自己写 camofox 调用必须带 `userId` + `sessionKey`**：`POST /tabs` 缺任一个直接回 400 `userId and sessionKey required`（看着像接口不存在）。路由也不是平铺的：`/tabs` 建、`POST /tabs/<id>/navigate`、`POST /tabs/<id>/evaluate`、`DELETE /tabs/<id>?userId=<uid>`。要取文章页 meta（`citation_date` 等）或整页 HTML 时，**直接复用 `scripts/fetch_all_sources.py` 的 `camofox_html(url, warm=...)`**，不要另写一套——里面已处理好 warm 页、重试和关 tab。
2c. **中文政府站文章页（不只是列表页）也要 camofox**：NMPA 批件公告页 curl 同样 412，正文里有适应症/商品名/优先审评等关键信息，必须走浏览器读。
3. `record-list --output` 同名文件会 `failed_precondition`，每次换名或加 `--overwrite`，否则会把旧 manifest 当新结果。
4. 同一新闻中英文两次收录（STAT/Medscape/Nature 各一版）→ 按主题只留信息最全的一条。
5. 中文 SEO 站（选刊指南站、软件测评软文、知乎/CSDN）日期缺、正文空，优先官方机构页与期刊正式文章。
6. 摘要里的数字不可信，正文口径以原文为准；"相关≠因果"这类限定词必须保留。
7. **EuropePMC 并发抓会偶发单源 timeout（一轮能挂十来个源）——别重跑整批**：先看上一轮结果里哪些刊缺失，用 `scripts/retry_missing_journals.py` 串行补，几乎必成功；补完仍为 0 的（麻醉/重症/泌尿/精神类）是发文节奏慢，不是源坏了。
8. **`PUB_TYPE:"Clinical Trial, Phase III"` 标签覆盖不全，别据此判「某刊这段没有 III 期」**：同窗口按 `ISSN:<刊> AND FIRST_PDATE:[起 TO 止]` 过滤，Lancet Oncology 返回 3 条而 NEJM、JCO 返回 **0 条**——不是没有，是没打这个标签。找顶刊大试验要**全量拉下来按标题/摘要自己筛**，再用 `resultType=core` 的 `pubTypeList` 复核类型。手写这条查询时 `terminal` 取回的 EuropePMC JSON 偶含控制字符，`json.loads(txt, strict=False)` 才能解析——直接 `json.loads` 会报 `Invalid control character`，别误判成接口坏了。

## 八、自动化（每天定时跑）

需要日更时用 `cronjob_manage`（action=create，schedule `0 8 * * *`，skills=[`scilink-topic`]，deliver=origin）。prompt 必须自包含，至少写清：抓取脚本绝对路径与参数、筛选排除项与科室配额、三核方法与状态码判读、飞书 base/table 与**字段 id**、差集规则（含无 DOI 二次去重）、写入形状（create_records 数组 + epoch 毫秒日期）、汇报格式。

- 库与字段 id 写进 prompt，不要指望 cron 会话自己去查（每轮多花几次调用，且会话无当前聊天上下文）。
- 定时任务只跑「抓取→筛选→三核→写表→汇报」，**不出图**——出图等用户点名（见第四节）。

## 相关

- **用户丢来 `/record/<token>` 说「先帮我总结一下，我再看看有什么话题点可以切入」时**：`+url-resolve` 拿整行（见下一条），然后按六段交付——这一步**只总结，不写稿**，用户明说要先判断：
  1. **一句话**——把核心矛盾压进一句（「降了 78%，事件零变化」），不写背景铺垫
  2. **设计表**——中心数/国家数/入组数/人群特征/干预剂量与频次/对照/背景治疗
  3. **结果**——主要终点 + 关键亚组 + 效应量，数字逐条列全
  4. **安全性/次要发现**——媒体最常漏、专业读者最认这一段（停药率、严重过敏、满意度分项）
  5. **研究者原话**——引 1–3 句，优先那句承认失败/意外的
  6. **话题切入点**——4–6 条，按可写性排序，每条一句「为什么这个角度有劲」
  数字拿不全先补摘要（§七·1b、1c），**不要用「据报道」糊过去**；也别在这步给标题成品或正文，抢跑等于白费。
