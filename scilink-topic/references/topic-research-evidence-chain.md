# 主题调研型选题：给定主题，建一条能站住的证据链

用户给一个主题（「抗炎的真相」「二甲双胍过时了吗」这类），**不要求最新，要求证据链全**。这和按日期抓新闻是两种活：抓新闻靠 `--days` 窗口，主题调研靠「找关键试验 → 逐字核效应量 → 排证据等级」。

## 流程

### 1. 先把主题压成一句可证伪的论点

「抗炎的真相」不是论点，是标题。论点要写成：

> 慢性低度炎症与疾病相关（观察性强），但药理抑制炎症并不改善结局（干预试验连续失败）。

论点定了，才知道要找什么证据、要反驳什么叙事——不然会一路收集「炎症有害」的材料，写成一篇人云亦云的养生稿。

### 2. 找干预试验，不找综述

**试验名直接扔进 web_search 会被同名干扰吃掉**：搜 `CANTOS trial` 返回的是庞德诗集、同名公司、创投机构；搜 `PREDIMED` 返回葡萄牙房产中介。**用 Crossref 的 `query.bibliographic`**，一次给 DOI + 期刊 + 日期：

```bash
curl -s "https://api.crossref.org/works?query.bibliographic=<试验名+干预+结局>&filter=from-pub-date:2015-01-01&rows=5&select=DOI,title,container-title,published-online" \
  -H "User-Agent: Hermes/1.0 (mailto:jin@example.com)"
```

知道 DOI 后照样跑 `api.crossref.org/works/<DOI>` 确认标题对得上（正式论文的 PMID/DOI 才是真源）。

找的是**同一个问题的多次尝试**，不是一篇综述的结论。好用的组合：阳性试验 + 学名药阴性试验 + 最新最大规模失败试验 + 生活方式干预试验。

### 3. 效应量必须逐字核，不能凭记忆

记忆里的 HR 会记成 0.85 也可能记成 0.87，CI 更容易记错。**每个要写进正文的数字，都从 EuropePMC 摘要里 grep 出来**：

```bash
curl -s "https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=DOI:%22<doi>%22&resultType=core&format=json&pageSize=1" \
  | python3 -c "import sys,json,re; ab=json.load(sys.stdin)['resultList']['result'][0].get('abstractText') or ''; i=ab.lower().find('hazard ratio'); print(re.sub(r'<[^>]+>','',ab[max(0,i-350):i+420]))"
```

写进稿子的每个数都要能指回一段原文：样本量、HR + 95%CI、对照组与干预组的事件率、关键安全性结局（尤其「严重感染增加」这类会翻转结论的）。

### 4. 判证据等级，并在稿子里标出来

同一个「大新闻」可能只有四种成色，写法完全不同：

| 成色 | 判据 | 正文怎么写 |
|---|---|---|
| 正式论文 | Crossref 有记录、EuropePMC `pubType` 是 `Journal Article` | 正常引用，可写全部预设终点 |
| 顶线公告 | 只有公司新闻稿 + ClinicalTrials.gov，Crossref 查不到结果论文 | 只写公告里明确公布的数字（主终点 HR、是否达统计学差异、明显安全性信号），**不写亚组、不写次要终点**，并在文末/评论区标「全文尚未发表」 |
| 会议报告 | 只有会议摘要，无期刊全文 | 写「会议报告」，数据加限定 |
| Letter / 通信 | DOI 是 `10.1056/NEJMc…` 这类 | 可以收，但必须写样本量和「以通信形式发表」，不能当大样本 RCT 卖 |

### 5. 组织成链，不是罗列

能站住的结构（约 1000 字）：

1. **现象**：一两句点出读者正在经历什么（身边人在抗炎），不评价、不嘲讽
2. **医学定义**：把口语词拆成病理概念（急性炎症 vs 慢性低度炎症 + 2-3 个指标名），一句「相关，不是因果」
3. **干预证据，按时间倒序或规模递进**：每次尝试写「做了什么 → 结果如何 → 代价是什么」，失败的说失败，半成功的说清适应证
4. **例外**：唯一有效的那条，同时写清它的限制（是要处方的药、只对高危人群）
5. **那什么有用**：把结论落到可执行且被验证过的做法（撤掉炎症来源 + 饮食「模式」而非「单品」）
6. **⚠️ 两条边界**：别自己吃药/补剂；指标不是诊断，已确诊的归主治医生
7. **收口一句**能记住的话，不煽情

**阴性/失败证据优先放前面**：一味堆阳性结果的稿子是宣传，读者划两屏就走；「三个几十亿美元的试验都失败了」才是让人停下来的东西。

## 不洗稿的边界

用户会拿一篇爆款文当参考（例如一篇写「抗炎人日常」的情绪稿）。

- **可以借的**：它捕捉到的现实现象、读者情绪、开头那句共鸣
- **不能借的**：它的段落顺序、句子、案例、数据、结论
- 判定标准：把参考文和成稿并排放，除开头一句现象之外，**不应有任何一段能对得上**。交付时主动说明「借了什么、没借什么」，比让用户自己比更省事

## 坑

- **主题型选题不需要 `--days` 窗口**，也不要跑 `fetch_all_sources.py`——它是按日期抓 RSS 的，与「给定主题」不匹配
- **Crossref 的 `published-online` 常常只到月**（`2026-10`），到不了日。写正文用月份+年份即可，不要为了「看起来很精确」编一个日
- **别用综述代替试验**：综述给的是「领域共识」，而主题调研要的是「哪几个试验、结果如何」，共识恰恰是被试验推翻的东西
- **数字口径看清终点定义**：主终点是 MACE、是 CV 死亡、还是含血运重建的复合终点，写法差别很大；同一试验的 HR 在不同终点下能差出十几个百分点
- 交付时给一张证据表：`试验 | 关键结果（含 HR/CI）| 期刊 | 日期 | DOI`，DOI 用 `https://doi.org/…`。用户会逐条点开核
