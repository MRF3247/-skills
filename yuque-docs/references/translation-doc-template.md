# 外文报道中译 → 语雀文档骨架

适用：用户发一篇外文报道/新闻/论文解读链接，要求「中文译文放进知识库，再建子文档存英文原文」。
目标位置：医时知识库 `liink/yishi` → 顶层分区「4. 医学资讯译文」。

## 第 0 步：取原文正文

- 先 `web_extract([url])`。若返回空正文或 Blocked 类错误（部分媒体站会命中），**直接上 `browser_navigate(url)`**：正文在返回快照的 `article` 段，完整快照自动落盘到 `~/.hermes/cache/web/browser-snapshot-*.txt`，用 `read_file` 带 offset 分页读，比反复滚动快
- 补元信息：`browser_console` 读 `meta[property|name*=author|date|title]` 拿正式标题与发布日；URL 里的 `YYYY/MM/DD` 可交叉核对
- 逐段抄全，别丢引用块与机构名；原文里的超链接保留在译文里（读者要能点回原始出处）

## 第 1 步：中文译文文档（父文档）

标题：`<核心事实一句话>（中文译文）` —— 例：「日本NIMS认定：41篇撤稿的材料学者存在“大范围”图像操纵（中文译文）」

正文顺序固定，别自由发挥：

1. `> **一句话总结**：…` —— blockquote 开头，说清「谁/做了什么/量级/后果」
2. 元信息 bullet：原文出处（媒体 + 原标题 + 发布日）、原文链接、指向英文子文档的一句指引
3. `## 译文` → `### <译后标题>` → 逐段翻译，**按原文段落顺序，不合并不重排**；术语首次出现带括号大白话（fabrication=凭空捏造并根本不存在的数据；falsification=有真数据但改成想要的样子）
4. `## 名词白话解释` —— 两列表格：名词 | 大白话+生活化比喻（撤稿/自我抄袭/自引/掠夺性期刊/PubPeer 这类圈内词一律收进来）
5. `## 这案子为什么值得关注（选题视角）` —— 3–5 条，每条「结论 + 一句机制/证据」，服务内容选题而非科普

图：语雀 API 不能传图，正文用 `*（图片：xxx）*` 占位，交付时告知用户图未搬入、可另行上传。

## 第 2 步：英文原文文档（子文档）

- 标题：`【English Original】<原文标题原样>`
- 正文：`# <标题>` → `*<媒体> · <发布日>*` → `Source: <url>` → `---` → **英文原文逐段原样**（含 markdown 超链接）→ 末尾 `*Source (fetched YYYY-MM-DD): <domain>*`
- 不做改写、不删减、不翻译；它的作用是可核查底稿

## 第 3 步：挂进 TOC

1. 两个文档 create 完都在 TOC 根级（`create_doc` 无 parent 参数）
2. `appendNode` + `node_uuid` 把中文译文挪为「4. 医学资讯译文」的子节点
3. 再套一次把英文文档挪为中文译文的子节点（`target_uuid`=中文文档 uuid）
4. 核对返回 TOC 的 `level`：分区 0 / 译文 1 / 原文 2

## 交付话术

回复里直接给「知识库 + 分区位置 + 两个文档链接」，一行一句。另说明两件用户会问的事：库是密码保护（打开需密码）、原文配图未搬入（要不要补）。
