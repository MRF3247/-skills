# benchmark-account-grading

## 何时使用

- 用户要求把账号库（B站/小红书/抖音等对标账号）按「与产品相关性」分级打标签，如 S/A/B/C/D、高/中/低。
- 用户给出飞书多维表格（/base/ 或 wiki 链接）说「给所有账号打标签，新增一列」。
- 用户要给已有账号库补充/重打相关性等级（产品定位变了、新增平台账号）。

## 分级框架（以 SciLink 医学科研产品为例）

分级依据**账号定位/内容方向**，不是粉丝量。五级定义：

| 级 | 含义 | 判定要点 | 例 |
|---|---|---|---|
| S | 科研刚需：论文/统计/生信/Meta/文献/投稿/查重/润色/科研工具/科研绘图/科研服务/AI科研 | 粉丝即潜在付费用户；内容直接解决发论文/做科研 | 解螺旋、统计之光、生信技能树、SCI论文写作、CNSknowall、AIPaperGPT |
| A | 医学人群：医护生科普/日常/临床/医考/药学/健康 | 受众与产品人群高度重合，但内容非科研工具 | 兔叭咯、丁香医生、耿同学讲故事、银成教育 |
| B | 泛科学/学术：生物/化学/科普/学术平台/科研生活 | 受众有交集（学生/研究生），间接相关 | 生物化学online、蔻享学术、毕导 |
| C | 泛知识/科技：AI/编程/升学/职场/财经/留学 | 基本不重叠 | 张雪峰、安迪讲AI、研途考研教育 |
| D | 无关：影视/游戏/娱乐/汽车/宠物/蹭名号 | 与医学科研无关 | 罗翔说刑法、新华社、柏林护士乐队 |

关键判定规则：
- 正式对标账号（有完整画像，如 redfox 回填过）**人工逐一判级**，不跑规则——这是最准的部分。
- 扩展账号用规则引擎初分 + 两轮人工修正，不要纯手工逐条打 1300 个。
- **蹭名/恶搞号清洗**：0 粉 + 名字呈「XX学家/XX科学家/XX教授/XX博士」结构 + 奇怪后缀（"多久能打开""酷狗""哈哈佛""我要上哈佛""史上最骚"）→ 归 D，不管名字多像学术号。
- 社团/乐队/学生会类账号即使带名校前缀（"北京大学医学部管弦社"）→ 归 D（非内容账号）。
- 医学考研机构（银成教育、昭昭医学考研）→ A 不是 S（受众是医学生但内容是考试非科研）。
- 泛统计教学（统计战线、概率统计小迷哥，非医学向）→ C，医学统计类 → S。
- 玩梗号（"审稿人""海拉鲁审稿人""我不要写文献综述"）→ B/C 不上 S。
- 教授/医生个人号按简介判断领域：有临床/医院背景 → A，纯基础科学 → B。

完整规则表见 `references/account-grading-rules.md`。

## 工作流

1. **解析目标表**：`lark-cli base +url-resolve --url "<wiki或base链接>" --as user` 拿 base_token；`+base-block-list` 找 table_id；`+field-list` 看现有字段（注意是否已有「是否对标」select 字段）。
2. **全量拉数据**：`+record-list --limit 200 --offset N` 循环，**同时保存 `record_id_list`**（见下方批量更新机制）——这是后续写入的钥匙，丢了就得逐条 search，极慢。
3. **分级**：规则引擎初分 → 输出各级别名单人工抽查 → 修正层覆盖 → 统计分布确认合理（D 通常占一半以上）。
4. **抽查关键账号**：对各级代表账号用 `+record-search` 读回验证（不要信本地 grades.json，读表才算数）。
5. **新建字段**：`+field-create --json '{"type":"select","name":"产品相关性","multiple":false,"options":[{"name":"S","hue":"Red",...}...],"description":"..."}'`（hue 可选 Red/Orange/Yellow/Blue/Wathet/Gray，按等级给不同色，方便视图筛选）。
6. **批量写入**：`+record-batch-update` 每批 ≤200 条，串行执行批次间 sleep 2s，payload 见 references。
7. **读回验证**：按 `产品相关性` 字段分页统计各等级数量，确认 total 一致、无未打标。

## LLM 批量评级（2026-08-15 实测 479 账号，比规则引擎更准）

规则引擎按账号名/简介关键词打分，**会误判名字有误导性的账号**。LLM 逐个分析「账号名+认证+简介+标签+最近100条稿件标题」评级更准（看内容实际做什么，不看名字）。

- **评级口径**（SciLink 医学科研场景实测）：S=科研工具核心受众（论文/SCI/统计/生信/Meta/科研绘图/基金）、A=医学相关（临床/疾病/医学生/医生日常）、B=泛健康（养生/健身/护肤/心理）、C=泛知识（科普/历史/财经/教育）、D=无关（娱乐/游戏/影视/音乐）。⚠️ 与旧版框架差异：**泛科研（材料化学/社科统计）降 C 不升 S**；纯科普（丁香医生/医路向前巍子）A 而非 S。
- **必须单条逐个分析，不要批量塞多个账号**：DeepSeek 推理模型批量 20 账号输入太大时 output 为空或丢 JSON（配 max_tokens≥4000 才稳）。实测单条约 5s/账号，479 个约 40 分钟后台跑，断点续传（结果文件 name→grade，已有跳过）。
- **JSON 解析容错四种形态**（LLM 输出不稳定）：整段数组 / 单对象 / 带 ```json 代码块 / 每行一个 JSON 对象——先整段 json.loads，失败再按行解析。
- **⚠️ 防并发覆盖**：两个分析脚本写同一结果文件会互相覆盖，症状 = 已分析计数**不增反减**。启动新脚本前先 `ps aux | grep <脚本名>` 确认旧实例已死（kill 可能没杀干净，用 pkill -f 兜底）。
- **实测打脸案例**（证明基于内容优于名字）：小小统计菌=虎扑娱乐号(D)、科研人FrankG=社科科研(C)、生信Di=医学生信教学(S)、图形科学Graphics-Sci=设计号(D)、科研云/科研论=材料化学(C)。交付前抽样校验降级/升级账号的标题。
- 208/479 账号评级变化：D→C 87、D→A 42 最多（很多名字像无关号实际有医学内容）。

## 飞书 Base 批量更新机制（踩过的坑）

- **record_id 来源**：`+record-list` / `+record-search` 返回的 `record_id_list` 数组与 `data` 数组**按位置一一对应**（CLI 把原始 API 的 record 对象拆成了两个平行数组）。zip 两数组即得 record_id→业务键映射。`+record-list` 输出默认是列值数组，字段顺序由 `fields` 给出。
- **raw `api GET /records` 的 page_size 不透传**：无论 URL 参数还是 `--params '{"page_size":200}'` 都固定返回 20 条；`--page-all` 也只拿到一页。**不要用 raw api 拉全量**，用 `+record-list --limit 200 --offset N`。
- **`--json @file` 必须是相对路径**：`@/tmp/xxx.json` 报 `invalid JSON file path ... must be a relative path within the current directory`。先 `cd` 到文件所在目录再传 `@filename.json`（或复制文件过去）。
- 批量更新 payload 形状：`{"update_records": {"<record_id>": {"产品相关性": ["S"]}, ...}}`，select 单元格值用**数组**形式 `["S"]`。
- 写 select 前确认选项已存在（`+field-list` 看 options），写不存在的选项会报类型错误。
- 单批 >200 条被接口拒绝（1254104 类错误），分片后串行执行。

## 验证

- 分级完成后统计表内实际分布（读回而非本地），打印 S/A/B/C/D 计数 + 未打标数（应为 0）。
- 抽查 10-20 个各级代表账号确认落位正确，特别是规则容易误伤的名字（如「毕导」这种无关键词的知名科普号，会被规则漏到 D，需人工修正层兜底）。

## 是否对标 三档标签（2026-08-17 实测 735 账号，用户确认口径）

「是否对标」select 字段从两档（对标/暂不对标）升级为**三档**，语义基于**用户身份**（SciLink 产品内容运营，**没有学术身份**）：

| 标签 | 含义 | 判定规则 |
|---|---|---|
| **官号对标** | 对 SciLink 官方号宣传产品有参考价值 | 相关性 S 级（医学科研工具：生信/统计/论文/期刊服务/科研服务）+ 腰部及成长高粉(≥2万) |
| **博主对标** | 对博主号有参考价值（能吸引医学生/研究生/医生） | 相关性 A/B 级中的**内容型/教学型/媒体型**账号 |
| **不对标** | 两者都无参考价值 | ①起步/尾部低粉 ②**医学身份强绑定** ③C级泛知识 |

**核心修正逻辑（用户原话）**：分享医生/医学生日常的账号 → **不对标**，因为用户没有学术身份，「那些与医学身份强绑定的没办法参考」。
- **医学身份强绑定 → 不对标**：医生本人号（刘加勇医生/皮科医生魏小博/眼科医生陶勇/卢骁急诊日记/协和手足外科陈江海/皮肤科医生张武/血管科李友山 等）、医学生本人号（边学边哭的医学生/医学汪的日常/一只奶糖鸭/kiki的医学生日记 等）、护士本人号（柱哥是个男护士/曼曼学护理 等）——靠身份吃饭，内容不可复制
- **内容型/教学型/媒体型 → 博主对标**：丁香医生、医学科普联盟、深读视频、nagi真的很文静、大物是也、耿同学讲故事、兔叭咯、Chubbyemu、医学教育徐琦、鼎湖影像、人卫医学课堂、忠保研道、营养师顾中一 等——运营方式可参考，即使内容是医学
- 实测分布：官号对标 43 / 博主对标 71 / 不对标 621（735 全量）

**⚠️ 博主对标二次收窄（2026-08-17 用户补充定位后实测）**：用户博主号定位 = **医学领域的热点/新闻/行业资讯**（不是泛健康科普），因此「博主对标」从 71 收窄到 **23**：
- **保留**：医学媒体（丁香医生/医学科普联盟/深读视频/医学边界/梅斯医学/六层楼先生/大白牛）、医学热点内容号（Chubbyemu/搞科研的K哥/徐德文科学频道/淘淘酱酱/远途安/胖胖小智智）、行业资讯号（咸鱼堡的医药海滩/杨昊天浪迹天涯/苏惜埮/医班见识/时光派官方/Emmon_石一毛）、医学专业内容（医点通/YouTube医学频道/医学学长/清宜轩）
- **降不对标（48个）**：泛健康科普（营养师顾中一/心理医生老秦/健康减重韩医生/养生知识分享/护肤变美号/健身号）、泛科普（毕导/这不科学啊science/兔叭咯）、搞笑短剧（大物是也/耿同学讲故事/疯人传の医学版）、教学机构（医学教育徐琦/鼎湖影像/忠保研道/银成教育/医路领航/昭昭/研大/迈德森/医学老师刘忠保/小凯/崔老师讲医疗 等24个）、母婴（孕产知识分享/田予桐儿童健康管理）
- **教训**：判断博主对标前先问用户博主号的内容定位——「医学资讯型博主」和「泛健康博主」的对标池完全不同；泛科普/泛健康/教学机构都不匹配资讯型博主

**字段更新**：`+field-update --field-id 是否对标 --json '{"name":"是否对标","type":"select","multiple":false,"options":[{"name":"官号对标"},{"name":"博主对标"},{"name":"不对标"}]}' --yes`（full PUT 语义，旧选项会被替换；已有记录若引用旧选项值会自动清除，需随后批量重写全部记录）

## 账号库清理：删除标准是「是否对标=不对标」，不是「评级=D」（2026-08-17 用户纠正）

**教训**：整理账号库时只删了 D 级 558 个，留下 C 级不对标的腰部大号（数学建模老哥98万/每日英语一点通66万/研途考研教育45万/师说考研考公56万/高考蓝哥53万等）。用户看到后问「我不知道你为什么会留着它们」——**这些泛知识号（考研/考公/英语/数学建模/高考/全科目速成资源）即使粉丝百万+、腰部层级，对官号/博主号都没有对标价值，应该删**。

**正确清理标准**：
- 删除依据 = 「是否对标」= 不对标（含 C 级泛知识、泛科普、教学机构），**不是**只看 D 级
- 粉丝量/层级不是保留理由——「数学建模老哥 98万」这种腰部大号，内容是数学建模教学，与医学科研/医学资讯完全无关
- 典型无对标价值账号类型：数学建模、考研考公、英语教学、高考志愿、全科目速成资源（没冇耳朵的兔子）、泛科普（毕导）、泛内容

**完整删除流程**（账号记录 + 稿件 sheet 双删，可回滚）：
1. **备份**：把待删账号的完整记录（含 record_id + 全部字段）存 `B站工作流/备份/<批次>备份_<日期>.json`
2. **删多维表格记录**：`+record-delete --json '{"record_id_list":[...]}' --yes`，每批 ≤100
3. **删稿件表 sheet**：`+sheet-delete --url <表URL> --sheet-id <sid> --yes`（先 `+workbook-info` 确认 sheet_id 与账号对应）
4. **验证**：`+table-list` 看记录数（719 = 735-16）、`+workbook-info` 看 sheet 数

**先列清单给用户确认**：批量删除前把待删账号清单（名称+粉丝+类型）列给用户，用户常会追加/缩减名单（本次用户主动列出 16 个）。**用户点名的账号必须用模糊匹配查证，不能精确匹配**：用户说「张雪峰」，表里实际是「张雪峰老师官方号」（416万头部号）——精确搜「张雪峰」显示不在表里会误判「已删除」，实际是 4 个张雪峰相关账号（官方号/高考讲座/雪峰说规划/考研和升学）全在。查证用 `+record-search --keyword <关键词> --search-field 账号名` 或本地遍历 `'关键词' in name`，把同一实体的所有变体（含官方号/讲座/考研等后缀）一次列全再删。

**删除范围以用户点名为准，不擅自扩大**：用户点名删 16 个后说「剩下的凑数也就凑数了」——159 个 C 级不对标账号（腰部38+成长121，含见医知二83万/科研云/科研论等）虽无对标价值，但用户明确不删。别自作主张扩大删除范围。

**⚠️ 验证必须重新拉取最新数据，不要用会话早期快照**：删除/更新后验证时，用会话开头拉的 `/tmp/base_records_v2.json`（回写前快照）会误报「仍有不一致」——因为快照是旧状态。验证一律重新 `api GET /records` 拉最新（存 v3/v4…），对比当前实际状态。同理 `+record-search` 读回才是真值，本地 JSON 只作参考。
