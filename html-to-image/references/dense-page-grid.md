# 多本文档的目录页 → 展示图（长横图 / 3:4 密集收集感图）

适用：用户手里有一套自产 PDF（教材、手册、白皮书、课程讲义），要求「把这几本的目录截出来」，做成能发出去的展示图。典型两个交付：一条横向长图（完整目录一览）+ 一张 3:4 密集图（小红书封面/内页，要“收获感”）。

整个流程是 PIL 拼版，不走 HTML+Chrome：页码、比例、对齐都是纯像素算术，用 HTML 只会多一层换算。

## 1. 先定位目录页，别按「第 2 页」写死

```python
import fitz
for i in range(min(4, d.page_count)):
    print(i + 1, d[i].get_text().strip()[:90])
```

判定：含「目　录 / 目录」且紧跟一行「全书 N 篇 · N 章 · N 节」的就是目录首页；**下一页若还是「第X章 / N.M」条目说明目录跨页，继续收**，直到出现「第一篇 …本篇目标」这类正文。实测一本 1–2 页目录是常态（4 本 = 7 页）。

渲染 `dpi=200` → A4 1653×2339，文件名带 `<书号>_<页号>`：后面分组、书签标签、封面格都要靠这个映射。

## 2. 长横图：按「书」分组，标签居中于该书的页组

先把页列表折叠成组（`{start, end, title, pages}`：一条记录带书名就开新组，不带就延长上一组），算标签 x 时用组的首末索引：

```python
x0 = margin + g["start"] * (pw + gap)
x1 = margin + g["end"]   * (pw + gap) + pw
d.text(((x0 + x1 - tw) / 2, margin + 8), f'{g["title"]}  ·  {g["pages"]}', ...)
```

- 每页高度写死（如 1200），宽 = `高 × 0.707`，**所有页同一高度**才对得齐。
- 页数少的书占 1 格、多的占 2 格，标签按组展宽居中，不要每页各挂一个标签。

## 3. 3:4 密集图：把格子填满，一格不留白

画布 1242×1656。先按高度反算格子，再按宽度验一次：

```python
head_h = 104                                   # 顶部标题条
gh = H - margin*2 - head_h
ch = (gh - gap*(rows-1)) // rows               # 格子高
cw = (W - margin*2 - gap*(cols-1)) // cols     # 格子宽
```

格子数取 **≥ 页数的最小方阵**（7 页 → 3×3，多出 2 格）。**空格必须用真实正文页补满，不要自制数据块或封面合图**——实测被用户连打两条：「第 8 张莫名其妙来了一页 248 页的页面很奇怪」「第 9 页的封面合集也不对」。这类图的全部说服力来自“每一格都是书里真有的页”，任何合成块都会打断这个印象。

补页怎么挑（用 `get_drawings()`，不是 `get_images()`）：

```python
rows = [(i + 1, len(p.get_drawings()), p.get_text().strip()[:50])
        for i, p in enumerate(d)]
rows.sort(key=lambda r: -r[1])      # 表格线/流程线越多，drawing 数越高
```

表格线逐条计入，实测同一本书内 163→524 能一眼排出最密的页；**`get_images()` 几乎全是 0**（书里的插图是 CSS/矢量重绘，不是位图），按图片数挑会挑空、白扫一遍。挑“你想做什么 / 用什么”“错误 / 正确做法”“你要评价的是 / 用哪个工具”这类三列速查表——视觉上最像结构化内容，和双栏目录页混排也协调。

### 关键坑：实心块必须与页图同宽同轴

页图按高度贴进格子时，它的实际宽 = `ch × 0.707`，**比格子宽小 30–40px，两侧会各留一截白**。此时若把数据块/封面框按 `cw` 画，它们就比页图宽、贴到格子边缘——整图看是“右下角那块贴着画布边”，vision 复查会报「右侧贴边被裁」，而且左右边距量出来不对称。

```python
page_w = round(ch * 1653 / 2339)      # 页图在格子里的真实宽
pad_x  = (cw - page_w) // 2           # 内容块统一缩进
# 页图、数据块、封面框全部用 page_w 宽 + pad_x 缩进
```

### 数据块（仅当用户点名要，默认不做）

上一节「每格放真实页」是硬规矩，**默认不出数据块**。只有用户明确说「要个总结格子」时才做：深色底（`#16324F`）+ 白字，三行 `248 页`（数字与单位**同一行同一字号**，拆成 132px 数字 + 60px 小“页”会被读成松散）／`4 本 · 18 篇`／`57 章 · 356 节`。数字从各书自报的篇章节实测加总，别估。

### 文案：标题由用户定，数字只说一次

顶部标题条用**用户给的短名**（如「医学科研起步SOP」），别自创长标题；副标题写领域关键词（「文献检索 · 硕博自救 · 临床研究 · 综述写作」）。**248 页 / 18 篇 / 57 章 / 356 节这组数字全文只写一次**——副标题写了数据块就别再写，两处都写会被评审为信息冗余（实测被指出）。

## 4. 验收用像素，不用眼睛

```python
a = np.array(Image.open(out).convert("L"))
cols = np.where((a < 235).any(axis=0))[0]
print(cols.min(), a.shape[1] - 1 - cols.max())   # 左右边距必须相等
```

- 左右边距不等就是有块超宽（几乎一定是上面那个 `page_w` 没统一）。实测一侧 46px、另一侧 27px，就是这么查出来的。
- 四角各 20px 内墨点应为 0。
- 成品 1500–2500px 高的 3:4 用 `quality=95` PNG。
