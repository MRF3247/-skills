# 刀客轻研标准小红书封面生成器

**一句话目标**：把「一个主题」变成一张 1080×1440 的刀客轻研标准封面（插画 + logo + 顶部白渐变 + 底部蓝渐变）。

画风、配色、封面模板、比例全部内置，**用户只提供主题**。

## When to Use

- 用户要给某篇稿子/新闻/文档配一张小红书封面
- 用户描述一个画面（「画个造假者得意、编辑追着打电话」）要出封面
- 已有的刀客轻研封面要按同一套规范重做/改构图

## 固定资产（内置于 skill，不要问用户要）

| 文件 | 作用 | 能不能换 |
|---|---|---|
| `assets/ref-set/*.png` | **画风与配色的唯一标准**（5 张官方封面：单色蓝系统、无五官人物、半透明玻璃质感、颗粒噪点）；`palette-sheet.png` 是它们拼成的色调参照板 | ❌ 不换 |
| `assets/cover-template.psd` | 1080×1440 封面模板（顶部 logo + 白渐变；底部蓝 #0073B7 渐变） | ❌ 不换 |
| 比例 | 3:4（生图 2448×3264 4K → 缩到 1080×1440） | ❌ 不换 |

> `assets/ref-style.png` 是旧版（奶油黄 + 钢蓝）参考图，**已废弃**，仅供对比；现行标准只看 `assets/ref-set/`。

脚本：`scripts/palette_check.py`（色板验收）、`scripts/finalize_cover.py`（叠封面出成品）、`scripts/hue_align.py`（仅蓝域校正）、`scripts/cover_compose.py`（调试用，打印图层与 mask）。

## 用户唯一输入

| 要 | 说明 |
|---|---|
| **主题** | 飞书文档链接 / 文章 URL / 一段话描述，任一 |
| 可选：必须出现的元素 | 谁、在干什么、印章写什么英文词 |

**不要问**：参考图在哪、用什么比例、要不要叠封面。这些已固定。
主题缺失就问主题；画面元素缺失就自己按主题提炼，并在交付时告知。

## 人物规则（遇到具体人物名字时）

用户给出一个具体人名（如「主角是李子祺」）时，**先问一句**：

> 这个名字是网上能搜到的公众人物，还是你原创/内部的人物？

| 图分类 | 做法 |
|---|---|
| **网上能搜到**（公众人物、综艺嘉宾、名人） | 自己去找 1–2 张参考图（百度图片搜「名字 + 节目名」、百度百科图册、新闻图），下载后作为第二张参考图入边；从图里读出 2–3 个高辨识特征（发型分缝 / 眼镜 / 胡须 / 脸型）写进提示词 |
| **原创/内部人物** | 请用户描述 3 个识别特征，或直接要一张参考图 |
| 用户没给名字、只说职业 | 自己按主题设计一个不指向真人的形象 |

**面部画法（强制，照 ref-set）**：**不画具体五官**——没有鼻子、没有嘴；眼睛仅靠眼镜框暗示或两点极简形状；皮肤用**极浅的灰蓝／乳白色**，不用肉色；靠头部轮廓、发型、眼镜、下颌线区分人物。头身比 1:4——1:5，头略大。提示词里必须显式写「面部不画五官：无鼻子无嘴巴，眼睛仅用眼镜暗示，皮肤用极浅蓝白，不要肉色」，否则模型会画成写实或半写实脸，跟画风打架。

**肖像提醒**：把真人画进对外发布的封面时，交付时提一句「这是基于公开图片的漫画化呈现，用之前确认一下场景」。

> **写规则前先分类**：画风 / 配色 / 比例 / 封面模板 / 文字门槛 / 安全区 = 固定项，可写死；**人物身份、职业、服装、画面内容、出现哪些字 = 内容项，永远跟主题走**，不能固化。把个案要求写成通用规则会被用户当场纠正。

## 固定规则（每次生成都必须满足）

1. **人物身份由主题决定**：画谁、什么职业、什么衣着、什么神态，全部跟着主题走（可以是医生、学生、审稿人、教授、编辑、商人……）。**不要预设身份**；用户没指定时按主题最合理的身份画，并在交付说明里写清用了什么身份。参考图里是医生不代表新图也是医生——身份变了就必须在提示词里点名写出来。
2. **配色不得偏离 ref-set 的单色蓝系统**：米白／乳白 #FDFBF1 打底，中蓝 #246DB4、亮蓝 #3A88C7、天蓝 #90BDDC、浅中蓝 #6C9DCA、浅灰蓝 #BFD4E2 层层递进，深蓝 #1250A1 只做暗部与强调；整体是**同一色相的明度梯度**，几乎不用第二个色相（红色最多做小面积印章）。明度高、干净通透、有玻璃感和颗粒。
3. **文字只渲染被要求的内容**：用户或画面脚本里明确要求的文字才出现（印章、标签、标题等），逐字照写；**没要求的一律不生成**——纸张/屏幕/胸牌上的「文字」用横线或色块占位，避免乱码和编造。
4. **安全区**：顶部 0–250px 会被白渐变淡化、800–1440px 会被蓝渐变盖住。主角的脸和核心道具必须落在 **y≈300–800** 区间。

## 流程

```
0. 读主题 → 1. 写画面脚本 → 2. 生成（档 A/B）→ 3. 色板验收 → 4. 叠封面 → 5. 交付
```

### 0. 读主题

```bash
lark-cli docs +fetch --doc "<飞书文档URL>" --doc-format markdown --as user
curl -sSL <文章URL> | head -200      # 或 web_extract
```

### 1. 写画面脚本（三行，不写长文）

- 主角：谁 + 什么职业身份 + 在哪 + 什么姿态 + 什么表情
- 配角/环境：谁在做什么 + 其他道具
- 文字道具：哪些位置需要真实文字（逐字写出，如印章 REJECTED）；其余地方一律不写

### 2. 生成（只换引擎，不换画风）

#### 档 A（首选，引擎支持编辑指令）

libtv 实测通路；其 nano-banana / qwen-edit / gpt-image edit 同理换命令即可。

```bash
libtv workspace use <文件夹id> && libtv project create "<主题>-封面" && libtv project use <uuid>
libtv upload "参考图1" -t image --resource <skill目录>/assets/ref-set/ref5-doctor-chart.png
libtv upload "参考图2" -t image --resource <skill目录>/assets/ref-set/ref2-gut-antibody.png
libtv upload "参考图3" -t image --resource <skill目录>/assets/ref-set/ref1-weightloss.png
libtv upload "人物照" -t image --resource ./face.png      # 仅当需像某个真人
libtv node create "封面" -t image --left 参考图 --left 人物照 \
  -s "model=Lib Image 2.5 Pro" -s modeType=image2image -s ratio=3:4 \
  -s resolution=4K -s quality=max -s count=1 --prompt "<提示词>" --run
```

- `--run` 是同步等待，不要外面再包轮询。
- 取图用 `data.url[]` 的 CDN 原 URL 直 curl（`libtv download` 会叠水印）。
- `算力不足 [1200000136]` = 账号没算力，换账号，降规格无用。

#### 档 B（只能图生图，如 Agent 自带生图 / seedream / MJ）

仍用固定的 `assets/ref-set/` 做参考图入边（挑 2–3 张：有人物的 ref5、有元素/质感的 ref1、ref2），提示词用下面的模板 B。色值会漂，第 3 步必验。

#### 档 C（只能文生图）

把模板 B 的【画风】【配色】段当正文提示词，并在交付时告知用户：色值只能接近，不能逐色对上。

### 提示词模板 A（小改，保留原构图）

```
保持第一张参考插画的画风、配色、光线、构图和所有物体形状完全不变，只做以下修改：
<逐条：人物身份与衣着改成 …（如参考图是医生而主题是研究员，就写明换掉）/ 道具换成 … / 某处写 …>
除此之外不改动任何东西：单色蓝系统（米白底 + 中蓝/亮蓝/浅蓝灰）、无五官的脸、半透明玻璃质感、颗粒噪点、光源与安暗关系全部不变。只渲染上面点名要出现的文字，其余位置不要任何文字。
```

### 提示词模板 B（重构构图，主题驱动）

```
以第一张参考图为唯一的画风与配色依据，生成竖版 3:4 的编辑插画。
【画风】扁平化矢量编辑插画 + 微弱立体感：形状简洁圆润、无黑色描边、用大色块分割明暗、局部柔和渐变与半透明叠压，全图铺细腻颗粒噪点；元素常有玻璃／半透明质感（球体、气泡、瓶体）。
【配色】单色蓝系统：米白／乳白 #FDFBF1 打底，中蓝 #246DB4、亮蓝 #3A88C7、天蓝 #90BDDC、浅中蓝 #6C9DCA 层层递进，浅灰蓝 #BFD4E2 做中间调，深蓝 #1250A1 做暗部与强调；几乎不用第二个色相；明度高、干净通透。
【构图】<主角/配角/空中元素，明确谁最大最靠前；主角面部放在画面中部偏上>
【人物】<谁、什么职业、怎么穿、什么神态；点名 1–3 个识别特征。若与参考图人物身份不同（如参考图是医生、主题是审稿人），必须明确写出替代后的身份与衣着>
【文字】只渲染：<这里逐个列出要出现的字，如“右下角印章写大写英文 REJECTED”>；其它位置不要任何文字，纸张内容用横线占位。
【不要】写实照片质感、粗黑描边、暗黑霓虹配色。
```

> 色号（#2B72A8）不要写进提示词：会被当正文渲染成乱码。用自然语言描述色感。

### 3. 色板验收（必跑）

```bash
python <skill>/scripts/palette_check.py <skill>/assets/ref-set/palette-sheet.png 生成的图.png
```

主色（占比前 4）**ΔRGB ≤ 25** 算对上；`25–30` 可交付，但要在交付说明里把偏差写出来（用户接受过一次 26.3）；`> 40` 必须重生或跑 `scripts/hue_align.py` 只调蓝色域。

### 4. 叠封面（必跑，这一步才成成品）

```bash
python <skill>/scripts/finalize_cover.py --art 生成的图.png \
  --psd <skill>/assets/cover-template.psd --out 封面成品.png
```

输出固定 1080×1440，已含 logo、顶部白渐变、底部蓝渐变。

### 5. 交付

报四件事：像素尺寸（成品与原图分开报）、最差 ΔRGB、用户点名的元素是否达标（数量/文字/身份）、以及叠没叠封面。用户提过的修改逐条核过再说完成（他会逐条回看）。

**固定交两份**：叠好封面的 1080×1440 成品 + 未叠封面的 4K 原图（用户常拿原图自己再排版）。传进飞书后要下载回来算 sha256 与本地文件比对，确认没传错、没被转码。

## 发布与归档（偶尔需要）

成品要放进飞书文档的分栏、或要给稿件做新闻原文截图＋马克笔高亮存证时，看 `references/publish-and-archive.md`（含完整命令与坑）。

## 后处理红线

| 别做 | 后果 |
|---|---|
| 全局 LAB 均值方差迁移 | 参考图自带灰绿，整图变绿，全废 |
| 把成图颜色映射到参考色板 | 红印章被并进深蓝，肤色变红斑 |
| 调色后不告知 | 用户拿到的是修过的，不是生成的 |

唯一可用：`scripts/hue_align.py`，只动单一色相域。

## 引擎无关的硬事实（踩过）

- `psd-tools` 的 `layer.topil()` **不含图层蒙版**。模板的渐变写在 `layer.mask` 里，必须读 mask 自己合成。
- 图层顺序：白层在蓝层之上、logo 最上；隐藏的旧底图（`ChatGPT Image ...`）直接跳过。
- **脸太具体**：默认模型会把眼睛鼻子嘴巴全画出来。提示词写死「不画鼻子、不画嘴，眼睛只用眼镜暗示」，皮肤指定极浅蓝白而非肉色；细节见「人物规则」。
- **元素数量不可控**：要求「正好 N 个」时模型不会数（实测：要 10 张纸→出 8 张；下指令补足→变 12 张；再下指令减两张→才到 10）。做法：按实测差值下「加/减 M 个」的具体指令，连做 1–2 轮；**每轮编辑后都重新数、重跑色板验收**，因为每次编辑会让色值再漂一档。
- 配色漂成「亮蓝一片」：只对蓝色域跑 `hue_align.py`（色相 175–255）拉回来，不要动全局。
- 英文印章/标签（REJECTED、RETRACTED 等）现代模型基本拼对；中文方块字作印章易乱码，中文需求优先做成“无字图案”或大字标题单独排版。
- 用户没点名的文字：模型会自己编小字（论文标题、胸牌、招牌）。提示词必须写「纸张内容用横线占位，不要自行编造文字」。

## QA 清单

- [ ] 1080×1440（叠封面后）
- [ ] ΔRGB 主色 ≤ 25
- [ ] 人物身份符合主题（没有照搬参考图的旧身份）
- [ ] 若是真人：脸部照 ref-set **不画五官**（只留发型/眼镜/脸型），皮肤极浅蓝白
- [ ] 用户点名的数量（如「十篇论文」）逐个数过，不用肉眼估算
- [ ] 视觉复核只查客观项（乱码 / 畸形 / 多指 / 文字 / 数量 / 安全区）；模型对风格的审美建议（如「补上五官」）不当作返工理由，用户规格优先
- [ ] 只出现被要求的文字，逐字正确无乱码；多余位置无文字
- [ ] 主角脸部在 y≈300–800 安全区
- [ ] 已叠 PSD（顶部有 logo、底部有蓝渐变）
