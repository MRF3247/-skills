# AI 海报分层合成（整块插画 + HTML 排版 + 视觉审核）

小红书/B站/公众号封面、方法卡、知识卡海报；AI 生图 + 大量中文文案需要精确排版的场景。用户明确要求过「分图层生成、HTML 里组合排版、用视觉模型审核审美」时必用本流程。

## 核心原则（用户实测纠正过 2 次，直接照做）

1. **AI 只出「整块视觉插画」，不出成品海报**。让生图引擎生成 3:4 插画并**在画面下方预留空白区**（提示词写明「画面下方留出约四分之一高度的干净空白区供排版文字」），文字全部由 HTML 精确排版叠加。AI 直接生成含长文案的海报 = 错字/丢文案/丑排版（用户原话「都好丑啊」）。
2. **不要抠图叠元素**。rembg（白边光晕）、白底阈值（残留黑点）、CSS multiply（主体被压暗）三种方案实测全部不干净。绕开抠图，用整块插画方案。
3. **审核用视觉模型看审美，不用 OCR 式查文字**（用户明确要求）。文字准确由 HTML 层保证，审核只评构图/配色/风格/衔接。

## 标准流程

1. **选风格**：从视觉风格家谱（Obsidian 库/医时知识库/视觉风格参考/视觉风格家谱/ 各家族 md）提取风格提示词 + 参考配色。
2. **生成插画**：libtv node create -t image，模型首选 `Seedream 5.0 Pro`（中文排版最强），`-s ratio=3:4 -s quality=2K -s count=2`（抽 2 卡）。prompt 结构 = 风格提示词 + 画面内容 + 「画面下方留出约四分之一高度的干净空白区供排版文字，高细节，无文字」。
3. **下载归档**：libtv download -n <节点>，移入 风格插画/ 目录（保留 _1/_2 抽卡编号）。
4. **视觉分析配色**：用视觉模型读插画主色调，为文字层定配色（背景色/主字色/强调色/副标色），保证上下呼应。
5. **HTML 分层排版**：1242×1656（3:4）模板，关键层：
   - 标题区**实底背板**（bandbg，不透明）——彻底杜绝背景干扰
   - 引导句**半透明圆角背板** + 左侧强调条（leadbg）
   - 封面插画→文字区接缝用 **80px 渐变遮罩**（.seam）
   - 信息卡用高不透明底（0.85-0.92）+ 左色条
6. **Chrome 导出**：headless + `--force-device-scale-factor=2 --virtual-time-budget=8000`（等 10MB 大图加载）+ 页面 file:// URL 必须完整 quote（中文路径）。
7. **视觉审核迭代**：每张图打分（10 分制），不达标按「可读性 → 衔接 → 配色 → 风格」顺序修 HTML 层；HTML 修不动再换抽卡卡2 / 重生成插画。
8. **存档提示词**：每次生成的完整 prompt 追加到 提示词存档.md（模型名+日期+结果），用户会抽查。

## 变体：客户给了 PSD 封面模板

用户提供 PSD（常见 1080×1440，含顶部白渐变 + 底部品牌蓝渐变 + logo）时，**不要重建版式、不要用 HTML 重做**，直接把插画嵌进 PSD 的图层结构里。要点：

1. `layer.topil()` 不含蒙版，纯色填充层会显示成一整片纯色 —— 形状在 `layer.mask` 里，先读蒙版行均值判断渐变方向（顶部/底部）。
2. 底图图层隐藏时，`psd.composite()` 就是正确的**覆盖层**（中部 alpha=0），插画 `alpha_composite` 上去即成品。
3. 装库走清华镜像（官方源国内超时）：`pip install psd-tools -i https://pypi.tuna.tsinghua.edu.cn/simple`。

完整命令、验收清单与坑见 [references/psd-cover-overlay.md](./references/psd-cover-overlay.md)。

## 内容设定（画什么）：从原稿取事实，不套通用形象

- **新闻/事件类稿件的配图，主角必须是文档里的当事人，不是泛化的“医生/科研人员”**。用户提交一篇文档让“按这个主题出图”时，先把文档里的当事人画像/单位/身份捞出来当参考图（飞书文档里的图用 `docs +media-download --token` 下，模糊也照用，当长相参考传给图生图）。套通用白大衣/手术服人物会被打回：“主角也不是医生啊，文档里不是有那个问题作者的画像吗”。
- **去医疗化设定**：科研诚信/拒稿/学术不端这类题材，人物穿衬衫/学者装，**不要手术服、手术帽、白大衣、听诊器**；提示词显式写“不要医院元素”。
- **叙事要带情绪对比**：用户要的不是中性记录，而是有态度的画面（如当事人抱臂得意 vs 编辑打电话焦急追赶 vs 漫天盖着 REJECTED 的论文）。做候选图时主动提一个情绪版、一个中性版。
- **盖章文字直接用源报道的措辞**（撤稿用 RETRACTED，拒稿用 REJECTED）——两者语义不同，别混用。

## 关键坑（实测）

- 提示词里写色号（如 `#0E4C4C`）会被引擎当正文渲染成乱码文字 → 颜色一律用自然语言描述。
- **要锁死参考图的画风/配色时改用编辑指令模式**：`-s model="Lib Image 2.5 Pro"`（lib-image-2.5-s）+ 「保持画风配色构图不变，只改这几处：①②③」；纯图生图会把蓝色发灰青、奶油黄发土，被用户一眼看破。规则与逐色验收见 libtv-cli「关键坑」与 `references/image-generation.md`。
- 生图引擎 OCR 原图文字不可靠（「保持原图文案不变」会丢正文）→ 长文案显式内嵌 prompt + 用【顶部】【中部】等区域标签描述位置。
- 同提示词抽 2 卡质量差异巨大（10/10 vs 7.5/10 随机出现）→ **抽卡选优是刚需**。
- bash 双引号嵌套提示词会提前闭合炸脚本（报 command not found）→ 批量用 Python subprocess 传参。
- 图生图必须显式 `-s modeType=image2image`；`-s quality` 范围因模型而异（doubao 只收 1K/2K）。
- 提示词含「人体雕像/人体」类元素 → MiniMax 审核 422（小红书平台也会拦）→ 换成纯物件（显微镜/细胞/DNA/化学器皿）。
- CSS 花括号与 Python str.format 冲突 → 模板用 `${key}` 占位 + replace 填充。
- 网页端查积分需单独登录；CLI 无积分命令 → 按「预算制」控制批量规模，或问用户。

## 什么时候**不**该分层设计

素材本身就是截图（用户给的是 N 份模板/文档/网页的截图）时，他要的是**素材排在一起**，不是海报。默认交白底、均匀间距、无装饰的整齐网格；衬板、投影、旋转、编号标签、kicker 都会被「设计感太重了，就整整齐齐拼图给我」打回。先生成一张朴素拼图给他看，他想加东西再问。拼图用 PIL 直接贴（不绕 HTML + Chrome），算术与验收见 `html-to-image` 的「多份文档/截图整齐拼图」节。

## 用户偏好（务必遵守）

- 审核用视觉模型看审美，不要 OCR 式查文字。
- 每次生成提示词存档（提示词存档.md），用户会抽查并综合意见改进。
- 时刻关注 libtv 积分；**积分用完可切 MiniMax API 生图，但必须在交付里标注图片来源**。
- 每个版本编号保存（成品/ + 风格插画/ 抽卡全留），用户自己挑选。
