# 素材入库核验与台账对账

触发：用户发素材链接/文件要求「归档到素材库」；要求核对素材库台账与目录是否一致；或对已入库条目的内容、命名、来源提出疑问。

核心口径：**画面实证 > 平台标注；规格实测不估算；台账双向对账、不擅自配对。**

配套：giphy GIF 的下载→提帧→命名流水线在 `gif-meme-collection` 技能（用户自有）。本技能管**入库前的画面核验 + 台账完整性**；两者配合——命名之前先过 §2。

## 0. 素材库位置

- 根目录 `~/Documents/素材/`：`表情包/GIF动图/`（成片文件）、`表情包/README.md`（逐条台账）、`音效/`、`视频/`、`字体/`、`参考文献/` 等。
- 「归档到素材库」默认指这里；不确定具体子目录时先问，不要新建平行目录。

## 1. 入库六步（顺序固定，每步都要能回查）

1. **去重**：先按素材 ID 对台账；用户对「是不是重复」有疑问时上 **md5 实锤**——重下用户给的完整 URL，与库内文件比 md5 + 字节数，比只比 ID 有说服力。
2. **下载**：用用户给的完整签名 URL（短链/去签名链接会偶发失败）；失败重试**同一 URL**，不换素材（见 §6）。
3. **画面核验**：三级阶梯，见 §2。
4. **信源回查**：原题/作者/来源/标签/水印，见 §3。
5. **命名**：见 §4。
6. **落库 + 台账登记 + 双向对账**：见 §5。

## 2. 画面核验三级阶梯（成本从低到高）

1. **首帧单图** —— 只用来确认「主体是什么」。单帧会把动作与姿态读错（坐/躺、爪子/戴手套的手、有无支撑物，都真实错过）。
2. **时间轴 5-9 帧** —— 确认「动作怎么变、最后停在哪」。抽帧后一条消息塞多图、按时间顺序问。
3. **可疑部位裁切 + 3 倍放大** —— 破僵局用。裁目标区域放大，问二元问题（是 A 还是 B、依据是什么）。

规则：
- **单帧读与多帧读冲突 → 以放大读裁决**；仍冲突就取中性事实命名。
- **结尾单独验**：中段姿势 ≠ 结尾姿势（实测有素材结尾主体已走出画面、末帧是空镜）。
- **规格必须实测**，不按「时长 × fps」估算帧数（帧延迟不均）；分辨率/帧数/体积都写进台账，低分辨率或特大体积要明说后果。
- **时间轴一次成图**：抽完帧用 `~/Documents/Hermes/scripts/montage.py`（真源副本 `visual-identification/scripts/gif_montage.py`）拼成一张带序号的长图，再用 `vision_analyze` 自己的眼睛一次看完整条序列——比逐帧多次问模型快、也不漏中段切场景（实测有素材中段从「桌前用电脑」切到「站着举爪」）；超宽图会被缩小，宁分 2~3 张。
- 具体命令、判读阈值、无效口径见 `references/verification-recipes.md`；逐帧位移探针 `scripts/gif_motion_probe.py`。

## 3. 信源回查与数据完整性

- 平台标注（alt 文案、标签）是**上传者/平台的二手说法**，不是画面事实；两者冲突时以画面为准，**把分歧原文写进台账**并提示「要按 X 使用请先看片确认」，不替平台圆场。
- 标签里的贬义/立场词（whip、slave 之类）不得当作内容描述写进台账，只记画面。
- 缺字段就写「原页未标注」并说明查过哪几处（页面 + oembed），**不留空、不编**。
- 「N Views」若取自**频道页**，那是频道累计量、不是本条计数：要么不写，要么加注。
- 小字/外文多次识读结果不一致 → 一个字都不写进台账，只备注「多次识读不一致、未采信」。宁可缺，不可编。
- 画面内水印/台标/版权字（第三方站名、官方 logo + ©）必须记入台账并标位置——它决定素材能不能进成片。

## 4. 命名规则

- 中文描述性名，短、可检索；名字里每个词都要能被画面支持。
- **身份/材质无实锤 → 中性事实命名**：分不出真人与仿真娃娃、认不出的人，只写看得见的动作与外形，台账里明说「既不写 X 也不写 Y」。
- **同一角色沿用库里既有写法**：定名前先查库（`ls GIF动图/ | grep <关键词>`），否则同一角色散成两处、检索不到。
- 名字与平台标注冲突时按画面取，并在台账写明分歧，给出改名选项让用户定。

## 5. 台账登记与双向对账

- 条目至少含：文件路径+名、数量、来源链接、内容描述（含动作时间轴要点）、水印、规格、适合场景、日期。
- **不写未量化结论**：「本库最大的几条」这种必须有当场扫库的排名支撑，否则删掉。
- 每批入库后跑 `scripts/asset_ledger_audit.py`（输出条目数/文件数、有登记无文件、有文件无登记、重名、体积 Top5）。
- **发现旧错位不要自作主张配对或改名**（名字像是改过名但没有实锤）：报告用户 + 给选项——用户给对应关系 / 拉源文件做 md5 比对 / 加「待核对」备注挂起。

## 6. 坑

- 下载偶发 `HTTP 000`/超时（**完整签名 URL 也会**）：同一 URL 重试即可，用循环包住、成功即 break，别换 URL 别换素材；成批下载单条可能耗 100s+，**命令级 timeout 给足（≥300s）**，否则整批在最后一条被掐断、前面白下。
- `select='eq(n,N)'` 抽帧请求的帧号超出总帧数时**静默少出图**且不报错——发问前先 `ls` 确认实际存在哪些帧文件，别按预期清单发问。
- **别用相邻帧差分判断有没有动作**：GIF 抖色噪点让差异区铺满整帧，结论必然是「全身在动」，该口径无效。质心探针只能当旁证：探测区选**颜色可区分的部位**（人脸=肤色、动物头=深色斑块；全帧暗像素会被衣物/背景稀释），阈值逐幅调（实测同一张小图暗阈值 80 零匹配、100~140 才有信号；阈值过松又会把背景吃进来），结论措辞停在「趋近静帧 / 轻摇」，**不外推成「它在摇头」**。
- 视觉模型会自信地错，且**同一帧两次读可能互相矛盾**：抽查不是可选项；小批全查首帧，可疑的抽时间轴 + 放大。
