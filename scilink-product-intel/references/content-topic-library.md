# 刀客轻研选题库（飞书表）维护规范

## 三节结构与各节用途

| 章节 | 列 | 用途 |
|-|-|-|
| 一、大类选题 | 痛点分类｜场景｜功能点｜亮点｜选题 | 跨科室通用卡点，营销向，只打痛点不做干货 |
| 二、研究类型细分 | 用户处境｜研究类型｜做什么｜痛点｜场景｜业务对接点｜选题 | 按「手里有什么资源」分处境，每条直通产品能帮到的环节 |
| 三、业务直接相关 | 功能｜业务对接点｜选题 | 按产品能力清单逐项生成，功能列先落位再写选题 |

## 填写顺序（跳步必返工）

1. **痛点 → 场景 → 功能点 → 选题**，一步都不能跳。场景写不出来，说明这条痛点还是假的。
2. **场景 = 谁 ＋ 什么时候 ＋ 卡在哪**，且必须能对上某个已确认能力。反例：「没时间读文献」是痛点不是场景；正例：「规培生在轮转间隙读，一篇断三次，读完记不住哪篇说了什么」。
3. **痛点按能力分档**：能接住 / 半接 / 接不住（分档规则见 `scilink-capability-boundary.md`）。接不住的用灰字删除线标出（`<span text-color="gray"><del>`），该行选题栏留空——空栏就是「这类只适合曝光、不挂转化」的标记。
4. **选题落点必须落在实锤能力上**；痛点范围可以比能力宽（用来共情引流），落点不行。整类都接不住的研究类型（如基础研究湿实验、病例报告）不要挂转化。
5. **选题标题不加手工编号**。用飞书原生有序列表，不要在同一条里再叠 ①②③——两套编号并存会被要求删掉。
6. 研究类型按「手里有什么资源」分类：只有科室病历 ／ 没有自己的数据 ／ 能前瞻收数据 ／ 能做干预 ／ 有实验室或影像数据。回顾性与前瞻性不是并列类型，是队列研究的两种时机。
7. 大类维度要统一（方法／产出物／流程节点三种维度混用会越加越乱，且同一痛点重复投放）；方法类（统计、机器学习、预测模型）宜降级为某个阶段下的子类。
