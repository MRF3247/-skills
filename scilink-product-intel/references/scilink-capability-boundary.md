# SciLink 能力边界（做选题 / 写文案前核）

判定顺序：**帮助文档 20 篇 > 会议纪要 > 业务对接点 / 方案文档**。业务对接点写了但帮助文档没收录的，一律标「待确认」，不得说成已有能力。

## 关键词命中 ≠ 能力存在

先 grep 本地 `产品资料/SciLink帮助文档.md`，再读**首现上下文**：

- 「权重」27 次几乎全是 learning_rate / class_weight / min_child_weight 等算法超参，**不是 NHANES 抽样权重**。
- 判断「有没有」要看该能力专有词是否为 0：校准 0、PSM/倾向性/IPTW 0、决策曲线 0、外部验证 0、样本量 0、伦理 0、注册 0、STROBE/TRIPOD/CONSORT 0、文献 0。为 0 才是真缺。

## ✅ 实锤（帮助文档写明，可直接承诺）

一键数据预分析（异常检测 / 缺失处理 / 数据质量报告）；一键智能科研（多模型批量训练）；自定义科研（相关性、二/多分类回归、二/多分类模型）；数据清洗；变量筛选（方差 / 相关 / 模型筛选 Lasso、ElasticNet）；敏感字段自动删除（姓名 / 住址 / 证件号 / 住院号等 20+ 类）；训练测试划分与交叉验证；AutoML（进化算法 / 贝叶斯优化 / 随机搜索）；ROC/AUC 与阈值选择；DeLong 检验；正类设定；混淆矩阵；学习曲线；瀑布图；线性 / Logistic / Cox / Kaplan-Meier；方法学可写「R 4.5.0 + SciLink」。

**图表种类清单（实测，别凭感觉答「能不能画某张图」）**：帮助文档收录的只有 ROC/AUC、混淆矩阵、学习曲线、瀑布图、KM 生存曲线、线性/Logistic/Cox 相关图表；**桑基图、冲积图、韦恩图零命中**。需要脚本自动排版的复杂图型（多层级冲积、每行带编号的密集图）属能力缺口：先讲缺口，再给替代路线（写代码出图 / 外部工具），不要建议用户「再多给点材料」——材料齐全不等于工具能画。

上传限制：分组变量只允许一列；每个分组标签 ≥50 条；二分类 ≤2 类；不支持非数值与时间格式（异常置空）。

## 🟡 待确认（业务对接点写了，帮助文档未收录）

选题论证 / 纳排设计、样本量依据校验、伦理与注册路径、文献检索（含「无假文献」）、论文精读与知识卡、Gap 分析、校准曲线、决策曲线、PSM/IPTW、报告规范审计（STROBE/TRIPOD/CONSORT/STARD/PRISMA）、返修辅助、写作类能力、影像特征提取。

### 文献系列：产品方自述清单（可信度＝PM 功能清单，不是帮助文档）

用户向产品方 Agent 要过一份全量功能清单，明确列出下列文献相关能力。它能让选题/教材/文案写得具体，但**仍是产品自述、未经帮助文档确认**，对外写作时挂「以产品当前版本为准」。

- 查文献：同一题中英文各查一遍，返回标题 / 年份 / 期刊 / DOI / 摘要要点
- 按条件筛：时间窗、影响因子或分区、只要核心期刊
- 引文网络：谁引用了它 / 它引用了谁 / 相似文章（找奠基性研究与来龙去脉）
- 取全文：开放获取的能拿正文
- **核验引用真伪**：给 DOI 或标题，查是否存在、作者期刊年份对不对
- 批量排参考文献（Vancouver / APA / MLA / BibTeX / RIS）、按刊物要求排版
- 论文精读卡：拆解问题、方法、图表、证据边界，**带原文定位**

**两条写文案前必须分清的红线（它们决定能不能说「合规」「可靠」）：**

1. **「库是真的」≠「它写的引用是真的」。** 「4000 万篇真实文献」只说明检索命中的条目真实；只要它还有「初稿撰写」环节，就有生成式模型编造参考文献的风险。没见到「逐条回源核验 DOI/PMID」的说明前，不得写成「不会出现假文献」。
2. **语义/主题式检索 ≠ 可复现的检索策略。** 它按疾病/方向/模糊关键词梳理脉络，但没有证据说能导出检索式、命中数、检索日期。而 PRISMA 2020 要求检索可复现，所以**不能把它写成「可作为论文方法学里的正式检索策略」**；适合写成「找方向 / 快速摸底阶段的工具」。写教材或攻略前先问产品：数据源是否覆盖中文库、检索可否导出复现——后者是硬伤。


## ❌ 明确不做

Meta 定量合并、生信 / 孟德尔随机化、网络药理学、湿实验执行、多模态（研发中）。

## 甜区与死区

- 甜区＝**数据已经在手之后**：清洗 → 基线 → 建模 → 评估 → 出图。
- 死区＝数据到手之前（研究设计、伦理注册、数据收集）与执行层（湿实验、RCT 盲法、随访管理）；病例报告、基础研究两类几乎全在死区。

## 痛点 → 选题的三道筛子

1. **场景筛**：合格的「场景」必须一句说清 **谁 + 什么时候 + 卡在哪**；只写「没时间读文献」仍是痛点，不是场景。
2. **常识筛**：自问「会不会有人不知道这事」。答案是「都知道」的，不能立选题——用户会当场质疑「这个会有人不知道吗」。
   改写成「知道但做不到」或「做了会踩什么坑」：例「只读综述会让人选错方向」可立，「要读原始文献」不可立。
3. **落地筛**：能否落到产品真能做的环节。落不到的只做曝光 / 引流，不挂转化，否则用户来了会验证失败。

### 补选题时的常见误写（逐条修）

- 把「行业惯例」写成「硬性规定」。例：期刊不规定引言引几篇，「每句断言都要有出处」才是真规则；开题报告要写「国内外研究现状」是各校模板常见要求（国自然是实锤），措辞留余地「多数院校」。
- 拒稿理由只写「没观点」不够硬：更常见的硬理由是**综述类型不符**（叙述性综述投了只收系统评价的刊，编辑直接退）。
- 涉及能力边界的选题，标「待确认」而不是直接投放。
