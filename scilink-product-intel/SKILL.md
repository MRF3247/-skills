# SciLink 产品情报查询

## 触发条件
用户问 SciLink 试用方式、免费次数、价格、版本差异、功能权限、运营活动现状等产品状态类问题（常见于内容运营选题、文案话术、用户答疑场景）。

## 核心原则
1. **产品状态问答：先查本地知识库**（用户明确指示「基于会议记录和知识库回答」）。权威源 = `~/Documents/刀客轻研内容增长/产品资料/`（会议纪要、产品简介、帮助文档、平台科研能力清单）+ `增长策略/独立方案/`（冷启动、口碑扩散）。
   **例外（审查/撰写对外文案时反过来）**：必须同时抓 `https://www.drscilink.com` 首页与该篇官方新闻稿。软文里的越界说法往往照抄官网（如「因果推断」「Vector Synthesizer」「24 小时物理擦除」「任务失败 100% 返积分」），只比本地资料会把「官网口径」误判成「文案瞎编」。
2. **区分状态再回答**：已定稿（产品侧规则，如会议5 试用账号）vs 运营活动（已确认/未落地，如会议2 招募）vs 规划中（方案文档，如 Freemium 漏斗）。必须标注状态，不夸大（用户重视准确性）。
3. **发现矛盾以会议纪要为准**：如产品简介.md 载 ¥500/年，而会议1 定价为 196/596/796——产品简介可能过时，回查最新会议确认。
4. 功能参数细节（统计方法、max_iter 等）查 `产品资料/SciLink帮助文档.md`。

## 能力边界判定（做选题、写文案、答「这个能解决吗」之前必做）

1. **以帮助文档 20 篇为准，不以业务对接点/方案文档为准。** 业务对接点里写了、帮助文档没收录的，一律标「待确认」，不得对用户说成已有能力。
2. **关键词 grep 命中≠能力存在，必须看上下文。** 「权重」在帮助文档里几乎全是 learning_rate / class_weight 等算法超参，不是 NHANES 抽样权重；某能力是否真缺，看首现上下文或直接 grep 该能力专有词（校准、PSM、决策曲线等）是否为 0。
3. **结论分三档**：✅帮助文档实锤 / 🟡业务对接点有但帮助文档无（待确认）/ ❌产品接不住。给清单时三档必须逐条列全，并写清每档条数。
4. **甜区＝数据在手之后**（清洗→基线→建模→评估→出图）；数据到手前的设计、伦理、收集，以及湿实验、RCT 盲法等执行层接不住。选题可以把这些讲成痛点引流，但**落点必须转到产品能做的环节**，否则用户来了会当场验证失败。
5. 帮助文档是短板：20 篇全在数据与建模，文献检索/写作/选题/投稿零收录。若这些能力是产品真实卖点，先提请补文档，再据此写转化型内容。
6. **能力清单分三层可信度**：帮助文档（实锤）＞ 产品/PM 功能清单（意向，可写「即将支持」，不可作投放依据）＞ 业务对接点与方案文档（意向）。拿到「X 项能力」这类概括摘要时，先数具名/未具名条数——概括摘要通常只列出五到六成，缺的部分先要完整名单，否则批量生成选题只能覆盖一部分、还要返工。
7. **跨来源口径冲突并列提出，不替产品裁决**：同一能力在不同来源说法相反时（如一处写「效应量合并」、另一处写「Meta 无定量合并执行器」），把两处原文并列交回产品确认，不要挑一个当结论写进文案。
8. 能力清单每更新一次，回头把先前标「半接/待确认」的条目重过一遍：转正的改档、仍未覆盖的保留标注，别让旧结论一直挂在新清单上。

详细能力清单与痛点→选题判定规则见 `references/scilink-capability-boundary.md`。

**产品能力全景（11 大类完整清单，2026-11-03 录入）见 `references/scilink-capability-full-list.md`** —— 覆盖面远大于帮助文档（含检索/选题/写作/投稿/产出物/文档操作/中药靶点/长期记忆），属「产品功能清单」意向层，对外承诺前须与帮助文档或产品侧核对。

## 对外文案审查（用户丢来宣传稿问「有没有问题」时）

必须按五桶逐条判、五桶全给，每条附**替换句**而不只列问题（用户要能直接改稿）：

1. **专业硬伤（最高优先级）**——术语越界，懂行的医生/审稿人一眼看穿：「因果分析」（产品只有混杂控制：PSM、RCS、竞争风险、回归；无 IPTW/DID/工具变量/中介，清单原文「不把探索性相关解释为因果」）；「估算样本量」（独立工具、须给效应量/事件率/脱落率，边界写明「不编造样本量」）；「符合期刊要求」（稿约逐刊不同）；「直接可用的交付物」（选题/写作/投稿在帮助文档 20 篇零收录，属新版技能包与官网层）。
2. **事实与资质口径**——ISO 9001 / ISO-IEC 27001 / 等保三级备案 / 互联网药品信息服务资格证：对外一律带证书编号；「信息安全管理体系认证」这种模糊说法三甲核查会追编号；该资格证管「药品信息服务」，与科研数据合规不同赛道。安全口径有两套说法时先让产品统一再写。
   - **人群规模 ≠ 产品用户数（对外最容易犯的一条）**：产品简介里的「188 万+」是**市场盘子估算**——二三级医院有论文要求的 HCP 保守取 134 万 ＋ 高校课题组硕博约 54 万（按卫健委 2024 执业医师数推算），**不是注册用户量、不是「在用」人数**。对外禁写「188 万+ 在用／188 万+ 医护生在用」，被一句「有后台数据吗」当场问穿。要引用就写「面向 188 万+ 论文刚需人群」并标是估算，或换成产品真有的数据底座（300 万篇精选文献 ＋ 4000 万篇知识底座）。
   - **凡是准备印进图里/稿里的数字，落版前回查它在本文件里的原始出处与口径**（市场规模／用户数／文献量／机构数），不要从旧文案、旧 skill 例句或记忆里照抄——转手两次后「市场估算」就会变成「用户在用的」。
3. **广告法与平台规则**——第三方测评口吻＋单一产品推荐＝商业广告，须标「广告」；点名竞品「无法完成 X」技术上站不住（通用模型写代码能做统计），改中性表述；「最致命/最容易被忽略」属极限词；「实打实能支撑三甲合规核查」是对医院做承诺。
4. **与公司合规红线冲突**——会议7 禁保证性承诺与代写一条龙；全流程闭环文案须补「不代写、不承诺录用，研究者署名与判断自负」。
5. **平台投放合规（聚光 / 蒲公英 / 千川等广告平台）**——最致命的一条：小红书把「论文、期刊、课题的代写代发与辅导」列为 P1 高危禁投（9 分、素材下线、账号冻结 30 天），而产品定位「从想法到论文投稿」正是照这个口径写的。审投放素材时还要连带查落地页二跳、私信、客服话术（规则明说这些都算推广内容）。判级、禁词、改写句与处置梯度见 `references/platform-ad-compliance.md`。

另加两件常被漏的：**产品硬限制必须在文案里披露**（分组变量只允许 1 列、每组 ≥50 例、二分类 ≤2 类、不支持非数值/时间格式；AutoML 展示模型数受套餐限制），否则用户第一次上传就报错，落差全算在文案头上。

判定表、句式降级对照与发布前材料清单见 `references/copy-review-rules.md`；各平台禁投条款、SciLink 风险矩阵与合规改写句见 `references/platform-ad-compliance.md`。

## 资质与合规口径（写任何对外文案/投稿前核，2026-11-04 更新）

权威表在 `医时知识库/产品资料/SciLink产品简介.md` 文末「资质与安全口径」节，要点：

1. **等保三级备案：已完成**（2026-11-04 产品侧确认）。2026-09 版产品简介与其冲突的「等保三级合规规划」已改。
2. **ISO 9001 / ISO/IEC 27001：仍待证书核对**。官方新闻稿称已通过，但旧版产品简介写「2026 年推进 ISO 27001 认证」。对外只写全称 + 证书编号，禁写笼统的「信息安全管理体系认证」。
3. **互联网药品信息服务资格证书**管的是向公众提供药品信息，不是科研数据合规证明，不可当科研背书。
4. **数据留存有三套说法**（PDF 口径=加密与部署、会议8=不存储删除即清、官网=沙箱+缓存 24h 擦除），对外前必须统一成一套并落到隐私政策条款。
5. 禁写承诺句：「能支撑三甲医院合规核查」「直接可用于投稿」「一键生成符合期刊要求」。
6. **「因果推断」是官网与原话口径，不是工具清单口径**：能力清单只到 PSM / 竞争风险 / RCS / 混杂调整，且明确「不把探索性相关解释为因果」，对外须降级为「因果推断取向的混杂控制」。

## 读取技巧（坑）
- 会议纪要 md 常被 read_file **误判为 binary**（实为 UTF-8 文本，含超长行/特殊字符）。改用 search_files 关键词+context 抓段落，或 terminal python 按行读取。
- 纪要文件结构：开头=结构化纪要，中间=章节概要（时间戳），后半=**逐字稿**（说话人+时间戳）。找原话去逐字稿段。
- 逐字稿是语音转写，有错字（如「早读」=「小红书」），语义以结构化纪要为准。

## 官网帮助文档（20 篇）在哪
官方帮助中心没有独立目录页，是前端页面：`https://www.drscilink.com/document/list?id=0` ~ `?id=19`，**每篇一个独立网址**（`?id=N` 直接打开第 N+1 篇，已实测）。文章内容内嵌在 `https://www.drscilink.com/js/view-Base.DeKpjsN4.js`（`documentList:[{id,name,content}]` 数组），抓正文/配图从该 JS 取最省事；配图路径 `/document/<id>-<n>.png`。
