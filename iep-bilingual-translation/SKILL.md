## When to use

用户要求把哲学百科库（IEP 词条原文存档）里的词条批量译成「逐段中英对照」版、或继续译下一篇时使用。单篇顺序做、多篇并行做。

# IEP 词条逐段中英对照翻译流水线

## 已定稿格式（勿改，库内按此格式的篇目持续增加）

对库内 `/Users/Jin/Documents/Obsidian Vault/哲学百科/IEP词条/原文存档/` 下的词条：
- frontmatter 加三行：translator: GLM 5.3 Flash｜translation_date｜translation_format: 逐段中英对照
- 第一个 H1 后：折叠译注 callout（格式说明 + GLM 5.3 Flash 署名 + 术语对照 + 人名对照）
- 第二个 H1 后：粗体「**译**：中文标题（English）」
- 每个正文段后：单行引用块「> **译**：完整译文」；章节标题（##/###/#### 均含）后：粗体「**译**：编号 中文名（English）」；「### Table of Contents」标题本身不加译行（由目录译块覆盖）
- 纯公式/图占位不译；承载自然语言的公式块/表格/图用紧凑「> **译**（表）：/（图）：/（方阵）：」转述，符号保留
- 参考文献不译（加一行保留说明）；文末作者信息整段译出
- 术语：学界通行译法，首次出现括注英文；人名通行译名；中文弯引号

## 流程

1. **单篇小文档**：自己顺序做——read_file 读全文（截断处用 execute_code 补读）→ 分批定义译文 dict（T1、T2…，键=行号）→ Python 程序化插入写回 → 自验。
2. **批量/长文档（≥3 篇或单篇 >40KB）**：delegate_task 并行，一篇一子代理，契约整段塞进每个 task 的 goal（模板见 references/contract.md），一次 4 篇；结果回来核验后再放下一批，按文件名字母序推进；每批核验后用署名标记串全文扫描统计已完成数、列出下一批候选。重派失败过的文件时，context 里注明「备份已存在不要覆盖」；曾被中断污染的文件必须先从备份逐字节还原再派。
3. **父代理必须核验（子代理自报不可信）**：跑 scripts/verify.py 对比 scratch/iep-backups 里的原件——原文零改动（保留数+顺序子序列）、translator 在 frontmatter 结束 --- 之前、译块数>0、无双重\r、总行数防爆稿、译行顺序抽查；不合格 steer 修复或自己重做。
4. 额度耗尽或用户叫停即停，汇报已完成/待办清单。额度重置后继续时，先程序化统计已完成/剩余篇数报给用户，再放下一批（用户明确要求过）。

## 坑

- delegate_task 的 goal 里不能出现尖括号占位符（会被当未展开模板拒发），写「」或圆括号。
- Python read_text() 默认 universal newlines 会把 CRLF 变 LF；内容无损、Obsidian 无碍，但若要严格保持原字节就二进制读写。写回前先备份原件到 scratch（核验与回退都靠它）。
- read_file 会截断超长行/超长文件；被截断的段落必须用 execute_code 分段补读，否则译文会缺段。
- 纯符号行（公式、对当方阵图）逐行翻译没有意义，合并成一个紧凑译块转述自然语言部分即可。
- 插入循环必须先 append 原行、再 extend 译文行；写反成「先译后原」时对照顺序全颠倒，且常规自验（保留子序列、行数、无双重\r）照样全过——自验必须加一条「每条译文行的前一行是非空原文行」。
- extend() 必须传列表：译文行包成单元素列表再 extend，传裸字符串会被逐字符展开成上万行爆稿（行数爆增数十倍）；自验加一条硬指标「成品总行数 ≈ 原行数＋插入行数」，行数异常即写入层结构性错误，从备份恢复重来。
- 自验从磁盘复核备份时必须用二进制读（read_text() 的 universal newlines 会把 CRLF 变 LF，再按 \r\n split 会得到整块一行、kept 误报为 0）；以 scripts/verify.py（字节级）为准。
- 子代理整批失败先分清两类再重派：429 限流（报错带额度重置时间，到点直接重派）；输出 token 超限（报错为 response truncated / reasoning consumed budget，长文翻译最常见，重派时在 goal 里加「每次调用只译少量段落、分多次完成」的小步指示）。两类都要先查失败篇是否被写入残稿（搜 translator 标记、看 mtime），干净才重派；查到标记即为污染：核对备份无标记后用 shutil.copyfile 逐字节还原（还原后比对字节数一致）再派。污染形态可能是「有骨架无正文」——frontmatter、译注、文末作者块齐备但段译几乎全缺，行数检查查不出来，要数段译块数是否与长原文段数匹配。
- 子代理常会自己犯错又自己从备份恢复（插错行、双重\r、frontmatter 插到结束---之后、译块前缀漏粗体）——核验不能只信自报数字，要跑脚本查全部硬指标，verify.py 已内置这些检查。
- 契约里必须带两条写入防线：①备份已存在不覆盖（备份就是原件）；②组装完毕、自验全过后一次写回，绝不写半成品——限流/中断若发生在写入后，会留下「有译注骨架但正文大量缺译」的残稿，下游清理要多花一整轮。
- 父代理的「长原文段后无译行」检查有规则内豁免：纯公式行、文献条目、图占位本来就不译。标记出现后先逐条检视内容再定性，不要直接判失败返工。
- 子代理回报里的文件路径可能笔误（如把「原文存档」写成「原件存档」）；核验一律按库内真实路径重新扫描，不按回报里的路径找文件。
