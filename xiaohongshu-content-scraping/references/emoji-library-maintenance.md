# 表情包素材库维护：查重 + 内容命名（2026-08-18 实测定稿）

库位置 `/Users/Jin/Documents/素材/表情包/`：组文件夹 `<主题>（<博主名>）`，根 README.md 逐组登记（标题/来源链接/赞/藏/分享/日期 + 快照时间）。脚本在 `/Users/Jin/Documents/Hermes/scripts/`。

## 一、查重（用户明确要求「留下清晰版删重复」，表情包博主互相搬运重复率很高）

1. **dHash 初筛**：`emoji_dedup.py`（PIL，9x8 灰度相邻比较 → 64-bit hash，hamming ≤ 阈值聚类）。
   - 阈值 **≤4 太少**（只查出 9 簇），**≤10 出 17 簇但混入误报**——dHash 会把「同系列同风格不同内容」聚成一簇。
   - 实测误报案例：负鼠三部曲 3 张不同场景（「金盆洗手/怎么又是大修/查盲审结果」）被聚成一簇；「未读洋文请放心/师夷长技读洋文」配套梗被误判重复；「一稿橙花 vs 初稿郁金香」细节不同被聚簇。
2. **逐簇人工/KIMI 复核（必须，不能直接按 hash 删）**：每簇拼对比图（`保留版|待删版` 并排，PIL 拼，标注簇号）→ KIMI 判断「内容是否完全相同」→ **只删 KIMI 判「重复」的簇**。实测 17 簇只 9 簇真重复。
   - 保留规则：分辨率优先、文件大小次之（`-w*h, -size` 排序取首个）。
   - 同组内「同图多版本」也删低清留高清（如 1154x1080 与 1200x1080 同图）。
3. 删除后**立即核对各组张数**（README 同步更新，标「去重后」）。
4. **新组下载后立即与全库快速查重（2026-08-18 实测）**：单组入库时用 `emoji_dedup.py` 阈值 **8** 只扫该组 vs 全库（排除自身组），检出命中即比较分辨率**留高清删低清**（实测：科研日记（momo）/04.jpg 1080x1080 ↔ 邪恶企鹅读研版/07-文盲歹毒学习.jpg 1110x1080，删前者）。比全库 17 簇复核流程轻量，单组场景够用；组内新下载还可能有同组重复（下载源本身混杂），一并处理。

## 二、按内容批量命名

1. **识别**：`emoji_name_batch.py <组名>... --out <绝对路径>`——KIMI 逐张看图，PROMPT 要求「≤12 汉字简短名描述内容或梗点，只输出名字」。
   - **并行提速**：按组分 4-6 路后台进程同时跑（用户偏好并行），每路一个独立 `--out`。
   - 命名质量好（实测：「诊脉诊出论文烂」「等导师回复心跳骤停」「公鸡硬装火烈鸟读研」）；偶发泛化名（如「科研表情包」）和「未命名」，收尾抽查补跑。
2. **重命名**：`emoji_rename.py <names.json>...`——原 `01.jpg` → `01-内容名.jpg`；同组重名自动 `-2` 后缀；无映射文件保持原名；目录不存在 SKIP 不创建。支持 `EMOJI_BASE` 环境变量覆盖库路径（用于临时目录验证）。
3. **收尾**：核对每组文件数（= 解析 image_count - 去重数）；README 说明栏加「文件已按内容命名（序号-内容名.jpg）+ 已全库查重」。

## 三、坑（全部 2026-08-18 实测踩过）

- **`--out` 必须绝对路径**：`--out logs/x.json`（相对）在 cwd=scripts 时 `logs/` 不存在 → 脚本跑完全部识别后 `json.dump` 抛 FileNotFoundError，**整批结果丢失**（实测 3 路 87 张命名丢失）。修复=先 `mkdir -p` 或直接用 `/Users/Jin/Documents/Hermes/logs/`。**已丢的结果可从进程 stdout 恢复**：`进程名/文件 → 名字` 逐行正则 `^(.*?)/(\d+\.jpg) → (.+)$` 重建 JSON（log 是唯一留存，别关进程）。
- **kimi-k2.5 的 `max_tokens` 必须 ≥1000**：设 200 时 API 正常返回 200 但 `content` 为空字符串（无报错），表现为全批「未命名」。默认 1500。
- **脚本顶层禁止放主流程**：`emoji_name_batch.py` 曾顶层执行 `for folder in args: ... json.dump(...)`——被 import（复用 clean/ask）时用空 args 跑一遍**覆盖输出 JSON**（实测 fix2 补跑时把 emoji_names.json 清成 0 张）。主流程必须包进 `if __name__ == "__main__": main()`。
- **批量 mv 前先验证脚本**：`EMOJI_BASE` 指向临时目录 + 假文件 + 假 names.json 端到端跑一遍（断言重命名/重名后缀/扩展名剥离/无映射保名/SKIP）。验证抓出过真 bug：名字带 `.jpg` 会被拼进新文件名（`03-不存在的组x.jpg.jpg`）→ clean 需剥离扩展名；`os.listdir` 顺序不定 → 断言要 `sorted()`。
- **下载后核对文件数**：本会话发现一组下载报 18/18 但实际缺 `18.jpg`（原因不明），重抓一次原笔记补齐即可（同 noteId 重跑 xhs_emoji_collect.py 覆盖下载，幂等）。
- **vision_analyze 在当前模型下不可用**（400 `unknown variant 'image_url'`）→ 一律走 KIMI（kimi_ask.py / kimi_ocr.py），不要反复试 vision_analyze。
- PIL：hermes venv 的 pillow `_imaging` 损坏 → 用 `uv venv` + `uv pip install pillow` 建临时环境跑 dHash（或 /usr/bin/python3）。

## 四、giphy/外部动图入库（2026-08-18 新增，用户连发 6 个 giphy 链接）

1. **下载**：`curl -sL "https://media.giphy.com/media/<id>/giphy.gif"`（用户给的长 URL 带 `v1.Y2lk` 签名参数，短链一般可用）。**⚠️ 短链偶发失败（HTTP 000 / SSL exit 35，CDN 连接不稳，2026-08-18 实测一批 4 个里 2 个失败）**：失败时改用**用户原始完整签名 URL** + `curl --retry 3 --retry-delay 3` 基本都能成；**批量下载循环必须逐条容错**——单条失败别让脚本崩溃中断（实测 g1 失败后脚本异常退出，g2-g4 根本没下载，白白多等一轮），循环内 try/except 继续、最后统一核对所有文件非空（`file -b | cut -d, -f1` = GIF）再提帧。
2. **提帧**：`sips -s format png <gif> --out <帧>.png`（macOS 自带；ffmpeg 常不在 PATH，不要依赖）。
3. **命名**：`kimi_ask.py` 逐张调用，prompt 给格式样例效果最好（「≤10字名字，如『狒狒办公看文献』」）。**坑：多图一次调用且 prompt 带「图1到图4」时，KIMI 会对单张图幻觉编造多段描述**（实测一张卫生纸图被编出 4 段「图1-图4」）——必须逐张调用；首帧描述含糊时（如「举灯探路」）再单独问一句画面细节确认再定名。
   - **批量命名后必须抽查（2026-08-18 第二批 16 张实测错 4 张）**：KIMI 首轮命名错误率不低，错误全是「脑补动作/场景」——实测「风起了赶图纸」实为伏案翻阅文件、「胖大叔整理衣衫」实为西装男整理衣衫、「指人猫」实为黄手指指猫（是手指指猫不是猫指人）。**可疑信号 = 命名含动作猜测词（起/赶/翻/指）或与图面主体风格不符**；抽查 prompt 用「用一句话描述画面内容：主体是谁？在做什么？有无文字？」单张复问，确认后修正再入库。
   - **撞名处理**：同批多张可能得到同名（实测 g09/g13 都叫「震惊猫」）——`mv` 入库前先列一遍目标名查重，第二个按细节区分（虎斑猫震惊）；`emoji_rename.py` 有自动 -2 后缀但手动批量 mv 没有，需人工处理。
4. **入库（2026-08-18 用户最后要求：gif 集中管理）**：存 `素材/表情包/GIF动图/` **子文件夹**（39 张已集中；单张动图不建组文件夹），命名 `<主题>.gif`；README 有独立 **「🎬 GIF 动图（GIF动图/ 文件夹）」小节**（每条：`**GIF动图/<文件名>**：1 张动图，来源 [GIPHY](链接)（内容描述+适用场景），日期`）。动图库条目多时用脚本把 README 的 gif 行批量移入独立小节（`- **` 前缀加 `GIF动图/`），移完核对 文件数 = README 记录数。
5. 动图命名贴合科研使用场景（「狒狒办公看文献」「被文件淹没」「碎纸机处理文件」），用户后续做动态封面/评论互动直接用。
6. **GIF ID 查重（2026-08-18 实测）**：用户连发链接时先看 ID 是否已在 README 登记过（同 ID = 同 gif）——已入库直接告知「已处理过」跳过下载（实测 wnoEutjol5ei4 = 章鱼哥震惊看文件.gif 被重复发送）；批量前先扫一遍 ID 列表去重，能省下载+命名时间。
7. **单张神图单独成组（2026-08-18 实测「论文创新点（阳小武）」9 万赞）**：单图爆款（9 万赞/2.2 万分享/4667 评）不并入其他组，单独建组文件夹 1 张，命名按梗点（创断点谐音梗.jpg），README 标 **⭐⭐ 超级爆款** + 提示评论区是素材富矿（4667 评可复制热评做选题沉淀）。
