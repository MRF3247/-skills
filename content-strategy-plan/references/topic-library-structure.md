# 选题库结构（产品账号内容选题库）

用于给产品官方账号（刀客轻研 / SciLink）建「选题库」：把「用户痛点」拆成可投放的标题，而不是散装灵感。

## 四层结构

| 层 | 字段 | 用途 |
|-|-|-|
| 一、大类选题 | 痛点 ｜ 选题 ｜ 要点 ｜ 参考笔记 | 营销笔记层：展示卖点、打直接痛点，**不做干货** |
| 二、细分选题 | 痛点 ｜ 标题 ｜ 封面文案 ｜ 首句 ｜ 要点 | 可直接拍摄：首句必须是钩子，要点 ①②③ |
| 三、研究类型细分 | 用户处境 ｜ 研究类型 ｜ 做什么 ｜ 痛点 ｜ 业务对接点 ｜ 选题 | 按「用户手里有什么资源」分处境 |
| 四、针对产品功能选题 | 功能 ｜ 业务对接点 ｜ 选题 | 依赖产品给完整功能清单，最后做 |

第三层的处境轴：只有科室病历 / 没有自己的数据 / 能前瞻收数据 / 能做干预 / 有实验室或影像数据。研究类型只保留产品真能承接的（Meta 定量合并、生信、孟德尔随机化、网络药理学做不了，不入表）。

## 场景怎么写：三筛子

场景 = **谁 + 什么时候 + 卡在哪**，缺一件就还是「痛点」不是「场景」。

- ❌ 没时间读文献
- ✅ 规培生在轮转间隙读文献，一篇断三次，读完记不住哪篇说了什么

场景写完还要过一道硬闸：**这条场景能不能对上产品的一个真实功能**。对不上的只能做品牌内容，不进这张表。

## 痛点筛选规则

1. **常识不能当选題**。见 SKILL.md「陷阱」。
2. **接不住的标出来**。产品做不到的环节（湿实验执行、RCT 执行、影像特征提取、真实世界数据导出合规）可以写进痛点博共情，但选题落点必须放回真能做的环节（选题论证、样本量、建模、出图），不承诺解决。
3. **来源可核**。任何「规定 / 标准 / 惯例」必须能指名到具体文件，拿不出就明说是举例——用户会追问「哪来的规定」，编造当场被拆。
4. **优先级按节点倒逼**：有硬时间节点 + 硬指标（职称、毕业、科室考核）> 有现成数据的；学习型内容（学机器学习）流量大转化弱，决策型内容流量小转化强。
5. **同一层只用一个维度**：方法（统计/机器学习/预测模型）、产出物（绘图/期刊）、流程节点（选题/数据）混在同级会越加越乱、重复投放。

## 科研主线（查缺口用）

查文献 → 选题 → 研究设计/样本量 → 数据收集处理 → 统计分析 → 图表 → 论文写作 → 选刊投稿 → 返修 → 基金/职称。

按主线走一遍，哪一段没有大类就是缺口。经验上最容易漏的三段：**查文献、写论文、投稿实操**（写论文往往是产品最强项却整块空缺）。

## 研究类型痛点的取材范围（每类 5–6 条）

设计类偏倚（选择/回忆/病例谱/适应证/不死时间）、样本量与检验效能、数据可得性与清洗、统计方法选配、报告规范、发表门槛。

已核可直接引用的标准：

- 报告规范：CARE（病例报告）、STARD（诊断准确性）、CONSORT（RCT）、TRIPOD（预测模型）、PRISMA（系统评价）、ARRIVE（动物实验）、STROBE（观察性研究）
- 公共数据库：NHANES 官方要求加权分析（不用权重结果会偏）；MIMIC 需认证培训；SEER 无复发与具体化疗方案
- 真实世界研究：NMPA《真实世界证据支持药物研发与审评的指导原则》（2020 年第 1 号）
- 影像组学：RQS（影像组学质量评分）、CLEAR 清单、IBSI 特征标准化

术语首次出现必须带括号白话（「不死时间偏倚（把确诊前就死亡的人算进暴露组）」这类），用户硬要求。
