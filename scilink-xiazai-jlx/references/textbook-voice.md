# 教材文风规范

目标：读起来是一个懂行的人自己写的，不是从课程转录的，也不是 AI 生成的。

## 一、删掉课程指涉

以下全部要改：

| 原写法 | 改法 |
|---|---|
| 这门课/本节课/这堂课 | 直接删，或改「这一节」 |
| 上次我们讲/前面讲过/刚才讲 | 改「前面说过」或删 |
| 讲师说/老师提到 | 删，直接给结论 |
| 我是某某讲师某某某 | 删。教材没有作者自我介绍，也不要职称 |
| 本课程共 X 大部分，第一部分讲… | 删。这是系列课导览，读者拿到的是书 |
| 各位学员 / 各位小伙伴 | 删 |
| 咱们/我们平台/小伙伴们 | 改「你」「读者」 |
| 大家一定要记住 | 删（命令式），改成陈述 |

**开头第一段最容易漏。** 录播课普遍以「各位学员大家好，我是…，本课程共…」开场，转写下来占前两三百字。写书时不能在这个位置接一句“本章将…”就算了，要把开场重写成读者的问题场景。

**原则：教材即信源。** 不引用、不转述、不背书，直接给结论。

## 二、删掉平台痕迹

见 `quality-gates.md` 的完整词表。核心：

- 平台名、品牌名、域名
- 讲师花名（如「XX 大大」）
- 平台专属方法论缩写（可能是品牌资产）
- 平台旗下工具/公众号名
- 版权方公司名

**最难查的是缩写被拆开**：

```
| **挑** | 找差异分子 |      ← 词面搜「挑圈连靠」搜不到
| **圈** | 功能富集 |
```

必须做结构级检查。

## 三、去 AI 味

### 禁「不是 A 而是 B」翻案腔

```
改前：文献检索的终点不是把文献下载下来，而是能快速获取知识。
改后：文献检索的终点在获取知识与思路，下载只是中间步骤。
```

正则：`不是[^，。]{2,20}，?而是`

### 禁提示性冒号

```
改前：### 12.5 一句话总结这个判断流程
改后：### 12.5 判断流程回顾
```

正则：`一句话总结|关键点[:：]|关键是[:：]`

### 少用破折号

`——` 计数应为个位数。表格/列表里的 `正文（Body）—— 方法` 改成 `正文（Body）：方法`。

### 禁命令式「记住」

```
改前：记住这四个字母，开题前逐条自查一遍。
改后：这四个字母，开题前逐条自查一遍。
```

保留描述性用法：`一首打油诗记住全流程`（标题）、`读者读完只记住三篇文献`（描述）。

### 禁评价性引导语

```
改前：第 8 条值得单独说
改后：第 8 条单独说

改前：第三问最关键
改后：第三问决定后面怎么做

改前：最后一条，也是全书最重要的一条
改后：最后一条
```

正则：`值得|最重要|最关键`

## 四、信息守恒

**源里没有的数字，一个都不许填。**

典型的自我欺骗：源里说「比例很高」，写教材时为了具体化，顺手填了 60%；源里说「读很多」，填了 100 篇。

规则：

1. 每个数字必须能指到源文件的具体位置（逐字稿第几讲 / PPT 第几页）
2. 修辞性举例可以带数字，但要明显是举例语气（「硬盘里存了 800 篇 PDF」）
3. 文献数字要给出处（作者 + 期刊 + 年份），能给 PMID/DOI 更好

## 五、结构

### 不照抄课程章节

课程按录制顺序（DAY01、DAY02…），教材按读者的使用顺序。

第二本书的重排示例：课程把统计学放在倒数第 4 讲，教材把它挪进「中期」篇——中期考核就要报数据分析，放到毕业篇就晚了。

**也不要把节号 1:1 搬成章号。** 录播课常整门课只有一章，章名就叫「课程目录」，十几节平铺，没有任何分组。若把十节写成十章，读者对照课程目录会发现完全一样，一看就是转录。

先查真实分组再定结构：

```python
get(f"{API}/edu/courses/{UUID}/lessons")   # 每节带 chapter / lesson_chapter 字段
```

`chapter.uuid` 相同就是同一章；只有一章且标题无意义时，分组信息为零，必须自己按认知顺序重新分层。

**处理时长极不均的节。** 同一门课里常有 6 分钟的节和 37 分钟的节。直接一节课一章会撑不住，处理方式是并进相邻章，但内容不能丢——短节往往回答的是“为什么要做这件事”，适合当开场动机。

### 层级

篇 → 章 → 节，三层。节以下用加粗小标题或列表，不再编四级编号。

### 每章要有可执行物

清单、检查表、不合格信号。纯讲道理的章节读者读完什么都留不下。

## 六、配图

**全部重绘，绝不用课程截图。**

理由有两条：版权，以及「像课件」的观感会暴露来源。

做法：HTML/CSS 线框风 → Chrome `--force-device-scale-factor=2` 渲染 → PNG 1920px 宽。

颜色统一用：主色 `#12202e`、辅色 `#2f5f8f`、强调 `#8a4b2f`、浅底 `#f7f9fb`。
