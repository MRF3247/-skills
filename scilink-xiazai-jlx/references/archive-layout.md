# 项目归档结构

每本书一个项目文件夹，放在：

```
/Users/Jin/Documents/刀客轻研内容增长/教材项目/
```

## 铁规则：直接在项目文件夹里生产

**新课程不要先下到 `~/Downloads` 再搬到项目。** 一开始就把下载输出指向项目的 `06_原始视频/`，所有中间产物也落在项目内。

```bash
A="/Users/Jin/Documents/刀客轻研内容增长/教材项目"
dir="$A/03_课程名"
mkdir -p "$dir"/{00_成书,01_教材源/插图和源,02_逐字稿,03_PPT帧OCR/帧图,04_审查记录,05_脚本,06_原始视频,07_原始音频}
cd "/Users/Jin/Documents/Open Programs/jlx-download"
.venv/bin/python download_course.py --course <UUID> --out "$dir/06_原始视频"
```

好处：不用搬、不用二次校验字节数、不会漏文件（之前就漏了 947 张帧图，因为它们在双层嵌套目录里）。

旧项目的 `~/Downloads` 原件确认归档后可删；新项目根本没这一步。

## 单个项目的标准结构

```
<书名>/
  00_成书/          最终 PDF（全书 + 分篇）
  01_教材源/        md 源文件 + 插图 PNG/HTML
  02_逐字稿/        NN_proofed.json（校对版）+ NN.json（原始）
  03_PPT帧OCR/      NN_slides.json + 帧图（如体积可控）
  04_审查记录/      自查说明、整改清单、外部审查意见
  05_脚本/          该项目专用的生成脚本
  README.md         项目说明：素材来源、生产参数、文件对应关系
```

## 体积控制

| 类型 | 体积 | 默认归档 |
|---|---|---|
| 成书 PDF | 3-6MB | ✅ |
| md 源 | 几百 KB | ✅ |
| 逐字稿 json | 4MB | ✅ |
| PPT 帧图 | 200-300MB | ✅ |
| 音频 wav | 900MB | 用户要封存时 ✅ |
| 视频 mp4 | 0.7-4GB | 用户要封存时 ✅ |

默认只记视频音频的绝对路径；但用户明确说「要打包封存」时，**必须把视频与音频也复制进项目文件夹**，否则封存件不完整。完整归档约 5-6GB/两本。

### 复制工具坑（macOS）

系统自带 rsync 是 2.6.9（2006 年版），**不支持 `--info=progress2`**：报 `source ... directory`，然后**一个文件也不复制，却返回 exit code 0**——看起来成功，实际是空目录。

```bash
# 错：静默失败
rsync -a --info=progress2 "$SRC"/*.mp4 "$DST/"

# 对
cp -p "$SRC"/*.mp4 "$DST/"
```

复制完必做逐文件字节数比对，不能只看目录非空：

```bash
for f in "$SRC"/*.mp4; do
  b=$(basename "$f")
  [ "$(stat -f%z "$f")" != "$(stat -f%z "$DST/$b")" ] && echo "✗ $b"
done
```

## README 必含

1. 书名、版本、页数、章节结构
2. 原始课程：UUID、课程页 URL、节数、时长
3. 素材路径对照表（视频 / 音频 / 逐字稿 / 帧图，绝对路径）
4. 生产参数（抽帧阈值、校对批量、OCR 过滤线）
5. 出书流程命令（能一键重建）
6. 已知局限（未验证项、保留项）

## 分类原则：什么进项目，什么不进

判断标准只有一条：**打包封存后能不能不看别处就复现这本书**。

| 材料 | 进项目 | 理由 |
|---|---|---|
| 成书 PDF | ✅ `00_成书/` | 交付物 |
| 章节 md + 插图 | ✅ `01_教材源/` | 内容本体 |
| 逐字稿 json（原始 + 校对） | ✅ `02_逐字稿/` | 信息溯源的唯一依据 |
| PPT 帧 OCR json | ✅ `03_PPT帧OCR/` | 核对教材数据时的证据 |
| 帧图 jpg | ✅ `03_PPT帧OCR/帧图/` | 体积可接受（200-300MB） |
| 审查记录 / 整改清单 | ✅ `04_审查记录/` | 证明质量经过检查 |
| 项目专用脚本 | ✅ `05_脚本/` | 能重建 |
| 原始视频 mp4 | ✅ `06_原始视频/` | 封存后唯一母本 |
| 原始音频 wav | ✅ `07_原始音频/` | 转写输入档 |
| 通用工具脚本 | ❌ | 在 skill 的 `scripts/` 里 |
| 中间产物（临时 HTML、合并前 PDF） | ❌ | `/tmp` 里，可重建 |
| 营销物料（小红书封面、目录拼图） | ❌ | 另存，与教材本体无关 |

**视频音频要复制，不要只记路径。** 用户要的是能整体打包封存的文件夹，链接或路径说明在换机器后就失效了。

## 归档执行步骤

### 1. 建骨架

```bash
A="/Users/Jin/Documents/刀客轻研内容增长/教材项目"
P="$A/01_书名"
mkdir -p "$P"/{00_成书,01_教材源/插图和源,02_逐字稿,03_PPT帧OCR/帧图,04_审查记录,05_脚本,06_原始视频,07_原始音频}
```

序号用两位数字，保证按字典序就是阅读顺序。

### 2. 大文件用 cp，不用 rsync

macOS 自带 rsync 是 2.6.9，**不支持 `--info=progress2`**，会报 `source ... directory` 并一个文件都不复制。

```bash
cp -p ~/Downloads/<课程>/*.mp4 "$P/06_原始视频/"
cp -p <工作目录>/audio/*.wav "$P/07_原始音频/"
```

超过 1GB 用后台进程跑，跑完通知。

### 3. 逐文件校验字节数

复制完必须验，不能只看文件个数：

```bash
fail=0
for f in "$SRC"/*.mp4; do
  b=$(basename "$f")
  s1=$(stat -f%z "$f"); s2=$(stat -f%z "$DST/$b" 2>/dev/null || echo 0)
  [ "$s1" != "$s2" ] && { echo "✗ $b"; fail=$((fail+1)); }
done
echo "不一致: $fail"
```

### 4. 写 README

每个项目根目录一份，写清：课程 UUID、素材路径表、生产参数、重建命令、已知局限。

总目录再放一份 `README.md` 做索引。

### 5. 打包（用户确认后）

```bash
cd "$A"
zip -r "01_书名_封存.zip" "01_书名"
```

mp4/wav 已压缩，zip 压缩率极低；走网盘直接传文件夹更快。

## 删除源文件前先查这四类

归档完不要立即删原目录，先确认：

| 检查 | 后果 |
|---|---|
| 脚本里是否硬编码了工作目录路径 | 删了 `sskt_book/book/` 等目录，`build_*.sh` 直接跑不起来 |
| 是否有项目里没收录的东西 | 例如 `course_index.json`（扫课结果）、`token.txt` |
| 桌面是否还有营销物料 | 小红书封面、目录拼图不在教材项目里 |
| 原目录里是否有旧版本 PDF | 容易和归档版搞混 |

安全顺序：**先复制 → 验字节数 → 写 README → 再删源**。
