# 解螺旋课程 → 原创教材 全流程

（用户内部叫法：scilink-xiazaiJLX。skill 命名只允许小写，实际名 `scilink-xiazai-jlx`。）

已购课程 → 原创教材，配套素材（逐字稿、PPT 帧、OCR 文字）全程留档可追溯。

**凭证**：`credentials/login.txt`（账号密码）、`credentials/token.txt`。脚本自动读，**不在对话里打印明文**。

---

## When to Use

触发条件（任一）：

- 用户说「下载解螺旋课程」「把这套课做成教材」「课程转书」
- 用户给了 `helixlife.cn/edu/courses/<UUID>` 链接
- 要重建已有教材（改封面、改目录、改文案）
- 要查教材里的平台痕迹、编造数字、AI 表达
- 要决定先做多门待处理课中的哪一门（先估体量、查重叠，再把选项交用户拍板）

不适用：其他平台的课程（登录与下载接口不同）；纯文档转 PDF（用 md2pdf 即可）。

## 0. 开工前：估体量、查重叠、定选题

新课到手，先做三件事再动工。

### 估体量

| 指标 | 换算 |
|---|---|
| 逐字稿字数 | 课时长(h) × 2 万字 |
| 教材字数 | 逐字稿 × 1/6 |
| 转写耗时 | 音频时长 × 1/6.5（CPU，8.4 小时音频约 87 分钟）|

照这个估，才不会转写完才发现工作量是前三本的总和。

批量取视频时长用 macOS 原生的 `mdls`，比 ffprobe 兼容性好（精简版 ffprobe 不认 `-show_entries`）：

```python
subprocess.run(["mdls", "-name", "kMDItemDurationSeconds", "-raw", f])
```

### 查重叠

同一平台、同一批受众的课，内容必然交叉。开工前先建对照表：

| 新书节点 | 与哪本重叠 | 角度怎么切 |
|---|---|---|

三条切法：

1. **初级 vs 进阶**：检索类内容，一本讲「怎么搜到一篇」，另一本讲「综述要穷尽到什么程度、怎么保证不漏」。
2. **场景分开**：降重，学位论文有查重率红线，期刊投稿看润色重点。
3. **只讲方法不讲平台**：工具类内容两本都去品牌化。

不建表就写，成书必然整章重复，审稿方一眼看出来。重叠表写进项目 README，写教材时对照。

### 定选题由用户拍板

多门课排先后时，给体量对比 + 推荐顺序 + 理由，但**做哪门由用户定**。体系衔接更顺不等于他会选它——推荐完停下来等确认，不要自己开工。

## 1. 登录抓 token

```bash
cd "/Users/Jin/Documents/Open Programs/jlx-download"
uv venv --python 3.11 .venv
.venv/bin/pip install aliyun-python-sdk-vod aliyun-python-sdk-core requests \
  -i https://pypi.tuna.tsinghua.edu.cn/simple
.venv/bin/python jlx_login.py
```

camofox 开登录页 → 读 `credentials/login.txt` 填表 → 抓 token 写 `token.txt`。只打印「已填表 / 结果 / token 长度」。

> ⚠️ **每次批量下载前先重登。** 隔夜 token 能通过认证，但会话状态已失效（老化，或被别的登录顶掉）——同一门课会部分节能下、部分节报「无权限」。实测旧 token 8 节只 1 节能过，重登后 8/8 全过。详见 `references/auth-and-token.md`。

### 最大的坑：两个 token

| 来源 | 行为 |
|---|---|
| `localStorage.token` | 新购课常报「该视频您无权限观看」 |
| `document.cookie` 的 `token=` | 网页实际使用，权限完整 |

登录后**轮询 8 次 × 2 秒**等 cookie 写入，优先 cookie，不回退 localStorage。

另一个坑：**任何一次 `jlx_login.py` 都会作废旧 token**。所以：下载前登一次，之后到任务结束**不再登录**。排查时连续跑会登录的脚本，会把正在下载的任务反复踢下线，表现成「有的节能下、有的节不能」，很容易误判成权限问题。

`play_auth` 返回 `400003 无权限` **不能**用来断言「这门课没买」——同一 token 同一节重测会翻成 `20000`。下购买结论前，必须先用真实浏览器验证网页能不能播，做法见 `references/auth-and-token.md` 的「验证网页到底能不能播」。

## 4-5. 抽音频 + 转写

```bash
ffmpeg -i 01.mp4 -vn -ac 1 -ar 16000 -c:a pcm_s16le 01.wav
cd "/Users/Jin/Documents/Open Programs/funasr"
.venv/bin/python batch_transcribe.py <wav目录> <输出目录> "<热词>"
```

FunASR 输出 `01.json`（`text` + 分句时间戳）。

### 热词必须按课程定制

第三个参数是热词。脚本里的 `DEFAULT_HOTWORDS` 是按文献检索课定的，换课直接沿用等于让 ASR 猜。

热词 = 这门课反复出现的**术语、平台名、工具名、缩写**：

```bash
# 综述写作课
HOT="综述 叙述性综述 系统评价 Meta分析 循证医学 PubMed 知网 CNKI
     Web of Science Embase Cochrane 文献管理 EndNote Zotero
     影响因子 投稿 修回 审稿 同行评议 提纲 摘要 关键词 参考文献
     润色 降重 查重 重复率 检索式 主题词 自由词 MeSH"
```

听错一个词，校对阶段要多改十几处；热词写对，校对批量和返工都少。

### 转写跑着的时候别干等

转写 10 小时音频要一个多小时，抽帧/OCR 也一样。这几个长任务一律丢后台（`notify=true`），期间去做：

1. 把进度表、重叠对照表、**教材结构草案**（哪些课合并成哪一章）写进项目 README
2. 结构草案在对话里给用户看一眼再动笔，比写完 3 万字才发现重组方向不对便宜得多

## 6. DeepSeek 校对

**分批上限 3000 字 / 150 句**。6000 字会撞 `max_tokens` 截断，整批 JSON 解析失败并静默回退原文。

典型修正：`解罗旋→解螺旋`、`深性研究→生信研究`。

## 9. 页面文字反校

两个不同方向的反校，别搞混：

| 方向 | 工具 | 作用 |
|---|---|---|
| PPT 文字 → 逐字稿 | `proofread_slides.py` | 修 ASR 错字，三道闸门（长度差 / 字符重合率 / 术语白名单）|
| 逐字稿 + OCR → 教材 | 手动检索 | 查教材有没有编数字、偏离原意 |

第二个方向是出书后的必做项，方法与双源顺序见 `references/quality-gates.md` 的「反校」一节。只查 OCR 会大量误报：PPT 图多字少（约 1 万字），术语常只在讲师口述里（逐字稿 7-8 万字）。

## 10. 写教材

### 硬规矩

1. **教材即信源**。删光「课程 / 讲师 / 这门课 / 上次我们讲」，直接给结论。
2. **平台痕迹清零**。品牌名、讲师名、专属术语、旗下产品名、专属方法论全不留（见下方清单）。
3. **去 AI 味**。禁「不是 A 而是 B」、禁提示性冒号、少用破折号。
4. **信息守恒**。源里没的数字不许自己填。宁写「比例很高」，不编「60%」。
5. **配图全部重绘**。HTML/CSS + Chrome 2x，绝不用课程截图。
6. **必顶植入刀客轻研宣传**（反方向的要求，见「产品植入」一节）。

### 平台痕迹清单（每本必扫）

除品牌名和讲师名，**产品名和专属方法论每本不一样，必须逐课开发**：

| 课 | 额外要清的 |
|---|---|
| 文献检索 | 挑圈连靠、三十六册、二十四型、仙桃学术 |
| 硕博课题 | 三五三、疾型模法标、祖传宝贝、酸菜 |
| 综述写作 | 综述工作台、NewIdea、PopMed、角蛙、深性/生信篇 |

这三门课里都踩过同一个坑：**讲师会用大篇幅推荐自家课程体系和 AI 工具**。综述写作课的第 07 讲整段推「三十六册文章套路全解」、第 13 讲全程演示「综述工作台」的按钮流程。这两类段落**不是润色能解决的，必须整段删或重写**：

- 课程推荐段 → 整段删，只保留真正的阅读方法
- 工具演示段 → 改写成方法论：AI 能帮哪几步、哪些必须自己做、生成的引用怎么核。**具体按钮和界面一概不写**

写完扫一遍：`解螺旋|尤里卡|helix|讲师名|学员|咱们|这门课|工作台|NewIdea|扫码`，应为零。

### 产品植入（刀客轻研）

**每本教材都要有，不能漏。** 这是用户明确要求的商业目的，不是可选项。

与「平台痕迹清零」不矛盾：清的是**别人家**的平台（解螺旋），植的是**自己家**的产品（刀客轻研 SciLink）。

**位置怎么选**：找与「效率 / 工具 / AI / 少走弯路」相关的章节，那里提得最自然。综述写作这本放在第十五章「AI 能帮到哪一步」的末尾，单开一节「一个现成的起点」。

**写法三条**：

1. **讲定位，不讲神器**。说清它把哪几段串成一条线（选题→检索→统计→写作→投稿），不要用「一键生成」。
2. **绝不贬低 AI**。不能写「AI 做不到 X，我们能做到」，用户已经明确反对这个卖点。正确角度：AI 能做的事它做得更稳，因为检索带来源、统计留参数、生成内容可追溯。
3. **卖给对的人**。目标读者是不熟统计、又需要拿出规范底稿的医生和学生。卖点是**稳定可重复、像顾问交上来的正规底稿、门槛低**，不是「智能」。

一段可复用的写法：

> 上面这套流程自己搭也能跑，代价是要花时间拼工具：检索在数据库，管理在文献软件，统计在 SPSS，写作在 Word，中间靠手工搬数据。
>
> 如果想把这几段串成一条线，可以用现成的科研 Agent 平台。刀客轻研（SciLink）把选题、文献检索、统计分析、写作辅助、投稿准备连成一条链，每一步都留可追溯的底稿。它不替你做判断，也不替你读文献，做的是把你已经想清楚的事更快落到文档里。对不熟悉统计、又需要拿出一份规范底稿的人来说，这个差别比「能不能自动生成」更实际。

**封面封底的二维码文案另算**：那是固定投放位，每本都一样，用户要求保留，不算平台痕迹。

### 结构重构，不照抄章节

课程按天排（DAY01-14），教材按读者时间线重组。第二本把 14 天改成「起步 / 开题 / 中期 / 毕业 / 发表」五篇 15 章，并把统计学从毕业篇挪进中期篇——中期考核就要报数据分析。

## 11. 出书

```bash
H2_BREAK=1 .venv/bin/python md2pdf.py 全书.md _body.html   # 每章另起一页，篇标题与首章同页
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless \
  --disable-gpu --no-pdf-header-footer --print-to-pdf=/tmp/body.pdf \
  "file:///绝对路径/_body.html"
.venv/bin/python make_toc_sskt4.py     # 目录装箱
.venv/bin/python merge_sskt.py         # 封面+目录+正文+封底
.venv/bin/python add_toc_links.py      # 书签 + 跳转
```

### 正文分页（用户两次纠正过的排版规则）

```
篇标题（h1） → 与本篇第一章同页
章标题（h2） → 每章另起一页
```

篇标题单独占一页只剩一行字、下半页全空，用户嫌丑。改成篇标题下直接接第一章。

「紧凑」这个词他只用来指目录，不指正文——正文要松，每章另起页。

md2pdf.py 用 `H2_BREAK=1` 环境变量控制：

```python
if os.environ.get("H2_BREAK"):
    CSS += """
h1 { page-break-before: always; break-before: page; }
h1:first-of-type { page-break-before: auto; }
h2 { page-break-before: always; break-before: page; margin-top: 0; }
h1 + h2 { page-break-before: avoid; break-before: avoid; margin-top: 20pt; }
"""
```

第四行是关键：`h1 + h2` 选中的是紧跟篇标题的那个章，取消它的分页。少了这行，篇标题仍会单独占一页。

### 目录三条硬要求

1. **只到节**（12.1 xxx），不展开知识点——用户明确嫌弃罗列太繁琐。
2. **不许留尾巴**。CSS `column-count` + `break-*` 在分页时不可控，必然出现某页只一两条。改用 **Python 加权装箱**（part 1.9 / ch 1.65 / sec 1.0），算容量分配，末栏权重 < 6 并回前一栏。
3. **可点击跳转**。从正文 PDF 定位标题页 → 目录页 `search_for` → `insert_link(LINK_GOTO)`。逐个反查目标页文字，验证 0 错跳。

### 出书硬坑

> 目录装箱算法、书签层级、分页参数、改名同步、成品体检的完整细节见 `references/book-assembly.md`。

1. **f-string 里不能有反斜杠**（Python < 3.12）。`f'{re.sub(r"^第..篇", "", t)}'` 直接 `SyntaxError`，整个脚本加载失败，连 combine 都不跑，后面每一步都报同一个错。把 `re.sub` 提成变量再插值。
2. **改完正文必须重跑目录**。目录是从 md 解析出的静态 HTML，改了节标题不重跑 toc，PDF 里挂的还是旧标题，跳转也定位不到。
3. **PDF 书签层级不能跳级**。某条 part 定位失败时，书签从 L1 直跳 L3，`set_toc` 抛 `bad hierarchy level`。写书签时兜底：`lvl = min(目标层级, 当前最大层级 + 1)`。
4. **PART 编号要跨栏连续**。计数器放在 render 函数外，否则每栏都从 PART 1 重新数。
5. **分栏页数按条数估，不按权重和**。`n_cols = 2 if len(entries) <= 95 else 4`；用权重和判断会误判成 4 栏，结果第 2 页只有 6% 内容。
6. **栏末不能是篇/章标题**。装箱后检查每栏最后一项，若是 `part`/`ch` 就搬到下一栏开头，否则标题孤悬栏底。

### 封面

**二维码文案全套固定，每本都一样，不要重新征询。** 系列内每本只改书名，这三行原字不动：

```
主标：扫码添加客服，立即接入最先进的科研Agent
副标：添加客服，限时送Token，助你科研起飞
网址：ag.scilink.link  →  href https://ag.scilink.link/
```

注意是「**助**你科研起飞」，不是「祝你」。封底用同一套，不要一面写 A、一面写 B。

**但这套文案是用户定的，不能擅自改。** 审方提出法律风险（如「最先进」属广告法禁用的绝对化用语）时，把风险和替代方案列给用户，由他定；定完三本一起重跑封面，不能只改一本。

**网址链接**：HTML 写 `<a href>`，Chrome 打印时**自动转成 PDF 链接注解**，别再手动 `insert_link`，否则重复两条。

**输出路径务必核对**：`make_cover_sskt.py` 曾错写到第一本目录，覆盖了另一本书的封面。新建一本时，先确认脚本里的 `out` 指向本项目 `00_成书/` 或项目根目录。

## 质量闸门（出书前必跑）

1. **品牌痕迹**：词面 + 结构级双查（缩写可能被拆成表格单元格）
2. **AI 表达**：破折号、不是…而是、提示性冒号、命令式「记住」、评价性「值得」
3. **信息守恒**：每个数字都能指到源文件具体位置
4. **术语全称**：HAMD / BDI / PSM 这类缩写首次出现必须带中文全称，零基础读者看不懂字母
5. **统计验算**：每个换算与临界值都跑脚本验证（OR↔RR、Cohen 标准、置信区间跨无效值）
6. **产品植入**：正向检查，必须命中「刀客轻研」或「SciLink」至少一次。**这条与第 1 条方向相反，不能一刀切删光**——删的是解螺旋，植的是自家产品

前五条要求全为 0，第六条要求至少 1。漏了第六条不算过。

详细扫描脚本与反校方法见 `references/quality-gates.md`。

成品体检一条命令跑完（闸门 + 目录跳转反查 + 分页核查，全部 ✓ 才算过）：

## 外部复核（Kimi 等）

**直接给项目路径 + 读取指南，不要打包。** 审方可以读本机项目文件夹，打包是多余动作，而且有真实代价：改一版要重打一次、容易漏文件、书改名后压缩包里的路径又失效，审方拿到的是旧快照。给路径则永远是当前版本。

### 读取指南要写清四件事

1. **只读哪几个目录。** 项目里 `06_原始视频`（上 G）、`07_原始音频`、`03_PPT帧OCR/*.jpg`（几百张帧图，上百 M）审核用不上，明确说「不要碰」。
2. **每个 json 的字段结构。** 逐字稿有 `text`（FunASR 原始，有同音错字）/ `text_proofed`（校对后，**查出处用这个**）/ `segments`（分句带时间戳）。不交代字段，审方会读错版本，然后报一堆假的无源。
3. **哪些文件是重复的。** `全书.md` 是各篇 md 的拼接，说了才不浪费它的上下文。
4. **本次已知情况**：哪处是无源补写及原因、哪处是设计要求（如产品植入位）、哪段已删。不交代，审方会把你的自查结论当新发现重报一遍。

### 给审方的指令要收窄

说清重点核什么（信息守恒 / 结构一致性 / 统计准确性 / 平台痕迹），不要只说「审一下质量」。范围越窄，命中的越硬。

### 审方的结论必须逐条验，不能照单执行

实测审方会犯三类错：

| 类型 | 表现 | 处理 |
|---|---|---|
| 算术误判 | 表格各项求和不等于文案，被判成「口径冲突」 | 自己重算，再决定改表格还是改文案 |
| 转述失真 | 把「大约三个月到半年」读成「必须三个月」 | 回逐字稿核原话，按原话定 |
| 体例误报 | 说各篇小结格式不统一 | 回查实际结构，不存在就不改 |

反过来，它抓对的地方往往很硬：换算公式（OR↔RR）、年代错误、工具名张冠李戴。**逐条验，对的改、错的驳回并说明理由。**

### 旧产物要清

改名或大改后，桌面和 `00_成书/` 里会残留旧包、旧名 PDF。审方拿到哪份看运气，自己下次也容易拿错。重建完顺手删，并在交付时说明「只留了一份」。

## 一个汇报口径的坑

统计校对效果时，**词频净减少量 ≠ 术语替换量**，不能混着报。

实测：「实验」319→288（净减 31）、「试验」51→56（净增 5）。真正的「实验→试验」只有 **5 处**，其余差异来自 ASR 断句重写和 `text` / `segments` 两个字段长度不同（差 156 字）导致的对齐缺口。

报了「修正 31 处」，被审方用三种方法核出只能坐实 1 处。正确口径：分开报两个词频，替换量靠逐段对齐确认，不靠相减。
