# Obsidian 读书导读生成 Skill

把一本源 `.md` 电子书加工成 Obsidian 读书知识库成品：拆分原文层、撰写九问问题链与正式导读、生成知识全览、跑自动验证。本 skill 合并并**取代**库内两份旧交接文档（《导读工作交接提示词.md》《读书导读生成-完整交接Prompt.md》——两者均含失效路径与互相矛盾的规则，不要再读它们）。

## When to Use

- 用户上传一本书的源文件，要求生成导读 / "继续处理这本书的导读工作"
- 用户要求为已有书补写知识全览，或排查已有成品的验证问题
- **Don't use for**: 回头"修复"历史旧格式书目——库内三代格式并存，本规范只约束新产出的书

## 核心事实（先读，防止踩失效路径）

- 读书库真实路径：`/Users/Jin/Documents/Obsidian Vault/读书/`。旧文档里的 `不卷/读书`、`/sessions/xxx/mnt/...` 全部失效。
- 每本书一个文件夹，成品根层**只有三样**：`导读《书名》.md`、`《书名》知识全览.md`、`原文/`。
- 原文文件命名：`原文 NN 章节名.md`（两位零填充，从 00 连续递增）。
- 书名中的引号等易混淆字符在文件夹名中替换为下划线（先例：`《_绝对_的制图学》`）；文件夹名、导读文件名、frontmatter `book` 字段三者保持对应。
- **源文件只读**：开工先记录 SHA-256，收工复核一致。绝不修改/移动/重命名。
- 库内已有 70+ 本成品。动工前先 `search_files` 确认《书名》文件夹不存在，避免覆盖；再检索库内相关书目（同作者、同学派、同主题），正式导读和知识全览中用尖括号链接引用它们。
- 所有含空格的文件名链接必须用尖括号：`[文字](<原文/原文 01 xx.md>)`。

## 质量标准（硬性）

| 项目 | 标准 |
|---|---|
| 导读总字符数 | ≥ 20,000 |
| `## 正式导读` 之后字符数 | ≥ 16,000 |
| 问题链 | 恰好 9 问，标题`### 问题一：`至`### 问题九：`（中文编号） |
| 问题回答 | 200–400 字连续散文/题（不含标题与读原文链接） |
| 主节（`## N.`） | 300–600 字，每节一个独立论点 |
| 补充节（`## N.M 补充：`） | 100–400 字，深化侧面不重复主节 |
| 正式导读禁则 | 不用列表、不用 `###` 子标题（`**加粗**` 标记概念、段内粗体引导可以） |
| 收尾 | 最后一个主节必须是`思想座标` |
| frontmatter | `type: layered-reading-article`，`created` 必填 |
| 原文层 | 除每文件最前一个包装 H1 外逐字符保真，不改写不补写 |

字数一律按 Python `len()` 字符数计，不是词数。主节数量**不设指标**，按论点自然划分（近期成品自然落在 18–35 节），严禁为凑数拆散论点或注水同义反复。

## 执行流程

1. **核实环境**：确认读书库路径存在、目标《书名》文件夹不存在（存在则先读现状再协作，不覆盖）。完成标志：路径结论明确。
2. **勘察源文件**：`terminal` 跑 `wc -l -c` 和 `shasum -a 256` 记录哈希；检查开头/结尾/标题层级、目录重复、正文起止、章节边界、目录与正文是否对应、是否截断、是否多卷合集；按章抽查内容建全书地图。完成标志：明确判断源文件完整性、拆分方案、哪些是包装层/序言/正文。
3. **核对书目**：书名/作者/译者优先取自源文件，存疑才外部核对。`year` 填原著首次出版年份（合集跨年用带引号范围 `"2008-2017"`）；译者无法确认就省略字段，不写"未知"；`created` 填当天日期。
4. **拆分原文**：普通单卷本按主要章节拆，序言/附录/译后各自成篇；多卷本以册为文件；重复目录、残篇按 references/templates.md 的特殊情况规则命名保存，不静默删除。每个文件 = 一个包装 H1 + 对应源行区间，无 YAML 无导航。临时清单用完即删。完成标志：所有非空源行恰好落入一个原文文件、顺序一致（用验证脚本 `--source` 复核）。
5. **精读建图**：整理中心问题、概念依赖、关键证据与转折、各章论证功能、作者立场与时代语境、最强反例与方法限制、序言译后如何重新框定作者。导读按**理解顺序**重组，不按目录复述。
6. **库内交叉链接**：检索同主题/同作者/同传统的已有书目，规划导读中的引用链接。
7. **分块写作**（每块写完立即验证，不要把 2 万字压成单次输出）：
   a. 问题链（9 问，功能覆盖：进入全书→关键概念→核心机制→方法难题→章节转折→现实应用→最强反例→伦理/政治风险→今天如何用；多问题可指向同一章节）；
   b. 正式导读（第 0 节总论起，思想座标收尾）；
   c. 知识全览。
8. **自动验证**：`python3 <本skill目录>/scripts/validate_guide.py "<读书库>/《书名》" [--source 源文件路径]`。全部 FAIL 清零才算完成；WARN 逐条判断。字数不足时加实质性补充节（机制失败条件、竞争解释、反例、现实检验、伦理边界），不加同义句。
9. **收尾**：删除临时脚本/中间稿；复核源文件 SHA-256；按报告格式回复用户。

## 写作纪律

区分四种声音，不得混淆：作者本人主张 / 译者与序言判断 / 导读的重建 / 外部研究校正。不把中文版简评当作者原话，不把外部常识伪装成源文件内容；源文件残缺时只用实际保存的原文作证，可注明"完整版本目录坐标"，不伪造读到的假象。

导读不是赞美式摘要，必须同时"理解作者"和"审查作者"。批评优先落在：概念定义是否稳定、证据能否支撑结论、样本选择偏差、因果反向或第三变量、反例与失败条件、谁被排除在外、从描述跳到规范主张缺了什么、有用机制何时变成操控工具。每节写"是什么"还要写"为何成立、何时失效、怎样被误用"。思想座标覆盖：继承什么、对话/对立谁、颠覆什么、影响谁、留下什么张力——不是生平介绍。

## 验证

脚本检查：目录结构、原文编号连续性、原文层逐字符覆盖（给 `--source` 时）、YAML 与 `type`、九问数量/顺序/每题链接唯一且指向存在文件、各节字数（目标区间外、放行区间内记 WARN）、正式导读无列表无 `###`、思想座标收尾、知识全览存在性与结构、双向链接、`created` 字段。退出码非 0 即有 FAIL，必须修复后重跑。

## Pitfalls

- 知识全览**允许**列表和表格，正式导读**禁止**——两种文体别混。
- 源文件内部原有的 H1 属于源文本，原样保留，不因"一个文件多个 H1"判违规。
- 问题回答字数不含问题标题和读原文链接行。
- 库内旧书（尤其 2026-08 前）有阿拉伯编号问题链、无知识全览等旧格式，验证不适用，也不要顺手改造。
- 新会话不要相信旧交接文档里的任何路径与哈希记录，一律以本 skill 为准。
