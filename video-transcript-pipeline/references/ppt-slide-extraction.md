# 课程视频：PPT 页 ↔ 页面文字 ↔ 口述 三路对齐

适用：已落盘的课程 mp4，要做出「每页 PPT 图 + 该页上的文字 + 该页期间讲师说的话」三层结构。
四个阶段顺序执行，每阶段可单独重跑。

```
extract_slides.py  场景检测提帧 + 去重 + 时间区间 + 逐句挂页号
clean_slides.py    合并 <2s 碎片页
ocr_slides.py      macOS Vision OCR + 页眉页脚剔除
make_md_slides.py  生成三层对照 Markdown
```

基准：14 节 / 143 分钟 / 220 页 → 提帧约 20 分钟（解码全片）、OCR 2 分 11 秒、页面文字 12.7 万字。

## 1. 提帧（extract_slides.py）

```bash
python extract_slides.py <视频.mp4> <XX_proofed.json> <输出目录> [scene阈值=0.08]
```

- **场景阈值 0.08**。0.4 在两小时课件视频里只切出 2 张；0.08 才抓得住淡入淡出的翻页。
- **首帧单独截 t=0.5s**：开场常是静止标题页，不触发切换，不补截前几分钟直接为空。
- **去重用双哈希**：`aHash ≤ 8 或 dHash ≤ 6` 判同页。只用 aHash 会把「同一页加了红框标注」误删（那是真不同页）；只用 dHash 会漏纯白底轻微变化。只跟最近 2 页比——讲师真翻回旧页要保留。
- **时间接近优先**：两帧间隔 < 1.5s 视为同一次切换的动画过程，直接合并。
- **取时长用 `ffmpeg -i` 解析 stderr 的 `Duration:`**：本机 `~/.local/bin/ffprobe` 是 ffmpeg 的软链，用 ffprobe 参数拿到空值 → 最后一页 end=0。
- **重跑前删同前缀旧图**：页数变少时残留文件会把拼图和引用全搞错位。
- 输出 `slide = {idx, start, end, img}`，并把每句 `segment.slide` 指向它所在页。

## 2. 去碎片（clean_slides.py <目录> 2.0）

演示操作类视频（点浏览器/切窗口）会切出一堆 1.8 秒的闪帧。**< 2s 的页并入前一页**再重编号、重命名图片、重算 `segment.slide`。纯讲授节不掉页，演示节能从 37 页压到 30 页。

页数多少不代表对错：演示操作节 30+ 页/10 分钟正常，纯讲授节可能只有 2 页。

## 3. OCR（ocr_slides.py + scripts/ocr_vision.swift）

先编译（一次即可，约 55 秒）：

```bash
swiftc -O scripts/ocr_vision.swift -o ocr_vision
```

```bash
python ocr_slides.py <逐字稿目录>
```

**两条清洗规则，缺一不可：**

1. **按位置剔页眉页脚**（主力）：`y + h > 0.94` 或 `y < 0.035` 的行丢掉。这是唯一稳定的办法——见下面「模板行别靠文字频次」。
2. **按频次剔模板行**（补充）：单节内出现 ≥ 40% 页数的重复行，再用正则 `版权|www\.|\.com|公司|讲师|解螺旋|®` 分成两类：命中 → 当页脚丢弃；不命中 → 当 `header` 保留（那是统一章节标题，有信息量，别丢）。

另外丢掉 `conf < 0.3`、长度 < 2、纯符号的行，并清掉行首 `> • · -` 残留。

### 模板行别只靠文字频次

同一段页脚在每页 OCR 出来**字面不同**（`解螺旋®` / `解螺旋。` / 被合并成 `解螺旋 陪伴医生科研成 长 /02 PubMed数据库介绍`），精确匹配的频次统计根本命中不了。位置过滤才是稳的，频次只能当补充。

反向的坑：**频次过滤会把页标题一起删掉**——统一章节名（如「PubMed数据库基本介绍」）可能出现在 60% 的页上，直接 `in repeated` 就丢了。所以要先分出 header 再删。

## 4. 出 Markdown（make_md_slides.py）

每页结构：

```markdown
## 第 N 页（起–止）· 页眉标题
![](slides/xx_00N.jpg)

**📄 页面文字**
> OCR 结果整段

**🎤 口述**
**[时间戳]** 该页期间逐字稿（按 ~200 字分段）
```

页图用相对路径 `slides/xx_00N.jpg`（md 与 slides/ 同级），别再改路径否则图挂。

## 关键洞察：PPT 文字可以反校正逐字稿

同一句话，两种来源准确度差一个档：

| 来源 | 文本 |
|---|---|
| PPT OCR | 回溯至1966年的数据涉及40多个语种，90%左右为英文文献 |
| ASR 逐字稿 | 回湖至1966年尚数堀涉及40多个语种，90%左右为黄文文献 |

讲师打在屏幕上的字是**他自己确认过的原文**，比任何 ASR + 术语表都可靠。要修 `回湖至/黄文文献` 这类错误，唯一有效的办法是拿同页 OCR 文字去对齐改写该页时段的逐字稿，而不是继续扩术语表。

## 已知残留

- 页面小字（脚注、表格里的数字）OCR 会错，如 `数据→数椐`。
- 页面边缘装饰文字（`陪伴医生科研成长`）位置不固定，偶尔混进正文。
- OCR 只出文字，不认图表结构；柱状图/流程图里的数值关系拿不到。
